第 2 周教程：任务规划、反思与长短期记忆

本周要回答的三个问题

  1. 子目标拆解与 ToT/MCTS 的规划谱系怎么选？
  2. <reflection> 自我纠错的工程闭环怎么搭？它的能力边界在哪？
  3. 短期记忆的上下文管理（压缩/摘要）与长期记忆（Visual RAG）怎么分工？

对应学习计划：第 2 周。交付物：一个具备自我纠错能力的 Agent——工具调用抛 Exception / API 超时时，自动进入 <reflection> 状态分析 Traceback，重生成修正后的代码/参数直至成功。

1. 第一性原理：Agent 的三大失败面与三大对策

1.1 根本矛盾：任务长于一次生成，反馈慢于一次推理

第 1 周的 Agent Loop 解决了"单步行动的合法性"；但真实任务的两个特性让它不够：

  1. 任务长度：复杂任务需要几十步，模型无法一次规划全部——且中间结果会改变后续计划（计划必须可修订）；
  2. 反馈延迟：错误往往在第 k 步才暴露（工具报错、结果不符），而错误根源可能在第 j < k 步——需要回看与修正的能力。

三大失败面对应三大对策：

失败面 症状 对策（本周）
一次性规划过脆 中途变化后死守原计划 规划：子目标拆解 + 动态重规划（ToT/MCTS）
错误后盲目重试 同样的调用反复失败 反思：失败归因 + 修正后再试
上下文撑爆/遗忘 长任务后半段失忆 记忆：短期压缩 + 长期检索

1.2 规划谱系：从线性到搜索

子目标拆解（Sub-goal Decomposition）：把长指令拆成有序原子动作序列。工程要点：

  • 原子性判据：每个子目标可被 1~2 次工具调用完成、有独立可验证的完成条件（"下载报告"可验证、"研究分析报告"不可）；
  • 计划的数据形态：显式的任务清单（plan list）优于隐式推理——显式计划可以被程序跟踪进度、检测偏航、触发重规划（ReAct 的 Thought 里隐式规划是无法被程序审计的）；
  • 动态重规划：每步执行后对照计划，若 Observation 与预期不符（工具失败/前置条件变化），触发重规划而非死磕——ReAct 原始论文的核心卖点正是这种"计划可被推理修订"。

Tree of Thoughts（ToT）/ MCTS：线性规划在"路径有分叉、错误代价高"时不够——ToT 把推理组织成树，每个节点是一个中间状态，可以分叉探索多个假设、回溯剪枝；MCTS 用"选择→扩展→模拟→回传"的循环在树上做启发式搜索（AlphaGo 血统）。工程定位：

方法 搜索深度 成本（额外推理调用） 适用
线性 ReAct + 重规划 1 条路径 1× 步骤清晰、失败成本低
ToT（广度/深度搜索） 树形分叉 数×~数十× 关键决策点少但分叉价值高
MCTS 深度搜索 + 价值回传 数十~数百× 可模拟/可验证的环境（数学、代码、游戏）

经验规则：搜索的每一分收益都要用推理成本买单——先用线性 ReAct 打基线，仅在"已知会卡在特定分叉决策"时局部引入 ToT；全任务 MCTS 只在"验证便宜"（RLVR 式 Verifier 现成）时划算。RLVR 与搜索的深层关系：RL 训练是把搜索的成果蒸馏进策略——训练时多搜、推理时少搜。

1.3 Reflection：把错误反馈变成修正信号的闭环

Reflexion（Reflexion: Language Agents with Verbal Reinforcement Learning, NeurIPS 2023）的核心思想：把环境反馈（报错/失败）转化为语言形式的自我反思文本，存入记忆，指导下一次尝试——“verbal RL”：不用梯度，用文字强化。用大白话说：模型考试错了，把"错在哪、下次怎么改"写成便条贴在试卷旁边，重考时先读便条——便条（反思文本）就是"强化信号"，只是它作用在上下文里而不是参数上。

工程闭环的四要素：

  1. 触发条件（程序判定）：工具报错、结果校验失败、步数/预算超限——确定性触发，不依赖模型"自觉反思"；
  2. 反思输入：错误信息（Traceback 全文！不是摘要）+ 失败动作 + 相关上下文——Traceback 的行号与异常类型是归因的最强线索，喂摘要等于自废武功；
  3. 反思结构：<reflection> 标签内强制三段式——失败原因（归因）→ 证据（Traceback 中的哪一行）→ 修正方案（具体到参数怎么改）；
  4. 防循环：同一次失败的反思次数上限（如 2 次）、反思内容与上次失败的相似度检查（反思了却提出同样的方案 = 归因失败，升级为换策略/求助）。

能力边界（必须诚实）：Reflection 修的是"可从反馈推断原因"的错误（参数错、超时、格式错——反馈里有线索）。对"反馈正确但模型不理解"（能力不足）或"反馈本身误导"的情况，反思只是高级的复读。Reflection 提升的是"把会做的事做对"，不是"把不会的变成会"——后者属于训练问题（Stage 4/7 的数据与 RL）。

1.4 记忆架构：短期压缩与长期检索的分工

短期记忆（Context Window 内）：

  • 问题：多步轨迹（尤其含图像/长 Observation）迅速撑爆窗口；
  • 手段：历史压缩——旧的 Observation 用摘要替换（保留结论与关键数据，丢弃过程文本）；旧截图缩略化；工具结果超过阈值即截断+指针；
  • 关键纪律：压缩的是过程，不是约束——任务目标、已完成的关键结论、坐标约定等"约束性信息"永不压缩（Stage 9 的 Agent 失忆高发点：把坐标约定压没了，后续全部坐标引用错位）。

长期记忆（Visual RAG）：把历史关键帧/截图 + 对应坐标与 Action 写入向量库，跨任务/跨时域检索：

  • 写入时机：任务完成点、关键中间结论点（不是每帧都存——噪声入库会稀释检索）；
  • 检索键：任务语义（embedding）+ 结构化过滤（时间/任务类型/实体）；
  • 与 Stage 4 的关系：这就是 RAG 在轨迹数据上的应用——检索的是"过去的经验"而非"知识文档"；
  • 坑：检索到的旧经验可能是错误经验（当时的失败教训）——存储时要带"成功/失败"标签，检索时优先成功案例、失败案例作为警示注入。

2.1 本周 MVP：自我纠错 Agent（Reflection 闭环）

预期输出：

断言验证反思闭环的四个关键行为：Traceback 驱动的归因（NameError/KeyError 被正确分类）、三段式结构、逐次修正的推进（第 1 次反思修一个 bug、第 2 次修另一个）、同方案失败的升级策略（防反思循环）。

3. 工程权衡与失效模式

3.1 决策表：记忆与规划的成本谱系

手段 成本 收益 起用时机
History 截断 零 防溢出但丢信息 首选兜底
Observation 摘要 少量 LLM 调用 保留结论省窗口 轨迹 > 10 步
显式 Plan 清单 1 次规划调用 可审计/可重规划 ≥3 子目标的任务
Visual RAG 长期记忆 向量库 + 写入策略 跨任务经验复用 多任务持续运行
ToT/MCTS 数十×推理 关键分叉的决策质量 验证便宜 + 决策点少而关键

3.2 三个代表性失效模式

失效 1：反思循环（Reflection Loop）——归因错误导致的"改错方向"

  • 症状：同一错误反复出现，每次 reflection 都在变但都没修到点上，步数耗尽。
  • 根因：反馈与真实根因脱节（Traceback 显示 KeyError，但根因是上游数据没加载）；或模型归因能力不足，反思是"重新表述错误"而非定位错误。
  • 定位：审计反思链——相邻两次反思的"修正方案"若无实质推进即确认。
  • 修复：升级策略（换工具/换方法/请求人工——1.3 节的防循环闸）；或给反思器喂更多结构化上下文（前置步骤的状态快照）；承认能力边界，把"反思解决不了"的失败导流到训练侧（Stage 4/7）。

失效 2：长期记忆的"错误经验污染"

  • 症状：Agent 在新任务中重复旧任务的错误做法（或拒绝旧任务里已验证可行的方法）。
  • 根因：Visual RAG 检索到的经验不带对错标签，或相似度检索把表面相似、实质不同的任务错配。
  • 定位：抽查检索命中记录 vs 当前任务的适配性。
  • 修复：经验入库带成功标签与任务指纹；检索后加一层"适用性自检"（让模型显式判断"这个经验适用吗"）；定期清洗记忆库（Stage 4 清洗纪律的记忆版）。

失效 3：摘要压缩丢掉了关键约束

  • 症状：长任务后半段坐标引用错位、单位混乱、目标漂移。
  • 根因：摘要器把约束性信息（坐标约定/单位/任务目标）当过程文本压缩掉了。
  • 定位：对压缩前后 diff，检查约束性关键词是否存活。
  • 修复：约束保护名单（2.2 的 CONSTRAINT_KEYS）+ 关键约束置顶注入每轮 prompt；摘要 prompt 显式声明"禁止压缩约束与结论"。

4. 延伸思考题

  1. Reflexion 与 RL 的光谱：Reflexion（文字强化）与 GRPO（梯度强化）处在什么光谱的两端与中间？给一个任务特征表：什么时候文字反思够用，什么时候必须上梯度训练？（提示：任务新颖性、反馈密度、算力预算、部署是否允许长上下文反思——Reflexion 的成本在推理侧、RL 的成本在训练侧。）
  2. Plan 的可审计性：显式 Plan 清单让"程序检测偏航"成为可能。设计一个"计划偏航检测器"：每步执行后判断当前轨迹是否仍服务于计划中的子目标，偏航时触发重规划。（提示：子目标的完成谓词 + 当前 Observation 的相关性判定；这是把"规划"从 prompt 里的自由文本升级为可管理状态机的一步。）
  3. 记忆的遗忘权利：长期记忆里的历史截图可能包含敏感信息（用户数据）。设计一个"可撤回的记忆"机制：用户要求删除后，向量库与摘要中的对应条目如何真正消失？（提示：这是 RAG 系统的经典 GDPR 难题——向量的删除与派生摘要的传播，值得系统设计期就考虑。）

第 4 周教程：Agent 轨迹合成、Sanity Check 与异常数据清洗

本周要回答的三个问题

  1. TaskCraft 式的轨迹合成机制（depth/width 扩展）怎么运作？
  2. 死循环检测、逻辑断层检测、Trajectory Pruning 各自的判定算法是什么？
  3. 清洗后的轨迹如何格式化反哺 SFT/RL 训练？

对应学习计划：第 4 周。交付物：Trajectory Filter——对 200 条多步 Agent Trace 自动审查，过滤死循环/环境反馈异常/盲目操作，产出可训练的 JSONL 数据集。

文献勘误与核实：学习计划所引标题 “TaskCraft: Structuring Execution Trajectories for Agentic Post-training” 不准确。已核实（arXiv:2506.10055，v2）：正确标题为 TaskCraft: Automated Generation of Agentic Tasks——其核心机制是 depth-based 与 width-based 两个扩展算子（对原子任务做深度扩展【加推理深度/子任务链】与宽度扩展【加工具多样性/多跳】），生成难度可扩展、多工具、可验证的 Agentic 任务与执行轨迹，规模约 3.6 万条。第 4 阶段教程已按此勘误过一次，本篇按正确机制展开。

1. 第一性原理：轨迹数据的"噪声放大器"效应

1.1 根本矛盾：Agent 的失败轨迹比 SFT 错标更毒

第 6 阶段第 3 周已论证"偏好数据是 DPO 的裁判"；本阶段的轨迹是 SFT/RL 的行为示范，噪声的危害机制不同且更隐蔽：

  1. SFT 的行为模仿是全过程的：模型不只学"最终答对"，还模仿每一步的风格与节奏。若轨迹里充满试错（调用→失败→重试），模型学会的不是"如何排错"，而是**"先随便试、失败很正常"的行为先验**——低效试错被当成了标准动作（学习计划达成标准的原文：剪枝确保模型学习最短最优路径）。
  2. 死循环轨迹 teaches 循环：重复同一动作的轨迹若混入训练，模型在推理时遇到相似状态就会进入同样的循环——这是部署期死循环的重要来源之一。
  3. 伪成功比失败更毒：最终答对但过程有错的轨迹（错误中间量被后续巧合纠正）教模型"过程不必严谨"。

因此 Agent 轨迹的清洗标准必须严于一般 SFT 数据：不只查"对不对"，还要查"过程是否高效、每步是否有依据"。

1.2 TaskCraft 的合成机制（正确版）

TaskCraft 的合成流程（已核实 arXiv:2506.10055 v2）：

关键设计：任务与验证器原子绑定（Stage 4 的纪律）、难度由扩展算子参数化（可控地生成难例课程）、轨迹来自真实工具环境执行（Observation 不许编造）。这套"算子化合成"比人工标注可扩展得多——3.6 万条任务，且 depth/width 两个轴天然支持课程化采样（Stage 7 的动态难度）。

1.3 三类清洗的判定算法

① 死循环检测（Loop Detection）：

  • 精确重复：相邻 kkk 步的 (tool, args) 完全相同且无 intervening 成功信号；
  • 语义重复：动作参数略变但目标相同（连续 3 次对同一区域 Crop）——用动作嵌入相似度或"同一元素+同类动作"判定；
  • 状态不前进：连续 N 步的环境状态指纹（页面 URL+关键元素哈希/文件哈希）无变化。

判定不是"有重复就删"：带进展的合法重试（每次参数不同且逐步逼近，如二分查找式的尝试）是有价值的纠错示范。判定核心是"重复且无信息增量"。

② 逻辑断层检测（Thought-Action 因果一致性）：

  • Thought 声称"先搜索价格"而 Action 却调用了 OCR——语言与行为脱节；
  • 判定手段：(a) 规则版——Thought 中的动词/宾语与工具功能词表匹配；(b) 模型版——用 LLM 判"该 Thought 是否支持该 Action"（Stage 3 的 Judge 纪律：固定 prompt、报一致率）；
  • 最强信号仍是执行验证（Stage 4 第 3 周）：Observation 与 Action 语义不符的步就是断层证据。

③ Trajectory Pruning（轨迹剪枝）：

  • 目标：从"10 步试错轨迹"提取"4 步最优直线轨迹"；
  • 前提：只有成功轨迹可剪（失败轨迹要么整条剔除、要么只保留到失败点并标注失败原因作负样本）；
  • 剪枝准则：删除"对最终结果无贡献"的步——判定方式是消融回放：把候选步从轨迹中移除后重放，若最终结果与工具状态不变则该步冗余（严格版）；近似版用"该步的 Observation 是否被后续步引用"（引用图分析）判定；
  • 剪枝后必须重新校验：剪枝轨迹重放成功（环境有状态时，剪枝可能破坏前置条件——只有无副作用/可重放的轨迹才能激进剪枝）。

2. 实现与验证

2.1 本周 MVP：Trajectory Filter

配套测试数据与运行：

健康度判读：保留率 60~85% 是真实混合数据的典型区间；接近 100% 说明过滤器没生效（用注入的坏轨迹组验证漏报率）；低于 40% 说明数据源质量崩了（回查合成管线而非调松过滤器——Stage 5 的"修复点在上游"纪律）。

2.2 断层检测的模型版（LLM Judge）

规则版词表覆盖有限；模型版把 (thought, action) 对交给 LLM 判定"该 Thought 是否为该 Action 提供依据"，输出 yes/no + 理由。纪律沿用 Stage 3 第 1 周：裁判 prompt 固定、温度 0、抽样人工校准一致率（Kappa >0.6 才可用）。规则版与模型版混跑取交集（两者都判断层才剔）可显著降误杀。

3. 工程权衡与失效模式

3.1 决策表：过滤与剪枝的阈值

决策点 保守 激进 说明
死循环窗口 3 步全同 2 步全同 窗口小易误杀合法短重试
断层判定 规则+模型双确认、≥2 处才剔 单处即剔 误杀好轨迹的代价 > 漏放差轨迹（SFT 噪声不对称）
失败轨迹处理 全部剔除 带标注保留（纠错示范/RL 负样本） 取决于下游用途（SFT 剔、偏好训练留）
剪枝强度 只删"确认无引用"步 消融回放严格验证 有状态环境必须保守

3.2 三个代表性失效模式

失效 1：过度剪枝破坏了环境前置条件

  • 症状：剪枝后的轨迹重放失败（如删掉了"登录"步，后续"下单"步失去前置状态）。
  • 根因：引用图分析只看了文本引用，没看环境状态依赖（登录/建目录/加购物车这类状态变更步是隐式前置条件）。
  • 定位：剪枝轨迹抽样重放，统计失败率。
  • 修复：状态变更类动作标记 essential=True 不可剪（本 MVP 已内置字段）；有条件时以重放验证为剪枝准绳。

失效 2：断层检测的误杀——工具语义与用词不匹配

  • 症状：合理的轨迹被大量剔除（保留率异常低）。
  • 根因：规则词表覆盖不足（Thought 写"提取文本"而词表只有"识别"，工具是 OCR）——语义相关但词面不匹配被判断层。
  • 定位：抽样被剔除的"断层"轨迹人工复核，误杀率 >20% 即确认。
  • 修复：模型版 Judge 兜底（规则判断层的再过一道 LLM 确认）；词表按实际工具描述对齐扩充。

失效 3：剪枝剪掉了"有价值的纠错示范"

  • 症状：清洗后的模型在真实环境遇错就卡死（训练数据里全是直线轨迹，没见过失败）。
  • 根因：把失败步全剪成"完美轨迹"，模型没有习得"从 Observation 中的错误信号恢复"的行为（第 2 周 Reflection 的能力没有数据支撑）。
  • 定位：对比清洗前后模型在"含错误注入的任务"上的恢复率。
  • 修复：分池策略——SFT 主池用剪枝直线轨迹，另设 10~20% "带一次纠错"的轨迹池（保留一次失败+反思+修正），与 Stage 4 第 3 周的负样本注入比例一致。

4. 延伸思考题

  1. 剪枝与探索的辩证：Stage 7 的 RL 需要探索（奖励会强化成功路径，探索由采样机制保证），而 SFT 的轨迹剪枝消灭探索痕迹。论证：为什么"SFT 用最优轨迹 + RL 用原始轨迹"是正确分工？（提示：SFT 是行为克隆——克隆什么就成为什么；RL 的优势加权天然会放大好轨迹、稀释差轨迹，原始轨迹反而提供必要的探索分布。）
  2. 断层检测的边界：Thought 与 Action 的"因果一致性"真的可判定吗？构造一个"Thought 与 Action 字面不相关但行为合理"的反例（如 Thought 决定"先确认页面状态"而 Action 是无操作等待）。（提示：状态检查类/等待类动作天然"无依据"——断层检测必须带工具语义知识或跳过白名单，纯文本判定有天花板。）
  3. 跨阶段审计链：把 Stage 4（合成）、Stage 7（RL 轨迹）、本阶段（清洗剪枝）的轨迹流水线写成一张"质量闸门图"：每一环的输入/输出/质量闸/失败流向。检查点：Stage 7 的"全同组无梯度"与本阶段"死循环剔除"的判定逻辑同构（信号为零的数据没有训练价值）。

第 3 周教程：视觉 GUI / Web / OS 操作控制 Agent（Screen Grounding Agent）

本周要回答的三个问题

  1. 截图到动作（Click/Type/Scroll）的映射管线怎么搭？
  2. Set-of-Mark（SoM）为什么能把"连续坐标回归"变成"离散选择题"？它的失效面是什么？
  3. Playwright 自动化环境怎么与 Agent Loop 安全地接起来？

对应学习计划：第 3 周。交付物：Playwright + SoM/Grounding 的 Web GUI Agent——自然语言指令驱动，实时截图解析、生成点击/输入操作，连续完成 ≥5 步网页操作。

1. 第一性原理：GUI 操作是"感知粒度"与"动作精度"的双重考验

1.1 根本矛盾：VLM 的坐标精度 vs 交互元素的像素要求

点一个按钮需要 ±5 像素级的定位精度，而 VLM（Stage 1/3 的结论）对绝对坐标的预测能力薄弱：视觉 Token 的粒度（Stage 1 的 patch 网格）、空间编码的先天薄弱、训练数据里坐标约定混乱，都让"直接预测 (x, y)"成为 Agent 成功率的最大短板。

两条技术路线直击这个矛盾：

路线 思路 代表 精度来源
专用 Grounding 模型 用大规模"截图-元素框"数据专门训练 GUI 元素定位 SeeClick（SeeClick: Harnessing GUI Grounding for Advanced Visual GUI Agents, ACL 2024）、OmniParser（微软，截图→结构化 UI 元素解析器） 专项训练的定位头
SoM 提示工程 在截图上叠加编号标记，让模型"选编号"而非"算坐标" Set-of-Mark（SoM prompting） 把回归问题变成分类问题

两者常组合使用：OmniParser 解析出所有可交互元素 → SoM 叠加编号 → VLM 选编号 → 程序取编号对应元素的精确中心坐标执行点击。

1.2 SoM 的第一性原理：回归 → 选择的难度坍缩

为什么"选编号"远易于"算坐标"：

  1. 输出空间的性质：坐标回归要求模型从连续空间精确输出数值（且要求与视觉 Token 网格对齐——Stage 1 的 14px patch 粒度决定了原生精度极限）；而选编号是一个离散分类，模型只需在语义层面回答"哪个标记是目标"——这正是 LLM/VLM 最擅长的"指认"能力。
  2. 感知辅助：编号标记本身就是视觉锚点——模型不需要在密集 UI 里"内部定位"，标记替它完成了"关注点显式化"。这与 Stage 3 的发现同源：模型对"图中有什么"尚可，对"哪里"很弱——SoM 把"哪里"外包给了程序画上去的标记。
  3. 精度兜底：编号对应的可点击区域由程序（OmniParser/浏览器 DOM）给出精确几何坐标——点击精度与 VLM 无关，100% 对齐。

SoM 的失效面（同样重要）：标记过密时编号拥挤/遮挡 UI（标记本身干扰感知）；元素语义不清时编号选择仍靠模型（SoM 只解决定位不解决语义理解——"哪个是搜索按钮"仍要模型判断）；动态页面标记过期（标记基于旧截图，DOM 已变——必须"截图→标记→决策→执行"原子化，禁止跨轮复用标记）。

一句话总结：SoM 把"模型算不准的连续坐标"换成了"模型最擅长的离散指认"，像素精度由程序兜底——模型负责选对，程序负责点准。

1.3 GUI Agent 的动作空间与安全边界

动作空间（从 Web 到 OS 递增危险等级）：

动作 Web（Playwright） 桌面（PyAutoGUI） 危险等级
Click (x,y) page.click / 元素引用 坐标点击 中（点错按钮可能不可逆）
Type page.fill 键盘模拟 中（输错文本可撤回，但可能触发提交）
Scroll page.scroll 滚轮模拟 低
提交类（下单/删除/发送） 表单提交 回车/按钮 高——必须有确认闸

安全边界三原则：白名单域（Agent 只在指定网站活动）、破坏性动作人工确认（下单/删除/支付类动作必须停下来等人批准）、全程审计日志（每个动作的截图/参数/结果可回放——Stage 4 轨迹审计的地基）。

3.2 三个代表性失效模式

失效 1：标记过期（Stale Annotation）——点错位置

  • 症状：点击执行后落点与预期元素无关；轨迹里出现"element_id 不存在"。
  • 根因：页面在标记生成与执行之间发生了变化（动画/异步加载/广告轮播）——SoM 的编号与当前 DOM 已错位。
  • 定位：执行前重截屏 diff（像素差或元素集 diff）。
  • 修复："截图→标注→决策→执行"严格原子化，执行前校验元素几何未变（重查 bounding_box 一致性）；不稳定页面在动作间加 wait_for_load_state。

失效 2：SoM 标记遮挡与编号爆炸

  • 症状：密集 UI（后台管理系统）上模型选错编号，或干脆"看不见"某些编号。
  • 根因：可交互元素过多（>40 个）时编号重叠、字体过小；标记遮挡了目标元素本身的视觉特征。
  • 定位：人眼看标注图——你自己认不清编号，模型更不行。
  • 修复：元素过滤（只标可交互且可见的）；分区域标注（先选区域再局部标注——层次化 SoM）；编号字体/位置优化（外部角标而非覆盖中心）。

失效 3：破坏性动作的自动化事故

  • 症状：验收跑得很顺，直到 Agent 在真实站点上点了"确认支付"/清空了测试数据。
  • 根因：缺少危险动作确认闸与白名单域；验收环境与生产环境未隔离。
  • 定位：审计日志里的事故动作回放。
  • 修复：三原则落地（白名单/确认闸/审计）；测试账号 + 测试环境隔离；对"提交类"DOM 事件做静态拦截（Playwright route 拦截支付接口）。

4. 延伸思考题

  1. SoM 的信息论视角：把"选编号"与"预测坐标"作为两个通信信道比较——前者传递 log⁡2N\log_2 Nlog2​N bit（N 个元素），后者要求连续数值精确到像素。从"信道容量与任务需求匹配"的角度，论述为什么 UI 元素语义分割（OmniParser 类）+ 离散选择是更优的编码方式，以及它牺牲了什么（自由落点、画布类应用）。
  2. Grounding 的跨域泛化：SeeClick 类模型在 Web 上训练，到 OS 桌面（图标/菜单栏风格完全不同）泛化会掉多少？设计一个跨域评测协议（Web/OS/移动端三域同任务族），并预测掉分模式。（提示：布局先验与元素形态先验是域特定的——这正是 OmniParser 走"通用 UI 解析"路线的动机。）

1. 第一性原理：从单 Agent 到多 Agent 的决策

1.1 根本矛盾：上下文是共享的，而职责是冲突的

单 Agent（一个模型 + 全部工具 + 完整上下文）在任务复杂后有四类退化：

  1. 上下文竞争：任务规划需要的全局视野与子任务需要的细节细节挤同一个窗口——细节多了规划变糊，视野够了细节装不下；
  2. 指令稀释：工具越多决策越差（Stage 9 第 1 周失效 2）；提示词既要管规划又要管 OCR 要领，哪个都写不透；
  3. 错误级联：单 Agent 的一个坏决策直接传导到最终输出，无隔离；
  4. 不可审计：所有推理混在一条轨迹里，失败归因困难。

多 Agent 的本质是"职责分治"：每个专职 Agent 有窄工具面、聚焦的 System Prompt、独立的上下文——用消息传递交换结论而非共享全部过程。这换来可审计性（每个 Agent 的输入输出清晰归档）与隔离性（Vision Agent 的失败不污染 Reporter），代价是通信开销与全局视野损失——协调者看不到执行细节，可能做出脱离实际的规划。

1.2 多 Agent 的决策判据（什么时候值得拆）

信号 建议
任务可分解为异质能力域（视觉检查/代码计算/写作） 值得拆——各域的 prompt 与工具可深度专业化
单 Agent 上下文已溢出或工具 >10 个 值得拆
子任务高度同质、串行依赖 不拆——多 Agent 是通信开销纯浪费
需要并行处理独立子任务 值得拆（并行化收益）

反面提醒：多 Agent 不是高级的标志。业界常见教训是"为拆而拆"——三个 Agent 互相传话损失的信息比专业化的收益还大。先证明单 Agent 失败的具体环节，再为那个环节拆出专职 Agent。

2.3 鲁棒性四件套

件 实现 防的是什么
超时控制 每个工具/子任务带 timeout（asyncio.wait_for / 沙盒 timeout），超时按失败处理 单点挂死拖垮全局

Guardrails 的实现原则：静态拦截在执行前（便宜、确定），动态审查在执行后（LLM 审计，抽查）——顺序不能反（先执行后审查的 Guardrail 只能善后）。

3.2 三个代表性失效模式

失效 1：错误级联的静默传导——上游低置信结果被下游当真Influencer

  • 症状：最终报告的数字与源文档不符，逐环节检查才发现图表读数就错了（置信度 0.2 被标注但无人处理）。
  • 根因：子 Agent 报告了 issues 与低 confidence，但 Planner 没有按置信度分流的逻辑——审计信息只是记了没用。
  • 定位：审计日志回放，找置信度低于阈值仍被消费的消息。
  • 修复：Planner 的谓词逻辑加入置信度门槛（<0.5 触发重试或人工标注降级路径）；"issues 非空 → 必须有处置动作"作为系统不变量。

失效 2：多 Agent 的"传话失真"

  • 症状：Planner 汇总的结论与子 Agent 的原始发现不一致（数字被四舍五入丢精度、限定条件丢失）。
  • 根因：消息在多跳传递中被自然语言转述而非结构化透传——每跳转述都是一次信息有损压缩。
  • 定位：逐跳 diff payload。
  • 修复：结构化数据（数字/表格/文件引用）透传不转述，转述只用于自然语言摘要；关键数字在最终报告中可溯源到消息 ID。

失效 3：Guardrails 误伤与漏防的失衡

  • 症状：正常代码被拦截（误伤）导致任务频繁失败；或上线后仍出现破坏性操作（漏防）。
  • 根因：静态规则过宽/过窄；Guardrails 只在单点（Planner）设防，专职 Agent 的直接工具调用绕过了检查。
  • 定位：拦截日志的误报率 + 红队测试（故意注入危险指令）的漏报率。
  • 修复：Guardrail 作为总线层的统一关卡（所有副作用动作必经）而非各 Agent 自查；规则分级（硬拦截/确认闸/仅记录），红队集持续回归。

1. 第一性原理：量化 = 把连续值塞进有限网格

1.1 问题定义

量化的本质是一个多对一映射：把 FP16/FP32 的连续（或高分辨率）数值，映射到 2b2^b2b 个离散码点上。位宽 bbb 决定码点数：8-bit 有 256 个码点，4-bit 只有 16 个。

量化三要素：

  • 位宽（bit-width）：码点数 2b2^b2b；
  • 缩放因子（scale） sss：决定网格步长，即一个码点代表多大的实数；
  • 零点（zero-point） zzz：整数网格中哪个码点对应实数 0（仅非对称量化需要）。

1.2 对称量化（Symmetric）

假设权重分布关于 0 近似对称（LLM 权重基本满足），直接用绝对值最大值定网格：

s=max⁡(∣w∣)2b−1−1,q=round ⁣(ws),q∈[−2b−1, 2b−1−1]s = \frac{\max(|w|)}{2^{b-1} - 1}, \qquad q = \mathrm{round}\!\left(\frac{w}{s}\right), \quad q \in [-2^{b-1},\ 2^{b-1}-1] s=2b−1−1max(∣w∣)​,q=round(sw​),q∈[−2b−1, 2b−1−1]

反量化（dequantize）：w^=q⋅s\hat w = q \cdot sw^=q⋅s。

这个公式在干什么：sss 是"一个整数格有多宽"。除以 sss 把实数轴压到整数格上，round 负责吸附到最近的格点，乘回 sss 就还原成实数——误差因此永远不超过半格 s/2s/2s/2。它回答"用 2b2^b2b 个等距码点表示这段权重，最粗能到什么分辨率"。

注意 INT8 对称量化的分母是 27−1=1272^{7}-1 = 12727−1=127 而不是 128——为了保持网格关于 0 对称，负侧的 -128 被舍弃（否则负侧比正侧多一个码点，0 会偏离网格中心）。

优点：无零点、乘法路径简单（整数乘 + 一次缩放）；缺点：若分布偏斜（如 ReLU 激活全为正），一半网格被浪费。

1.3 非对称量化（Asymmetric）

用完整的 [wmin⁡,wmax⁡][w_{\min}, w_{\max}][wmin​,wmax​] 区间铺满整个码域：

s=wmax⁡−wmin⁡2b−1,z=round ⁣(qmin⁡−wmin⁡s)s = \frac{w_{\max} - w_{\min}}{2^b - 1}, \qquad z = \mathrm{round}\!\left(q_{\min} - \frac{w_{\min}}{s}\right) s=2b−1wmax​−wmin​​,z=round(qmin​−swmin​​)

这个公式在干什么：非对称量化不再假设分布关于 0 对称，而是把 [wmin⁡,wmax⁡][w_{\min}, w_{\max}][wmin​,wmax​] 这段"实际用到"的区间恰好铺满 [qmin⁡,qmax⁡][q_{\min}, q_{\max}][qmin​,qmax​] 全部码点——sss 仍是一个格的宽度，zzz 则回答"实数 0 落在第几个码点上"。反量化时先减 zzz（回到以 0 为原点的整数格）再乘 sss。

优点：对偏斜分布（激活值常见）网格利用率 100%；缺点：多一个零点，GEMM 展开后多出若干校正项，内核更复杂。这就是面试标准答案：权重常用对称（分布对称、内核简单），激活常用非对称（分布偏斜、范围动态）。

1.6 离群值：LLM.int8() 的实证

LLM.int8()（Dettmers et al., 2022，arXiv:2208.07339）观察到一个规模相关的涌现现象：模型规模越过 6.7B 后，Transformer 隐藏状态中涌现出极端离群特征——幅度比普通激活高 1~2 个数量级（大模型中可达 ±60~100，普通激活约 ±10），且它们高度系统性地集中在极少数固定通道（约占隐藏维度的 0.1%，如数千维中只有几维到几十维），跨层、跨样本位置不变。

后果：对激活做 per-tensor 量化时，sss 被这 0.1% 的通道拉大两个数量级，其余通道的有效分辨率几乎归零，精度崩塌。LLM.int8() 的解法是把离群通道拆出来走 FP16（混合精度分解）；后续的 SmoothQuant（难度迁移）与 AWQ（显著通道保护）是两条不同的路线——第 2 周与 Stage 2 第 2 周详解。

4. 工程权衡与失效模式

4.1 权衡

  • 对称 vs 非对称：对称内核简单但浪费偏斜分布的网格；非对称多一个零点与校正项。权重对称、激活非对称是默认配方。
  • 粒度越细越准，但 scale 存储与内核复杂度上升：per-group(128) 相比 per-tensor 每 128 权重多 2 字节（FP16 scale），4-bit 下相对开销 +3%（0.125/4.25），换来显著的精度隔离——值得。
  • 位宽与误差的平方律：降位宽是最便宜的压缩（8→4 体积减半），但 MSE 是平方恶化，4→2 通常需要换算法（NF4/imatrix/QAT）而不是硬降。

4.2 失效模式（至少记住四条）

  1. 离群值撑爆 scale：症状——per-tensor 量化后 PPL 暴涨；根因——个别通道幅度超主体 1-2 个数量级；定位——画激活/权重直方图、按通道统计 abs().amax()；修复——per-group、SmoothQuant 或混合精度。
  2. 校准区间未覆盖：症状——部署分布与校准分布不同（如长序列、新领域）时精度骤降；根因——wmin⁡/max⁡w_{\min/\max}wmin/max​ 只是校准集的统计；修复——校准集覆盖真实流量分布（第 2 周）。
  3. 舍入偏置累积：症状——深层网络逐层误差漂移，输出分布偏移；根因——round 的期望误差在偏斜输入下非零；修复——随机舍入（stochastic rounding，QAT/QLoRA 用）或二阶补偿（GPTQ，Stage 2 第 1 周）。
  4. 反量化位置放错：症状——自己写的推理路径与官方结果不一致；根因——scale 应作用在 GEMM 之后（先整数累加再缩放），放错位置既慢又可能溢出；修复——核对内核的数据流图。

Q1：权重范围 [−3.2,4.8][-3.2, 4.8][−3.2,4.8]，INT8 对称量化的 scale 和步长是多少？与非对称相比谁的量化误差更小？
A：对称 s=4.8/127≈0.0378s = 4.8/127 \approx 0.0378s=4.8/127≈0.0378；非对称 s=8.0/255≈0.0314s = 8.0/255 \approx 0.0314s=8.0/255≈0.0314。非对称步长更小且区间铺满，本例误差更小；但对称量化把 4.8~8.0 之外的负区间也留给网格（对称扩展到 ±4.8），若真实分布对称则两者接近。偏斜越严重，非对称优势越大。

Q2：per-group(128) 相比 per-tensor 额外存储多少？7B 模型 INT4+g128 的总 bpw 是多少？
A：每 128 个权重多一个 FP16 scale = 16 bit / 128 = 0.125 bpw；若零点也用 FP16 则再加 0.125。常见实现只存 FP16 scale（零点为常数 8 或与 scale 打包），总位宽 ≈ 4 + 0.125 ≈ 4.125~4.25 bpw。7B ≈ 7×10⁹ × 4.25/8 ≈ 3.7 GB。

Q3：为什么 FP8 需要两种格式？E4M3 和 E5M2 分别用在哪？
A：前向的权重/激活幅度集中（±448 足够），需要尾数精度 → E4M3；反向梯度跨多个数量级且可能瞬时很大，需要动态范围 → E5M2（最大 57344）。这是"精度优先"与"范围优先"的分工。

Q4：NF4 为什么对 LLM 权重是"信息论最优"？如果权重不服从正态分布会怎样？
A：NF4 码点取正态分布的分位数中点，使每码点期望平方误差最小——前提假设就是权重 ~ 正态（QLoRA 用分块归一化强制满足该假设）。若权重分布明显偏离正态（如稀疏化后、某些蒸馏模型），码点失配，NF4 优势消失甚至不如 INT4+GPTQ。

Q5：量化误差为什么可能让 softmax 后的分布"偏移"而不仅仅是"变噪"？
A：softmax 对 logits 的差异做指数放大：若量化误差在类别维度上系统性偏置（非对称舍入、离群通道），头部 token 的相对优势被压缩或放大，采样分布整体漂移——表现为生成质量下降但 PPL 只微涨。这就是评测不能只看 PPL 的原因（Stage 2 第 5-6 周展开）。

1. 第一性原理：校准 = 用少量数据估计"该用哪张网格"

1.1 问题定义

第 1 周讲过：量化误差 E[ε2]≈s2/12\mathbb{E}[\varepsilon^2] \approx s^2/12E[ε2]≈s2/12，而 sss 由校准统计量决定。PTQ（Post-Training Quantization，训练后量化）的核心问题就是：

在不更新任何权重的前提下，用一小批有代表性的数据，为每一层选出使下游任务损失最小的 (s,z)(s, z)(s,z)。

权重是静态的，一次统计终身有效；激活是输入相关的，必须用校准集"看一遍"才能定范围——这是"校准"二字的由来。

1.2 校准数据集：多少条、怎么选

  • 数量：128~1024 条足够。激活分布的统计量（分位数、直方图）收敛很快，边际收益在几百条后趋平。
  • 代表性：校准集必须覆盖部署分布。通用 LLM 用 WikiText-2 / C4 切片（每条约 2048 token）；垂类部署（如客服、代码）必须混入领域数据，否则激活范围估计偏小 → 部署时裁剪（clipping）激增。
  • 长度：按模型训练序列长度截取（常见 2048），太短会低估长上下文激活。

1.3 统计量怎么收

对每一层的输入/输出激活，在校准前向时挂 hook，累积以下之一：

  • 运行极值 min⁡/max⁡\min/\maxmin/max（MinMax）；
  • 全量样本的分位数（Percentile）；
  • 直方图 h(x)h(x)h(x)（MSE 与 KL 都需要，典型 2048 个 bin）。

5. 工程权衡与失效模式

5.1 权衡

  • 校准成本 vs 精度：KL/MSE 要遍历直方图若干遍，比 MinMax 慢一个量级；但只在离线做一次，通常值得。
  • 裁剪点选择：阈值越激进（分位数越低），网格越细、裁剪越多——PPL 曲线通常呈 U 形，最优点在 99.5%~99.99% 之间。
  • 静态量化 vs 动态量化：动态量化（运行时算激活 scale）免校准但每步多一次统计开销，只适合激活难校准的场景。

5.2 失效模式

  1. 校准集与部署分布错位：症状——评测 PPL 正常、线上长文本崩坏；根因——校准文本过短或领域不符；修复——按真实流量采样校准集、加长序列。
  2. KL 校准的直方图饱和：症状——TRT 校准出的模型在极端输入上输出乱码；根因——校准集未覆盖极端幅度，直方图边界即裁剪边界；修复——扩大校准分布范围或用 Percentile 回退。
  3. 逐层误差累积：症状——浅层单层余弦相似度都 > 0.999，整模型 PPL 仍明显上涨；根因——误差沿深度复合放大，敏感层（通常是第一层与 lm_head 邻近层）需要保护；修复——敏感层保留 FP16（混合精度量化）。
  4. 激活非对称却按对称校准：症状——ReLU/正偏激活量化后均值漂移；根因——对称网格浪费一半码域；修复——激活改用非对称 + 零点（第 1 周公式）。

6. 延伸思考题（含解析）

Q1：为什么 128 条校准数据通常就够了？什么情况下必须加量？
A：激活的分位数/直方图统计量收敛速度是 O(1/n)O(1/\sqrt{n})O(1/n​)，128 条 ×2048 token ≈ 26 万样本点，估计误差已低于量化步长本身。需要加量的情况：部署分布多峰（多领域混合）、序列极长（长上下文激活漂移）、动态范围随位置变化大。

Q2：KL 校准为什么在 TensorRT 上是默认，而在 LLM 社区少见？
A：TRT 面向视觉/分类为主的时代，softmax 输出分布的形状保持是正确目标；LLM 社区更关心权重侧二阶误差（GPTQ）与离群通道（AWQ），KL 对激活长尾的收缩不如显式 Percentile 可控，且 LLM 校准还要喂逐层重建目标，工具链就绕开了 KL。

Q3：Percentile 的裁剪误差和舍入误差怎么相互消长？最优点怎么找？
A：阈值 ccc 变小 → 步长 sss 变小 → 舍入误差 ↓\downarrow↓，但被裁尾部 ↑\uparrow↑。总误差 U 形；实践上在分位数 99%~100% 网格搜索重建 MSE（即 §2.3），或直接画"PPL vs 分位数"曲线取最低点。

Q4：为什么第一层和嵌入层常常量化收益差、甚至要跳过？
A：第一层直接吃原始嵌入，误差无前置层"平滑"，且其权重分布常有特殊结构（与词表相关）；lm_head 输出直接进 softmax 指数，误差被放大。工业配方通常对这两层保留高精度——混合精度是免费午餐。

Q5：如果校准集里混入了大量重复样本，四种策略谁受伤最重？
A：MinMax 受伤最轻（极值不依赖频率）；KL 受伤最重——直方图形状被重复样本扭曲，PPP 本身就是错的分布，最小化"与错误目标的距离"反而更差。这提示校准集要先去重（呼应数据工程方向）。

1.3 Wanda 为什么有效：一行输出的误差分解

考虑线性层 y=Wxy = Wxy=Wx。剪掉 WijW_{ij}Wij​ 造成的输出误差期望约为 ∣Wij∣⋅∣xj∣|W_{ij}| \cdot |x_j|∣Wij​∣⋅∣xj​∣——权重小但输入通道幅度大的连接，剪掉同样致命。Wanda 的重要性即按列激活范数加权：

两个关键设计：① 按输出行独立剪（保持每行稀疏率一致，避免某些神经元被剪空）；② 激活范数用一小批校准数据统计——与第 2 周校准完全同构。这就是"不重训也能工作"的原因：它用的是一阶泰勒项的幅度，而 LLM 权重在预训练后已处于良好局部极小，一阶近似足够。

1.4 SparseGPT：把剪枝写成逐列最小二乘

SparseGPT 把每层剪枝视为

arg⁡min⁡W^∥XW⊤−XW^⊤∥F2s.t. W^ 满足稀疏约束\arg\min_{\hat W} \|XW^\top - X\hat W^\top\|_F^2 \quad \text{s.t. } \hat W \text{ 满足稀疏约束} argW^min​∥XW⊤−XW^⊤∥F2​s.t. W^ 满足稀疏约束

用 Hessian H=2XX⊤H = 2XX^\topH=2XX⊤（与 GPTQ 完全同源的累积式，Stage 2 第 1 周会再推一遍）做二阶补偿：剪掉某元素后，把该行其余元素的误差按 H−1H^{-1}H−1 最优摊还。相比 Wanda 的一阶近似，它在 60%+ 高稀疏率下显著更稳，代价是要逐层解小线性系统（慢一个量级，但仍免重训）。

1.5 LLM-Pruner：结构化剪枝的依赖图

非结构化剪枝产生稀疏矩阵，通用硬件上并不加速（稀疏存储格式与密集计算单元的矛盾）。LLM-Pruner 转向结构化剪枝：直接删整条通道/头/层。难点是 Transformer 内部存在耦合结构（残差、RoPE 多头、共享 FFN 门控），盲删会破坏形状一致。它的方案：

  1. 依赖图（dependency graph） 分析：识别必须同剪同留的结构组；
  2. 对每个结构组用 LoRA 式低秩恢复：剪掉的主干旁挂一个低秩分支做少量数据恢复训练（通常 < 3 小时），避免全参微调。

1.6 2:4 稀疏：为硬件而生的结构化格式

NVIDIA Ampere 引入的 2:4 结构化稀疏（2:4 Structured Sparsity）：每连续 4 个权重中至多 2 个非零。

硬件机制（A100 稀疏 Tensor Core）：

  • 权重侧：非零值按 2:4 模式压缩存储——只存 2 个非零值 + 2-bit 索引（记录位置），体积近减半；
  • 激活侧：保持密集，但 Tensor Core 的 MMA 单元内置选择逻辑，每个时钟周期跳过索引标记为零的乘累加；
  • 效果：等效算力翻倍（FP16 312 → 稀疏 624 TFLOPS 量级），且不需要稀疏矩阵格式（CSR/COO）的间接寻址。

2:4 压缩存储=2×16-bit 值⏟非零权重+2×2-bit 索引⏟位置编码⇒每 4 个权重共 36 bit≈9 bit/权重\text{2:4 压缩存储} = \underbrace{2 \times 16\text{-bit 值}}_{\text{非零权重}} + \underbrace{2 \times 2\text{-bit 索引}}_{\text{位置编码}} \Rightarrow \text{每 4 个权重共 } 36 \text{ bit} \approx 9 \text{ bit/权重} 2:4 压缩存储=非零权重2×16-bit 值​​+位置编码2×2-bit 索引​​⇒每 4 个权重共 36 bit≈9 bit/权重

为什么任意 50% 稀疏不加速而 2:4 可以：普通稀疏需要索引间接访存 + 不规则计算，访存与调度开销抵消算力收益；2:4 的固定模式让硬件用确定性电路跳过零元素——稀疏要变成硬件指令才有收益。cuSPARSELt / torch.sparse 的 to_sparse_semi_structured 是软件入口。

4. 工程权衡与失效模式

4.1 权衡

  • 非结构化精度高但无通用加速：Wanda/SparseGPT 的 50% 稀疏只在稀疏 Tensor Core / cuSPARSELt 上有收益；CPU、普通 GPU、NPU 上推理速度不变甚至变慢（稀疏格式间接寻址）。
  • 结构化直接减体积但精度代价大：删通道 = 真减 FLOPs，任何硬件都加速；但容量硬损失，必须微调恢复，且高剪枝率下不可逆。
  • 免重训剪枝的隐含假设：模型处于良好极小点、校准集代表部署分布——微调过的下游模型上效果会打折。
  • 剪枝-量化叠加：先剪后量是可行方向（稀疏权重分布更集中，量化网格更好定），但两者误差会复合，叠加后必须重测全指标，不能线性外推。

4.2 失效模式

  1. 剪枝后 PPL 正常、长文本崩坏：与量化同款陷阱——局部指标不敏感于累积漂移；修复——加长输出评测（Stage 2 第 5-6 周）。
  2. 按行剪导致神经元死亡：症状——某些输出行非零元素极少，激活饱和；根因——全局 top-k 而非按行；修复——Wanda 的按行保留设计（§3.1 已实现）。
  3. 2:4 投影误差：把任意 50% 掩码强行投影到 2:4 模式会丢掉"重要但位置不合"的连接；修复——训练感知稀疏（SparseGPT 有 2:4 变体，直接按 2:4 约束选元素）。
  4. 通道剪枝后忘记重校准 BN：症状——剪完精度崩得离谱；根因——BatchNorm 统计量还对应旧通道集；修复——剪后先跑几个 batch 重建 BN 统计再微调。

5. 延伸思考题（含解析）

Q1：Wanda 为什么按输出行独立保留 top-k，而不是全层全局 top-k？
A：全局 top-k 会让"整行权重都偏小"的神经元被剪空（该行全零 → 神经元死亡、输出恒为 0）。按行保留保证每个神经元至少存活 k%k\%k% 的连接，维持层内表达维度。

Q2：SparseGPT 的 Hessian H=2XX⊤H = 2XX^\topH=2XX⊤ 与 GPTQ 是同一个东西——这暗示了什么？
A：两者都在解"逐列修改权重使层输出重构误差最小"的 OBS 问题：剪枝把某列置零、量化把某列舍入到网格，都是对单列的受约束修改，都用 H−1H^{-1}H−1 把误差摊给其余列。所以 GPTQ 可以看作"把量化当成一种特殊剪枝/约束投影"。（Stage 2 第 1 周推导。）

Q3：为什么 2:4 稀疏的加速只在 batch 较大（算力瓶颈）时明显？
A：batch=1 的 decode 是访存瓶颈（Stage 3 Roofline），稀疏 Tensor Core 翻的是算力上限，对访存瓶颈无用武之地；只有 batch 拉大、GEMM 变成算力瓶颈后，2:4 的 2× 算力才兑现。

Q4：LLM-Pruner 为什么用依赖图？直接删通道会发生什么？
A：Transformer 里残差分支要求加和两侧维度一致、多头注意力的头维耦合、门控 FFN 的两分支必须同维。盲删会产生形状不匹配直接报错，或（若只删一侧）语义破坏。依赖图把必须同剪的结构绑成组，保证剪后仍是合法网络。

Q5：同一个模型，50% 剪枝 vs INT4 量化，哪个对 LLM 更划算？
A：INT4 量化：体积 4×↓、精度损失小（配 GPTQ/AWQ）、所有引擎通吃；50% 剪枝：非结构化无通用加速、结构化掉点大。端侧/云端通用结论都是量化优先，剪枝作为叠加项——这也是本方向课程把量化放在主线的原因。

1. 第一性原理：蒸馏 = 用教师的分布形状当监督信号

1.1 软标签的信息量

分类的 one-hot 标签只说"答案是 3"，而教师的 softmax 输出说"答案是 3（0.85），但 5 也有点像（0.10），7 有一点点像（0.03）"。这些**类间相似性（dark knowledge，暗知识）**正是泛化的来源。Hinton et al.（2015, Distilling the Knowledge in a Neural Network）的原始配方：

piT=exp⁡(zi/T)∑jexp⁡(zj/T),LKD=T2⋅KL ⁣(pteacherT ∥ pstudentT)p_i^T = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}, \qquad \mathcal{L}_{\text{KD}} = T^2 \cdot \mathrm{KL}\!\left(p^T_{\text{teacher}} \,\|\, p^T_{\text{student}}\right) piT​=∑j​exp(zj​/T)exp(zi​/T)​,LKD​=T2⋅KL(pteacherT​∥pstudentT​)

  • 温度 TTT：T→1T \to 1T→1 退化为一键分布；TTT 升高把概率质量从头部摊向尾部，暴露类间结构。典型 T∈[2,10]T \in [2, 10]T∈[2,10]。
  • T2T^2T2 系数：温度升高后梯度幅度按 1/T21/T^21/T2 缩小，乘回 T2T^2T2 保持蒸馏损失与交叉熵同量级（这是推导题常考点：对 z/Tz/Tz/T 求导多出一个 1/T1/T1/T，两处共 1/T21/T^21/T2）。

1.2 LLM 蒸馏的特殊性：逐 token 的序列蒸馏

语言模型的蒸馏天然发生在每个生成位置上：教师在上下文 x<tx_{<t}x<t​ 下给出整个词表的分布 pT(⋅∣x<t)p_T(\cdot \mid x_{<t})pT​(⋅∣x<t​)，学生在同样上下文上拟合它：

LKD=∑tKL ⁣(pT(⋅∣x<t) ∥ pS(⋅∣x<t))\mathcal{L}_{\text{KD}} = \sum_t \mathrm{KL}\!\left(p_T(\cdot \mid x_{<t}) \,\|\, p_S(\cdot \mid x_{<t})\right) LKD​=t∑​KL(pT​(⋅∣x<t​)∥pS​(⋅∣x<t​))

教师与学生共享同一输入序列（on-policy/off-policy 的选择见 §1.4），无需任何标签——教师本身就是标注器。这正是 7B → 1.5B 蒸馏比"先标注再 SFT"便宜且信息更稠密的原因。

1.3 MiniLLM：反向 KL 避免模式覆盖

标准蒸馏用前向 KL KL(pT∥pS)\mathrm{KL}(p_T \| p_S)KL(pT​∥pS​)（教师在前）。它的失效模式是模式覆盖（mode-covering）：学生在教师概率低的地方也被迫分配概率，导致输出稀释、质量平庸。MiniLLM（Gu et al., 2023）改用反向 KL：

LMiniLLM=Ey∼pS[KL(pS(⋅∣x) ∥ pT(⋅∣x))]\mathcal{L}_{\text{MiniLLM}} = \mathbb{E}_{y \sim p_S}\Big[\mathrm{KL}\big(p_S(\cdot \mid x) \,\|\, p_T(\cdot \mid x)\big)\Big] LMiniLLM​=Ey∼pS​​[KL(pS​(⋅∣x)∥pT​(⋅∣x))]

  • 反向 KL 是模式寻找（mode-seeking）：学生集中拟合教师的高概率模式，在教师不支持的区域主动清零；
  • 期望在学生自己采样的序列上计算（policy gradient + 长度归一化 + 单步分解技巧），这是它工程上比前向 KL 贵的原因。

一句话记忆：前向 KL 让学生"处处讨好"，反向 KL 让学生"重点精通"——生成式模型要的是后者。

Q1：为什么蒸馏损失里要乘 T2T^2T2？不乘会怎样？
A：softmax 对 z/Tz/Tz/T 求导带出 1/T1/T1/T，前向与反向各一次共 1/T21/T^21/T2，蒸馏梯度随 TTT 增大而缩小；乘 T2T^2T2 恢复与 CE 同量级，使 α\alphaα 的加权有意义。不乘则需要把 α\alphaα 调到接近 1 且随 TTT 重调，失去可解释性。

Q2：MiniLLM 的反向 KL 为什么必须在学生自己的采样上算？
A：反向 KL KL(pS∥pT)\mathrm{KL}(p_S \| p_T)KL(pS​∥pT​) 的期望下标是学生分布——在教师语料上算会系统性漏掉学生自己会走到的状态（分布不匹配），这正是 on-policy 采样修正训练-推理 gap 的动机。

Q3：学生比教师小很多时，为什么"蒸馏后再量化"比"直接量化大模型"常常更优？
A：大模型 INT4 已接近无损，但体积仍大、端侧跑不动；蒸馏出的小模型 FP16 就放得下，再量化是锦上添花。选型逻辑是先满足部署预算（体积/延迟），再谈精度保留。

Q4：llm-compressor 产出的模型为什么能被 vLLM 直接加载，AutoGPTQ 的却需要转换？
A：llm-compressor 输出 compressed-tensors 规范（量化配置写进 config，权重按 vLLM 加载器预期的布局打包）；AutoGPTQ 是自己的 checkpoint 格式，需要 vLLM 内置的 GPTQ 加载分支。格式与引擎匹配是 Stage 2 第 5-6 周的主题。

Q5：你的语音方向里，哪些模型会走"蒸馏 → 量化 → 端侧"这条链？
A：端侧 ASR（如 SenseVoice-Small 这类为端侧延迟与部署设计的模型）、TTS 声码器/轻量解码器、VAD/降噪小模型。共同点：教师提供质量上限，学生满足实时率与内存预算——与本方向完全同构。

第 1 周教程：GPTQ——逐层最优二阶量化

本周要回答的问题

  1. 为什么 RTN（直接舍入）在 4-bit 以下崩得厉害，而 GPTQ 能救回来？
  2. 量化一列后，其余列的最优补偿 Δw=−Hqq−1(wq−w^q)eq\Delta w = -H_{qq}^{-1}(w_q - \hat w_q)e_qΔw=−Hqq−1​(wq​−w^q​)eq​ 是怎么推出来的？

对应学习计划：第 1 周。交付物：① llm-compressor 对 Qwen2.5-7B 做 GPTQ-4bit（group=128）并测 PPL/速度；② 手写单层 GPTQ 循环（50 行内），与官方输出对齐。

1. 第一性原理：把量化写成"逐列最小二乘"

1.1 目标：层输出重构误差最小

对线性层 Y=XW⊤Y = XW^\topY=XW⊤（XXX 为校准激活，d×nd \times nd×n；WWW 为 m×nm \times nm×n），GPTQ 要解：

W^=arg⁡min⁡W^ ∥XW⊤−XW^⊤∥F2s.t.W^ij∈量化网格\hat W = \arg\min_{\hat W} \ \big\| XW^\top - X\hat W^\top \big\|_F^2 \quad \text{s.t.} \quad \hat W_{ij} \in \text{量化网格} W^=argW^min​ ∥∥∥​XW⊤−XW^⊤∥∥∥​F2​s.t.W^ij​∈量化网格

直接逐元素舍入（RTN, Round-To-Nearest）完全忽略约束之间的耦合：舍入 wijw_{ij}wij​ 造成的输出误差本可以由同行其他列部分抵消。GPTQ 的核心动作就是显式地把这个抵消算出来。

1.2 OBS 的钥匙：单列量化的最优补偿

把目标函数对 WWW 的某一行做泰勒展开。注意这里不是因为"预训练模型处于极小点"才没有一阶项——层输出重构误差 ∥X(w−w^)⊤∥F2\|X(w-\hat w)^\top\|_F^2∥X(w−w^)⊤∥F2​ 本身就是 (w−w^)(w-\hat w)(w−w^) 的严格二次函数，一阶项恒等于 0：

∥XW⊤−XW^⊤∥F2≈(w−w^) H (w−w^)⊤,H=2X⊤X\|XW^\top - X\hat W^\top\|_F^2 \approx (w - \hat w)\, H\, (w - \hat w)^\top, \qquad H = 2X^\top X ∥XW⊤−XW^⊤∥F2​≈(w−w^)H(w−w^)⊤,H=2X⊤X

其中 HHH 是该行重构误差的 Hessian（n×nn \times nn×n，nnn 为输入特征维）。OBS（Optimal Brain Surgeon, Hassibi 1993）告诉我们：把第 qqq 个元素强行改成 w^q\hat w_qw^q​ 后，其余元素的最优调整是

Δw=−wq−w^q[H−1]qq H−1eq⟺w−q+=−wq−w^q[H−1]qq [H−1]⋅q, −q\Delta w = -\frac{w_q - \hat w_q}{[H^{-1}]_{qq}}\, H^{-1} e_q \quad\Longleftrightarrow\quad w_{-q} \mathrel{+}= -\frac{w_q - \hat w_q}{[H^{-1}]_{qq}}\, [H^{-1}]_{\cdot q,\,-q} Δw=−[H−1]qq​wq​−w^q​​H−1eq​⟺w−q​+=−[H−1]qq​wq​−w^q​​[H−1]⋅q,−q​

配套的最小误差增量为

ΔE=(wq−w^q)22 [H−1]qq\Delta E = \frac{(w_q - \hat w_q)^2}{2\,[H^{-1}]_{qq}} ΔE=2[H−1]qq​(wq​−w^q​)2​

直觉：[H−1]qq[H^{-1}]_{qq}[H−1]qq​ 衡量"第 qqq 列方向上的曲率平坦度"——越平坦，强行改动的代价越小；补偿项沿 H−1H^{-1}H−1 的第 qqq 列方向摊还误差，恰好抵消输出变化。这就是"为什么 GPTQ 比 RTN 精度好这么多"的标准答案：RTN 只做了舍入，GPTQ 还做了最优补偿。

1.3 Hessian 累积：H=2X⊤XH = 2X^\top XH=2X⊤X 不需要反向传播

（记号约定：本文 XXX 按"样本数 × 特征数"排布，故 Hessian 写作 2X⊤X2X^\top X2X⊤X；GPTQ 原论文把 XXX 按特征维在前列排布，写作 2XX⊤2XX^\top2XX⊤——是同一个矩阵的转置记法。）HHH 是激活的外积和，可以按 batch 在线累积：

H+=2 Xb⊤Xb（每个校准 batch 累加一次）H \mathrel{+}= 2\, X_b^\top X_b \quad \text{（每个校准 batch 累加一次）} H+=2Xb⊤​Xb​（每个校准 batch 累加一次）

原因：重构误差是 WWW 的二次型，其系数矩阵只依赖输入的二阶矩——与损失函数、反向传播无关。这与第 1 周（Stage 1 的剪枝周）里 SparseGPT 用的是同一个 HHH：剪枝是"把列置零"，量化是"把列舍入到网格"，OBS 框架下两者同构。

1.4 三个工程开关

  • block size（默认 128）：一次只处理 128 列（HHH 按块求逆），控制内存并避免误差长程累积；块间误差不补偿——这是精度与速度的折中。
  • act-order（desc）：按 1/[H−1]ii1/[H^{-1}]_{ii}1/[H−1]ii​ 降序处理列，即先量化"最疼"的列。先处理的列拿到完整补偿空间，误差敏感度低的列放最后牺牲。通常带来 0.1~0.3 PPL 的收益，代价是权重列序重排（推理内核必须支持）。
  • dampening：H+=λ⋅mean(diag(H))⋅IH \mathrel{+}= \lambda \cdot \mathrm{mean}(\mathrm{diag}(H)) \cdot IH+=λ⋅mean(diag(H))⋅I（典型 λ=0.01\lambda = 0.01λ=0.01）。校准数据少时 HHH 病态（近奇异），H−1H^{-1}H−1 数值爆炸；加对角阻尼换稳定性——失效模式兜底，不是免费午餐。

4. 工程权衡与失效模式

4.1 权衡

  • 精度：GPTQ-4bit(g128) 在 7B 上 PPL 损失通常 < 0.3；3-bit 开始明显（0.5~1.5），必须配 act-order。
  • 速度：离线量化 7B 约 10-30 分钟（单卡），比 AWQ 慢（AWQ 只搜 scale），比 RTN 慢两个量级——但只付一次。
  • act-order 的代价：列置换要求推理内核支持（vLLM/Marlin 支持）；不支持的引擎要么拒绝加载，要么回退慢路径。
  • 校准集敏感度：512 条是常见值；过少（< 64）→ HHH 病态 → 补偿方向噪声大。

4.2 失效模式

  1. HHH 奇异导致补偿爆炸：症状——量化后权重出现 inf/NaN；根因——校准样本线性相关、HHH 近奇异；修复——加/调大 dampening，或增补校准数据。
  2. act-order 与引擎不匹配：症状——模型加载成功但输出乱码；根因——引擎未应用列置换表；修复——确认引擎声明支持 desc_act，或关掉 act-order 重量化。
  3. group size 与内核约束冲突：症状——某些引擎只支持 g=128，g=32 的 checkpoint 拒载；根因——内核硬编码组大小；修复——按目标引擎倒推 group 选择（先选引擎再选格式）。
  4. 逐层独立最优 ≠ 全局最优：症状——每层重构误差都小，整模型仍掉点；根因——层间误差复合（Stage 1 第 2 周同款问题）；修复——敏感层保留高精度、或上 QAT 收尾。

5. 延伸思考题（含解析）

Q1：为什么 GPTQ 的 Hessian 用 2XX⊤2XX^\top2XX⊤ 而不是损失函数的真 Hessian？
A：GPTQ 优化的是层输出重构这个代理目标（二次型），其 Hessian 恰好是输入二阶矩，免反向传播、可逐层独立求解。真损失 Hessian 需要全模型二阶信息，代价不可承受；逐层重构误差小 → 整模型损失增量小，是经验上成立的近似。

Q2：act-order 为什么"先处理敏感列"？顺序反过来会怎样？
A：先处理的列在补偿时还有全部未量化列可动用；后处理的列只能吃掉残余补偿空间。敏感列（[H−1]ii[H^{-1}]_{ii}[H−1]ii​ 小、曲率陡）放后面会被迫接受大误差。反过来（asc）等价于把最疼的伤口留到最后缝，PPL 明显变差。

Q3：per-group(128) 在 GPTQ 里除了隔离离群值，还有什么作用？
A：它限制了补偿的作用范围——误差只在 128 列内摊还，避免长程补偿把数值噪声传到远处，同时把 H−1H^{-1}H−1 的求逆规模控制在 128×128。组越小越局部、越稳，但 scale 开销与内核约束上升。

Q4：为什么 GPTQ 量化过程不能并行处理多列？
A：第 qqq 列的补偿项要写入所有 q′>qq' > qq′>q 的列——存在顺序数据依赖。工程上靠"块内串行 + 层间/样本并行 + 分块求逆"摊薄成本，但列扫描本身是串行的，这是它比 AWQ 慢的根本原因。

Q5：什么情况下 GPTQ-3bit 是可接受的选择？
A：显存/带宽预算硬约束（如 24G 卡跑 14B）、且任务对长文本连贯性容忍度高（短问答、分类抽取）时；必须配 act-order + g=64/128 + 足量校准，并在评测里加长输出项——3-bit 的崩坏往往先出现在长生成而非 PPL。

Q：GPTQ 一句话原理？
逐列量化，用剩余列按 H−1H^{-1}H−1 二阶补偿输出误差——把量化写成带约束的逐层最小二乘。

Q：为什么 RTN 在低比特崩、GPTQ 不崩？
RTN 各列误差独立累积、互不抵消；GPTQ 每列的误差被主动摊还给未量化列，层输出重构误差被压到二阶最优。

Q：Hessian 从哪来？
重构目标的二阶导 = 输入二阶矩 2XX⊤2XX^\top2XX⊤，按校准 batch 外积累积，不需要反向传播。

Q：act-order 的收益与代价？
收益：敏感列先处理拿到完整补偿空间（0.1-0.3 PPL）；代价：列置换表要求推理内核支持 desc_act。

Q：block size 为什么是 128？
块内求逆的内存与数值稳定性、块间不补偿的精度损失、内核效率三方平衡的经验值。

Q：手写 50 行 GPTQ 与官方实现的差异在哪？
官方：Cholesky 分解求逆（数值更稳）、act-order 列重排、死组检测、并行块处理；教学版：直接求逆、固定列序——数值语义一致，工程鲁棒性不同。

1. 第一性原理：离群值在激活里，解法却有两条路

1.1 共同的问题陈述

Stage 1 已实证：LLM 激活的离群值按通道固定出现、幅度可达主体 10~100 倍。权重量化（W4A16）绕开了激活这个雷区，但代价是计算仍在 FP16——算力没省。要同时量化激活（W8A8 走 INT8 Tensor Core），就必须正面处理激活离群值。两条路线：

路线 核心动作 位宽形态 目标场景
SmoothQuant 把激活难度迁移给权重 W8A8 云端大 batch 服务
AWQ 保护显著权重通道，激活保持 FP16 W4A16 端侧/显存受限

1.2 SmoothQuant：难度迁移的数学

1.3 AWQ：1% 显著通道保护

AWQ（Lin et al., 2023）的两个观察：

  1. 权重并非同等重要：仅约 1% 的权重通道对应着大激活幅度的输入通道，剪掉/量化坏它们会造成显著精度损失（与 Wanda 的 ∣W∣⋅∣X∣|W|\cdot|X|∣W∣⋅∣X∣ 观察同源）；
  2. 保护不必保留全精度：对这 1% 通道做 per-channel 缩放 sss，让它们的数值幅度变大再量化——等价变换后这些通道的相对量化误差被压小，不需要混合精度、不需要额外存储原始权重。

1.4 AWQ vs GPTQ：一阶保护 vs 二阶补偿

  • GPTQ：接受量化误差，然后用 H−1H^{-1}H−1 把它摊还给其他列——误差仍在，只是被最优分配；
  • AWQ：从源头减少重要通道的误差产生（缩放后网格相对更细），不做列间补偿——因此免校准数据（只需激活统计），速度远快于 GPTQ。

1.6 速览：QUIP# 与 SqueezeLLM

两者都走码本（codebook）路线：不用均匀网格，而是学一组非均匀码点。

  • QUIP#：随机正交旋转（incoherence processing）把权重/激活的离群值"打散"成近似高斯，再用向量量化码本——旋转后分布规整，2-bit 也能活；
  • SqueezeLLM：k-means 学码本 + 把离群值单独拎出来稀疏存储（呼应 LLM.int8() 的混合精度思想）。

它们的意义：证明 4-bit 以下要活得靠非均匀码点 + 分布整形，为 Stage 1 讲的 NF4 与 imatrix 提供同族背景。

4. 工程权衡与失效模式

4.1 权衡

  • AWQ 免校准二阶信息：只需激活统计 → 量化速度快、对校准集不敏感；代价是它不做误差摊还，极端低位宽（≤3bit）下不如 GPTQ。
  • SmoothQuant 的 α\alphaα 是全局超参：不同层的最优 α\alphaα 其实不同，逐层搜索成本高；0.5~0.8 是安全区间。
  • 等价变换的位置约束：sss 必须能被吸收进相邻算子（LayerNorm/前一层），对非标准结构（某些 MoE、共享嵌入）要逐层检查。

4.2 失效模式

  1. AWQ 显著通道选错统计量：症状——保护后仍掉点；根因——用 max 而非 mean 统计激活（max 又被离群样本污染）；修复——AWQ 论文用均值 + 跨样本聚合，照做。
  2. SmoothQuant 后权重反而难量化：症状——激活平滑了、权重侧误差暴涨；根因——α\alphaα 过大，权重被放大出新的离群列；修复——调低 α\alphaα，或对权重用 per-channel 量化兜底。
  3. scale 吸收位置错误：症状——数学等价但输出变了；根因——sss 被同时应用于变换两侧（抵消错误）或漏吸收；修复——单元级数值对齐测试（变换前后输出差 < 1e-4）。
  4. W8A8 在小 batch 下"负优化"：症状——上线 W8A8 后延迟反升；根因——b=1 时瓶颈是访存，INT8 算力收益为零，反量化与格式转换白付开销；修复——按 §1.5 边界回退 W4A16。

5. 延伸思考题（含解析）

Q1：SmoothQuant 的等价变换为什么"免费"？它的隐藏成本是什么？
A：sss 离线吸收进相邻参数，推理图与算子数不变，无运行时开销。隐藏成本：被放大的权重列可能恶化权重侧量化、且吸收位置受模型结构约束——等价是数学的，工程落地要逐层核对。

Q2：AWQ 为什么用激活的均值幅度而不是最大值选显著通道？
A：最大值对单个异常样本敏感（又引入了离群值问题），均值反映通道的持续性重要程度——AWQ 保护的是"总是重要"的通道，不是"偶尔巨大"的通道。

Q3：为什么说 AWQ 与 Wanda 共享同一个观察？两者的动作差在哪？
A：都观察到 ~1% 的输入通道激活幅度显著大、与之相连的权重"更重要"（∣W∣⋅∣X∣|W|\cdot|X|∣W∣⋅∣X∣）。Wanda 据此决定剪谁（保留显著连接），AWQ 据此决定缩放谁（放大显著通道再量化）——同一观察，剪枝与量化两种用法。

Q4：QUIP# 的随机旋转为什么能救 2-bit 量化？
A：旋转（正交矩阵）保持模长不变但把能量在维度间"摊匀"（incoherence）：原本集中在少数通道的离群幅度被打散成近似高斯的均匀分布——网格/码本对规整分布的表示效率最高。代价是推理时要付旋转变换（可与相邻线性层合并）。

Q5：同一个 7B 模型，端侧（你的 RK3588）和云端服务各选什么？
A：端侧：AWQ W4A16（或直接 Stage 4 的 GGUF Q4_K）——内存是硬约束、batch=1 访存瓶颈，带宽收益直接兑现；云端：SmoothQuant W8A8 + TensorRT-LLM——大 batch 下 INT8 算力翻倍才是真金白银。选型的本质是认清当前负载的瓶颈资源（Stage 3 Roofline 的预演）。

6.1 一个公式包住三种方法

7.1 两分钟口头复述稿（自测用）

激活离群值集中在约 1% 的固定通道，幅度可达主体百倍。要量化激活，有两条路：SmoothQuant 做难度迁移——用等价变换 Y=(X/s)(sW)Y=(X/s)(sW)Y=(X/s)(sW) 把激活通道的极端幅度搬给权重，迁移比例由 α 控制，结果是激活变得可量化，走 W8A8 INT8 Tensor Core，适合云端大 batch。AWQ 做显著通道保护——不动激活（保持 FP16），只对那 1% 重要权重通道做缩放放大再量化，让重要通道的相对误差变小，走 W4A16，适合端侧与显存受限场景。两者本质都是"等价变换 + 难度重分配"，方向相反：一个迁激活，一个保权重。
