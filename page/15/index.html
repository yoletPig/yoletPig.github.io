第1周-说话人表征学习

发表于 2026-11-04 更新于 2026-11-05 分类于 语音方向 ， Stage 4-说话人分离与声纹识别 本文字数： 4.4k 阅读时长 ≈ 16 分钟

第 1 周教程：说话人表征学习——从 i-vector 到 ECAPA-TDNN

本周要回答的三个问题

  1. 一段 3 秒的语音和一段 30 秒的语音，如何都变成同一个固定维度的声纹向量？
  2. 统计池化（Stats Pooling）在数学上做了什么？为什么它是"变长 → 定长"的关键？
  3. ArcFace/AAM-Softmax 这类度量学习损失，如何让"同人聚拢、异人分离"？

对应学习计划：第 1 周。交付物：用预训练 spkrec-ecapa-voxceleb 提取 192 维声纹，验证"同人余弦相似度 > 0.75、异人 < 0.4"的经验区间，并解释阈值校准的必要性。

1. 第一性原理：说话人识别 = 表征 + 度量

1.1 问题定义

给定一段语音，判断"是谁说的"。三个子任务：

  • 验证（Verification, 1:1）：这段语音是否属于声称的某人？（门禁、支付）
  • 辨认（Identification, 1:N）：这段语音是底库 N 人中的谁？
  • 分离（Diarization）：这段音频里有几个人、各说了什么？（本周为第 3-4 周铺路）

三个任务共享同一个原子能力：把变长语音映射成定长的说话人表征（embedding），且该空间里"同人近、异人远"。

1.2 表征学习的两代演进

第一代：i-vector（统计模型，Kenny 等提出，Dehak et al. 2011 系统化）

这个公式在干什么：i-vector 的思路是——先对每段语音估计一个 GMM（通用背景模型 UBM）的高维统计量，把它们拼接成一个很长的超向量（supervector，每帧维度 × 高斯分量数，可达数万维）。超向量太长、太稀疏，但其中真正变化的"自由度"其实不多。于是用一个低秩分解把几万维压到几百维：

M=m+Tw\mathbf{M} = \mathbf{m} + T\mathbf{w} M=m+Tw

  • M\mathbf{M}M：这段语音的超向量（数万维）；
  • m\mathbf{m}m：所有说话人平均下来的全局超向量（"人人都一样"的部分）；
  • TTT：总变化矩阵（Total Variability Space，形状数万 × 400）——"大家各不相同的部分"集中在哪些方向上；
  • w\mathbf{w}w：该语音的坐标，就是 i-vector（通常 400 维）。

类比：超向量是"这个人的完整档案"（几万字），m\mathbf{m}m 是"所有档案的模板"，TTT 列出"人们真正有差异的 400 个要点"，w\mathbf{w}w 就是这 400 个要点上的评分——这就是随身携带的声纹。

关键缺陷：TTT 是无监督因子分析训练的，说话人差异和信道（麦克风/房间）差异混在同一个空间里，无法分开。所以要配后端：

深入拆解：后端 PLDA 在做什么

PLDA（Probabilistic Linear Discriminant Analysis，概率线性判别分析，Ioffe 2006；Prince & Elder 2007）是一个"生成式"的两人比较模型。它假设一个 i-vector x\mathbf{x}x 由三部分相加生成：

x=μ+Py+Γz,y∼N(0,I)（说话人），z∼N(0,I)（信道）\mathbf{x} = \boldsymbol{\mu} + \mathbf{P}\mathbf{y} + \mathbf{\Gamma}\mathbf{z}, \quad \mathbf{y} \sim \mathcal{N}(0, \mathbf{I}) \text{（说话人），} \mathbf{z} \sim \mathcal{N}(0, \mathbf{I}) \text{（信道）} x=μ+Py+Γz,y∼N(0,I)（说话人），z∼N(0,I)（信道）

大白话：同一个人的多条语音共享同一个隐变量 y\mathbf{y}y（他的"真声纹"），但各自带着不同的信道噪声 z\mathbf{z}z。PLDA 先从数据里学出 P\mathbf{P}P（说话人变化的子空间）和 Γ\mathbf{\Gamma}Γ（信道变化的子空间），打分时计算"这两条语音来自同一个 y\mathbf{y}y"与"来自两个不同 y\mathbf{y}y“的似然比。直觉上它相当于"在比较两人声纹前，先把已知的信道干扰’洗’掉”——i-vector 时代的余弦打分是毛坯，PLDA 是精装修。

局限：依赖 GMM 特征统计、信道鲁棒性全靠 PLDA 等后端修补、无法端到端用判别损失优化。被深度方法全面取代。

第二代：d-vector → x-vector → ECAPA-TDNN（深度端到端）

  • d-vector（Variani et al., ICASSP 2014）：最早的深度声纹——LSTM 逐帧输出帧级向量，取平均得到段级声纹，用于文本相关验证；
  • GE2E（Generalized End-to-End Loss，Wan et al., ICASSP 2018）：Google 提出的度量学习损失。这个损失在干什么：一个训练批次里同时放 NNN 个说话人各 MMM 条语音，算出 N×MN \times MN×M 个声纹和 NNN 个说话人质心；GE2E 同时要求"每条声纹离自己的质心近、离其他 N−1N-1N−1 个质心远"（triplet 思想的批量化），一次前向就能学"同人聚、异人散"。它比逐对比较的训练效率高得多，曾支撑 Google Duplex 的声纹；
  • x-vector（Snyder et al., ICASSP 2018）：TDNN + 统计池化 + 512 维段级向量（见第 2 节），把"变长 → 定长"做成了标准组件；
  • ECAPA-TDNN（Desplanques et al., Interspeech 2020）：x-vector 的现代强化版（见 2.3 节），至今仍是开源基线。

这条"神经网络提特征 + 池化定长 + 度量学习损失"的路线就是本周重点。

2. x-vector：池化让"变长 → 定长"

2.1 架构三段式（Snyder et al., ICASSP 2018）

帧级特征→TDNN 帧级层逐帧向量→统计池化段级向量→段级层x-vector\text{帧级特征} \xrightarrow{\text{TDNN 帧级层}} \text{逐帧向量} \xrightarrow{\text{统计池化}} \text{段级向量} \xrightarrow{\text{段级层}} \text{x-vector} 帧级特征TDNN 帧级层​逐帧向量统计池化​段级向量段级层​x-vector

  1. 帧级层：TDNN（Time-Delay Neural Network，时延神经网络）——本质是带上下文窗口的一维卷积：每层看"当前帧 ± 前后几帧"（如 {-2, 0, 2}），不是因果卷积（x-vector 的帧级层会用未来帧，离线场景没有约束）；多层堆叠后，每帧的向量都携带着越来越宽的时间上下文；
  2. 统计池化（Stats Pooling）：把所有帧的向量聚合成定长——这是变长到定长的关键；
  3. 段级层：全连接层进一步压缩，输出 x-vector（论文中 512 维）。训练时先用 softmax 分类损失训练说话人分类，再去掉最后一层分类头，取倒数第二层的 512 维向量当声纹。

一句话总结：TDNN 负责"逐帧看懂"，池化负责"把几百到几千帧压成一个定长指纹"，段级层负责"把指纹打磨成可比较的向量"。

2.2 统计池化的数学（本周自测题）

这个公式在干什么：变长语音的问题出在"帧数 TTT 不固定"，而下游任何全连接层都需要固定维度的输入。统计池化不关心 TTT 是多少，只关心这堆帧向量长什么样——用"平均姿态 + 波动幅度"两组统计量来概括，所以输出维度永远固定。

对 TTT 帧的特征向量序列 {h1,…,hT}\{\mathbf{h}_1, \dots, \mathbf{h}_T\}{h1​,…,hT​}（每个 ht∈Rd\mathbf{h}_t \in \mathbb{R}^dht​∈Rd）：

μ=1T∑t=1Tht（均值：逐维平均，刻画"平均音色"）\boldsymbol{\mu} = \frac{1}{T}\sum_{t=1}^{T} \mathbf{h}_t \quad \text{（均值：逐维平均，刻画"平均音色"）} μ=T1​t=1∑T​ht​（均值：逐维平均，刻画"平均音色"）

σ=1T∑t=1Tht2−μ2（标准差：逐维算方差再开方，刻画"波动幅度"）\boldsymbol{\sigma} = \sqrt{\frac{1}{T}\sum_{t=1}^{T} \mathbf{h}_t^2 - \boldsymbol{\mu}^2} \quad \text{（标准差：逐维算方差再开方，刻画"波动幅度"）} σ=T1​t=1∑T​ht2​−μ2​（标准差：逐维算方差再开方，刻画"波动幅度"）

小例子（d=2d = 2d=2，3 帧）：h1=[1,0]\mathbf{h}_1 = [1, 0]h1​=[1,0]，h2=[3,2]\mathbf{h}_2 = [3, 2]h2​=[3,2]，h3=[5,4]\mathbf{h}_3 = [5, 4]h3​=[5,4]。

  • 均值 μ=[3,2]\boldsymbol{\mu} = [3, 2]μ=[3,2]；标准差 σ≈[1.63,1.63]\boldsymbol{\sigma} \approx [1.63, 1.63]σ≈[1.63,1.63]；
  • 输出 [3,2,1.63,1.63][3, 2, 1.63, 1.63][3,2,1.63,1.63]——4 维定长。再来 30 帧也还是 4 维。

直觉：均值刻画"这个人的平均音色"，标准差刻画"音色的起伏方式"（发元音和擦音时声学特征会系统性变化，每个人的"变化模式"也是身份线索）。TTT 无关性意味着 3 秒和 30 秒的语音输出维度相同——变长问题被池化解决。

2.3 ECAPA-TDNN：现代骨架

ECAPA 在 x-vector 基础上三个升级：

  1. SE-Res2Block：Squeeze-Excitation（通道注意力，“哪些特征通道重要就放大谁”）+ Res2Net（多尺度卷积，同层内用不同感受野），增强特征表达；
  2. 多层特征聚合（Multi-layer Aggregation）：把多个中间层的输出拼接起来用，融合不同抽象层次；
  3. Attentive Stats Pooling（注意力统计池化）：池化不再是简单平均，而是先给每帧打重要度分，再按分数加权：

μ=∑t=1Tαtht,α=softmax(v⊤tanh⁡(WH))\boldsymbol{\mu} = \sum_{t=1}^{T} \alpha_t \mathbf{h}_t, \quad \boldsymbol{\alpha} = \text{softmax}\big(\mathbf{v}^\top \tanh(\mathbf{W}\mathbf{H})\big) μ=t=1∑T​αt​ht​,α=softmax(v⊤tanh(WH))

  • H\mathbf{H}H 是所有帧向量的堆叠矩阵，W\mathbf{W}W（矩阵）+ tanh⁡\tanhtanh 把每帧映射成一个"打分特征"，v\mathbf{v}v（向量）给每帧打出一个标量分数，softmax 把分数归一化成和为 1 的权重 αt\alpha_tαt​。
  • 为什么需要它：一句话里不是每帧都"像本人"——静音、呼吸、背景噪声帧是干扰，元音主音区帧才是音色的稳定代表。注意力池化让模型学会挑帧，统计量只由"像本人的帧"主导。标准差同样做注意力加权（σ2=∑tαtht2−μ2\boldsymbol{\sigma}^2 = \sum_t \alpha_t \mathbf{h}_t^2 - \boldsymbol{\mu}^2σ2=∑t​αt​ht2​−μ2）。

SpeechBrain 的 spkrec-ecapa-voxceleb 输出 192 维声纹，正是这套架构的产物（在 VoxCeleb 上训练，EER 约 0.8% 量级）。

3. 度量学习：让空间"同人近、异人远"

3.1 分类损失的局限

若用普通 softmax 分类 N 个说话人，模型只学会"区分训练集里的 N 人"，对没见过的人泛化差。声纹要的是开放集能力：任意两人的相似度可比。

3.2 AAM-Softmax / ArcFace（Deng et al., CVPR 2019）

核心思想：把分类边界从"特征空间"搬到"角度空间"，并强制缩小同人夹角、拉大异人夹角。

为什么是角度空间：训练时特征和分类器权重都做 L2 归一化，落在单位超球面上——此时一个向量的全部信息只剩"方向"，方向之间的差异就是夹角。所以"同人聚拢、异人分离"翻译成数学就是"同人夹角小、异人夹角大"，直接在角度上做约束最对症。

对特征 x\mathbf{x}x 与第 iii 类中心 Wi\mathbf{W}_iWi​（都归一化），夹角 θi\theta_iθi​。ArcFace 在目标类的角度上加惩罚 mmm：

L=−log⁡es⋅cos⁡(θy+m)es⋅cos⁡(θy+m)+∑j≠yes⋅cos⁡θj\mathcal{L} = -\log \frac{e^{s \cdot \cos(\theta_{y} + m)}}{e^{s \cdot \cos(\theta_{y} + m)} + \sum_{j \neq y} e^{s \cdot \cos \theta_j}} L=−loges⋅cos(θy​+m)+∑j=y​es⋅cosθj​es⋅cos(θy​+m)​

这个公式在干什么：它就是普通 softmax 交叉熵，只是把"目标类的得分"从 cos⁡θy\cos\theta_ycosθy​ 换成了 cos⁡(θy+m)\cos(\theta_y + m)cos(θy​+m)。

  • mmm（angular margin，角度间隔）：把目标类的角度人为加大 mmm，相当于考官说"你不光要答对，还要答得比及格线高出 mmm 才算对"。cos⁡(θy+m)<cos⁡θy\cos(\theta_y + m) < \cos\theta_ycos(θy​+m)<cosθy​，目标类的"得分"被打了折扣，模型必须把同人样本的 θy\theta_yθy​ 压得更小（聚得更紧）才能维持正确分类——margin 就这样把"类内紧凑"写进了训练目标；
  • sss（scale，缩放）：cos⁡\coscos 的取值只有 [−1,1][-1, 1][−1,1]，差距太小 softmax 梯度太弱；乘上 s≈30s \approx 30s≈30 把 logits 放大，让"对/错"的差异足够陡峭，训练才有推力。

效果：训练后，同人样本在超球面上紧凑成簇，异人之间被 margin 撑开。推理时只需算余弦相似度即可判断。CosFace（余弦间隔）与 ArcFace（角度间隔）同族，效果相近；声纹社区更常用 “AAM-Softmax” 这个名字。

动手验证：拿第 4.1 节的 6 个声纹算两两夹角。你会发现同人对的夹角通常 < 35°，异人对的夹角 > 70°——这正是 margin 间隔塑造出来的几何结构。

3.3 为什么推理用余弦相似度

归一化后的声纹向量在单位超球面上，余弦相似度 = 内积 = 角度的单调函数。两个声纹 e1,e2\mathbf{e}_1, \mathbf{e}_2e1​,e2​：

sim=e1⋅e2∥e1∥∥e2∥=cos⁡θ\text{sim} = \frac{\mathbf{e}_1 \cdot \mathbf{e}_2}{\|\mathbf{e}_1\| \|\mathbf{e}_2\|} = \cos\theta sim=∥e1​∥∥e2​∥e1​⋅e2​​=cosθ

训练目标（ArcFace）优化的就是角度，所以推理沿用同一把尺子最自然。同人接近 1，异人接近 0 或负值。

一句话总结：ArcFace = softmax 交叉熵 + “目标类角度加 mmm”，把"分类对"升级为"同人夹角足够小"，于是角度（余弦相似度）成为训练与推理通用的声纹距离。

4. 实现与验证（交付核心）

4.1 提取声纹并验证相似度区间

预期：同人三条相似度大多在 0.75-0.95，异人大多在 0.4 以下。这个"区间分离"是声纹可用的直接证据。

注意：0.75 / 0.4 是 VoxCeleb 干净录音下的典型区间，不是硬性规律。如果音频里全是噪声、电话信道或极短的发言，assert 可能失败——这本身就是有价值的观察，说明该做域内校准（第 2 周）而不是调阈值。

4.2 关键提醒：阈值不是常数

0.75 / 0.4 只是 VoxCeleb 干净英语 + 这个模型下的经验值。换数据集、换语言、换信道，整个分布会平移——这就是阈值必须校准的原因（第 2 周主题：EER 与 minDCF 就是校准工具）。

为什么需要校准（本周自测题）：

  • 不同录音条件（麦克风、房间）让同人相似度整体下移；
  • 不同人群（语言、年龄）让异人相似度分布变化；
  • 攻击样本（合成语音）会落在异常区域。

生产上用一个开发集（已知同人/异人对）画出相似度分布，再按业务可接受的误识/误拒率定阈值——绝不是拍脑袋用 0.75。

5. 工程权衡与失效模式

5.1 权衡

  • 表征维度：高（512）表达力强但检索贵；低（128/192）省存储。ECAPA 192 是甜点；
  • 池化方式：均值池化简单；注意力池化更准但多一点计算；
  • 训练数据：VoxCeleb1（1,251 位名人、约 15 万条 / 约 350 小时）+ VoxCeleb2（6,112 位、约 109 万条 / 2,000 多小时）合计英语为主；中文/多场景可补 CN-Celeb（中文名人语音，11 种真实场景，约 300 小时，另有扩展版 CN-Celeb2）微调。

5.2 失效模式

  1. 短语音不稳定：< 1 秒的片段声纹方差大。修复：保证切块 ≥ 1.5 秒或多块平均。
  2. 信道失配：训练干净、部署嘈杂 → 相似度整体下移。修复：前端降噪（联动 Stage 3）+ 域内校准。
  3. 双胞胎/相似音色：天生声纹接近，任何模型都难分。属于任务固有上限，需结合其他信号。

Q1：x-vector 的统计池化层在做什么？为什么 ECAPA 的多层聚合更好？

Q2：声纹模型怎么处理变长语音？3 秒和 30 秒的向量能直接比吗？
A：靠池化层把任意时长聚合成固定维度，所以可直接比余弦相似度。但时长太短（<1 秒）统计不稳定，相似度方差大，建议 ≥1.5 秒。

Q3：为什么不用普通 softmax 而用 ArcFace/AAM-Softmax？
A：softmax 只学区分训练集 N 人，开放集泛化差。ArcFace 在角度空间加 margin，直接优化"同人紧、异人散"的几何结构，学出的表征对任意新人都可比——这是开放集验证的前提。

Q4：同人 0.75、异人 0.4 这个阈值能直接用于生产吗？
A：不能。它只是特定数据集 + 模型的经验值。换域后分布平移，必须用开发集重新校准（第 2 周的 EER 流程），按业务可接受的误识率定阈值。

Q5：i-vector 为什么被 x-vector 取代？
A：i-vector 依赖 GMM 统计与独立后端（信道补偿靠 PLDA），无法端到端用判别损失优化，且信道鲁棒性靠补丁。x-vector 端到端学习、池化处理变长、配度量学习损失，精度与工程简洁性全面胜出。

1. 第一性原理：验证 = 假设检验

1.1 问题框架

声纹验证是一个二元假设检验：

  • H0H_0H0​：试语音与注册人不是同一人（冒用）；
  • H1H_1H1​：试语音与注册人是同一人（合法）。

模型输出相似度分数 sss，系统设定阈值 τ\tauτ：s≥τs \ge \taus≥τ 判"接受"（同一人），否则"拒绝"。

于是有四类结果：

实际同人 (H1H_1H1​) 实际异人 (H0H_0H0​)
判接受 正确接受 误识（FA, False Accept）
判拒绝 误拒（FR, False Reject） 正确拒绝

两个核心错误率：

FAR(τ)=P(接受∣H0)（误识率：坏人进来）\text{FAR}(\tau) = P(\text{接受} \mid H_0) \quad \text{（误识率：坏人进来）} FAR(τ)=P(接受∣H0​)（误识率：坏人进来）

FRR(τ)=P(拒绝∣H1)（误拒率：好人被挡）\text{FRR}(\tau) = P(\text{拒绝} \mid H_1) \quad \text{（误拒率：好人被挡）} FRR(τ)=P(拒绝∣H1​)（误拒率：好人被挡）

这个公式在干什么：FAR 是"拿所有异人试验对来考系统，有多大比例被放进来"；FRR 是"拿所有同人试验对来考，有多大比例被挡在门外"。两者都是阈值 τ\tauτ 的函数——同一个系统，配不同阈值，就有不同的 FAR/FRR，所以单独报 FAR 或 FRR 必须连带说明阈值（或用下文的 EER/minDCF/DET 这类阈值无关的指标）。

τ\tauτ 越高：FAR 降（更严，坏人难进）但 FRR 升（好人也被挡）；τ\tauτ 越低：反之。这是所有阈值系统的根本权衡。

1.2 EER：两条错误率曲线的交点

把 FAR 和 FRR 都画成阈值 τ\tauτ 的函数，两条曲线会相交——交点处 FAR=FRR\text{FAR} = \text{FRR}FAR=FRR，这个共同值就是 EER（Equal Error Rate，等错误率）：

EER:FAR(τ∗)=FRR(τ∗)\text{EER}: \quad \text{FAR}(\tau^*) = \text{FRR}(\tau^*) EER:FAR(τ∗)=FRR(τ∗)

这个公式在干什么：在整条阈值轴上找一个"天平恰好平衡"的工作点——误放进来的人和被挡住的好人一样多。它把"模型的判别能力"从"阈值怎么选"里剥离出来：分布重叠越小，这个平衡点越低。

深入拆解：亲手算一次 EER。假设 4 个试验对，同人、异人各 2 个（分数已按降序排好）：

分数 sss 标签 扫描到此处：FAR FRR
0.92 同人 0/2 = 0 1/2 = 0.50
0.80 异人 1/2 = 0.50 1/2 = 0.50
0.71 同人 1/2 = 0.50 0/2 = 0
0.40 异人 2/2 = 1.00 0

扫描规则：把每个观测分数依次当作阈值 τ\tauτ（判"分数 ≥ τ 为接受"），走到哪一行，就统计"此时异人被放进来的比例"（FAR）和"同人被拒在外的比例"（FRR）。第一行只有 0.92 被接受，另一个同人样本（0.71）还没放进来，所以 FRR = 1/2；扫到第二行（阈值 0.80），异人 0.80 也被放进来，FAR = 1/2——此时 FAR = FRR = 0.50，两条曲线恰好相交，EER = 0.50（4 个样本太少，EER 显得高；真实评测用数百上千对才能得到平滑曲线，第 2.2 节代码就是这套扫描的向量化版本，取 ∣FAR−FRR∣|\text{FAR}-\text{FRR}|∣FAR−FRR∣ 最小处报 EER）。

为什么 EER 能做单一数字对比：它不依赖具体阈值选择，只反映"模型把同人和异人分布分开的能力"——分布分得越开，交点越低。EER 从 3% 降到 2% 就是实打实的进步，适合论文打榜与模型选型。

一句话总结：EER = "拿一个公平的阈值考一次试"的总体成绩，衡量的是模型本身，不是部署策略。

1.3 DET 曲线

DET（Detection Error Tradeoff）图：横轴 FAR、纵轴 FRR（常用正态分位数刻度让曲线更直），每个点对应一个阈值。曲线越靠左下越好。EER 就是曲线与对角线的交点。

1.4 minDCF：带"代价"的评价

EER 假设误识和误拒"一样坏"——这在很多业务里不成立：

  • 支付场景：误识（别人刷走钱）远比误拒（本人重试一次）严重；
  • 会议转写：分错说话人影响可读性，但漏分几秒无所谓。

DCF（Detection Cost Function） 给两类错误加权：

3. 分数校准：让分数"可比"

3.1 为什么原始分数不可比

两个模型（或同一模型在两个数据集上）的相似度分数尺度不同：模型 A 同人集中在 0.8-0.9，模型 B 集中在 0.5-0.7。直接用同一个阈值判断会完全错位。

3.2 校准方法

  • Logistic 校准：学一个映射 p=σ(a⋅s+b)p = \sigma(a \cdot s + b)p=σ(a⋅s+b)，把分数映射成"是同人的概率"（σ\sigmaσ 是 sigmoid，aaa 管斜率、bbb 管平移，用一批带标签的开发集试验对拟合）；
  • PAV（Pool Adjacent Violators，保序回归）：非参数单调校准，把分数分箱后强制"分数越高、后验概率不降"，更灵活。

校准后，不同模型/数据集的分数落到同一语义空间（0-1 概率），阈值可迁移。生产声纹系统一定有这一步。

3.3 打分归一化：AS-Norm

为什么还需要它：校准解决"全局分数不可比"，但同一模型里，不同注册人的分数分布也不齐——有人天生分数偏高（“羊群效应”：山羊型说话人的异人分数系统性偏移）。AS-Norm（Adaptive Score Normalization，自适应分数归一化） 的做法：

snorm(stest)=stest−μtopσtops_{\text{norm}}(s_{\text{test}}) = \frac{s_{\text{test}} - \mu_{\text{top}}}{\sigma_{\text{top}}} snorm​(stest​)=σtop​stest​−μtop​​

对每条测试语音，从**协同队列（cohort，一大群背景说话人的声纹）**里找出与它最相似的 top-NNN 个，用这 top-NNN 个相似度的均值 μtop\mu_{\text{top}}μtop​ 和标准差 σtop\sigma_{\text{top}}σtop​ 做标准化。直觉：给每个测试语音配一把"针对它自己难度"的尺子——如果它跟谁都像（top-N 相似度普遍高），就往下压；如果它天生分数低，就往上提。NIST SRE 与 VoxSRC 前排系统的打分链路里几乎都有它（通常在 PLDA/余弦打分之后、校准之前）。

4. 工程权衡与失效模式

4.1 权衡

  • 阈值选择：高阈值安全但扰民，低阈值顺滑但危险——按业务代价定，不按 EER 定；
  • 测试集设计：必须包含跨信道、跨时长的配对，否则评测虚高；
  • minDCF 的先验：PtargetP_{\text{target}}Ptarget​ 设多少取决于业务（门禁 0.5，支付 0.01）。

4.2 失效模式

  1. 阈值照搬：把论文的 0.75 或 EER 阈值直接上生产，误识率失控。修复：开发集校准。
  2. 测试集泄漏：同一说话人的录音同时出现在注册与测试，EER 虚低。修复：按说话人严格划分。
  3. 忽略攻击：只测真实语音，上线后被合成语音攻破。修复：攻击样本纳入评测 + 反欺骗模块。
  4. 样本不平衡误读：异人配对远多于同人，accuracy 会虚高（全判拒绝也能 99%）。必须看 FAR/FRR/EER，不看 accuracy。

5. 延伸思考题（含解析）

Q1：EER 的定义？为什么实际部署不用 EER 而用业务阈值？
A：EER 是 FAR = FRR 交点处的错误率，反映模型区分能力、与阈值无关，适合对比。但部署时两类错误代价通常不等（误识比误拒严重得多），必须按业务代价在 DET 曲线上另选工作点，而不是恰好在交点。

Q2：声纹门禁的阈值怎么定？
A：① 用开发集画 FAR/FRR 曲线；② 确定业务可接受的误识率上限（如 0.1%）；③ 取满足该 FAR 的最高阈值（此时 FRR 最小）；④ 上线后监控实际误识并定期重校。

Q3：minDCF 里的 PtargetP_{\text{target}}Ptarget​ 为什么重要？
A：它是真实"同人请求"的先验。支付场景 PtargetP_{\text{target}}Ptarget​ 极小（绝大多数验证是冒用），误识的期望代价被放大，系统会更偏向保守。先验错了，选出的阈值就错了。

Q4：为什么不能用 accuracy 评价声纹验证？
A：异人配对占绝大多数，一个"全拒绝"的系统 accuracy 也能到 99%，但完全没用。必须用与阈值、代价挂钩的 FAR/FRR/EER/DCF。

Q5：你合成的变声攻击让相似度下降了多少？这说明什么？
A：（填你的实测）通常变声让同人相似度下降 0.1-0.3，可能跌破阈值——说明声纹对音色扰动敏感；也说明高级攻击（零样本克隆，相似度可能不降反近）更危险，必须加反欺骗。

1.2 EEND 的重新定义

EEND（End-to-End Neural Diarization，端到端神经分离，Fujita 等提出，2019）把分离定义为：

输入：音频特征⟶输出：每帧×每说话人的活动概率\text{输入：音频特征} \quad \longrightarrow \quad \text{输出：每帧} \times \text{每说话人的活动概率} 输入：音频特征⟶输出：每帧×每说话人的活动概率

即输出矩阵 Y∈[0,1]T×S\mathbf{Y} \in [0,1]^{T \times S}Y∈[0,1]T×S（SSS = 最大说话人数），Yt,sY_{t,s}Yt,s​ = "时刻 ttt 说话人 sss 在说话"的概率。每帧可以同时有多个说话人为 1——重叠被输出空间天然支持。

小例子（2 人 × 3 帧，每帧 25 ms）：

t1t_1t1​ 0.98 0.02 只有 A 在说
t2t_2t2​ 0.97 0.95 两人同时说（重叠）
t3t_3t3​ 0.01 0.96 只有 B 在说

对照第 3 周的聚类路线：它的输出空间是"每段挑一个标签"，t2t_2t2​ 这一帧只能二选一；而 EEND 的 t2t_2t2​ 行有两个高概率，重叠被原样表达出来。这是输出空间层面的差异，也是两条路线所有行为差异的根源。

1.3 训练目标：逐帧二元交叉熵

对每个说话人维度独立做二分类：

L=1T⋅S∑t,sBCE(Yt,s,Y^t,s)\mathcal{L} = \frac{1}{T \cdot S} \sum_{t,s} \text{BCE}(Y_{t,s}, \hat{Y}_{t,s}) L=T⋅S1​t,s∑​BCE(Yt,s​,Y^t,s​)

2. PIT：置换不变训练

2.1 问题

若直接用固定编号算损失，网络会被"编号"本身干扰：同一内容换个编号顺序，损失就不同。这会让训练信号充满噪声。

2.2 PIT 的解法

对每个样本，枚举所有说话人置换，取损失最小的那个置换作为该样本的监督方式：

LPIT=min⁡π∈PS  1T⋅S∑t,sBCE(Yt,s,Y^t,π(s))\mathcal{L}_{\text{PIT}} = \min_{\pi \in \mathcal{P}_S} \; \frac{1}{T \cdot S} \sum_{t,s} \text{BCE}(Y_{t,s}, \hat{Y}_{t,\pi(s)}) LPIT​=π∈PS​min​T⋅S1​t,s∑​BCE(Yt,s​,Y^t,π(s)​)

这个公式在干什么：π\piπ 是一种"给输出神经元重新贴标签"的方案，Y^t,π(s)\hat{Y}_{t,\pi(s)}Y^t,π(s)​ 表示"按方案 π\piπ 重排后的标注"。在 PS\mathcal{P}_SPS​（S!S!S! 种方案）里挑出让损失最小的那个——意思是：不管网络内部把"真 A"叫 0 号还是 1 号，只要存在一种对应关系能把预测和真值对上，就算预测对了。

小例子（2 人 × 3 帧，沿用 1.2 的真值：A 在 t1t_1t1​、t2t_2t2​ 说话，B 在 t2t_2t2​、t3t_3t3​ 说话）：

真值 Y^\hat{Y}Y^（说话人 0 / 1） 预测 YYY（神经元 0 / 1）
t1t_1t1​ 1 / 0 0.02 / 0.97
t2t_2t2​ 1 / 1 0.04 / 0.96
t3t_3t3​ 0 / 1 0.95 / 0.03

网络实际上把"真 A"学在了神经元 1、把"真 B"学在了神经元 0——和真值的编号正好相反。若按固定编号算 BCE，t1t_1t1​、t3t_3t3​ 几乎全错，损失巨大；但置换 π\piπ = “0↔1 互换"后，预测与真值几乎完美吻合，PIT 损失 ≈ 0。没有 PIT：这份好预测会被当成错误去惩罚；有了 PIT：它被正确识别为"只是贴反了标签"。训练信号从此与编号无关，网络专注学"有几股不同的声音、各自何时在响”。

直觉：不告诉网络"1 号神经元必须是谁"，只要求"存在某种一一对应，使预测与真值吻合"。网络因此可以自由组织输出神经元。

代价：S!S!S! 随 SSS 阶乘增长。S=3S = 3S=3 时有 6 种置换，S=5S = 5S=5 时有 120 种——这是 EEND 说话人数上限受限的根源。

动手验证：用 itertools.permutations(range(S)) 打印 S=2,3,4S=2,3,4S=2,3,4 时的置换数量，感受阶乘爆炸；再对 1.2 的小例子手算两种置换下的 BCE，验证"取最小"翻转了训练信号。

一句话总结：PIT = “标签随便贴，对上就行”——把"编号歧义"从训练目标里彻底移除。

3. EEND 家族演进

3.1 EEND（基础版，Fujita et al. 2019）

最初版本用 BLSTM 编码器 + PIT 损失；随后 ASRU 2019 版本（Fujita et al., “End-to-End Neural Speaker Diarization with Self-attention”）换成 Transformer Encoder + 线性层 → T×ST \times ST×S 概率。适合 2-3 人的固定上限场景，官方实现见 hitachi-speech/EEND。

3.2 EEND-EDA：动态说话人数（Fujita et al., Interspeech 2020）

问题：基础版 SSS 固定，但真实会议人数不定。

EEND-EDA（Encoder-Decoder based Attractors，编解码吸引子）：核心概念是吸引子（attractor）——一个"说话人画像向量"，与每帧特征做内积就得到该说话人的活动概率。EDA 用一个 LSTM 编码-解码器逐个生成吸引子，并额外生成一个"空吸引子"表示"没有更多说话人了"，生成到它为止。人数不再是超参数，而是模型输出。

3.3 EEND-VC：局部 EEND + 全局聚类（Horiguchi et al. 2020）

问题：EEND 每次处理一段音频，不同块（乃至不同会议）里的"说话人 1"无法对应同一个人；且 Transformer 的上下文长度限制了单次能处理的音频。

EEND-VC（EEND-vector clustering）：局部 EEND + 全局声纹聚类结合——EEND 网络除了输出每帧分离标签，还输出每帧的说话人嵌入；先在块内做局部分离，再用声纹向量跨块聚类对齐标签。兼顾了 EEND 的重叠处理与聚类路线的可扩展性。

3.4 TS-VAD：目标说话人路线（Medennikov et al., Interspeech 2020）

TS-VAD（Target-Speaker Voice Activity Detection，目标说话人语音活动检测）：给定每个目标说话人的参考声纹（或前一轮估计），模型输出"这些特定说话人各自的活动"。

输入：音频 + S 个目标声纹→输出：这 S 人各自的逐帧活动概率\text{输入：音频 + } S \text{ 个目标声纹} \quad \to \quad \text{输出：这 } S \text{ 人各自的逐帧活动概率} 输入：音频 + S 个目标声纹→输出：这 S 人各自的逐帧活动概率

优势：说话人身份由输入（参考声纹）指定，不再依赖输出神经元编号——PIT 都不需要；可迭代精化（用上一轮输出作参考再跑一轮）。TS-VAD 是 DIHARD II 竞赛头部方案（如三星/STC 系统）的核心组件。
前提：需要说话人参考（注册声纹或聚类初始化）。

6. 工程权衡与失效模式

6.1 权衡

  • SSS 上限：EEND 的 S!S!S! 置换代价限制说话人数。3-4 人是实用上限；
  • 上下文长度：Transformer 窗口限制，长音频要分块 + 跨块对齐（EEND-VC）；
  • 计算成本：端到端前向远贵于声纹提取，端侧慎用。

6.2 失效模式

  1. 人数超出 SSS：真实 5 人但 S=3S=3S=3，模型只能硬凑。修复：EEND-EDA 或切段处理。
  2. 跨会话混淆：两段音频的"说话人 1"不是同一人。修复：EEND-VC / TS-VAD + 全局声纹。
  3. 重叠漏检：EEND 在重叠段置信度低。修复：加重叠辅助损失、提升训练数据重叠比例。
  4. 长音频漂移：分块处理时块间标签不一致。修复：声纹对齐块间标签。

7. 延伸思考题（含解析）

Q1：PIT 损失为什么必要？不用会怎样？
A：说话人编号是任意的，固定编号监督会给网络引入与内容无关的编号噪声。PIT 枚举所有置换取最优，让网络只学"内容分组"不学"编号"。不用会训练不稳、收敛到与编号绑定的错误解。

Q2：聚类法与 EEND 的重叠处理能力差异的根因？
A：在输出空间设计。聚类法每段输出互斥单标签，重叠段只能选一个；EEND 输出每帧多标签，重叠天然可表达。这是架构层面的差异，不是调参能弥补的。

Q3：两人同时说话怎么办？
A：① 若用聚类路线：加 OSD 检测重叠区，标"多说话人"，但拆不开内容；② 若用端到端：EEND/TS-VAD 直接输出两人各自的活动区间。要求精确拆分时必须走端到端。

Q4：EEND 为什么有说话人数上限？
A：PIT 需枚举 S!S!S! 置换，且输出层维度随 SSS 线性增长，训练与推理成本阶乘/线性上升。实用上限 3-4 人。EEND-EDA 用吸引子动态生成缓解，但仍有天花板。

Q5：你的结论表会怎么写"什么场景选什么方案"？
A：短片段、≤4 人、重叠多 → 端到端（EEND/TS-VAD）；长会议、人数多、重叠少 → 聚类路线；工业折中 → 聚类骨架 + 重叠检测，或聚类初始化 + TS-VAD 精化。用实测 DER 数据支撑。

第 3 周教程：说话人分离——聚类路线（主流工业方案）

本周要回答的三个问题

  1. 主流工业分离流水线的五个步骤是什么？每步的输入输出是什么？
  2. 谱聚类为什么比 K-Means 更适合声纹聚类？亲和矩阵是什么？
  3. 说话人数量怎么估？重叠语音为什么是聚类路线的先天缺陷？

对应学习计划：第 3 周。交付物：跑通 pyannote.audio 3.x 分离流水线，输出 RTTM 文件，用 pyannote.metrics 计算 DER 并拆解为 Miss + False Alarm + Confusion 三部分。

1. 第一性原理：分离 = “无监督的说话人分组”

1.1 问题定义

给定一段多人音频，输出每个时刻是谁在说话：

{(start,end,speaker)} 区间的集合\{(\text{start}, \text{end}, \text{speaker})\} \text{ 区间的集合} {(start,end,speaker)} 区间的集合

关键难点：没有标签（不知道有几个人、谁是谁），也不知道说话人数量。这是纯无监督问题。

1.2 聚类路线的核心假设

同一说话人的声纹向量彼此接近，不同说话人的彼此远离。

于是分离 = 把切片的声纹向量聚类，每个簇对应一个说话人。这就是聚类路线（pyannote、NeMo 等工业流水线的核心骨架）。

2. 五步流水线（工业标准）

音频→① VAD/切块片段→② 声纹提取向量集→③ 聚类标签→④ 重分段区间→⑤ 输出RTTM\text{音频} \xrightarrow{\text{① VAD/切块}} \text{片段} \xrightarrow{\text{② 声纹提取}} \text{向量集} \xrightarrow{\text{③ 聚类}} \text{标签} \xrightarrow{\text{④ 重分段}} \text{区间} \xrightarrow{\text{⑤ 输出}} \text{RTTM} 音频① VAD/切块​片段② 声纹提取​向量集③ 聚类​标签④ 重分段​区间⑤ 输出​RTTM

① 切块（Segmentation）

  • 用 VAD 去掉静音，把语音切成片段；
  • 经典做法是滑动窗口：窗长 1.5 s、帧移 0.75 s（50% 重叠）；
  • 输出若干候选片段，每段假设"只含一个说话人"。

为什么 1.5 s：太短声纹不稳（第 1 周讲过），太长容易横跨两人。1.5 s 是经验甜点。

与 pyannote 3.x 的对照：pyannote 3.x 不再手工定长滑窗，而是先用一个说话人分割模型（10 秒窗口的端到端网络，逐帧输出"每个说话人在说话的概率"）切出候选区，再在候选区上提声纹聚类——思想相同（切割 → 表征 → 分组），只是"切"这一步也交给了神经网络。

② 声纹提取

对每个片段用 ECAPA 提取声纹向量。1 小时音频、0.75 s 帧移 → 约 4800 段 → 4800 个向量。

③ 聚类（核心）

把 4800 个向量聚成 KKK 簇，KKK = 说话人数。难点：KKK 未知。

④ 重分段（Re-segmentation）

聚类只给出每段的说话人，但段边界粗糙。重分段用更细粒度（逐帧）的声纹或 VAD 边界，把标签平滑成连续区间，消除碎片。

⑤ 输出 RTTM

RTTM（Rich Transcription Time Marked，NIST 定义）是分离结果的标准交换格式，每行 10 个空格分隔字段：

# 字段 本例取值 含义
1 类型 SPEAKER 行类型（说话人轮次）
2 文件 ID file 音频标识
3 声道 1 声道号
4 起始时间 12.34 秒
5 持续时长 5.67 秒
6 正字法 <NA> 转写占位（分离场景不用）
7 说话人类型 <NA> 占位
8 说话人名 speaker_0 核心字段
9-10 置信度/附加 <NA> <NA> 占位

之后任何组件（ASR 对齐、评测、人工校对）都读写这个格式，它是分离系统的"通用货币"。

3. 聚类算法：谱聚类为什么胜出

3.1 K-Means 的局限

K-Means 假设簇是凸形、各向同性的，用欧氏距离找球心。但声纹簇在超球面上形状不规则，且 K-Means 需要预设 KKK、对初始化敏感。

3.2 谱聚类（Spectral Clustering）

谱聚类基于图论：把"4800 段谁和谁像"变成一张图，再沿图的连通结构分组。

  1. 构造亲和矩阵 A\mathbf{A}A：Aij=sim(ei,ej)A_{ij} = \text{sim}(\mathbf{e}_i, \mathbf{e}_j)Aij​=sim(ei​,ej​)——声纹余弦相似度，再做阈值化（低于阈值的相似度置 0，等于"不像就不连线"；这是声纹分离场景的经典做法，如 Wang et al. 2018 的 LSTM 分离系统）；

  2. 构建图拉普拉斯 L=D−A\mathbf{L} = \mathbf{D} - \mathbf{A}L=D−A（D\mathbf{D}D 是度矩阵，对角线为每行的相似度总和）；

    这个公式在干什么：L\mathbf{L}L 是"图的能量账本"——AijA_{ij}Aij​ 记录"点 iii 和 jjj 之间弹簧拉多紧"，L\mathbf{L}L 的特征值刻画"把这幅图切成 KKK 块要花多少能量"。图越接近"KKK 个互不相连的团体"，L\mathbf{L}L 的最小 KKK 个特征值就越接近 0；

  3. 取 L\mathbf{L}L 的最小 KKK 个特征向量，把每行当新坐标 → 降维后的点"簇内紧、簇间散"；

    为什么有效（直觉）：特征向量是"图的和谐振动模式"。同一个真实团体里的点，在任何低频振动模式上取值都一样——于是取前 KKK 个特征向量当新坐标后，同一团体被映射到几乎相同的坐标，K-Means 变成了"切豆腐"。

  4. 在新空间做 K-Means。

为什么更适合声纹：谱聚类能捕捉非凸簇结构（通过图的连通性），且亲和矩阵直接编码"两两相似度"，与声纹的度量天然匹配。pyannote 2.x 就是用谱聚类做分离的。

3.3 AHC：凝聚层次聚类（pyannote 3.x 的默认选择）

这个算法在干什么：自底向上——开始每个片段自成一簇，反复"把最像的两簇合并"直到停。pyannote 3.x 的配置是：声纹余弦相似度 + centroid（质心）链接（两簇的距离 = 两簇质心的距离）+ 阈值 0.70（相似度低于阈值就停止合并）+ min_cluster_size = 12（太小的簇并入邻居，防"幽灵说话人"）。

与谱聚类的分工直觉：谱聚类"全局看图、一步到位"，AHC"局部贪心、逐步合并"。AHC 不需要特征分解，对几万段的长音频更省内存，且阈值天然带出"自动停"——说话人数由阈值决定，不用预设 KKK。

3.4 说话人数量估计

谱聚类和 K-Means 需要 KKK。常用手段：

  • 特征值法（eigengap）：拉普拉斯矩阵的特征值会呈现"前 KKK 个很小、之后跳变"的模式，跳变点即 KKK；
  • NME-SC（Normalized Maximum Eigengap Spectral Clustering，归一化最大特征间隙谱聚类）：在候选 KKK 范围上逐个跑谱聚类，取"特征间隙最大 + 轮廓系数最高"的 KKK，是学术系统与竞赛中常用的自动估数方案；
  • 预设 + 校验：先猜一个范围，用轮廓系数等选最优；
  • AHC 阈值法：如上节，合并到"最好的两簇相似度低于阈值"为止，簇数自动确定（pyannote 3.x 路线）；
  • 业务先验：会议系统让用户点一下"这是 3 人会"，往往比一切自动估计都稳。

估错 KKK 的后果：估多 → 同一人被拆成多个；估少 → 不同人被合并。这是聚类路线的主要误差源之一。

4. 重叠语音：聚类路线的先天缺陷

4.1 问题本质

聚类假设"每段只含一个说话人"，且每个时刻只能分配一个标签。当两人同时说话（overlap），该段的声纹是两人混合，聚类只能选一个 → 另一个人的语音被错标或漏标。

4.2 缓解手段

  • OSD（Overlap Speech Detection）：先检测重叠区，重叠区允许两个标签；
  • 但 OSD 只能标记"这里重叠"，无法精确拆出每人说了什么——这是聚类路线的根本上限。

彻底解决重叠要端到端方法（第 4 周）。

5.2 计算 DER 并拆解

DER 三分解（本周自测题，必须记住）：

DER=Miss⏟漏检语音+False Alarm⏟把噪声当语音+Confusion⏟说话人标错\text{DER} = \underbrace{\text{Miss}}_{\text{漏检语音}} + \underbrace{\text{False Alarm}}_{\text{把噪声当语音}} + \underbrace{\text{Confusion}}_{\text{说话人标错}} DER=漏检语音Miss​​+把噪声当语音False Alarm​​+说话人标错Confusion​​

  • Miss：真实有语音但系统没标（VAD 漏检）；
  • False Alarm：无语音（静音/噪声）但系统标了人；
  • Confusion：检测到了语音，但说话人标错了（聚类错误）。

这个公式在干什么：把所有时间帧按"参考标注里是谁 vs 系统说是谁"分桶，三类错误帧的时长占比相加。分母是参考语音总时长——所以 DER 本质是时间占比而不是帧数占比，"漏掉 30 秒"在 1 分钟和 1 小时的音频里权重完全不同。

口径提醒（重要）：报 DER 必须说明"怎么算的"，否则数字不可比：

  1. collar（缓冲区）：NIST 传统评测在标注边界两侧各放宽 0.25 s 不计错误（人标边界本身有 ±0.1 s 误差）；pyannote.metrics 默认 collar = 0，数字会更"狠"；
  2. 重叠区算不算：早期 NIST 口径把两人重叠的帧从 DER 统计中剔除（当时聚类法都处理不了，剔除是为了公平）；现代评测（含 pyannote）默认把重叠区算进 Miss/Confusion。同一份结果按两种口径报，DER 可以差好几个点；
  3. JER（Jaccard Error Rate）：DIHARD 评测引入的补充指标——按"每个说话人各自的时间重叠率（Jaccard 指数）“算误差再对所有说话人取平均，每个人权重相同，避免"话多的人主导 DER、话少的人被漏光也看不出来”。JER 通常略高于 DER，对"小话痨被漏"更敏感。

分析价值：Miss/FA 高 → 改 VAD/切块；Confusion 高 → 改声纹模型或聚类。这是分离调优的诊断地图。

6. 工程权衡与失效模式

6.1 权衡

  • 窗长：短 → 时间分辨率高但声纹不稳；长 → 反之。1.5 s 是甜点；
  • 说话人数估计：估多伤 Confusion，估少伤完整性；
  • 重叠处理：纯聚类不处理重叠，需加 OSD，但能力有限。

6.2 失效模式

  1. 说话人数估错：同一人被拆或不同人被合并。诊断：Confusion 高；修复：改用自动估数（NME-SC）或提供人数先验。
  2. 短发言漏标：说话人只说了一两个字，声纹不稳被归入别人或丢弃。修复：降低切块长度阈值 + 后处理合并。
  3. 重叠区错标：两人同时说话，聚类只给一个标签。诊断：听重叠区音频；修复：OSD + 端到端（第 4 周）。
  4. 信道不一致：不同说话人录音条件差异大，声纹分布被信道污染。修复：前端降噪（Stage 3）+ 域适应。

1. 第一性原理：TTS 的两段式分解

1.1 任务定义

给定文本，生成自然、流畅、（可选）像特定人的语音波形。难点在于：文本是离散、稀疏、无韵律信息的符号序列，而语音是连续、稠密、带丰富韵律的信号——两者之间隔着巨大的信息鸿沟。

1.2 经典两段式分解

文本→文本前端音素序列→声学模型梅尔谱→声码器波形\text{文本} \xrightarrow{\text{文本前端}} \text{音素序列} \xrightarrow{\text{声学模型}} \text{梅尔谱} \xrightarrow{\text{声码器}} \text{波形} 文本文本前端​音素序列声学模型​梅尔谱声码器​波形

  • 文本前端（Text Frontend）：文本 → 音素（G2P, grapheme-to-phoneme），处理多音字、数字、标点停顿；
  • 声学模型（Acoustic Model）：音素 → 梅尔谱，决定"说什么、什么韵律"；
  • 声码器（Vocoder）：梅尔谱 → 波形，决定"音质"。

这个分解的意义：把难题拆开。声学模型专注内容与韵律，声码器专注音质，各自可独立优化。

2. 声学模型演进：Tacotron → FastSpeech

2.1 Tacotron（Seq2Seq + Attention）

把 TTS 当序列到序列（Seq2Seq，源自机器翻译）：编码器读音素，解码器自回归逐帧生成梅尔谱。中间靠 attention（注意力） 对齐"当前该生成第几帧、对应哪个音素"。

这个机制在干什么：把翻译里的"对齐源词与目标词"搬到语音里——对齐"第 iii 步解码 ↔ 第 jjj 个音素"。每一步解码时，解码器状态 sis_isi​ 与编码器每个音素的隐状态 hjh_jhj​ 算一个匹配分数 eije_{ij}eij​，softmax 归一化成权重 αij\alpha_{ij}αij​，再对音素加权求和得到上下文向量 ci=∑jαijhjc_i = \sum_j \alpha_{ij} h_jci​=∑j​αij​hj​。cic_ici​ 回答的问题是：“现在生成这一帧，该重点参考哪个音素。” 权重应该沿时间轴单调移动（读完一个音素再读下一个）， Tacotron 系列用位置敏感 attention 等约束近似保证这一点。

问题：

  • 自回归慢（逐帧生成）；
  • attention 对齐易出错 → 跳字、重复、漏字（权重突然跳回前面音素，就会"复读"；跨过某音素，就会"漏读"）；
  • 鲁棒性依赖 attention 的单调性约束。

2.2 FastSpeech（非自回归 + 显式时长）

FastSpeech 的突破：不让模型自己学对齐，而是显式预测每个音素的时长（duration）。

2.3 FastSpeech 2 的改进

FastSpeech 2 直接放弃了 teacher 蒸馏：用 Montreal Forced Aligner（MFA）等强制对齐工具从 (文本, 真实音频) 对里提取精确时长，同时加入音高（pitch）预测器和能量（energy）预测器，把韵律也显式建模，可控性更强——这就是它的 variance adaptor（方差适配器）：时长、音高、能量三个"可变量"各由一个小预测器显式给出，训练时用真实值做标签，推理时用预测值。FastSpeech 2 是工业 TTS 的基石架构。

3. 声码器：梅尔谱 → 波形的"一对多"难题

3.1 难题本质

梅尔谱只保留幅度，丢失了相位。而重建波形需要两者。更麻烦的是：

同一个梅尔谱  ⟷  无数种可能的波形\text{同一个梅尔谱} \;\longleftrightarrow\; \text{无数种可能的波形} 同一个梅尔谱⟷无数种可能的波形

因为相位不确定，且人耳对相位不敏感。这就是"一对多"问题——声码器的任务是从一对多的映射里，挑出一个听起来自然的波形。

类比：梅尔谱像一张"黑白素描"（只有轮廓和明暗），波形是"全彩照片"。上色方案有无穷多种，每种上色听起来（看起来）都成立——声码器就是要挑一种"画得像真人画的"的上色方案。

一句话总结：梅尔谱丢掉了相位，"一谱多波"不可逆转；声码器的本质是在这个不确定集合里，生成一个相位结构自然、骗过人耳（和判别器）的波形。

3.2 三代声码器

第一代：Griffin-Lim（无模型）

迭代地从幅度谱估计相位（你在 Stage 1 第 2 周实现过）：先随机/零初始化相位 → FFT 变到频域 → 把幅度替换成已知的真实幅度 → 逆变换回时域，重复几十轮，相位会逐渐"长"出与幅度谱一致的结构。复杂度：每轮一次 FFT + 一次逆 FFT，即 O(Nlog⁡N)O(N \log N)O(NlogN)（NNN 为样本数），常用 32–60 轮（librosa 默认 32），所以整段合成是"秒级、CPU 可跑"——比逐点自回归快得多，但音质差、有"金属感"伪影：它只会让相位"自洽"，完全无法建模真实语音的相位结构（比如辅音的相位突变）。

第二代：WaveNet（自回归）

DeepMind 的 WaveNet（van den Oord et al., 2016）用因果膨胀卷积逐采样点生成波形，把联合概率按链式法则拆成逐点条件概率：

p(x)=∏tp(xt∣x<t)p(x) = \prod_{t} p(x_t \mid x_{<t}) p(x)=t∏​p(xt​∣x<t​)

这个公式在干什么：它就是"接龙"——把"生成一整段波形"这个大问题拆成无数个小的"下一个采样点是什么"问题，每个小问题都用神经网络输出一个概率分布（对 16-bit 音频是 65536 类的分类），采样一个点，拼回条件里继续。∏t\prod_t∏t​ 表示整段语音的概率 = 每个点条件概率的连乘。结果拿来做什么：训练时最大化 log⁡p(x)\log p(x)logp(x)（逐点交叉熵），推理时从左到右逐点采样。

音质极好（首次把合成语音的自然度做到接近真人，MOS 差距缩小到 0.1–0.2 以内），但逐采样点自回归——16 kHz 意味着每秒要串行前向 16000 次，慢到无法实用（WaveNet 论文里是"每秒音频需要数分钟合成"量级）。

第三代：HiFi-GAN（并行 GAN）

HiFi-GAN 的突破：用 GAN 一次性并行生成整段波形，不再是逐点自回归。

4. HiFi-GAN 深拆

4.1 生成器：从梅尔谱直接"上采样"出波形

生成器是一串转置卷积（上采样），把低帧率的梅尔谱逐步放大到高采样率波形：

梅尔谱(80,T)→上采样(1,T×hop)\text{梅尔谱} (80, T) \xrightarrow{\text{上采样}} (1, T \times \text{hop}) 梅尔谱(80,T)上采样​(1,T×hop)

这条流程在干什么：梅尔谱每帧对应波形里 hop 个采样点（HiFi-GAN 原配置 22.05 kHz、hop = 256），生成器就是要把每一帧"摊开"成 256 个波形点，再把这些点雕琢成真实振动的形状。类比：梅尔谱是"分镜脚本"（每秒 86 帧），波形是"逐格动画"（每秒 22050 张），转置卷积负责把脚本摊开成动画帧，MRF 负责给每帧补细节。

配合 MRF（Multi-Receptive Field Fusion，多感受野融合）模块：每级上采样后接多个不同 (卷积核, 膨胀率) 组合的残差块（论文用核 3/7/11 × 膨胀 1/3/5），并行处理后逐元素相加取平均。为什么需要：小感受野抓"即时波形纹理"，大感受野抓"跨周期的谐波结构"，融合后细节与结构兼得——类似多焦距镜头同时拍清近景与远景。

4.2 判别器：MPD + MSD

HiFi-GAN 用两个判别器从不同角度挑毛病：

  • MPD（Multi-Period Discriminator，多周期判别器）：把一维波形按周期 kkk 重排成二维——即每 kkk 个采样点抽出一列，形状从 (N,)(N,)(N,) 变成 (N/k, k)(N/k,\, k)(N/k,k)，用 k∈{2,3,5,7,11}k \in \{2, 3, 5, 7, 11\}k∈{2,3,5,7,11}（质数，避免不同 kkk 的切分方式重叠）。这个重排在干什么：语音波形有强周期性（基频与谐波）。重排后，同一列里的点恰好相隔 kkk 个采样点——如果 kkk 接近信号的真实周期，每一列的形态就高度相关，“周期对没对上"在二维图上一眼看穿。手算小例：波形 [1,2,3,4,5,6,7,8] 按 k=2k=2k=2 重排得 [[1,2],[3,4],[5,6],[7,8]]，第一列全是奇数位置的点——判别器沿列扫一眼，就能判断"这个周期规律自然吗”。
  • MSD（Multi-Scale Discriminator，多尺度判别器）：先对波形做 1/2、1/4 平均池化（下采样），再分别判别——粗尺度看整体包络与响度起伏，细尺度看局部纹理。

为什么两个：单一判别器有盲区。MPD 抓周期结构，MSD 抓多尺度波形形态，两者互补，逼生成器同时做好周期性和整体形态。

5. VITS：端到端的统一

5.1 动机

两段式（声学模型 + 声码器）要分别训练、误差累积。VITS（Kim et al., Kakao, arXiv:2106.06103, ICML 2022）把整个流程端到端进一个模型：

文本→编码器隐变量→Normalizing Flow→解码器（HiFi-GAN 式）波形\text{文本} \xrightarrow{\text{编码器}} \text{隐变量} \xrightarrow{\text{Normalizing Flow}} \xrightarrow{\text{解码器（HiFi-GAN 式）}} \text{波形} 文本编码器​隐变量Normalizing Flow​解码器（HiFi-GAN 式）​波形

5.2 三大组件

  1. VAE（变分自编码器）：把语音编码到隐变量空间 zzz（后验编码器），再从 zzz 解码波形；训练时从真实语音压出 zzz（可见"答案"），推理时从"文本条件下的先验分布"采样 zzz。zzz 的作用：它是一个"声学配方"——承载音色、韵律、相位等梅尔谱装不下的连续细节。
  2. Normalizing Flow（规范化流）：一个可逆变换，把"文本条件下的简单先验（高斯）"变换成与真实语音隐变量匹配的复杂分布。类比：把随手捏的橡皮泥（高斯）通过一套固定模具（可逆网络）捏成精确的目标形状——可逆性保证了训练时能算严格的似然。
  3. MAS（Monotonic Alignment Search，单调对齐搜索）：训练时用动态规划在"文本 ↔ 语音帧"的所有单调对齐方式里，找出使数据似然最大的那一个，从而得到每个音素的时长——不需要外部时长标签（对比 FastSpeech 需要 teacher/MFA）。

一句话总结：VAE 负责"隐空间里有东西"，Flow 负责"文本能指到对的隐变量"，MAS 负责"不靠别人标注也能学对齐"——三者合起来，文本直通波形。

5.3 VITS 的优势与代价

  • 优势：端到端、对齐自学、音质高、自然度好；推理是全并行的（一次前向出整段波形），速度并不慢；
  • 代价：训练复杂、调参难（GAN + VAE + Flow 三种目标要平衡），工程实现门槛高。

VITS 是"端到端零样本克隆"的重要基座（GPT-SoVITS 的 SoVITS 模块、Bert-VITS2 等大量克隆系统都基于 VITS 改造）。

7. 工程权衡与失效模式

7.1 权衡

  • 自回归 vs 非自回归：自回归质量高但慢（WaveNet/Tacotron）；非自回归快但需显式时长（FastSpeech）；
  • 两段式 vs 端到端：两段式灵活可替换、但误差累积；端到端一致性好、但训练复杂；
  • 采样率：22/24 kHz 音质好但算力高；16 kHz 省算力。

7.2 失效模式

  1. attention 对齐错误（Tacotron）：跳字、重复。修复：单调约束、位置敏感 attention。
  2. 时长预测不准（FastSpeech）：语速忽快忽慢。修复：更好的时长标签、韵律控制。
  3. 声码器伪影：GAN 生成出现噪声、嗡嗡声。修复：判别器增强、训练更久。
  4. 多音字/韵律平淡：文本前端或韵律建模不足。修复：G2P 词典、显式韵律控制。

8. 延伸思考题（含解析）

Q1：梅尔谱 → 波形的一对多难题是什么？三种声码器各怎么破？
A：梅尔谱丢相位，同一谱对应无数波形。Griffin-Lim 迭代估相位（无模型、音质差）；WaveNet 自回归逐点生成（建模相位但慢）；HiFi-GAN 用 GAN 并行生成（判别器逼出自然波形，快且好）。

Q2：HiFi-GAN 为什么要 MPD + MSD 两个判别器？
A：MPD 按周期重排判别周期性结构（谐波、音高），MSD 在多尺度判别整体波形形态。单一判别器有盲区，两者互补逼生成器同时做好周期性与形态。

Q3：FastSpeech 为什么比 Tacotron 快且稳？
A：FastSpeech 用显式时长预测器替代 attention 对齐，能并行生成所有帧（非自回归），且对齐由时长决定不再依赖易错的 attention。速度数十倍提升、鲁棒性更好。

Q4：VITS 的 MAS 相比 FastSpeech 的时长标签，优势是什么？
A：FastSpeech 需要外部 teacher 的 attention 提取时长标签（依赖预训练、误差传递）；VITS 的 MAS 在训练中自动单调对齐，端到端自学，无需外部标签，更简洁一致。

Q5：为什么现代零样本克隆多基于 VITS 或 flow matching，而不是 FastSpeech+HiFi-GAN？
A：克隆需要注入参考音频的说话人信息并高保真重建音色。VITS/flow 的端到端隐变量/流建模更能表达说话人细节与多样性；FastSpeech 的确定性梅尔谱路线对音色细节表达受限。

1. 第一性原理：语音可以当"语言"来建模

1.1 VALL-E 的核心洞察

传统 TTS 生成的是连续的梅尔谱。VALL-E（Wang et al., Microsoft, 2023, arXiv:2301.02111，全名 Neural Codec Language Models are Zero-Shot Text to Speech Synthesizers）的洞察：

如果把语音编码成离散的 codec token，那么 TTS 就变成了一个标准的语言建模问题——给定文本 token，自回归地预测语音 token。

文本 token  →  语音 codec token  →codec 解码  波形\text{文本 token} \;\to\; \text{语音 codec token} \;\xrightarrow{\text{codec 解码}}\; \text{波形} 文本 token→语音 codec tokencodec 解码​波形

这让 TTS 直接复用 LLM 的全部技术：大规模预训练、in-context learning、zero-shot 能力。

1.2 为什么这能实现零样本克隆

VALL-E 把零样本克隆变成 in-context learning：

prompt：参考音频的 codec token+目标文本  →  目标语音的 codec token\text{prompt：参考音频的 codec token} + \text{目标文本} \;\to\; \text{目标语音的 codec token} prompt：参考音频的 codec token+目标文本→目标语音的 codec token

模型见过海量"同一说话人不同句子"的数据，学会了"参考音频 → 该音色"的映射。给它几秒参考音频（论文用 3 秒录音）作为 prompt，它就能续写出同样音色的新内容——不需要任何微调。

这就是零样本克隆的通用配方：

2. 音频离散化：EnCodec 与 RVQ

2.1 Neural Audio Codec 是什么

音频 codec（编解码器）把波形压缩成紧凑的离散表示，再重建波形。代表工作：SoundStream（Zeghidour et al., Google, 2021，首次把 RVQ 用进神经音频编解码）、EnCodec（Défossez et al., Meta, 2022）、DAC / Descript Audio Codec（Kumar et al., Descript, 2023，改进 RVQGAN，主打 44.1 kHz 高保真）。结构都是同一副骨架：

波形→Encoder连续特征→RVQ离散 token→Decoder重建波形\text{波形} \xrightarrow{\text{Encoder}} \text{连续特征} \xrightarrow{\text{RVQ}} \text{离散 token} \xrightarrow{\text{Decoder}} \text{重建波形} 波形Encoder​连续特征RVQ​离散 tokenDecoder​重建波形

各环节的分工：Encoder 是个下采样卷积网络，把每秒几万个采样点压成每秒几十~上百个连续向量；RVQ 把每个向量变成一小组离散码；Decoder 是上采样网络，把离散码还原回波形——端到端训练，目标是"重建出来的波形听不出和原声的差别"。

2.2 RVQ（Residual Vector Quantization，残差向量量化）

这是离散化的核心，也是与"量化方向"联动的关键。

普通向量量化（VQ）：把连续向量 zzz 映射到码本（codebook）里最近的那个向量。这个操作在干什么：相当于"只允许用字典里的词说话"——zzz 是千变万化的连续点，码本是有限的 KKK 个"标准点"，量化 = 找到离你最近的标准点并记住它的编号（编号就是 token）。代价：最近的替代点与原点的距离就是量化误差；单个码本（哪怕 1024 个向量）表达力有限，误差太大。

每层 codebook 大致在建模什么（经验规律，不是严格定理）：

  • 第 1 层：主体信息——内容与韵律骨架（说了什么、怎么抑扬顿挫）；
  • 后续层：逐层细化的声学细节（音色纹理、相位、音质）。

注意：这是 EnCodec 这类声学重建导向 codec 的经验分层，第 1 层仍是"声学 token"而非干净的语义表示——它混合了内容与音色。这正是第 3-4 周要讲的 CosyVoice 改用"监督语义 token"的动机。

这个分层结构与量化方向的联系：

  • RVQ 是向量量化（把向量映射到码本）；
  • GPTQ/AWQ 是标量量化（把单个权重映射到离散电平）；
  • 两者互为镜像：都是"用离散近似连续"，只是量化的对象和粒度不同。

2.3 比特率计算（本周自测题）

EnCodec 24 kHz 模型的关键参数（Défossez et al., 2022）：

  • 采样率 24 kHz，单声道；

  • RVQ 最多 32 层，每层 codebook 大小 1024（2102^{10}210，即每个时间步每层 10 bit）；

3. VALL-E 的两段式架构

3.1 AR + NAR

VALL-E 用 EnCodec 的前 8 层 RVQ（即 6 kbps 档配置），把生成分两阶段：

  1. AR（自回归）模型：沿时间轴逐帧生成第 1 层 codec token。第 1 层承载内容与韵律骨架，决定"说什么、什么节奏"；
  2. NAR（非自回归）模型：以第 1 层 + 文本为条件，生成第 2–8 层（声学细节）。注意"非自回归"的方向：沿时间是并行的（一整句的所有帧一次算完），沿层间仍是串行的——生成第 iii 层时要看着第 i−1i-1i−1 层，一层一层补细节。

3.2 为什么这样分

  • 第 1 层（内容/韵律）需要长程时序建模 → 适合自回归（和时间轴逐点"接龙"）；
  • 后续层（声学细节）给定第 1 层后基本是"逐帧填色"，无长程依赖 → 沿时间并行，速度快。

这个"先语义后声学"的两段式，是后续所有 LM-based TTS 的共同骨架（CosyVoice、MaskGCT 都是变体）。

3.3 为什么工业界转向 flow matching

VALL-E 系的问题：

  • AR 解码慢、有误码累积；
  • codec token 是声学重建导向的，语义信息不够干净。

后续方案（MaskGCT、Seed-TTS、CosyVoice）的改进：

  • 用语义 token（从 ASR encoder 提取，更干净的"内容"表示）替代纯声学 codec token；
  • 用 flow matching / diffusion 生成声学细节，质量更稳、可控性更好。

这为第 3-4 周的 CosyVoice 拆解铺路：语义 token + flow matching 是当前工业 TTS 的主流配方。

4.3 用 LLM 算语音 token 的困惑度（进阶）

困惑度（Perplexity, PPL）定义为平均负对数似然的指数：

PPL=exp⁡(−1N∑i=1Nlog⁡p(xi∣x<i))\text{PPL} = \exp\left( -\frac{1}{N} \sum_{i=1}^{N} \log p(x_i \mid x_{<i}) \right) PPL=exp(−N1​i=1∑N​logp(xi​∣x<i​))

这个公式在干什么：把"模型每一步的预测分布"折算成一个"等效候选数"。若模型预测很准（p→1p \to 1p→1），log⁡p→0\log p \to 0logp→0，PPL →1\to 1→1（等于闭卷抄答案）；若模型完全瞎猜（词表 V=1024V=1024V=1024 上的均匀分布，p=1/1024p = 1/1024p=1/1024），PPL =1024= 1024=1024——这就是"随机基线 PPL = 词表大小"的由来。PPL = 50 的直观含义：模型每一步的不确定性约等于"在 50 个候选里挑"。

预期：语音第 1 层 token 的困惑度远低于 1024（随机基线），说明它有强结构、可被语言模型预测——这就是 LM-based TTS 可行的量化证据。

5. 工程权衡与失效模式

5.1 权衡

  • 码率：高（12/24 kbps）音质好但 token 多、LM 负担重；低（1.5 kbps）省但音质差；
  • 语义 token vs 声学 codec token：语义干净利于内容控制，声学完整利于音质重建；
  • AR vs NAR：AR 韵律自然但慢，NAR 快但需条件。

5.2 失效模式

  1. AR 误码累积：自回归生成中一个错误传播到后续。修复：温度回退、NAR 声学层。
  2. 音色泄漏：prompt 太短或音色特征不足，克隆不像。修复：加长参考音频、用说话人 embedding 增强。
  3. 内容漂移：生成的语音说了与文本不符的内容。修复：更强的文本-语音对齐、约束解码。
  4. codec 重建上限：再好的 LM 也超不过 codec 的重建质量。修复：用更高码率/更好的 codec。

Q1：EnCodec 24 kHz、启用前 8 层 RVQ（即 6 kbps 档）、每层 1024 词表，1 秒语音的 token 数与比特率？
A：75 帧/秒 × 8 层 = 600 token/秒；比特率 = 75 × 8 × 10 bit = 6 kbps。注意 8 层不是 EnCodec 的上限——24 kHz 模型最多 32 层（24 kbps），VALL-E 只用前 8 层。

Q2：RVQ 为什么分层？每层在建模什么？
A：第 1 层量化主体（语义/内容），后续层逐层量化残差（声学细节、音色）。分层让"内容"与"音质"解耦，可按需取用（低码率只用前几层）。

Q3：为什么 CosyVoice 选"语义 token + flow"两段式，而不是 VALL-E 的纯声学 codec？
A：语义 token（ASR encoder 提取）比声学 codec 的第 1 层更干净地表达内容，利于可控与对齐；flow matching 生成声学细节质量更稳、可流式。纯声学 codec 的语义不够干净、AR 易误码。

Q4：VALL-E 如何实现零样本克隆？为什么不需要微调？
A：把克隆变成 in-context learning：参考音频的 codec token 作为 prompt 拼在目标文本前，模型从海量"同人多句"数据中学会了"参考 → 音色"的映射，续写即克隆。无需针对目标人微调。

Q5：RVQ 与 GPTQ/AWQ 的关系是什么？（跨方向联动题）
A：RVQ 是向量量化（连续向量 → 码本向量之和），GPTQ/AWQ 是标量量化（权重 → 离散电平）。都是"离散近似连续"，互为镜像：一个量化激活/特征的向量，一个量化模型权重。理解其一有助于理解另一个。

1. 第一性原理：工业级流式克隆的三个设计决策

CosyVoice 2 是当前工业级零样本克隆的标杆（阿里通义 FunAudioLLM 团队，2024 年 12 月，论文 arXiv:2412.10117，开源模型 CosyVoice2-0.5B）。它的架构是"语义 token + 因果 flow matching"配方的集大成者。理解它，就理解了当前工业 TTS 的主流设计。

三个核心决策：

  1. 用监督语义 token（FSQ）而非声学 codec token → 内容更干净、更可控；
  2. 因果化 flow matching → 支持流式、低延迟；
  3. 大语言模型骨干 → 继承 LLM 的指令跟随与跨语言能力。

2.1 件一：监督语义离散 token（FSQ）

来源：不是 EnCodec 的自监督声学 codec，而是把 FSQ（Finite Scalar Quantization，有限标量量化）模块插入一个多语言 ASR 模型（SenseVoice-Large 系）的 encoder 里训练得到——监督信号是"识别说了什么"，约 20 万小时中英文数据。具体参数：codebook 大小 6561（=18318^3183，3 个维度、每维 18 个电平），token 帧率 25 Hz（每秒 25 个语义 token）。前代 CosyVoice 1 用的是 VQ（codebook 4096），实际码字利用率只有约 23%，CosyVoice 2 换 FSQ 后利用率 100%——这就是换量的动机。

与 EnCodec 的本质区别（本周自测题）：

EnCodec 声学 token CosyVoice FSQ 语义 token
训练信号 自监督重建（压缩-重建波形） 监督（ASR 识别任务）
承载信息 声学重建（内容+音色混合） 语义/内容为主（音色剥离）
量化方式 残差向量量化 RVQ（多层套娃） 有限标量量化 FSQ（单层、多维电平组合）
帧率 75 Hz 25 Hz
用途 VALL-E 式声学建模 干净的内容表示，利于可控

为什么用语义 token：ASR encoder 被训练来"识别说了什么"，其特征天然聚焦内容、剥离音色——这正是"内容可控、音色另注入"的理想解耦。

FSQ 是什么：把每个特征维度独立量化到一组固定的离散电平（如 18 个电平），多维电平组合成一个码字（18×18×18=656118 \times 18 \times 18 = 656118×18×18=6561）。与 VQ 的区别：VQ 是"在一本 4096 页的字典里查最近条目"，字典太大训练时容易"翻烂前几页"（码本坍缩，很多码字永远用不到）；FSQ 没有"字典"这个实体——每个维度的电平是固定的、等距的，天然每个码字都可能被用到（利用率 100%），训练更稳。手算小例：3 维特征 (1.2,−3.7,0.4)(1.2, -3.7, 0.4)(1.2,−3.7,0.4)，每维就近吸附到 18 电平网格，比如量化成 (1,−4,0)(1, -4, 0)(1,−4,0)——三个数字组合就是码字 (1,−4,0)(1,-4,0)(1,−4,0)，不需要查任何码本。

2.2 件二：自回归 LLM 生成语义 token

CosyVoice 2 直接用预训练 LLM Qwen2.5-0.5B 做骨干：把文本（字符 token）和参考音频的语义 token 按固定比例交错拼成序列，自回归地预测目标语义 token：

[参考音频语义 token  ∣  目标文本]  →AR LLM  目标语义 token[\text{参考音频语义 token} \;|\; \text{目标文本}] \;\xrightarrow{\text{AR LLM}}\; \text{目标语义 token} [参考音频语义 token∣目标文本]AR LLM​目标语义 token

为什么用现成 LLM：继承它的文本理解、指令跟随与上下文学习能力——这是"音色 in-context 学习"能工作的基础。

说话人信息的注入（本周自测题）：两条路一起用——① 参考音频的语义 token 作为 speech prompt 拼进序列（in-context，示范内容与韵律风格）；② 从参考音频提取全局说话人 embedding（基于 3D-Speaker 的 CAM++ 说话人验证模型）注入 flow matching 模型，锁定音色。语义 token 负责"说成什么样"，说话人 embedding 负责"用谁的嗓子说"。

2.3 件三：因果 Flow Matching 解码器

把语义 token 转成梅尔谱（50 Hz、24 kHz），用 Conditional Flow Matching（条件流匹配，CFM），并做了因果化。先把 flow matching 本身讲透：

flow matching 在学什么：定义一条从"纯噪声 ϵ\epsilonϵ"到"目标梅尔谱 x0x_0x0​"的连续路径。最常用的是直线（OT）路径：

xt=(1−t) ϵ+t x0,t∈[0,1]x_t = (1-t)\,\epsilon + t\,x_0, \quad t \in [0, 1] xt​=(1−t)ϵ+tx0​,t∈[0,1]

vt=dxtdt=x0−ϵv_t = \frac{d x_t}{d t} = x_0 - \epsilon vt​=dtdxt​​=x0​−ϵ

这两个公式在干什么：第一个公式把"生成"变成"走直线"——t=0t=0t=0 时 x0x_0x0​ 全是噪声，t=1t=1t=1 时全是有声梅尔谱，中间是两者的线性混合（像调音台从"白噪声"推子慢慢推到"语音"推子）。第二个公式是这条直线的速度：恒定不变，方向由"噪声指向目标"。模型的任务就一个：给定当前位置 xtx_txt​ 和时间 ttt，预测速度 vvv（训练目标是 x0−ϵx_0 - \epsilonx0​−ϵ，即 MSE 回归，比扩散模型的预测目标更直白）。推理时解一个常微分方程（ODE）：dxdt=vθ(xt,t)\frac{dx}{dt} = v_\theta(x_t, t)dtdx​=vθ​(xt​,t)，从噪声出发沿预测速度积分到 t=1t=1t=1，就得到梅尔谱。

手算小例（一维）：目标 x0=2x_0 = 2x0​=2，噪声 ϵ=10\epsilon = 10ϵ=10。直线路径：xt=10−8tx_t = 10 - 8txt​=10−8t，速度恒为 −8-8−8。若模型在 t=0t=0t=0 时就"看准"了速度 −8-8−8，一步积分就能到终点——这就是 flow matching 路径直、少步数推理快的直觉来源（对比扩散模型：预测的是"逐步去一点点噪声"，路径弯绕，需要更多步）。

因果化（Causal）：流匹配网络用因果卷积 + Transformer UNet 实现，每个时刻的梅尔谱只依赖当前及过去的语义 token（部分配置允许看有限帧未来）→ 可以边生成边解码，支持流式。同一模型支持流式与非流式两种模式。

声码器：仓库使用 HiFT 声码器（HiFi-GAN 风格的生成器 + iSTFT 思路的混合结构）从梅尔谱恢复相位出波形。

流式首包延迟 ~150 ms 的来源（论文报告值）：因果设计让模型在收到第一个语义 token chunk 后，就能立刻开始生成对应梅尔谱并出声，无需等整句生成完。论文给出了延迟上界公式：

LTTS=M⋅(dlm+dfm+dvoc)L_{\text{TTS}} = M \cdot (d_{\text{lm}} + d_{\text{fm}} + d_{\text{voc}}) LTTS​=M⋅(dlm​+dfm​+dvoc​)

其中 MMM 是流式块数，dlm/dfm/dvocd_{\text{lm}} / d_{\text{fm}} / d_{\text{voc}}dlm​/dfm​/dvoc​ 分别是 LLM、流匹配、声码器处理一个块的耗时——首包延迟 ≈ 一个块的"三段处理时间"，块越小延迟越低（但质量略降），这就是"chunk 大小 = 延迟-质量折衷"的定量表达。

3. 流式机制深拆

3.1 Chunk-aware 因果流

CosyVoice 2 支持文本流式输入：文本按小块送进来，LLM 每收到一小块文本就生成一小块语义 token，flow matching 再把每个语义 token 块变成梅尔谱块，声码器随即出声：

两个关键细节：

  • 语义 token 帧率 25 Hz、梅尔谱帧率 50 Hz，flow matching 前会先把 token 上采样 2 倍（带前瞻卷积）对齐帧率；
  • “chunk-aware” 的含义：训练时给流匹配模型喂了多种因果配置（非因果=离线、全因果=最低延迟、chunk 式=折衷），推理时可按延迟需求选——同一个模型既可流式也可非流式，不用训两版。

块大小的权衡：块越小首包越快，但单块上下文少、边界音质略差；块越大反之。这是延迟与质量的连续谱，工程上按场景选。

3.2 文本前端与一个常见误解

纠个错：CosyVoice 2 的论文与开源实现里，没有"用有限状态转换器（FST）纠正 LLM 生成的语义 token"这一机制——早期教程流传过这个说法，属张冠李戴。实际的两个相关机制是：

  1. 文本正则化（TN, Text Normalization）：文本前端把"12345.67 元"转成"一万两千三百四十五点六七元"这类读法、处理多音字与符号。TN 在工业界常用规则系统实现，FST（有限状态转换器）是这类规则系统的经典载体——FST 的作用位置在文本侧，不在 token 侧；
  2. LM 生成语义 token 的稳健性：主要靠大规模训练 + 解码时的温度采样、重复惩罚等常规手段控制，而不是外挂的序列约束器。

6. 工程权衡与失效模式

6.1 权衡

  • 流式因果性：因果（流式）质量略低于非因果（离线看全句），但换来低延迟——实时交互必须因果；
  • 语义 token 粒度：粒度细表达强但序列长、算力高；粒度粗反之。25 Hz 是 CosyVoice 的甜点；
  • 模型大小：0.5B 端侧/云两用；更大模型音质更好但更重。

6.2 失效模式

  1. 音色不像：参考音频太短/太嘈杂。修复：用 5-10 秒干净干声；也可用 add_zero_shot_spk 把参考音频注册成固定音色复用。
  2. 流式首包慢：非流式调用或 chunk 太大。修复：确认 stream=True、文本传入改成生成器（分块送文本）、调小 chunk。
  3. 内容错漏：LM 生成语义 token 出错（漏字、复读）。修复：调低温度、加重复惩罚、检查文本前端（TN）是否正常。
  4. 指令不生效：用了基础版模型（不支持 instruct2）。修复：换 CosyVoice2-Instruct 模型或微调。

7. 延伸思考题（含解析）

Q1：CosyVoice 的 FSQ 语义 token 与 VALL-E 的 EnCodec token 本质区别？
A：EnCodec 是自监督声学重建导向（RVQ 多层、75 Hz），内容+音色混合；FSQ 语义 token 从监督训练的 ASR encoder（SenseVoice-Large 系）提取（单层、25 Hz、codebook 6561），聚焦内容、剥离音色。前者适合声学建模，后者内容更干净、序列更短、更可控。

Q2：为什么 CosyVoice 选"语义 token + flow"两段式？
A：语义 token 干净表达内容，利于对齐与可控；因果 flow matching 生成声学细节，支持流式低延迟且质量稳。两段各司其职，是当前工业主流配方。

Q3：3 秒参考音频怎么让模型记住音色？
A：两条路：① 参考音频的语义 token 作为 speech prompt 拼进序列（in-context）；② 用说话人验证模型（CAM++）提取全局说话人 embedding 注入 flow matching。前者示范内容风格，后者锁定音色。

Q4：CosyVoice 2 首包延迟为什么能压到 ~150 ms？
A：因果 + chunk-aware 的 flow matching：收到第一个语义 token 块就立即解码出声，不等整句。首包延迟 ≈ 第一个块的"LLM + 流匹配 + 声码器"三段处理时间（见 2.3 节延迟公式），块足够小、每段够快，就能压进 150 ms。

Q5：FST 在语音合成链路里的正确位置是哪里？
A：在文本前端，不在语义 token 侧。FST（有限状态转换器）是文本正则化（TN）规则系统的经典实现载体——把数字、符号、单位转成读法。它不参与"纠正 LLM 生成的语义 token"（那是早期教程的讹误）；LM 侧的稳健性靠训练与解码策略（温度、重复惩罚）保障。

1. F5-TTS：极简主义的 Flow Matching 路线

1.1 设计哲学

F5-TTS（Chen et al., SWivid / 上海交通大学等，2024 年 10 月，论文 arXiv:2410.06885，A Fairytaler that Fakes Fluent and Faithful Speech with Flow Matching）追求极简：

  • 不用时长模型（对比 FastSpeech）；
  • 不用音素（对比几乎所有传统系统），直接用字符/文本；
  • 不用 phoneme alignment（对比 FastSpeech 2 的 MFA）。

它怎么做到的？答案是 Flow Matching + 填充对齐——这个思路来自 E2 TTS（MIT, arXiv:2406.18009），F5 的贡献是把 E2 的配方修得又快又好：ConvNeXt 文本编码器、DiT 骨干、Sway Sampling 推理加速。模型规模：Base 版 DiT 约 336M 参数，声码器用 Vocos，训练数据约 10 万小时（Emilia 数据集，中英为主）。

1.2 核心机制：填充（Padding）实现隐式对齐

问题：文本序列短（如 5 个字符），目标语音长（如 200 帧梅尔谱）。两者长度不匹配，怎么对齐？

F5（继承自 E2 TTS）的解法：把文本序列用填充符（filler token，E2 原文用 “mmm”）填到与目标语音等长：

文本 "你好"  →  [你,好,_,_,_,… ]  （填充到 200 帧）\text{文本 "你好"} \;\to\; [\text{你}, \text{好}, \_, \_, \_, \dots] \;\text{（填充到 200 帧）} 文本 "你好"→[你,好,_,_,_,…]（填充到 200 帧）

这个机制在干什么：填充后"文本表示"与"语音表示"等长，可以逐帧拼在一起喂给模型。模型要学的任务变成了"文本引导的语音填充"（text-infilling）：已知 200 帧的文本占位图和（训练时）带噪的语音，还原干净的语音。哪个字符出现在哪些帧、占几帧，全部隐式地由 flow matching 网络自己"悟"出来——不需要显式时长预测器。类比：给模型一张打了码的填字板（文本是格子里的提示词），它自己决定每个提示"横跨几格"。

代价：对齐完全交给模型，数字、专有名词这类"字符↔读音"不规则的内容容易读错（见 4.2 节失效模式）。

1.3 DiT 骨干

F5 用 DiT（Diffusion Transformer） 作为去噪/流匹配骨干——把 diffusion/flow 常用的 U-Net 换成 Transformer。Transformer 的全局注意力利于建模长程依赖（韵律），且方便像 LLM 一样堆规模。

1.4 Sway Sampling 推理加速

推理时沿 ODE 积分需要把 t∈[0,1]t \in [0,1]t∈[0,1] 离散成若干步。F5 用 Sway Sampling——非均匀的步长调度：把更多步数分配给轨迹的早期（ttt 小、还接近噪声的阶段），后期走大步。

为什么早期要多走几步：ODE 早期是"决定整段语音的结构和内容"的阶段（相当于草稿定型），误差会被后面放大；后期只是"润色细节"，粗一点无妨。类比：画画先起稿精修（多步），最后铺背景色可以大笔一挥（少步）。这样用更少步数（如 16–32 步）达到接近均匀采样的质量——纯推理期技巧，不用重训模型。

2. GPT-SoVITS：社区生态的少样本王者

2.1 双模型架构

GPT-SoVITS（作者 RVC-Boss，2024 年 2 月开源，GitHub: RVC-Boss/GPT-SoVITS）是两段式级联：

  • GPT 部分：自回归语言模型，条件是 BERT 文本特征 + 参考音频的 HuBERT 风格语义 token（作为 in-context prompt），逐 token 生成目标语音的语义 token——决定内容与韵律；
  • SoVITS 部分：把语义 token 转成波形，同时以参考音频作为声学 prompt（参考特征注入模型）复刻音色。注意：它的音色注入靠"参考音频特征"而不是一个显式的说话人向量（speaker embedding）——这点与 CosyVoice 2 不同。

版本演进（选型时要知道）：

  • v1/v2：SoVITS 部分基于 VITS 改造（GAN 训练）；v2 增加韩语、粤语支持；
  • v3/v4：SoVITS 声学模型改用 CFM（flow matching） 路线（参数量增至约 407M，声码器换 BigVGAN），零样本相似度显著提升；v4 修复了 v3 的金属音伪影并原生输出 48 kHz。

这个结构与 CosyVoice 的"LLM + flow"同构——都是"语言模型出内容、声学模型出音色"；v3 之后的 GPT-SoVITS 连声学模型路线都收敛到 flow matching 了。

2.2 为什么少样本这么强

GPT-SoVITS 的核心卖点（官方 README 数据）：5 秒音频就能零样本推理，1 分钟音频就能微调出高相似音色。原因：

  1. 参考音频双用：既做语义 prompt（GPT 的 in-context），又做音色参考（SoVITS 的声学 prompt）；
  2. 数据标注工具链完善：WebUI 自带切片、降噪（UVR5）、ASR 转写（中文 Paraformer / 中英日 Faster Whisper）、校对，几分钟音频很快能处理成训练集；
  3. 少样本微调极快：WebUI 里点两下就能分别微调 GPT 与 SoVITS 两个模块，低配 GPU 也能跑。

2.3 社区生态

GPT-SoVITS 的优势不只是技术，更是生态：中文社区活跃、教程多、WebUI 友好、数据工具齐全。对个人开发者做"克隆自己的声音"，它是上手最快的路线。

4. 工程权衡与失效模式

4.1 权衡

  • 极简（F5）vs 组件全（GPT-SoVITS）：极简易理解但对数据质量敏感；组件全鲁棒但链路长；
  • 零样本（5 秒）vs 少样本微调（几分钟）：零样本快但不贴；微调贴但要数据；
  • 流式能力：CosyVoice 强，F5/SoVITS 需额外工程。

4.2 失效模式

  1. F5 数字读错：无音素/文本前端，数字、电话号码易错。修复：预处理文本、加 G2P。
  2. GPT-SoVITS 吞字/重复：GPT 自回归失控。修复：调温度、长度惩罚。
  3. 相似度低：参考音频质量差或太短。修复：干净干声 ≥ 5 秒。
  4. 鲁棒性差：特定文本类型（数字、英文）崩溃。修复：针对性测试集 + 文本归一化。

5. 延伸思考题（含解析）

Q1：F5-TTS 为什么不需要时长模型？
A：它用"文本填充到与语音等长 + flow matching"让模型隐式学习文本在时间轴的分布，对齐由 flow 自动学，不需要显式时长预测器。这是用生成模型的表达力换掉了对齐组件。

Q2：GPT-SoVITS 的 GPT 和 SoVITS 各管什么？
A：GPT（自回归 LM）以 BERT 文本特征 + 参考音频 HuBERT 风格语义 token 为条件，生成目标语音的语义 token，决定内容与韵律；SoVITS 把语义 token 转波形，以参考音频作声学 prompt 复刻音色（v1/v2 基于 VITS，v3/v4 已改用 flow matching 路线）。与 CosyVoice 的"LLM+声学模型"同构。

Q3：为什么 GPT-SoVITS 少样本这么强？
A：参考音频双用（语义 prompt + 音色参考）、数据工具链完善（自动转写/对齐/切片）、少样本微调快。个人开发者 1 分钟音频就能微调出高贴合音色。

Q4：声纹相似度能完全代表"像不像"吗？
A：不能。它只测音色（频谱特征），韵律、说话习惯、情感都影响主观相似度。它是代理指标，需配合主观盲评。
