1. 第一性原理：为什么要"以耳为本"

1.1 根本矛盾

线性频谱（第 2 周的 ∣X[m,k]∣|X[m,k]|∣X[m,k]∣）在频率轴上是均匀的：每 31.25 Hz 一个 bin，从 0 到 8 kHz 一视同仁。但人耳不是线性仪器：

  • 低频区分辨率高：我们能轻松区分 100 Hz 与 200 Hz（差一个八度）；
  • 高频区分辨率低：8000 Hz 与 8100 Hz 听起来几乎一样。

把均匀频谱直接喂给模型，等于强迫模型用 60% 以上的参数去建模人耳不关心的高频细节。解决方案：按人耳感知重新划分频率轴——这就是 Mel 刻度。

1.4 Log-Mel 特征的计算链

这一串变换在干什么：把第 2 周输出的 257 维线性频谱，先"平方"成能量（功率谱），再用 80 顶三角帐篷加权求和（人耳频带池化），最后取对数（模拟响度感知）。三步之后得到的就是 ASR 最常用的 Fbank 特征。

2. MFCC：古典王者与其退位

2.1 MFCC 的完整流程

波形→STFT∣X∣2→Mel 滤波→log⁡→DCT 取前 13 维MFCC\text{波形} \xrightarrow{\text{STFT}} |X|^2 \xrightarrow{\text{Mel 滤波}} \xrightarrow{\log} \xrightarrow{\text{DCT 取前 13 维}} \text{MFCC} 波形STFT​∣X∣2Mel 滤波​log​DCT 取前 13 维​MFCC

DCT（离散余弦变换）在这里的作用：log-mel 相邻维度高度相关（三角滤波器大量重叠），DCT 做去相关 + 信息压缩，前 13 个系数承载绝大部分信息（第 0 维是总能量，1-12 维是谱包络形状）。

2.2 为什么深度学习时代弃用 MFCC

三个理由，按重要性排序：

  1. 信息有损：80 维 → 13 维的压缩是为 GMM-HMM 这种弱模型设计的（参数少、防过拟合）。神经网络容量足够，宁可要全量 80 维信息，自己学压缩。
  2. DCT 假设失效：DCT 去相关假设特征服从某种平滑性；神经网络用卷积/注意力能学到任意非线性组合，预设的正交基反而是束缚。
  3. 梯度不友好：MFCC 链路里的截断（取 13 维）不可微，端到端训练时无法反传——现代模型要么用全量 log-mel，要么把滤波器组做成可学习层。

一句话：MFCC = 为弱模型做的特征压缩；深度学习时代把压缩权交还给模型。Whisper、SenseVoice、Paraformer、CosyVoice 全部使用 log-mel（80 维或 128 维），没有一个用 MFCC。

4. CMVN：信道不变的最后一道工序

4.1 为什么需要

同一句话在不同麦克风/电话信道下，频谱会被整体染色（乘性失真）→ log 域变成加性偏移。CMVN（Cepstral Mean and Variance Normalization，倒谱均值方差归一化）对每个特征维度做标准化——这个公式在干什么：对每一维 iii，减去它整句的平均值 μi\mu_iμi​（消掉信道加的"直流偏移"），再除以标准差 σi\sigma_iσi​（把各维拉到相同幅度尺度），输出变成均值 0、方差 1 的分布。

z^t,i=zt,i−μiσi\hat{z}_{t,i} = \frac{z_{t,i} - \mu_i}{\sigma_i} z^t,i​=σi​zt,i​−μi​​

μi,σi\mu_i, \sigma_iμi​,σi​ 按时间轴统计。这能显著削弱信道差异，是 SenseVoice/Paraformer 前端的标配。

注意：流式推理时不能看到未来帧，要用滑动窗口或全局先验统计量（训练集预计算的 mean/var）——SenseVoice 就内置了全局均值文件。

5. 工程权衡与失效模式

5.1 权衡

  • 维度选择：80 维是 ASR 甜点；128 维用于高采样率（24 kHz+）音频；40 维以下细节损失明显。维度过高只增加算力不增加信息（高频滤波器已高度重叠）。
  • 对数底与缩放：log 与 log10、dB 缩放只差常数倍，但必须与下游模型的训练配置严格一致，否则输入分布错位，性能崩。
  • ϵ\epsilonϵ 选择：太小 → 静音帧数值不稳；太大 → 压缩低能量细节。跟随目标模型的官方配置，别自创。

5.2 失效模式

  1. 特征配置与模型不匹配：用 128 维喂 80 维模型（或反之），shape 报错是好的；更阴险的是维度恰好能过但语义错位（如 512 vs 400 的 n_fft 差异）。定位：打印官方 preprocessor 配置逐项比对。
  2. 忘记取对数或重复取对数：ASR 输出全错但"看起来在跑"。定位：画特征直方图——正常 log-mel 近似正态，原始 mel 严重右偏。
  3. 采样率与特征参数脱钩：把 16 kHz 的参数（n_fft=512）直接用在 48 kHz 音频上，频率轴整体错 3 倍。修复：所有特征函数显式传入 sr 并断言。

6. 延伸思考题（含解析）

Q1：16 kHz、10 秒语音、25 ms 窗、10 ms 移、80 维 Mel——最终特征 shape？
A：(1001,80)(1001, 80)(1001,80)。T=1+160000/160=1001T = 1 + 160000/160 = 1001T=1+160000/160=1001。

Q2：为什么滤波器组的点要在 Mel 轴上等距，而不是 Hz 轴？
A：等距于 Mel 轴 ⇔ 每个滤波器覆盖"相同的主观音高带宽"，与人耳分辨力匹配；若在 Hz 轴等距，高低频滤波器一样宽，就退化成均匀频谱，失去意义。

Q3：若有人坚持用 MFCC 训 Whisper 级模型，你预期会发生什么？
A：WER 显著上升。13 维截断丢失了发音细节（尤其高频辅音信息），且 DCT 基函数不匹配数据分布；历史上端到端模型多次验证过这一点。

Q4：CMVN 在流式场景怎么做？训练与推理不一致会怎样？
A：用滑动窗（如最近 3 秒）或训练集全局统计量。若训练用句级统计、推理用全局统计，归一化分布不一致，WER 会涨几个点——归一化统计量是特征的一部分，必须对齐。

Q5：Whisper 的 mel 是 80 维，但 n_fft=400（频率维 201）。它的滤波器组矩阵形状？
A：(80,201)(80, 201)(80,201)。原理相同，只是频率轴变短。这提醒你：特征维度（80）与 n_fft 无关，只与滤波器数有关。

2. SpecAugment：ASR 训练的标配增广

2.1 动机与原理

SpecAugment（Park et al., 2019）的核心洞察：对特征谱做随机掩码，等价于教模型"在信息残缺时也能识别"——模拟真实世界的遮挡、丢帧、噪声突发。它作用在特征域（不是波形域），实现简单、几乎零成本，却带来显著的 WER 下降。

三个操作：

  1. 时间掩码（Time Masking）：随机选连续 ttt 帧，全部置 0（模拟短暂静音/丢帧）。
  2. 频率掩码（Frequency Masking）：随机选连续 fff 个频带，全部置 0（模拟窄带噪声/信道凹陷）。
  3. 时间扭曲（Time Warping）：沿时间轴做轻微非线性扭曲（实践中常省略，收益边际）。

2.2 实现

关键工程细节：

  • 只在训练时开：推理/验证必须关闭，否则引入随机性破坏可复现性；
  • 上面的默认参数（F=27F=27F=27、T=100T=100T=100、各 2 条掩码）正是原论文在 LibriSpeech 上的 LD（Double）策略；中文/长音频可按比例调整；
  • torchaudio 也内置了 transforms.FrequencyMasking / TimeMasking，参数语义相同，生产中可直接用；
  • 掩码置 0 等价于"把该区域当静音"，与 CMVN 归一化配合时注意：应在归一化之后做掩码（先掩码会把 0 也统计进均值/方差，扭曲归一化参数）。

3. 波形域增广：模拟声学多样性

特征域掩码之外，波形域增广让模型见到更多声学条件。四类最常用：

3.1 加性噪声（SNR 控制）

复用第 4 周的 mix_at_snr()：从噪声库随机抽一条，按随机 SNR（如 5-20 dB）混入。这是鲁棒性增广的主力。

3.2 混响卷积（RIR）

y=s∗hy = s * h y=s∗h

RIR 数据源：OpenAIR、MIT IR Survey，或用 pyroomacoustics 数值模拟任意房间。

3.3 变速与变调

  • 变速（speed perturb）：改变时长但不改音高（如 0.9×/1.1×）——torchaudio 没有开箱即用的 API（旧版的 sox_effects 后端已在 2.9 中移除），常用 sox 命令行或 librosa.effects.time_stretch(y, rate=...)；
  • 变调（pitch shift）：改音高不改时长——模拟不同说话人。

Kaldi 经典配方是 0.9/1.0/1.1 三档变速，等价于数据量 ×3。

3.4 音量扰动

随机乘一个增益（如 ±6 dB），教模型对响度不变。注意别推出削波区。

5. 工程权衡与失效模式

5.1 权衡

  • 增广强度：过强（低 SNR 加噪 + 多重掩码）会让训练分布偏离推理分布，反而伤精度；从无增广基线出发，逐项加增广看验证集变化。
  • 特征提取一致性：训练与推理必须用完全相同的特征配置（同库、同参数），否则分布漂移。AudioPipeline 的价值正在于此——单点定义，处处复用。
  • 波形增广在线还是离线：在线增广每次 epoch 随机不同（多样性好，但慢）；离线预生成（快，但固定）。常用折中：在线波形增广 + 缓存特征。

5.2 失效模式

  1. 特征配置不一致：训练用 compliance.kaldi.fbank、推理用 MelSpectrogram，输入分布错位 → WER 暴涨且难排查。定位：打印两路特征均值/方差对比；修复：统一走 AudioPipeline。
  2. 推理时忘关增广：验证集带随机掩码，指标抖动且偏低。修复：use_specaugment 与训练阶段绑定，推理强制关。
  3. 增广后削波：加噪/混响后幅值超过 ±1。修复：增广后统一峰值归一化。
  4. 重采样遗漏：混合采样率数据集未统一到 16 kHz，帧数公式全错。修复：AudioPipeline 入口强制重采样并断言。

7. 延伸思考题（含解析）

Q1：SpecAugment 为什么作用在特征域而非波形域？两者互补吗？
A：特征域掩码直接模拟"信息缺失"，计算几乎免费且对模型输入空间精准；波形增广（加噪/混响）模拟声学条件多样性。二者作用层面不同、互补，实践中叠加使用。

Q2：为什么喂 ASR 用 compliance.kaldi.fbank 而不用通用 MelSpectrogram？
A：Kaldi fbank 严格复现训练该模型时的特征规范（能量、dither、预加重），保证输入分布一致；通用 Mel 谱细节不同，会引入分布漂移。特征提取必须与模型训练配置逐项对齐。

Q3：AudioPipeline 的帧数断言为什么留 ±2 容差？
A：compliance.kaldi.fbank 默认 snip_edges=True（不中心填充），帧数严格等于 1+(N−400)/1601 + (N-400)/1601+(N−400)/160；但其他实现（如 MelSpectrogram 的 center=True）会中心填充、多出几帧。容差是为了在混用实现时仍能抓住"量级错误"（如采样率错导致帧数差几倍），而不是纠结边界上的一两帧。

Q4：在线增广和离线预生成增广，各自适合什么场景？
A：在线增广多样性好、存储省，适合训练主流程；离线预生成速度快、可复现，适合把昂贵的增广（如混响卷积）固化成数据集。常见组合：昂贵增广离线、轻量增广在线。

Q5：如果把 AudioPipeline 输出直接喂给 Stage 2 的 Whisper，需要注意什么？
A：Whisper 用自己的 80 维、25ms/10ms、n_fft=400 的 log-mel，且内部自动提取——直接喂波形即可，不要喂你预计算的 512-FFT 特征（n_fft 不同）。特征必须与目标模型的官方前处理一致。

1. 第一性原理：滤波 = 对频率的选择性衰减

1.1 根本矛盾

真实录音永远是"目标信号 + 不想要的成分"：语音 + 背景噪声、回声、混响。**滤波（filtering）**的目标是设计一个系统，让想要的频率成分通过、把不想要的压下去。这要求我们能在频域"雕刻"频谱——第 2 周的 STFT 正是工具。

1.2 LTI 系统与卷积

数字滤波器几乎都是线性时不变（LTI）系统：输出是输入与脉冲响应 h[n]h[n]h[n] 的卷积。

这个公式在干什么：h[n]h[n]h[n] 是滤波器的"性格档案"——向它输入一个单点脉冲，看它输出什么尾巴；卷积的意思是"把输入的每个样本都换成一份缩放平移过的尾巴再叠加"。知道 h[n]h[n]h[n]，就能算任意输入的输出。

y[n]=(x∗h)[n]=∑kh[k] x[n−k]y[n] = (x * h)[n] = \sum_{k} h[k]\, x[n-k] y[n]=(x∗h)[n]=k∑​h[k]x[n−k]

逐符号读：x[n−k]x[n-k]x[n−k] 是"现在时刻往前数 kkk 步的历史输入"，h[k]h[k]h[k] 是"这段历史该占多少权重"，求和就是把所有历史加权平均。kkk 范围有限的是 FIR，无限的是 IIR（见 1.3）。

LTI 系统有一个决定性的好性质：卷积在频域变乘法。对频率 fff 的复正弦输入，系统只是乘一个复数 H(f)H(f)H(f)（频率响应）：

Y(f)=H(f)⋅X(f)Y(f) = H(f) \cdot X(f) Y(f)=H(f)⋅X(f)

读法：时域里"逐点加权叠加"的复杂操作，到频域只是每个频率各自乘一个数——∣H(f)∣|H(f)|∣H(f)∣ 决定该频率被放大/衰减多少，∠H(f)\angle H(f)∠H(f) 决定相位偏移。设计滤波器 = 设计你想要的 H(f)H(f)H(f)。低通、高通、带通、带阻，都是对 ∣H(f)∣|H(f)|∣H(f)∣ 的不同形状要求。

1.3 FIR vs IIR

两类实现结构：

FIR（Finite Impulse Response，有限脉冲响应）：

y[n]=∑k=0Mbk x[n−k]y[n] = \sum_{k=0}^{M} b_k\, x[n-k] y[n]=k=0∑M​bk​x[n−k]

读法：输出只由"当前与过去 MMM 个输入"加权而成——只有前馈项，没有输出回路。脉冲响应 h=[b0,…,bM]h = [b_0, \dots, b_M]h=[b0​,…,bM​] 有限长，MMM 项算完就归零。

y[n]=∑k=0Mbk x[n−k]  −  ∑k=1Nak y[n−k]y[n] = \sum_{k=0}^{M} b_k\, x[n-k] \;-\; \sum_{k=1}^{N} a_k\, y[n-k] y[n]=k=0∑M​bk​x[n−k]−k=1∑N​ak​y[n−k]

读法：多出的第二项把"过去的输出"也喂回来了——含反馈项（类似麦克风对着音箱的自激回路），因此脉冲响应理论上无限长；代价是可能不稳定（反馈发散），收益是低阶数就能做出陡峭的频率选择。

线性相位为何重要：语音若不同频率被延迟不同量（非线性相位），波形会"散开"产生相位失真。FIR 对称系数天然线性相位，这是音频偏爱 FIR 的核心原因。

2. 信噪比（SNR）：增强的度量语言

2.1 定义

这个公式在干什么：给"信号比噪声强多少"定一把对数尺子——分子分母都是平均功率（E[s2]\mathbb{E}[s^2]E[s2] 就是把信号平方后求平均），取比值后再套一层 10log⁡1010\log_{10}10log10​ 变成分贝，让"10 倍功率"只记作 +10 dB，方便书写与比较。

SNRdB=10log⁡10PsignalPnoise=10log⁡10E[s2]E[n2]\text{SNR}_{\text{dB}} = 10 \log_{10} \frac{P_{\text{signal}}}{P_{\text{noise}}} = 10 \log_{10} \frac{\mathbb{E}[s^2]}{\mathbb{E}[n^2]} SNRdB​=10log10​Pnoise​Psignal​​=10log10​E[n2]E[s2]​

  • 0 dB：信号与噪声功率相等；
  • 10 dB：信号功率是噪声的 10 倍；
  • 负值：噪声比信号还强（恶劣场景）。

语音增强的一切目标都可以表述为"提升 SNR 的同时保留信号"。注意 SNR 是功率比，所以系数是 10 不是 20。

3. 谱减法：最经典的频域去噪

3.1 思想与推导

假设带噪信号 y=s+ny = s + ny=s+n，且噪声与语音不相关。在某个时频单元上，功率近似可加：

∣Y[m,k]∣2≈∣S[m,k]∣2+∣N[m,k]∣2|Y[m,k]|^2 \approx |S[m,k]|^2 + |N[m,k]|^2 ∣Y[m,k]∣2≈∣S[m,k]∣2+∣N[m,k]∣2

这一步在干什么：把"带噪信号的能量"拆账——总能量 = 语音的账 + 噪声的账。（为什么能近似相加：噪声与语音不相关时，交叉项的长期期望为零；复数谱本身相位对不上，不能直接减——见思考题 Q1。）

若我们能估计噪声功率谱 N^2[k]\hat{N}^2[k]N^2[k]（通常从纯噪声段平均得到），则语音功率谱估计为：

∣S^[m,k]∣2=∣Y[m,k]∣2−N^2[k]|\hat{S}[m,k]|^2 = |Y[m,k]|^2 - \hat{N}^2[k] ∣S^[m,k]∣2=∣Y[m,k]∣2−N^2[k]

读法：每个时频单元上"总能量减去噪声的那份"，剩下的就当作语音。N^2[k]\hat{N}^2[k]N^2[k] 只依赖频率 kkk——假设噪声是平稳的（整段录音里频谱形状不变），这也是谱减法的最大软肋所在。再用原相位重建波形。这就是谱减法（Spectral Subtraction）——1979 年 Boll 提出，是深度降噪的古典原型。

噪声谱怎么来：实际系统用 VAD 检测出"无语音的静音帧"，对这些帧的功率谱取平均，作为 N^2\hat{N}^2N^2。本周实验我们简化：直接给定一段纯噪声。

3.2 过减与谱下限

直接相减有两个问题：

  1. 过减：噪声估计不准时会减过头，把语音也削掉。引入过减因子 α≥1\alpha \ge 1α≥1：减 αN^2\alpha \hat{N}^2αN^2。
  2. 负值：∣Y∣2−N^2<0|Y|^2 - \hat{N}^2 < 0∣Y∣2−N^2<0 时物理无意义。不能置零（会产生下一节的音乐噪声），要设谱下限（spectral floor） β∣Y∣2\beta |Y|^2β∣Y∣2：

∣S^∣2=max⁡(∣Y∣2−αN^2,    β∣Y∣2)|\hat{S}|^2 = \max\big(|Y|^2 - \alpha \hat{N}^2,\;\; \beta |Y|^2\big) ∣S^∣2=max(∣Y∣2−αN^2,β∣Y∣2)

读法：每个时频单元取"减完的结果"与"原能量的 β\betaβ 倍"中较大的那个——α≥1\alpha \ge 1α≥1 是过减因子（宁多减防漏减），β\betaβ 是保底比例，β∈[0.001,0.05]\beta \in [0.001, 0.05]β∈[0.001,0.05]：保底保留一点原始能量，避免彻底挖空。

3.3 音乐噪声：谱减法的致命伤

症状：去噪后的音频里出现随机的、忽隐忽现的"鸟鸣/金属碎片"声。

根因：噪声谱估计在时频面上有随机误差。某些时频单元噪声被高估 → 减成谱下限（接近 0）；相邻单元没被高估 → 保留正常能量。结果是孤立的、随机分布的能量尖峰散布在时频面上，听起来像散落的音符。

定位：画去噪后的语谱图，若背景不干净、有星星点点的亮斑，就是音乐噪声。

缓解：① 谱下限 β\betaβ；② 时频平滑（对增益做邻域平均）；③ 用更准的噪声估计（MMSE、最小值跟踪）。这些正是 Stage 3 深度降噪模型要彻底解决的问题——谱减法是你的对照基线。

4. 客观评价指标：量化"变好了多少"

主观试听不可复现，工程必须用客观指标。三个必须掌握的：

4.1 PESQ（语音质量，有参考）

ITU-T P.862 标准，模拟人耳感知，输出 -0.5 ~ 4.5 分（越高越好）。适合窄带/宽带语音质量评估。局限：对现代深度降噪的改进不够敏感，且需要干净参考。

4.2 STOI（可懂度，有参考）

Short-Time Objective Intelligibility，度量"能不能听清说了什么"，输出 0~1。对语音增强比 PESQ 更贴近"可懂度"目标。

4.3 SI-SNR（尺度不变信噪比）

5. 工程权衡与失效模式

5.1 权衡

  • 过减因子 α\alphaα：大 → 更干净但削语音、音乐噪声更重；小 → 残留噪声多。工程靠网格搜索 + 指标定标。
  • 噪声估计方式：静态（假设噪声平稳）简单但对非平稳噪声失效 → 这是 MCRA、最小值跟踪等自适应估计的动机。
  • 相位处理：谱减法保留带噪相位，重建音质受限；更好的相位估计是另一条研究线。

5.2 失效模式

  1. 噪声非平稳：键盘声、人声背景——静态噪声谱完全失配，去噪几乎无效。定位：画噪声段的功率谱随时间变化；修复：换自适应估计或深度模型。
  2. 削波：混合或去噪后超过 ±1.0。症状：波形顶部削平、引入谐波。修复：归一化或降低增益。
  3. 音乐噪声：见 3.3。这是谱减法的固有缺陷，不是实现 bug——但 β\betaβ 设 0 会极度放大它。

6. 延伸思考题（含解析）

Q1：为什么谱减法要在功率谱域相减，而不是幅度谱或复数谱？
A：噪声与语音不相关时，交叉项期望为零，功率近似可加；复数谱相位无法直接相减（相位不是能量量）；幅度谱不满足可加性。功率域是唯一近似线性可分解的表示。

Q2：mix_at_snr 里为什么缩放的是噪声而不是语音？
A：约定以语音为基准（信号功率固定），调节噪声强度达到目标比值；缩放语音会改变"信号本身"，不符合"加噪"语义。

Q3：音乐噪声为什么听起来是"离散的音乐碎片"而不是连续噪声？
A：减过头的单元被压到谱下限，能量残留随机散布在时频面上；孤立的窄带能量峰在听觉上被解析成一个个短促的音调——即"碎片"。时频平滑能抹平这种孤立性。

Q4：PESQ 和 STOI 哪个更适合评估"电话语音降噪"？
A：两者互补：STOI 更贴近"能否听清"（电话的核心诉求），PESQ 反映整体质量。论文通常同时报告；若只能选一个，语音通信场景优先 STOI。

Q5：真实系统没有"纯噪声段"可估计，怎么办？
A：用 VAD 在线标记静音帧并递推更新噪声谱；或用最小值跟踪（噪声功率谱的滑动最小值近似）；深度方法则直接端到端学习，不需要显式噪声估计——这是 Stage 3 的方向。

1. 第一性原理：增强 = 在时频域估计"干净的增益"

1.1 统一框架

几乎所有单通道语音增强都可归结为：对每个时频单元估计一个增益 G[m,k]G[m,k]G[m,k]，乘到带噪频谱上：

S^[m,k]=G[m,k]⋅Y[m,k]\hat{S}[m,k] = G[m,k] \cdot Y[m,k] S^[m,k]=G[m,k]⋅Y[m,k]

这个公式在干什么：把带噪语音做 STFT（Stage 1 第 2 周的手写 stft()）后，得到一张"时间 × 频率"的二维表格 Y[m,k]Y[m,k]Y[m,k]——mmm 是帧号（时间），kkk 是频率 bin。增强就是给表里每个格子配一个小旋钮 G[m,k]∈[0,1]G[m,k] \in [0,1]G[m,k]∈[0,1]：这个格子听起来像语音（清辅音、元音共振峰）就把旋钮拧到接近 1（全保留），像噪声就拧到接近 0（压掉）。旋完再逆变换回波形。整周要做的事只有一件：怎么决定每个旋钮的位置。

不同方法的区别只在如何估计 GGG。谱减法用功率相减，维纳滤波用最小均方误差——都是对同一个增益的不同估计策略。

1.2 观测模型

y[n]=s[n]+v[n]y[n] = s[n] + v[n] y[n]=s[n]+v[n]

这个公式在干什么：麦克风收到的每一个样本都是"干净语音 + 噪声"的叠加——sss 是干净语音，vvv 是噪声。这个加性假设是整周一切推导的地基（混响导致的卷积噪声不在此列，那是另一个课题）。

在时频域，假设两者不相关，功率可直接相加：

∣Y∣2=∣S∣2+∣V∣2|Y|^2 = |S|^2 + |V|^2 ∣Y∣2=∣S∣2+∣V∣2

这个公式在干什么：为什么"功率"能直接相加？展开 ∣S+V∣2=∣S∣2+∣V∣2+2Re(SV∗)|S+V|^2 = |S|^2 + |V|^2 + 2\text{Re}(SV^*)∣S+V∣2=∣S∣2+∣V∣2+2Re(SV∗)，多出来的交叉项是语音与噪声的乘积——两者不相关时它的时间平均趋于 0，于是剩下一个漂亮的加法式。它告诉你：只要你估得出 ∣V∣2|V|^2∣V∣2（噪声功率谱），就能从 ∣Y∣2|Y|^2∣Y∣2 里"减"出语音功率——这就是第 2.4 节噪声估计如此重要的原因。

由此定义两个信噪比。后验信噪比（posterior SNR，记号 γ\gammaγ）——直接用观测量算：

γ=∣Y[m,k]∣2σ^v2[k]\gamma = \frac{|Y[m,k]|^2}{\hat{\sigma}_v^2[k]} γ=σ^v2​[k]∣Y[m,k]∣2​

先验信噪比（priori SNR，记号 ξ\xiξ，希腊字母 xi）——干净语音与噪声之比，这是我们需要但观测不到的量：

ξ=∣S[m,k]∣2σ^v2[k]\xi = \frac{|S[m,k]|^2}{\hat{\sigma}_v^2[k]} ξ=σ^v2​[k]∣S[m,k]∣2​

这两个符号在干什么：分母都是噪声功率谱估计 σ^v2[k]\hat{\sigma}_v^2[k]σ^v2​[k]（“v 的方差"按频率 bin 给出）。γ\gammaγ 用的是 ∣Y∣2=∣S∣2+∣V∣2|Y|^2 = |S|^2 + |V|^2∣Y∣2=∣S∣2+∣V∣2——所以 γ\gammaγ 在纯噪声段围绕 1 波动（∣S∣2≈0|S|^2\approx 0∣S∣2≈0），有语音时明显大于 1；它可测但被噪声污染。ξ\xiξ 用的是干净的 ∣S∣2|S|^2∣S∣2——它是"真正的信噪比”，是真相但不可测。类比：γ\gammaγ 是"体检时带病测出的指标"，ξ\xiξ 是"健康的真实程度"；增强算法的全部智慧在于从 γ\gammaγ 估计 ξ\xiξ（第 2.3 节的 Decision-Directed 就是干这个的）。

类型 特征 例子 增强难度
平稳 统计特性不随时间变 白噪声、风扇、空调 易（噪声谱固定，好估）
非平稳 统计特性快速变化 键盘、街道、多人背景 难（噪声谱追不上）

噪声谱估计是经典方法的命门：

  • 平稳噪声：从初始静音段平均即可；
  • 非平稳：需自适应跟踪——MCRA（Minima Controlled Recursive Averaging，Cohen 2003）或最小值跟踪（Minimum Statistics，Martin 2001）：前者"只在最小值附近的帧做递归平均"，后者"滑窗取最小值天然落在噪声上"。本教程用最简单的静音段 + VAD 门控递归平均（2.4 节），为的是把精力集中在增益估计上。

2. 维纳滤波：最小均方误差意义下的最优增益

2.1 推导

维纳滤波要找一个增益 GGG，使估计 S^=G⋅Y\hat{S} = G \cdot YS^=G⋅Y 与真实 SSS 的均方误差最小：

2.3 Decision-Directed 方法

一句话直觉：像医生复诊——对当前病情的判断 = 大部分参考"上一次的诊断结果"（α\alphaα），小部分参考"今天的化验单"（1−α1-\alpha1−α）。两路信息按固定比例混合，既稳又不太迟钝。

2.4 噪声功率谱估计

本周用初始静音段平均（简化版），并实现一个基础的递归平均应对缓慢变化：

4. 工程权衡与失效模式

4.1 权衡

  • α\alphaα 平滑：大 → 稳但钝（抹瞬态）；小 → 快但噪。0.95-0.98 是经验区间；
  • 增益下限 gain_floor：太低 → 音乐噪声；太高 → 残留噪声。0.01-0.1；
  • 噪声估计：初始段平均简单但对非平稳失效——这是下周深度方法要解决的。

4.2 失效模式

  1. 非平稳噪声失效：键盘声、背景人声——静态噪声谱严重失配。定位：看增强后噪声是否"跟着变"；修复：自适应估计或深度模型。
  2. 音乐噪声：α\alphaα 太小或 gain_floor 太低。试听有"鸟鸣"；修复：加大 α\alphaα、提下限。
  3. 辅音被抹：平滑过强把 /s/ /t/ 的瞬态压掉，可懂度降。修复：降 α\alphaα、缩短平滑窗。
  4. 音乐噪声与失真的混淆：PESQ 升但听感"发闷"——这是过度平滑。PESQ 对平滑不敏感，需配合试听与 STOI。

1. 第一性原理：从"估增益"到"学滤波"

1.1 掩码估计路线的局限

第 1 周的维纳滤波本质是逐时频单元独立估增益 G[m,k]G[m,k]G[m,k]。深度学习最初也走这条路：网络预测一个理想比值掩码（IRM）或复数掩码，乘到带噪谱上：

S^[m,k]=M[m,k]⋅Y[m,k]\hat{S}[m,k] = M[m,k] \cdot Y[m,k] S^[m,k]=M[m,k]⋅Y[m,k]

这个公式在干什么：与第 1 周的 S^=G⋅Y\hat{S} = G \cdot YS^=G⋅Y 同构，只是 GGG 从手工公式（维纳）换成了神经网络输出的 MMM——可以是实数比值掩码（IRM），也可以是复数掩码（CRM，同时给幅度和相位一个缩放系数）。网络学的还是"每个时频格子该乘多少"。

这条路的天花板在于：掩码是对每个时频点独立的标量缩放。它无法表达"用相邻多个时频点的信息加权合成当前点"——而这恰恰是处理混响尾、宽带噪声所需要的。

1.2 Deep Filtering：把"增益"升级为"跨帧复数滤波器"

DeepFilterNet 的核心创新：不再预测单个增益，而是为每个频点预测一个跨多帧的复数滤波器，用这个滤波器对带噪谱做时间方向的加权合成（DeepFilterNet 论文中滤波阶数 N=5N=5N=5）：

S^[m,k]=∑n=0N−1hm,k[n]⋅Y[m+Δk−n,  k]\hat{S}[m,k] = \sum_{n=0}^{N-1} h_{m,k}[n] \cdot Y[m+\Delta_k - n,\; k] S^[m,k]=n=0∑N−1​hm,k​[n]⋅Y[m+Δk​−n,k]

这个公式在干什么：第 1 周的增益是 G[m,k]⋅Y[m,k]G[m,k]\cdot Y[m,k]G[m,k]⋅Y[m,k]——只用当前这一帧的数据；Deep Filtering 把"素材池"扩大到相邻 NNN 帧的同一频点（Δk\Delta_kΔk​ 是滤波器前瞻，DFN3 取 2 帧），每帧配一个复数权重 hm,k[n]h_{m,k}[n]hm,k​[n] 加权求和。复数权重同时改幅度和相位——相当于在频域给每个频点配了一个 5 阶小 FIR 滤波器。注意该滤波只作用于低频段（DFN3 中为最低 96 个 bin，约 4.8 kHz）——因为语音的周期性谐波成分集中在这里，高频段用第 1.3 节的 ERB 增益处理即可。

为什么这更强：

  1. 跨帧利用信息：谐波（基音及其倍频）在相邻帧间高度相关，用多帧合成能"借"邻近帧的能量去噪，也能平滑跟踪噪声的帧间抖动；
  2. 复数滤波：同时处理幅度与相位，相位估计不再靠"保留带噪相位"这种妥协；
  3. 仍是线性滤波：输出是输入的线性组合，保真度高、不易引入非线性伪影（对比纯生成式方法）。

直观对比：掩码估计 = 每个像素单独调亮度；Deep Filtering = 给每个频点学一个跨帧的小卷积核。后者的表达能力是前者的严格超集（掩码 = N=1N=1N=1 且只看当前帧的特例——论文中对应 CRM 复数比值掩码）。论文用实验证明了这一点：在 5–30 ms 的多种 FFT 帧长下，Deep Filtering 的 SI-SDR 全面优于 CRM，且帧长越短优势越大。

1.2.1 深入拆解：为什么"复数 + 多帧"是关键

维纳滤波（第 1 周）也满足 GGG 是实数、单帧——它的两个限制恰好被 Deep Filtering 逐一解开。

（一）实数增益动不了相位。 噪声和语音混在一起时，带噪相位 ≠ 干净相位。实数 GGG 只能缩放幅度，相位只能"继承带噪相位"。多数场景下带噪相位尚可接受，但在低 SNR 和谐波密集处，相位误差直接损伤波形结构。复数滤波器 h∈CNh\in\mathbb{C}^Nh∈CN 把相位也纳入可学习范围。

（二）单帧信息太少。 一个时频格里的观测是"语音+噪声"的混合，仅凭本帧无法分辨"这是语音的谐波还是恰好同频的噪声"。但谐波是准周期的：上一帧、上上帧同一频点的值提供了强先验。多帧线性组合 = 对"这个频点在时间上如何演化"建模——这正是卷积的语义。

（三）代价可控。 每个频点只有 N=5N=5N=5 个复系数，且只作用在 96 个低频 bin 上——相比"预测全部 481 个频点的复数掩码"（960 点 FFT），系数数量少一个数量级。这是"表达力↑、计算量↓"同时成立的关键。

1.3 双分支特征：ERB 包络 + 帧级细节

DeepFilterNet 的 Encoder 走两条路（以默认的 DeepFilterNet3 配置为例，48 kHz、FFT 960 点、帧移 480 点）：

  • ERB 分支：把 481 个频率 bin 按人耳听觉刻度 ERB（Equivalent Rectangular Bandwidth，等效矩形带宽） 合并成 32 个频带，对每个频带预测一个实数增益——负责重建语音的"频谱包络"（低频一声道密、高频一频带很宽）。对数压缩的 ERB 特征同时利用了"响度感知是对数的、频率感知也是对数的"两条心理声学规律；
  • 帧级（fullband）分支：每帧只取少量标量统计特征（归一化系数、局部 SNR 等），走轻量通路捕捉帧间动态。

两路特征各自经过带分组（grouping）的卷积和 GRU 后，ERB 增益先乘上带噪谱，再由 1.2 节的 Deep Filtering 精修低频段（96 个 bin，约 4.8 kHz），高低两段拼出最终增强谱。双分支的意义：人耳对包络远比对相位/精细结构敏感（论文正是以"感知动机"命名），粗粒度的 ERB 增益用极小的计算量就决定了听感主体，细粒度的 Deep Filtering 只需花在刀刃（低频谐波）上——这是"小模型、低延迟、好音质"三角的架构解。

2. 实时性：工程约束如何塑造架构

2.1 延迟预算

DeepFilterNet3 论文给出的设计参数（48 kHz 采样率）：

  • 帧长 20 ms（960 点）、帧移 10 ms（480 点）；
  • 前瞻（lookahead）2 帧 = 20 ms——模型会"偷看"未来 2 帧再决定当前帧的输出；
  • 总算法延迟 = 帧长 + 前瞻 = 40 ms（帧缓冲 20 ms + 前瞻 20 ms）；
  • 计算量：DeepFilterNet（第 1 代）约 1.8M 参数 / 0.35 GMACs；本教程实测 DeepFilterNet3（约 2.14M 参数）在普通笔记本 CPU 单线程处理 2 s 音频仅需 ~0.13 s，RTF ≈ 0.07（论文报告单线程 RTF 0.19）。

2.2 做到实时的三个手段

  1. 短前瞻的准因果设计：GRU 递归严格因果，卷积只允许 2 帧 lookahead → 延迟可控且有限（不是非因果的"看完整句"）。注意它并非纯因果：用 20 ms 前瞻换取质量，这是延迟-质量的显式折中；
  2. Deep Filtering 核很小：每个频点只有 5 个复系数，且只作用于 96 个低频 bin，计算量远小于全时频注意力；
  3. ERB 压缩 + 分组（grouping）：长时建模与卷积都在 ERB 粗粒度和分组稀疏化后进行，避免在 481 个 bin 的全分辨率上做大感受野。

这给端侧部署的启示：实时降噪不靠堆大模型，靠"短前瞻 + 小核 + 多分辨率"的架构纪律。你的结课助手前端（Stage 7）就用这类模型。

4. 工程权衡与失效模式

4.1 权衡

  • 频带宽度：48 kHz 全频带音质好但算力高；16 kHz 省算力但高频缺失。端侧按需裁剪；
  • 前瞻（lookahead）：前瞻越多质量越好、延迟越大。DeepFilterNet3 用 20 ms 前瞻；零前瞻方案质量略降但延迟减半。按场景折中；
  • 模型大小：DeepFilterNet3 约 2.1M 参数，极小——这是它端侧可行的根本。不要为了精度换大模型而牺牲实时性。

4.2 失效模式

  1. 采样率不匹配：16 kHz 输入直接喂 48 kHz 模型 → 输出错误。修复：统一升/降采样。
  2. 过度抑制：把轻声语音当噪声压掉。症状：弱语音段发虚；修复：调低降噪强度参数。
  3. 音乐噪声残留：极低 SNR 下仍有伪影。深度方法比谱减法好很多，但极端场景仍存在。
  4. 音乐/歌唱失真：降噪模型对"非语音"信号（音乐、歌声）处理差，可能当噪声压。场景不适配时慎用。

5. 延伸思考题（含解析）

Q1：Deep Filtering 相比纯掩码估计的本质提升是什么？
A：掩码是对每个时频点的独立标量缩放（且 DFN 的 ERB 增益更是每个频带一个实数）；Deep Filtering 为每个低频频点学一个跨 5 帧的复数滤波器，能利用帧间相关性加权合成、并同时修正相位，表达力是掩码的严格超集（掩码 = 单帧特例），对谐波增强与噪声抖动抑制尤其有效。

Q2：ERB 分支为什么能兼顾"大感受野"与"低计算量"？
A：481 个频率 bin 先按听觉刻度压缩成 32 个 ERB 频带，卷积与 GRU 都在 32 维的粗粒度上运行，运算量下降一个数量级；而频谱包络——决定听感主体的部分——恰好不需要更细的分辨率。再与帧级分支融合，"金字塔"式的多分辨率换来了效率。

Q3：为什么端侧实时降噪强调"短前瞻 + 小核"而不是堆大模型？
A：实时通信能接受的算法延迟有限（DeepFilterNet3 为 40 ms：20 ms 帧 + 20 ms 前瞻），看完整句的非因果模型不可用；端侧算力有限，大核/大模型算不动。短前瞻、小滤波核、多分辨率是延迟-精度-算力的工程最优解。

Q4：DNSMOS 的"无参考"特性为什么重要？它和 PESQ 的区别？
A：真实场景没有干净参考，PESQ 需要参考故只能用合成数据评测；DNSMOS 直接给真实录音打分，适合线上质量监控与打榜。代价是它是学习出来的代理指标，需与主观听感校准。

Q5：DeepFilterNet 是 48 kHz 全频带，你的端侧助手是 16 kHz，怎么取舍？
A：若端侧只要语音可懂度，可裁剪/换 16 kHz 轻量模型（如 DTLN）省算力；若要全频音质，升采样到 48 kHz 处理再降回，但算力开销大。按助手音质需求与算力预算决策。

1. 第一性原理：回声是"扬声器声音被麦克风重新采集"

1.1 物理成因

免提/会议场景中，远端语音 x[n]x[n]x[n]（far-end，对方说话）从扬声器播出，经房间传播后被麦克风重新采集，与本地说话人语音 s[n]s[n]s[n] 一起传回给远端——对方就听到了自己声音的延迟版本，即回声。

1.2 数学模型

麦克风采集信号：

d[n]=s[n]+∑k=0L−1h[k] x[n−k]⏟回声+v[n]d[n] = s[n] + \underbrace{\sum_{k=0}^{L-1} h[k]\, x[n-k]}_{\text{回声}} + v[n] d[n]=s[n]+回声k=0∑L−1​h[k]x[n−k]​​+v[n]

这个公式在干什么：麦克风在时刻 nnn 收到的声音是三股来源的叠加。逐符号拆开：

  • d[n]d[n]d[n]：麦克风信号（desired，含回声）——自适应滤波器要"修正"的对象；
  • x[n]x[n]x[n]：远端参考信号（扬声器播的，我们已知——这是 AEC 能成立的关键）；
  • h[k]h[k]h[k]：回声路径（房间 + 扬声器 + 麦克风的脉冲响应），长度 LLL 可达数百毫秒；
  • s[n]s[n]s[n]：近端语音（本地说话人）；v[n]v[n]v[n]：噪声。

那个求和式 ∑kh[k]x[n−k]\sum_k h[k]x[n-k]∑k​h[k]x[n−k] 就是卷积：当前麦克风里的回声，不只是"此刻播的声音"，而是过去 LLL 个时刻播出的声音各自经房间反射、按不同强度（h[k]h[k]h[k]）衰减后的总和。类比合唱团：你（麦克风）听到的是对方（扬声器）过去 300 ms 内唱出的每一句、各自拖着不同混响尾巴的叠影。AEC 的任务：已知歌词 xxx，反推出"混响规律" hhh，再合成出回声减掉。

目标：用已知的 x[n]x[n]x[n] 估计回声 h^∗x\hat{h} * xh^∗x，从 d[n]d[n]d[n] 里减掉，留下 s[n]s[n]s[n]。

1.3 核心难点：双讲

当本地说话人同时说话（s[n]≠0s[n] \neq 0s[n]=0），麦克风信号里既有回声又有近端语音。此时若继续用 d[n]d[n]d[n] 去更新滤波器 h^\hat{h}h^，近端语音 s[n]s[n]s[n] 会被当成回声路径的一部分"学进去"，污染 h^\hat{h}h^，导致回声消不干净甚至发散。这就是双讲（double-talk）问题——AEC 的灵魂难题。

类比：自适应滤波器像一个学做菜的学生，唯一的反馈是"成品好不好吃"（误差 eee）。只要厨房里只有一种食材（回声），差评就能准确指导改进；可一旦有人往锅里乱加调料（近端语音），学生把差错全归咎于自己的手法，把好好的手艺改坏——这就是污染。所以"有人加调料时（双讲）必须停止学习"。

2. 自适应滤波：估计回声路径

2.1 LMS / NLMS

用滤波器 h^[k]\hat{h}[k]h^[k] 卷积参考信号 xxx 得到回声估计 y^[n]=∑kh^[k]x[n−k]\hat{y}[n] = \sum_k \hat{h}[k] x[n-k]y^​[n]=∑k​h^[k]x[n−k]，误差信号：

e[n]=d[n]−y^[n]e[n] = d[n] - \hat{y}[n] e[n]=d[n]−y^​[n]

这个公式在干什么：e[n]e[n]e[n] 是"麦克风实际听到的"减去"按当前估计应该出现的回声"。理想情况下它只剩近端语音 + 噪声；估计不准时它还混着残余回声。e[n]e[n]e[n] 是唯一可用的反馈信号——一切自适应都围绕"让残余回声从 eee 里消失"。

LMS（Least Mean Squares，最小均方）按梯度下降更新滤波器：

h^[k]←h^[k]+μ e[n] x[n−k]\hat{h}[k] \leftarrow \hat{h}[k] + \mu\, e[n]\, x[n-k] h^[k]←h^[k]+μe[n]x[n−k]

这个公式在干什么：误差 e[n]e[n]e[n] 大，说明当前路径估得不准；往哪个方向修？梯度告诉我们：哪个抽头 kkk 此刻的输入 x[n−k]x[n-k]x[n−k] 越大，它对误差的"贡献嫌疑"就越大，就越该被 e[n]e[n]e[n] 推动修正。μ\muμ 是学习率。类比蒙眼调音台：误差是"观众的嘘声"，x[n−k]x[n-k]x[n−k] 是"这路推子刚刚推了多少"，嘘声越大、刚才推得越猛的那一路，越要往回拉。

NLMS（Normalized LMS，归一化 LMS）——用参考信号能量归一化步长，消除输入幅度影响：

h^←h^+μ∥x∥2+δ e[n] x\hat{\mathbf{h}} \leftarrow \hat{\mathbf{h}} + \frac{\mu}{\|\mathbf{x}\|^2 + \delta}\, e[n]\, \mathbf{x} h^←h^+∥x∥2+δμ​e[n]x

为什么分母必须是 ∥x∥2\|\mathbf{x}\|^2∥x∥2（本周自测题）：LMS 的实际步幅 = μ⋅e⋅x\mu \cdot e \cdot xμ⋅e⋅x——输入越大步子越大。大音量时一步迈过头来回震荡（发散），小音量时又挪得极慢（学不会）。除以当前参考向量能量 ∥x∥2\|\mathbf{x}\|^2∥x∥2，等于"按音量归一化的步幅"：无论对方说多大声，每次修正都是"相对音量的一小步"。小例子：μ=0.5\mu=0.5μ=0.5、∥x∥2=100\|\mathbf{x}\|^2=100∥x∥2=100（大声）时实际步幅系数 0.005；∥x∥2=1\|\mathbf{x}\|^2=1∥x∥2=1（耳语）时系数 0.5——自动缩放。δ\deltaδ 是防除零的小常数。μ∈(0,2)\mu \in (0,2)μ∈(0,2) 保证收敛（理论稳定界），实际取 0.5-1：μ\muμ 越接近 2 收敛越快但残留的"梯度噪声"越大。

为什么频域做（FDAF，Frequency-Domain Adaptive Filter）：回声路径 LLL 很长（几百毫秒 = 数千抽头），时域 NLMS 每个样本要 O(L)O(L)O(L) 次乘加，CPU 吃不消。频域用 FFT 把循环卷积变成逐 bin 相乘，每个块（如 LLL 样本）只需 O(Llog⁡L)O(L\log L)O(LlogL)，摊到每样本约 O(log⁡L)O(\log L)O(logL)。工程上常用分块版本 PBFDAF（Partitioned-Block Frequency-Domain Adaptive Filtering）：把长路径切成若干子块分别频域更新，兼顾延迟与效率。

2.2 ERLE：回声抑制效果指标

ERLEdB=10log⁡10E[d2]E[e2]\text{ERLE}_{\text{dB}} = 10\log_{10} \frac{\mathbb{E}[d^2]}{\mathbb{E}[e^2]} ERLEdB​=10log10​E[e2]E[d2]​

这个公式在干什么：ERLE（Echo Return Loss Enhancement，回声抑制增益）= “滤波前回声能量 / 滤波后残余能量”——被消掉的回声有多少 dB。注意它只在纯回声段（近端闭嘴）测量才有意义：此时 ddd 就是回声本身，eee 是残余；若在双讲段测，eee 里近端语音占主导，ERLE 自然低，不代表 AEC 变差了。ERLE 越大回声消得越干净。收敛曲线 = ERLE 随时间上升，是本周交付的核心图。

  • 能量检测：滤波器已收敛后，误差能量突然远超"回声估计的能量"——多出来的能量只能来自新声源（近端）。实现简单，是本节代码采用的方案（需配收敛门控：滤波器还没收敛时误差本来就大，不能误判为双讲——否则永远不收敛）；
  • Geigel 检测器：经典判据 ∣d[n]∣>τ⋅max⁡(∣x[n]∣,…,∣x[n−L+1]∣)|d[n]| > \tau \cdot \max(|x[n]|,\dots,|x[n-L+1]|)∣d[n]∣>τ⋅max(∣x[n]∣,…,∣x[n−L+1]∣)（τ\tauτ 常取 0.5，假设回声路径损耗至少 6 dB）；
  • 更先进：相干性检测、卡尔曼滤波（把"路径是否突变"建成状态估计，无需硬冻结，WebRTC AEC3 一脉即此思想）。

为什么要把路径能量归一化：扬声器到麦克风有声学损耗，回声能量必然低于远端信号（典型 -6 ~ -15 dB）。如果不做归一化，随机生成的 hhh 可能让"回声比远端还响 18 dB"——物理上荒谬，而且会让后面按远端能量校准的双讲检测全部失灵。

4. 工程权衡与失效模式

4.1 权衡

  • 滤波器长度：长 → 能建模长回声路径，但计算与收敛慢；短 → 反之。需覆盖房间实际混响时长；
  • 步长 μ\muμ：大 → 收敛快但不稳；小 → 稳但慢。0.5-1 常用；
  • 双讲检测灵敏度：太灵敏 → 频繁冻结、收敛慢；太迟钝 → 污染滤波器。

4.2 失效模式

  1. 双讲污染：冻结失效，近端语音被学进 h^\hat{h}h^，回声残留甚至放大。定位：看双讲段 ERLE 是否骤降；修复：加强双讲检测、用卡尔曼。
  2. 延迟失配：扬声器到麦克风的延迟与参考信号 xxx 对不齐，滤波器永远学不到。定位：互相关找延迟；修复：延迟估计与对齐（WebRTC 的 delay estimator）。
  3. 非线性回声：扬声器过载产生谐波失真，线性滤波器建模不了。修复：NLP/RES 非线性后处理。
  4. 收敛慢：长路径 + 小步长导致开头几秒回声明显。修复：频域加速、合理步长。

5. 延伸思考题（含解析）

Q1：为什么 AEC 必须依赖"远端参考信号"？没有它行吗？
A：回声 = 参考信号经未知路径的卷积。已知参考 xxx，才能用自适应滤波反解路径 hhh。没有参考，退化为盲源分离/纯降噪，难度陡增且无法精准消回声。这是 AEC 与降噪的本质区别。

Q2：双讲时为什么要冻结滤波器更新？不冻结会怎样？
A：双讲时误差 eee 里含近端语音 sss，若继续更新，sss 会被当成回声路径的一部分学进 h^\hat{h}h^，污染估计，导致回声消不净甚至发散。冻结即"近端说话时不学习"，保护 h^\hat{h}h^。

Q3：NLMS 分母为什么要除以 ∥x∥2\|x\|^2∥x∥2？
A：归一化步长，消除参考信号幅度影响：参考能量大时自动减小步长防止震荡，能量小时放大步长加快收敛。使算法对输入音量鲁棒，收敛行为一致。

Q4：线性滤波后为什么还要 NLP/RES？
A：线性滤波消不掉的残余回声来自：非线性路径（扬声器失真）、路径估计误差、双讲期间的残留。NLP（非线性处理）/RES（残余回声抑制）用频谱抑制把残余压下去，是最后的收尾。

Q5：AEC 为什么要在 NS（降噪）之前？顺序颠倒会怎样？
A：AEC 假设回声是参考信号的线性卷积；若先降噪，降噪的非线性谱改动会破坏回声与参考的线性关系，AEC 无法对齐消除。所以流水线必须 AEC → NS → AGC。这是本阶段主线的硬约束。

1. AGC：自动增益控制

1.1 根本矛盾

说话人远近、音量起伏，导致信号幅度剧烈波动。太大会削波失真，太小会淹没在噪声里。AGC 的目标：把信号响度稳定追踪到一个目标值，且过渡平滑无抽吸感。

1.2 两级结构

  • 数字增益：在数字域乘一个时变增益 g[n]g[n]g[n]；
  • 模拟增益：调整麦克风/放大器增益（硬件级，范围更大）。

数字域我们聚焦 g[n]g[n]g[n] 的计算。

1.3 核心：包络检测 + 平滑增益

这个流程在干什么：期望增益 gdesired=Rtarget/envg_{\text{desired}} = R_{\text{target}}/\text{env}gdesired​=Rtarget​/env 是"响度差的倒数"——当前比目标低多少 dB，就该放大多少。但绝不能直接用：语音的瞬时包络起伏剧烈（浊音强、清音弱），若每个样本都贴着期望增益走，增益会跟着波形抖动，把底噪也按增益调制放大，听感是"喘息/抽吸"（pumping/breathing）。所以要过一道不对称平滑。

攻击/释放不对称（本周自测题）：

  • 攻击（Attack）快：音量突然变大，要快速压低防削波 → 短时间常数（~5 ms）；
  • 释放（Release）慢：音量变小后，缓慢回升避免"抽吸"（pumping）感 → 长时间常数（~50-100 ms）。

类比：好的音响师跟推子——台上突然爆发时手要快（压下去，防啸叫防爆音）；台上安静下来时手要慢（慢慢抬，否则把座椅挪动的沙沙声也抬起来了）。不对称是同一双手的两个速度。

工程细节（本节实现里最关键的一处）：包络要按 10 ms 帧的 RMS 计算，而不能逐样本用 ∣x[n]∣|x[n]|∣x[n]∣。逐样本包络在信号过零处趋近 0，期望增益飙到上限；再叠加"攻击快、释放慢"的不对称，增益会被波形纹波一路"棘轮式"往下压（每次纹波都触发快速攻击、恢复却很慢），输出会越压越轻。帧级 RMS 天然滤掉了这个纹波。

1.4 LUFS 响度标准

LUFS（Loudness Units Full Scale）是广播响度标准：ITU-R BS.1770 定义了 K 加权（模拟人耳频响）+ 门限门控的响度测量，EBU R128 规定广播目标为 -23 LUFS；流媒体平台常用 -14 ~ -19 LUFS。它比峰值更接近人耳感知。本周教学实现用 RMS（dBFS）近似响度（够用且无需 K 加权滤波器），生产实现请用真实 LUFS 表。

3. 主动降噪（ANC）

3.1 物理原理

ANC 不靠算法"滤"噪声，而是产生一个反相声波物理抵消噪声：

原始噪声 d[n]  +  反相声波 −d[n]  =  0\text{原始噪声 } d[n] \;+\; \text{反相声波 } -d[n] \;=\; 0 原始噪声 d[n]+反相声波 −d[n]=0

这个式子在干什么：声波是气压波动，两个等幅、反相（相位差 180°）的波叠加，气压起伏互相抵消，耳朵听到的就是"安静"。类比：往水里同时扔两个石子，波峰遇上波谷，水面恢复平静。

耳机里的麦克风采集外部噪声，处理器生成反相信号从扬声器（耳机喇叭）播出，两者叠加抵消。这是物理层的消噪，与 AI 降噪（信号处理层）互补。

3.2 FXLMS：为什么需要次级路径估计

难点：反相信号从"误差麦克风"听回来时，经过了次级路径 S(z)S(z)S(z)（扬声器 + 耳道传播）——它既有增益也有延迟和相位旋转。若控制器不知道这个路径，就无法正确生成反相波。

类比：你朝峡谷对岸喊"喂——“想让回声正好抵消原声。如果你在听到自己的声音"该到"的瞬间就喊，声音还在路上，到达时完全错过了抵消时机——相位错了。你必须预判"声音穿过峡谷要多久、被削弱多少”，提前、按正确音量喊。次级路径估计 S^(z)\hat{S}(z)S^(z) 就是这张"预判表"。

FXLMS（Filtered-x LMS） 的"Filtered-x"正是指：参考信号要先通过次级路径估计 S^(z)\hat{S}(z)S^(z) 滤波，才能正确更新：

w←w+μ e[n] (S^(z)∗x)[n]⏟filtered-x\mathbf{w} \leftarrow \mathbf{w} + \mu\, e[n]\, \underbrace{(\hat{S}(z) * x)[n]}_{\text{filtered-x}} w←w+μe[n]filtered-x(S^(z)∗x)[n]​​

这个公式在干什么：对比第 3 周 NLMS 的更新式 h^+=μex\hat{h} += \mu e xh^+=μex——形式几乎一样，唯一的区别是 xxx 先过了 S^(z)\hat{S}(z)S^(z)。为什么必须这样？因为控制器权重 www 影响误差的"通路"是：w→w \tow→ 扬声器 →\to→ 次级路径 S(z)S(z)S(z) →\to→ 误差麦克风。梯度下降要求更新方向与"误差对 www 的真实敏感度"一致，而这个敏感度恰好是 S(z)∗xS(z)*xS(z)∗x。我们手里只有估计值 S^(z)\hat{S}(z)S^(z)，就用它代替。S^(z)\hat{S}(z)S^(z) 的相位准确性直接决定系统稳定——详见 3.3 节仿真：相位误差超过 90° 时梯度方向掉头，系统发散；误差在 90° 以内时只是收敛变慢，仍收敛到同一个最优解（增益误差则几乎无害，只影响等效步长）。

4. 工程权衡与失效模式

4.1 权衡

  • AGC 攻击/释放：攻击太快会压掉瞬态（辅音）；释放太慢有抽吸感。5/50 ms 是起点；
  • ANC 次级路径精度：估得越准越稳，但在线辨识增加复杂度；
  • VAD 灵敏度：太灵敏漏掉轻声语音；太迟钝把噪声当语音。

4.2 失效模式

  1. AGC 抽吸感：释放太快，音量起伏被放大成"呼吸声"。修复：加长释放时间常数。
  2. AGC 削波：增益过大顶到 ±1。修复：限幅 + 控制 max_gain。
  3. ANC 失稳：次级路径失配或步长过大，系统自激振荡（尖锐啸叫）。修复：精确辨识 S^\hat{S}S^、降 μ\muμ。
  4. VAD 漏检轻声：低音量语音被判为静音被切掉。修复：调低阈值、用 Silero 这类鲁棒模型。

5. 延伸思考题（含解析）

Q1：AGC 的攻击与释放时间为什么必须不对称？
A：音量突增要快速压低防削波（攻击快）；音量减小后要缓慢回升，否则增益快速拉高会把背景噪声也放大，产生"抽吸/呼吸"伪影（释放慢）。不对称是防削波与防抽吸的折中。

Q2：LUFS 相比峰值更能代表响度，为什么？
A：峰值只反映瞬时最大幅度，而响度是人耳对能量的时间加权感知。LUFS 按 ITU-R BS.1770 做 K 加权 + 时间积分，更贴近主观响度，故广播用 -23 LUFS 而非峰值标准化。

Q3：FXLMS 为什么叫 “Filtered-x”？参考信号为什么要先过 S^(z)\hat{S}(z)S^(z)？
A：控制输出经真实次级路径 S(z)S(z)S(z) 才到达误差麦克风，所以"误差对控制器权重的敏感度"就是 S(z)∗xS(z)*xS(z)∗x；为正确计算梯度，参考信号必须用估计 S^(z)\hat{S}(z)S^(z) 先滤波（即"filtered x"）。S^\hat{S}S^ 的相位误差在 90° 以内只影响收敛速度（仍收敛到同一最优解），超过 90° 梯度方向翻转，系统发散——因此 S^(z)\hat{S}(z)S^(z) 是稳定命门，需在线/定期重新辨识。

Q4：ANC 消低频、AI 降噪消中高频，为什么这样分工？
A：ANC 靠物理反相抵消，低频波长长、相位易控，适合稳态低频；高频波长短、相位难控且指向性强，物理抵消难，交给信号处理的 AI 降噪更合适。

Q5：你的结课助手里，ANC 和 AI 降噪分别部署在哪？
A：ANC 在耳机/麦克风硬件层（若有）；AI 降噪（如 DeepFilterNet/DTLN）在音频前端软件层，与 AEC/AGC/VAD 一起。两者串联，ANC 先消低频稳态，AI 再清其余。

1. 第一性原理：流水线顺序是因果约束的体现

1.1 为什么 AEC 必须在 NS 前

AEC 假设"麦克风信号里的回声 = 参考信号经线性路径卷积"。降噪（NS）对频谱做非线性修改，会破坏回声与参考之间的线性对应——AEC 找不到回声、消不掉。因此：

AEC（线性对齐消回声）  →  NS（非线性去噪）  →  AGC  →  VAD\text{AEC（线性对齐消回声）} \;\to\; \text{NS（非线性去噪）} \;\to\; \text{AGC} \;\to\; \text{VAD} AEC（线性对齐消回声）→NS（非线性去噪）→AGC→VAD

这条链在干什么：把四个模块按"破坏性"排序——越靠前的模块对信号的改动越"温柔、可逆、线性"，越靠后越"自由、非线性"。AEC 做的是减法（减去与参考线性相关的回声），必须最先；NS 做谱整形（乘时变增益）；AGC 乘整体增益（最温和，但会改变后续模块看到的电平）；VAD 只做判决不改信号，放最后还能享受前面所有处理的红利。任何一个对信号做了非线性改动的模块，都会让排在它后面的"依赖线性结构"的模块失效——这就是顺序的因果逻辑。

1.2 为什么 AGC 在 NS 后

降噪需要稳定的信噪比估计；若先 AGC 放大弱信号，噪声也被放大，干扰降噪的噪声谱估计。先降噪稳住信号，再 AGC 调响度。

1.3 为什么 VAD 在最后

VAD 需要尽可能干净的信号来判断"是否有语音"；放在链尾受益于前面所有处理。同时 VAD 的输出（语音段）供 ASR 只处理有效区间。

这条顺序就是本周交付流水线的骨架——也是自测题"前端与后端接口"的答案。

2.1 模块职责

5. 工程权衡与失效模式

5.1 权衡

  • 处理强度：激进前端更干净但可能伤语音、增加延迟；按场景调档；
  • 模块级联误差：每级都可能引入失真，级联放大。需消融验证每级的净收益；
  • 实时性：完整前端有累积延迟，实时通信要控制每级帧长。

5.2 失效模式

  1. 顺序颠倒：NS 在 AEC 前 → 回声消不掉（第 1 节原理）。这是最经典的配置错误。
  2. 过度处理：全开激进档，语音发闷、ASR 反而下降。消融表会暴露。
  3. VAD 切词：VAD 在词中误断，ASR 漏字。调端点参数。
  4. AGC 放大噪声：降噪不足时 AGC 把噪声也放大。确保降噪在前。

6. 延伸思考题（含解析）

Q1：为什么前端顺序是 AEC → NS → AGC → VAD？任意两级颠倒会怎样？
A：AEC 依赖回声与参考的线性关系，必须最先（非线性处理会破坏它）；NS 在 AGC 前以稳定信噪比估计；VAD 最后用干净信号判活。颠倒如 NS→AEC 会让回声消不掉；AGC→NS 会让降噪的噪声谱估计失真。

Q2：怎么量化"前端对 ASR 的增益"？只看音频质量指标够吗？
A：不够。音频指标（PESQ/DNSMOS）衡量听感，但 ASR 关心可懂度与特征稳定性。必须在下游 ASR 上测 CER 消融，才能证明前端对最终任务的净收益。两者结合：音频指标解释"干净了多少"，CER 回答"识别准了多少"。

Q3：完整前端全开激进档，ASR 反而变差，可能为什么？
A：过度降噪引入音乐噪声/频谱失真，AGC 放大残留噪声，这些伪影破坏 ASR 特征。激进档的失真代价超过了去噪收益。需消融找到每级的最优强度。

Q4：实时通信场景，前端延迟怎么控制？
A：每级用因果、短帧设计；AEC/NS 用流式模型（如 DeepFilterNet：20 ms 帧 + 20 ms 前瞻，总延迟 40 ms）；避免需要长上下文的非因果处理。总算法延迟控制在几十毫秒内。

Q5：你的前端如何与 Stage 7 的端侧助手对接？
A：前端（AEC+NS+AGC+VAD）作为助手的麦克风输入预处理，输出干净语音段喂端侧 ASR（SenseVoice-Small）。前端质量直接决定 ASR 上限，是助手可用性的关键一环。
