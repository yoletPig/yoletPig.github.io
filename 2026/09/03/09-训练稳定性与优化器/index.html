09 - 训练稳定性与优化器

本篇目标

读完本篇，你应该能做到：

  1. 从"方差守恒"推出 Xavier/Kaiming 初始化的公式，知道什么时候用哪个。
  2. 对比归一化家族 BN/LN/RMSNorm 的统计维度与适用场景。
  3. 解释 warmup 与学习率调度（cosine/one-cycle）各自的动机，写出标准调度代码。
  4. 画出优化器谱系 SGD→momentum→Adam→AdamW 的演进逻辑，理解权重衰减的"解耦"。
  5. 掌握梯度裁剪与混合精度（fp16/bf16/GradScaler）这两个大模型时代的基础件。

前 8 章解决"训得动"；本篇解决"训得稳、训得好"。这里的每个组件都是你在《VLM & VLA Stage 8（训练系统）》里会直接调用的旋钮。

1. 权重初始化

1.1 为什么需要它

前向传播是矩阵乘的串联：hl+1=Wlhl+blh_{l+1} = W_l h_l + b_lhl+1​=Wl​hl​+bl​。若 WWW 的元素方差是 Var(W)\mathrm{Var}(W)Var(W)，则输出方差大致为（以独立零均值元素近似推导）：

Var(hl+1,j)=∑i=1ninVar(Wji) Var(hl,i)=nin Var(W) Var(hl,i)\mathrm{Var}(h_{l+1,j}) = \sum_{i=1}^{n_{in}} \mathrm{Var}(W_{ji})\,\mathrm{Var}(h_{l,i}) = n_{in}\,\mathrm{Var}(W)\,\mathrm{Var}(h_{l,i}) Var(hl+1,j​)=i=1∑nin​​Var(Wji​)Var(hl,i​)=nin​Var(W)Var(hl,i​)

每过一层，方差被乘上 nin⋅Var(W)n_{in} \cdot \mathrm{Var}(W)nin​⋅Var(W)。默认 nn.Linear 的初始化是 U[−1/nin,1/nin]U[-1/\sqrt{n_{in}}, 1/\sqrt{n_{in}}]U[−1/nin​​,1/nin​​]（方差 =13nin= \frac{1}{3n_{in}}=3nin​1​），网络一深激活逐层收缩；反过来初始化过大则逐层爆炸。5 章的连乘在前向的镜像。

1.2 Xavier 初始化（tanh/sigmoid 网络）

目标：前向方差守恒——令 nin Var(W)=1n_{in}\,\mathrm{Var}(W) = 1nin​Var(W)=1。同时考虑反向传播的方差守恒（用 noutn_{out}nout​），取折中（Glorot & Bengio, Understanding the difficulty of training deep feedforward neural networks, AISTATS 2010）：

Var(W)=2nin+nout(Glorot normal: W∼N(0,2/(nin+nout)))\mathrm{Var}(W) = \frac{2}{n_{in} + n_{out}} \qquad \text{(Glorot normal: } W \sim N(0, 2/(n_{in}+n_{out}))\text{)} Var(W)=nin​+nout​2​(Glorot normal: W∼N(0,2/(nin​+nout​)))

1.3 Kaiming 初始化（ReLU 网络）

ReLU 会把一半激活置零，方差被砍半——同样 ninVar(W)n_{in}\mathrm{Var}(W)nin​Var(W) 的增益下输出方差只剩一半，深层连乘照样衰减（He et al., Delving Deep into Rectifiers, ICCV 2015，ResNet 同作者）。补偿一半的损失：

Var(W)=2nin(Kaiming normal: W∼N(0,2/nin))\mathrm{Var}(W) = \frac{2}{n_{in}} \qquad \text{(Kaiming normal: } W \sim N(0, 2/n_{in})\text{)} Var(W)=nin​2​(Kaiming normal: W∼N(0,2/nin​))

直觉总结：Xavier 保 tanh 世界的方差，Kaiming 为 ReLU 的"减半"加倍。卷积层的 ninn_{in}nin​ = in_channels × kH × kW。

2. 归一化家族：BN / LN / RMSNorm

6 章讲过 BN（沿 (N,H,W)(N,H,W)(N,H,W) 每通道归一化，依赖 batch 统计量）。补齐另外两位：

RMSNorm（Zhang & Sennrich, Root Mean Square Layer Normalization, NeurIPS 2019）去掉均值中心化和偏置，少一次统计、少一组参数，效果不降——LLaMA 系全线采用。为什么 Transformer 不用 BN：变长序列上"每通道跨 batch"的统计会被 padding 污染，且小 batch（大模型训练常态）统计噪声大；LN 按样本算，与 batch 无关。

3. warmup 与学习率调度

3.1 为什么需要 warmup

两个互相印证的理由：

  1. Adam 的二阶矩冷启动：vvv 从 0 开始指数平均，前期 v^\hat vv^ 偏小、m^/v^\hat m/\sqrt{\hat v}m^/v^​ 的步长被放大，梯度估计又最不可靠（参数乱）——开局最容易一步迈飞。RAdam（Liu et al., On the Variance of the Adaptive Learning Rate and Beyond, ICLR 2020）从方差角度论证了这一不稳定性。
  2. Transformer 的实践证据：原论文用 4000 步线性 warmup（公式 lr=d−0.5⋅min⁡(step−0.5, step⋅w−1.5)\text{lr} = d^{-0.5}\cdot\min(step^{-0.5},\ step\cdot w^{-1.5})lr=d−0.5⋅min(step−0.5, step⋅w−1.5)），不加 warmup 的深层 Transformer 训练发散或卡在高 loss（Vaswani et al. 2017 §5.3）。

策略：前 www 步从 0 线性升到峰值，之后按调度衰减。

3.2 cosine 衰减与 one-cycle

  • Cosine（Transformer 时代事实标准，SGDR 论文引入 cos 周期重启：Loshchilov & Hutter, ICLR 2017）：

ηt=ηmin⁡+12(ηmax⁡−ηmin⁡)(1+cos⁡π tT)\eta_t = \eta_{\min} + \frac{1}{2}(\eta_{\max} - \eta_{\min})\left(1 + \cos\frac{\pi \, t}{T}\right) ηt​=ηmin​+21​(ηmax​−ηmin​)(1+cosTπt​)

  • one-cycle（Smith, A Disciplined Approach to Neural Network Hyper-Parameters, 2018）：升-降一个周期，且momentum 反向（lr 升时 momentum 降），配合 LR range test 找峰值。

经验做法速记：Transformer 系 AdamW + peak 3e-4（小模型）~ 1e-4 及以下（大模型）+ 总步数 5-10% 的 warmup + cosine 到峰值 10%；CNN 分类常用 SGD momentum 0.9 + 0.1 × batch/256（见 10 章线性缩放）起步。

4.2 AdamW：权重衰减的解耦

传统 L2 正则把 λθ\lambda\thetaλθ 加进梯度再交给 Adam：梯度经过 m,vm, vm,v 的滑动平均"稀释"后，正则强度对每个参数变得不均——大梯度参数几乎不受正则，小梯度参数被过度衰减。AdamW（Loshchilov & Hutter, Decoupled Weight Decay Regularization, ICLR 2019）把衰减从梯度通路里拆出来，直接作用在参数上：

θ←θ−η(m^v^+ϵ+λθ)\theta \leftarrow \theta - \eta\left(\frac{\hat m}{\sqrt{\hat v}+\epsilon} + \lambda\theta\right) θ←θ−η(v^​+ϵm^​+λθ)

工程含义：AdamW(weight_decay=0.1) 中 0.1 的语义与 Adam(weight_decay=0.1) 完全不同；从 Adam 迁移到 AdamW 时衰减系数通常要加大一个量级（经验做法：Transformer 常用 0.01~0.1）。另一个细节：bias 与 LayerNorm 参数一般不衰减（衰减它们只会扰乱尺度，无正则收益——GPT-2/nanoGPT 的参数分组实践）：

6. 混合精度训练（fp16 / bf16 / GradScaler）

6.1 为什么需要它

fp32（1 符号 + 8 指数 + 23 尾数）对训练安全但贵。半精度把显存/带宽省一半、（有 Tensor Core 的卡上）计算翻倍——大模型训练的必修件。两种半精度的位分配决定性格：

类型 位分配(符号/指数/尾数) 数值范围 最大值 精度
fp32 1/8/23 ±3.4e38 巨大 高
fp16 1/5/10 ±65504 小 中
bf16 1/8/7 与 fp32 同量级 巨大 低

fp16 的两个坑：上界 65504，梯度大就溢出成 inf；下界附近（最小正规数约 6e-5），梯度小就整体下溢成 0。bf16 把尾数位拿去换指数位——范围和 fp32 一样宽，永远不会溢出/下溢，代价是精度粗（约 3 位十进制有效数字）。

6.2 GradScaler：给 fp16 梯度"整体放大"

混合精度（Micikevicius et al., Mixed-Precision Training, ICLR 2018）的分工：前向/多数计算用半精度，权重主副本与敏感计算（如 loss、归约）保持 fp32。fp16 的下溢问题用 loss scaling 解决：

机制三句话：loss 乘放大系数 SSS（初始 65536）→ 梯度整体上移避开下溢区 → optimizer.step 前检查 inf/nan，有则跳过该步并缩小 SSS。bf16 不需要 scaler（不会下溢），直接 autocast(dtype=torch.bfloat16)——这是 A100/H100 时代大模型训练默认 fp32 主副本 + bf16 计算的原因。

CPU 注记：torch.autocast("cpu", dtype=torch.bfloat16) 在较新 PyTorch + 支持 bf16 的 CPU 上可用但收益有限；本系列示例一律 fp32 跑通，混合精度只标记为 [GPU] 技能。数值感受：torch.finfo(torch.float16).max → 65504；torch.finfo(torch.bfloat16) 的指数位与 fp32 相同。

7. 常见陷阱

  1. Xavier 用在 ReLU 网络上：不报错，但深层激活逐层衰减，训练慢。按激活函数选初始化（1.2/1.3）。
  2. Transformer 里用 BN：小 batch + 变长 + padding 三连击，统计量失真；用 LN/RMSNorm。
  3. warmup 步数设 0 还疑惑"为什么前几百步 loss 横盘甚至上升"。
  4. AdamW 的 weight_decay 沿用 Adam 的 0.01 甚至 1e-4：解耦后强度语义变了，正则名存实亡（4.2）。
  5. fp16 手动 model.half() 全模型转：BN 统计量、loss、optimizer 状态全变 fp16，数值灾难；正确姿势永远是 autocast（6.2）。
  6. unscale 前做梯度裁剪：裁的是放大 SSS 倍后的梯度，max_norm 语义错乱——先 scaler.unscale_(opt) 再裁（6.2 顺序）。
  7. 以为 GradScaler 能救 bf16：bf16 没有下溢问题，加 scaler 白白引入跳步逻辑。

本篇小结

  • 初始化的本质是方差守恒：Xavier 2/(nin+nout)2/(n_{in}+n_{out})2/(nin​+nout​) 保 tanh 世界的方差；Kaiming 2/nin2/n_{in}2/nin​ 为 ReLU 的方差减半补偿。GPT 的 0.02 是工程约定。
  • 归一化选型：CNN 用 BN（batch 充足时最强），Transformer 用 LN，现代 LLM 用 RMSNorm（更简更稳）。
  • warmup 防"开局一步迈飞"（Adam 冷启动 + 深层 Transformer 实证）；cosine 衰减到 10% 峰值是默认收尾。
  • AdamW = Adam + 解耦权重衰减；bias/LN 参数不衰减；迁移时衰减系数要重调。
  • 梯度裁剪按全局范数、记录返回值当健康指标；混合精度用 autocast，fp16 配 GradScaler（跳步+缩放），bf16 免 scaler。

练习

  1. 用 torch.var 实测：100 层 nn.Linear(512,512) 串联（tanh），比较默认初始化与 Xavier 初始化下最后层输出的标准差，验证"方差守恒/衰减"。
  2. 同样实验换 ReLU + Kaiming，对比默认初始化的结果。
  3. 把 8 章 miniGPT 的训练换成"warmup 100 步 + cosine 到 3e-5"的调度（用本章 lr_cosine 函数），对比固定 lr=3e-4 的 300 步 loss 曲线。
  4. 实现"参数分组"的 AdamW（4.2 代码），打印两个分组的参数量，说明为什么 LN 的 γ/β 进了 no_decay 组。
  5. 在 CPU 上构造 x = torch.randn(4096, 4096)，分别用 fp32 与 bf16（x.to(torch.bfloat16)）做矩阵乘，计时对比并解释为什么收益远小于 GPU（提示：CPU 没有为低精度优化的 Tensor Core 等价物，转换本身有开销）。
