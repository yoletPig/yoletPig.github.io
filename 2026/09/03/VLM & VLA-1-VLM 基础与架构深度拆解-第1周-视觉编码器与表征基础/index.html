第 1 周教程：视觉编码器（Vision Encoder）与表征基础

本周要回答的三个问题

  1. 一张图片是如何变成一串 Token 的？为什么 Transformer 能吃图片？
  2. CLIP 的双塔对比学习到底在学什么？为什么它成了几乎所有 VLM 的视觉塔起点？
  3. SigLIP 用 Sigmoid 替代 Softmax，收益到底在哪里？

对应学习计划：第 1 周。交付物：加载 CLIP/SigLIP Vision Tower 并记录输出特征 Shape 的脚本。

1. 第一性原理：为什么图片需要被"Token 化"

1.1 根本矛盾

Transformer 的核心算子是自注意力（Self-Attention），其输入是一个一维 Token 序列，每个 Token 是一个 ddd 维向量。而图片的本质是二维连续信号：一张图片是 H×W×CH \times W \times CH×W×C 的张量（高、宽、通道数，如 224×224×3224 \times 224 \times 3224×224×3）。

前代方案受限于两条路线的根本缺陷：

  • CNN 路线（ResNet/VGG）：卷积算子天然带二维归纳偏置（局部性、平移等变性），但它的输出是特征图（Feature Map），没有"序列"概念，无法直接与文本 Token 序列做注意力交互；且感受野随深度线性增长，全局建模需要堆叠很多层。
  • ViT 之前的混合方案：把 CNN 特征图展平后接 Transformer，仍然依赖卷积的归纳偏置，无法验证 Transformer 能否端到端地从原始图片学习。

ViT 的答案是：图片本身就可以被切成块（Patch），每个 Patch 当作一个"视觉单词"。只要序列化方式合理，纯 Transformer 同样能从图片学到强表征——这用大规模数据弥补了归纳偏置的缺失。

1.2 Patching 的数学形式

设图片张量为 X∈RH×W×C\mathbf{X} \in \mathbb{R}^{H \times W \times C}X∈RH×W×C，Patch 大小为 P×PP \times PP×P，则：

N=HP×WPN = \frac{H}{P} \times \frac{W}{P} N=PH​×PW​

每个 Patch 被展平为 P×P×CP \times P \times CP×P×C 维向量，经一个可学习的线性投影 E∈R(P2⋅C)×d\mathbf{E} \in \mathbb{R}^{(P^2 \cdot C) \times d}E∈R(P2⋅C)×d 映射到 ddd 维：

z0=[xclass1; xp1E; xp2E; … ; xpNE]+Epos,z0∈RN′×d\mathbf{z}_0 = [\mathbf{x}^1_{\text{class}};\ \mathbf{x}^1_p \mathbf{E};\ \mathbf{x}^2_p \mathbf{E};\ \dots;\ \mathbf{x}^N_p \mathbf{E}] + \mathbf{E}_{\text{pos}}, \quad \mathbf{z}_0 \in \mathbb{R}^{N' \times d} z0​=[xclass1​; xp1​E; xp2​E; …; xpN​E]+Epos​,z0​∈RN′×d

其中 N′=N+1N' = N + 1N′=N+1（原版 ViT 含一个可学习的 [class] Token 用于分类；作为 VLM 视觉塔时常丢弃它，只取 NNN 个 Patch Token）。Epos\mathbf{E}_{\text{pos}}Epos​ 是可学习的位置嵌入，因为自注意力本身是置换不变的——打乱 Token 顺序结果不变，必须显式注入空间位置信息。

实现上的一个关键等价：Patch 切分 + 展平 + 线性投影，在数学上完全等价于一个 stride = kernel size 的卷积。PyTorch 中通常写作 nn.Conv2d(C, d, kernel_size=P, stride=P)，既高效又自动完成序列化。

1.3 Token 数量的物理含义

以 CLIP ViT-L/14（VLM 中最常用的视觉塔之一）为例：

N=33614×33614=24×24=576N = \frac{336}{14} \times \frac{336}{14} = 24 \times 24 = 576 N=14336​×14336​=24×24=576

  • 576：Patch Token 的数量，即图片被压缩成的"视觉单词数"。它直接决定了喂给 LLM 的序列长度，进而决定注意力计算的平方开销。
  • 1024：ViT-Large 的隐层维度 ddd，即每个视觉 Token 的特征维度（CLIP ViT-L/14 的 hidden_size 为 1024；SigLIP-SO400M 则是 1152，见 3.3 节与第 5 节）。

这两个数字（或它们的变体）会贯穿 Stage 1 的所有后续教程。自注意力的计算量为 O(N2⋅d)O(N^2 \cdot d)O(N2⋅d)，所以 Token 数是视觉塔最重要的复杂度指标。

2. CLIP：用对比学习把图片对齐到语言空间

2.1 双塔架构

CLIP 由两个独立的编码器组成：

  • Image Encoder：ViT（或 ResNet），将图片映射为一个 ddd 维归一化向量 I\mathbf{I}I。
  • Text Encoder：Transformer，将文本（通常是 prompt 模板，如 a photo of a {label}）映射为 ddd 维归一化向量 T\mathbf{T}T。

两个塔各自独立前向，只在损失函数处交互——这就是"双塔"的含义。这样设计的好处是推理时可以离线预计算所有图片特征，零样本分类只需与少量文本向量做点积，效率极高。

2.2 对比学习损失

取一个 batch 的 BBB 个图文对，计算两两余弦相似度矩阵：

Sij=Ii⋅Tj∥Ii∥⋅∥Tj∥S_{ij} = \frac{\mathbf{I}_i \cdot \mathbf{T}_j}{\|\mathbf{I}_i\| \cdot \|\mathbf{T}_j\|} Sij​=∥Ii​∥⋅∥Tj​∥Ii​⋅Tj​​

在 B×BB \times BB×B 的相似度矩阵上，对角线是正样本（配对的图文），其余 B2−BB^2 - BB2−B 个位置是负样本。CLIP 的 InfoNCE 损失是对行和列各做一次交叉熵后取平均：

L=12(Limg+Ltxt)\mathcal{L} = \frac{1}{2}\left( \mathcal{L}_{\text{img}} + \mathcal{L}_{\text{txt}} \right) L=21​(Limg​+Ltxt​)

其中每一项都是 softmax 交叉熵（τ\tauτ 为可学习的温度系数）：

Limg=−1B∑i=1Blog⁡exp⁡(Sii/τ)∑j=1Bexp⁡(Sij/τ)\mathcal{L}_{\text{img}} = -\frac{1}{B} \sum_{i=1}^{B} \log \frac{\exp(S_{ii}/\tau)}{\sum_{j=1}^{B} \exp(S_{ij}/\tau)} Limg​=−B1​i=1∑B​log∑j=1B​exp(Sij​/τ)exp(Sii​/τ)​

直觉：这个损失在做一个 BBB 分类任务——第 iii 张图要在当前 batch 的 BBB 个文本里"认出"自己的配对文本。学到的是"哪张图配哪句话"的对齐关系，而非图片的完整语义。对角线为 1、其余为 0 的目标驱动模型把配对的图文在共享空间中拉近、不配对的推远。

2.3 温度系数 τ\tauτ 的作用

  • τ\tauτ 越小，softmax 越尖锐，梯度越集中于困难负样本（相似度已很高的负对），训练后期靠它精细化表征；
  • τ\tauτ 越大，分布越平滑，梯度更均匀。

CLIP 将 τ\tauτ 设为可学习参数并 clamp 到上限（防止无限变小导致数值不稳）。经验规则：观察训练中 τ\tauτ 的轨迹，若训练后期仍剧烈波动，往往意味着表征尚未收敛。

2.4 伪负样本问题（对比学习范围的边界）

注意损失中的负样本只来自当前 batch。batch 中可能存在语义上与正样本接近但未配对的图文对（例如两段描述同一只狗的文本），它们被当作负样本强行推远。这决定了 CLIP 的表征是粗粒度的对齐——它擅长区分"这张图说的是狗还是船"，不擅长区分"这张图的狗是哪只"。这也是后续 SigLIP、以及 BLIP 系列引入 captioning 任务来补足细粒度理解的动机之一。

3. SigLIP：Sigmoid Loss 的收益分析

3.1 根本差异

SigLIP 把每一对 (i,j)(i, j)(i,j) 的损失独立计算，不再做 batch 内 softmax 归一化：

L=−1∣B∣∑i=1B∑j=1Blog⁡σ(zij⋅(Ii⋅Tj⋅τ+b))\mathcal{L} = -\frac{1}{|B|} \sum_{i=1}^{B} \sum_{j=1}^{B} \log \sigma\left( z_{ij} \cdot (\mathbf{I}_i \cdot \mathbf{T}_j \cdot \tau + b) \right) L=−∣B∣1​i=1∑B​j=1∑B​logσ(zij​⋅(Ii​⋅Tj​⋅τ+b))

其中 zij=1z_{ij} = 1zij​=1 当 i=ji = ji=j（正对），否则 zij=−1z_{ij} = -1zij​=−1（负对）；σ\sigmaσ 是 sigmoid；bbb 是可学习的偏置项（softmax 损失中没有这个自由度，因为 softmax 归一化使其不变）。正对的目标是让括号内为正，负对的目标是让它为负。

3.2 为什么 Sigmoid 优于 Softmax

softmax 是全局归一化：某个位置的概率依赖 batch 中所有其他负样本的相似度，因此每个样本的损失计算必须看到整个 batch。这带来两个限制：

  1. 分布式训练的通信瓶颈：全局 softmax 需要在设备间聚合完整的相似度矩阵和归一化项，跨机通信量大，batch 规模扩展困难。
  2. 伪负样本被强制惩罚：softmax 强迫"第 iii 张图对自己的文本的概率"在 batch 内竞争归一化，语义相近但未配对的文本会被硬性推向低概率。

Sigmoid 是逐对独立的二元判断，不依赖其他样本：

  • 通信开销更小：各设备可独立计算局部对损失，全局 batch 的聚合需求更低。SigLIP 论文实测：batch 小于 16k 时 sigmoid 显著优于 softmax（batch 越小差距越大）；同等 4 片 TPUv4 的显存约束下，sigmoid 可开约 4k 的全局 batch，而 CLIP 式 softmax 只能开约 2k；sigmoid 的性能在 32k batch 附近即饱和，不必像 softmax 系那样追求几十万级 batch。经验规则：全局 batch 越小，Sigmoid 相对 Softmax 的优势越明显。
  • 对伪负样本更宽容：负对只需"相似度低于阈值"（sigmoid 输出趋近 0）即可，不要求"必须是全 batch 最低"。相近语义的图文不会被过度推离。

3.3 为什么 VLM 界从 CLIP 迁移到 SigLIP

作为 VLM 视觉塔，SigLIP 的表征在常见 VLM 评测上普遍略优。SigLIP 论文的受控对比实验（Table 3，B 尺寸视觉塔、每图 196 patches）显示：ImageNet 零样本精度从 OpenCLIP 的 70.2% 提升到 SigLIP 的 76.3%；同规模的 from-scratch 训练（ViT-B/16、32k batch、TPUv4 上 2 天）为 72.1%（Table 1）。不同模型规模与训练配置下数字会有差异。更实际的工程理由是：SigLIP-SO400M（400M 参数、patch size 14、d=1152d = 1152d=1152、384 分辨率下 729 个 Token）等模型在开源权重许可、特征质量和推理成本之间取得了好的平衡，被 PaliGemma、IDEFICS2、LLaVA-OneVision 等主流 VLM 采用（注：PaLI-X 用的是 ViT-22B，Qwen2-VL 的视觉塔是重新训练的 675M ViT——它们都不是 SigLIP 本尊，只是训练思路同源）。经验规则：新训练一个 VLM，视觉塔首选 SigLIP 系列；CLIP 视觉塔更多出现在历史代码和教学场景。

4. 系统架构与数据流

以一张 336×336×3336 \times 336 \times 3336×336×3 的图片通过 CLIP ViT-L/14 为例：

步骤 操作 输出形状 说明
1 预处理（Resize + CenterCrop + Normalize） [3,336,336][3, 336, 336][3,336,336] 像素值归一化到 CLIP 训练分布
2 Patch Embedding（Conv2d, k=14, s=14） [1024,24,24][1024, 24, 24][1024,24,24] 576 个 Patch，每个 1024 维
3 Flatten + 转置 [576,1024][576, 1024][576,1024] 序列化为 Token 序列
4 加位置嵌入 + [CLS]（可选） [577,1024][577, 1024][577,1024] 或 [576,1024][576, 1024][576,1024] 自注意力需要显式位置信息
5 ViT Blocks × 24（多头自注意力 + MLP） [576,1024][576, 1024][576,1024] 形状不变，语义逐层抽象
6 取输出特征（LayerNorm 后） [576,1024][576, 1024][576,1024] 即 MVP 要求记录的 Shape

CLIP ViT-L/14 的 last_hidden_state 实际为 [1,577,1024][1, 577, 1024][1,577,1024]（含 [CLS]）；去掉第 0 位的 [CLS] 即 [1,576,1024][1, 576, 1024][1,576,1024]。作为对照，SigLIP-SO400M 输入 384×384384 \times 384384×384、patch 14 时输出 [1,729,1152][1, 729, 1152][1,729,1152]（其 hidden_size 为 1152）。

6. 工程权衡与失效模式

6.1 核心权衡：分辨率 vs Token 数

方案 Token 数（336px 输入） 注意力开销 小物体/文字识别
Patch 14，固定分辨率 576 基准 O(5762)O(576^2)O(5762) 弱：小字与细节易丢失
Patch 14，448px 输入 1024 ≈3.2×\approx 3.2\times≈3.2× 明显更好，成本上升
Patch 16（如 SigLIP 变体） 441 ≈0.6×\approx 0.6\times≈0.6× 略差于 Patch 14
动态分辨率（Qwen2-VL 路线，第 3 周展开） 随输入变化 可控 最好，需配套位置编码

经验规则：Token 数从 576 翻到 2304（4 倍），视觉塔与 LLM 的总计算量大约上升一个数量级级别的注意力开销。OCR、图表理解类任务通常必须上高分辨率或动态分辨率；纯图文描述类任务 576 Token 往往已够用。

6.2 三个代表性失效模式

失效 1：Resize 比例不当导致特征退化

  • 症状：下游任务精度莫名偏低，可视化注意力发现模型关注区域错位。
  • 根因：输入宽高比与训练分布差异大（如把 640×320640 \times 320640×320 的横图硬 Resize 成 336×336336 \times 336336×336 方图），Patch 网格与物体边界错开。
  • 定位：对比"原始比例 + letterbox padding"与"直接 Resize"两种预处理的特征余弦相似度；若差异巨大即确认。
  • 修复：预处理保持宽高比，用 padding 补齐；或直接采用支持动态分辨率的模型（第 3 周）。

失效 2：混合使用不同视觉塔的归一化统计量

  • 症状：加载权重后输出全是 NaN 或常数。
  • 根因：CLIP 与 SigLIP 的 image_mean / image_std 不同（CLIP 用 0.481/0.457/0.408，SigLIP 用 0.5/0.5/0.5），混用 processor 会让输入分布偏离训练分布。
  • 定位：assert torch.isfinite(feats).all()（上方脚本已包含）加上打印输入的均值方差。
  • 修复：始终用与权重配套的 AutoImageProcessor，不要手写归一化常数。

失效 3：误用 pooler_output 做密集任务

  • 症状：把 CLIP 的 pooler_output（[1,1024][1, 1024][1,1024]）直接 reshape 当作 Patch 序列喂给 Projector，报形状错误或效果崩溃。
  • 根因：混淆了两种输出——pooler_output 是全局单向量（服务于零样本分类），VLM 需要的是 last_hidden_state 的 Patch 序列（保留空间结构）。
  • 定位：打印两者的 shape；VLM 主干拼接处需要的是三维张量 [B,N,d][B, N, d][B,N,d]。
  • 修复：Projector 输入一律取 last_hidden_state（CLIP 需丢弃第 0 位的 [CLS] Token；SigLIP 无 [CLS]，729 个 Token 全部保留）。

7. 延伸思考题

  1. 复杂度推导：视觉 Token 数从 576 增加到 2304，自注意力的 FLOPs 变为几倍？若 LLM 序列中还有 2000 个文本 Token，总序列长度从 2576 变为 4304，注意力 FLOPs 变为几倍？（提示：O(N2)O(N^2)O(N2)，分别约 16 倍和 2.8 倍；前者是"只在视觉 Token 内部算注意力"的局部视角，后者是 LLM 全序列视角，两者结合才能解释为什么高分辨率微调显存爆炸。）
  2. 对比学习的边界：为什么 CLIP 学到的"576 个 Patch Token"对 VLM 有用，但 CLIP 原本的训练目标里根本没有"生成描述"这一项？谈谈特征对齐与特征完备性的区别。
  3. 温度系数实验：把第 5.2 节脚本改造成对两张图片与两条文本计算 6×26 \times 26×2 相似度矩阵（或直接用 CLIPModel 的完整双塔跑 2×22 \times 22×2 矩阵），观察对角线是否显著高于非对角线；思考若不显著可能是什么原因（图片语义相近、预处理错误、或温度/权重问题）。
