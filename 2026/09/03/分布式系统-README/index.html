分布式系统系列教程：从单机极限到 LLM 集群

面向以 Python 为主、目标成为**算法工程师（大模型训练/推理服务方向）**的学习者。库里的操作系统系列回答了"一台机器内部发生了什么"，模型性能优化 Stage 7/8 与 Agent 生产部署回答了"服务怎么上线"；但当你把两个八卡机连起来训一个 70B 模型、把推理服务扩到三个节点时，新问题出现了：节点之间会失联、会半死不活、会对同一件事各执一词。本系列补上这块理论地基——为什么单机不够、一致性怎么保、失败怎么处理。LLM 多机训练（数据/张量/流水线并行）本身就是分布式问题，本系列有一章专讲。
全系列为中文原创，共 13 章。以 Linux 单机模拟多节点（多进程/asyncio 当"节点"，socket 当"网络"），所有代码完整可运行、中文注释。关键论断标注可查证来源（Lamport 论文、Raft 论文即 In Search of an Understandable Consensus Algorithm、DDIA 即《数据密集型应用系统设计》Martin Kleppmann）；无法查证的经验一律标注"经验做法"。

学习路径

篇 主题 你将学会
01-为什么要分布式 单机物理极限、扩展性立方（AKF）、共享 nothing、分布式的代价 用数字回答"为什么必须上多机"；用 x/y/z 轴给任何系统定扩展方案；算清分布式要付的三笔账
02-不可靠网络与时间 分区与超时、两将军/拜占庭问题、NTP 偏移、Lamport 时钟、向量时钟 证明"超时不等于失败"；手写 Lamport 逻辑时钟；解释为什么不能用物理时钟给事件排序
03-CAP与一致性谱系 CAP 严格含义、PACELC、线性一致到最终一致、读己之写/单调读 纠正对 CAP 的三大误读；给每种业务选对一致性等级；用读写时序判定一致性级别
04-复制 主从（同步/半同步/异步）、复制滞后、多主冲突、无主 Quorum 手写主从复制+故障切换；推导 Quorum 交集条件；讲清三种读一致性与复制滞后的对策
05-共识-Raft详解 共识问题、Paxos 为什么难、Raft 选举/日志复制/安全性、成员变更 用 Python 模拟领导者选举与脑裂避免；论证"为什么必须多数派提交"；给 Raft 每条规则找到安全性理由
06-分区与一致性哈希 范围 vs 哈希分区、一致性哈希环、虚拟节点、rendezvous hashing 手写一致性哈希并实测虚拟节点改善数据倾斜；给缓存集群设计扩容方案；识别热分区
07-事务与隔离级别 ACID 辨析、四种隔离级别、脏读/不可重复读/幻读、2PL、SSI、分布式事务难点 用时序图复现三类并发异常；讲清 MySQL 可重复读与幻读的恩怨；说出两阶段锁与 SSI 的取舍
08-分布式事务 2PC 全流程与故障分析、3PC、Saga、TCC、本地消息表/outbox 逐一分析 2PC 每个节点宕机的后果；写完订票 Saga 的补偿链；用决策表给业务选分布式事务方案
09-消息队列 MQ 三大价值、投递语义、幂等设计、Kafka/RabbitMQ/Redis Stream、死信与重试 证明 exactly-once 是端到端性质；用幂等键写不重不漏的消费者；设计带退避抖动的重试
10-超时-重试与弹性模式 超时设置、指数退避+抖动、熔断器、舱壁、令牌桶/漏桶、降级、Hedge 手写熔断器状态机与两种限流器；解释重试风暴怎么形成；给下游雪崩画完整防线
11-成员管理与故障检测 心跳误判、Φ Accrual、Gossip/SWIM、租约、脑裂与法定人数、服务发现 用 Python 模拟 Gossip 收敛过程；解释为什么故障检测只能"怀疑"不能"判决"；给服务发现选型
12-分布式存储案例与LLM时代的分布式 Redis/etcd/ZooKeeper/Cassandra 架构拆解、数据并行 AllReduce、张量/流水线并行、推理侧分布式 Ring AllReduce 手写模拟；讲清 PS vs AllReduce 的取舍；衔接 Stage 8 说清 KV cache 分片与 PD 分离
13-实战与面试清单 综合项目：asyncio 手写 Raft KV 存储（全量代码）；面试 30 题；设计题框架 把选举/日志/快照写成能跑的 KV 服务；刷完分布式高频 30 题；用统一框架答秒杀/短链/feed 流

阶段划分

  1. 动机与地基篇（01–03）：为什么单机不够、网络与时间这两座大山、CAP 与一致性谱系。这三章建立世界观：分布式系统的第一性问题不是"功能"而是"部分失败"与"没有全局视角"。
  2. 数据篇（04–08）：复制、共识（Raft）、分区、事务与隔离级别、分布式事务。这是分布式存储系统的全部骨架——DDIA 第三、四部分的路线图，也是面试出题最密的地带。
  3. 工程篇（09–11）：消息队列、超时重试与弹性模式、成员管理与故障检测。从"数据对不对"转向"系统活得下来吗"：削峰、防雪崩、自愈。
  4. 实战篇（12–13）：拆四个真实存储系统、讲透 LLM 训练/推理的分布式本质，最后用 asyncio 手写一个带 Raft 选举的 KV 存储并整理面试清单。

与本仓库其他方向的衔接

  • 操作系统系列 = 本系列的单机地基：02 讲的"不可靠网络"建立在 OS 12 篇（网络栈与 socket）之上；asyncio 的事件循环就是 OS 09 篇的 Reactor/epoll；05 章模拟节点用到的进程概念在 OS 02 篇。单机内的并发问题（OS 11 篇）是分布式并发的缩小版——锁、竞态、死锁在那里，扩展到这里。
  • 模型性能优化 Stage 7（生产级推理服务）= 本系列的实战应用：Stage 7 里的 Ray Serve 多副本、K8s 扩缩容、健康检查探针，本质就是本系列 11 章的成员管理与故障检测、10 章的弹性模式。读完 10/11 再回头看 K8s 的 liveness/readiness 配置，你会知道每个参数在为什么理论买单。
  • 模型性能优化 Stage 8（端云一体/多机推理）：Stage 8 的多机推理调度与端云协同是 12 章推理侧分布式（KV cache 分片、PD 分离）的直接前情；本系列补的是"为什么这么分片"背后的复制/分区/一致性理论。
  • PyTorch与深度学习系列：12 章的数据并行/AllReduce 会解释 DistributedDataParallel 背后发生了什么——NCCL 的 Ring AllReduce 就是本篇手写模拟的算法，torch.distributed 的 init 方法就是 11 章的服务发现。
  • Agent 生产部署：Agent 的多步任务、工具调用重试、状态管理，是 08 章 Saga/补偿、09 章投递语义、10 章重试策略在 LLM 场景的直接应用。

约定

  • 平台约定：以 Linux 为准（Ubuntu 22.04 / WSL2 验证），以单机模拟多节点为主——一个进程（或 asyncio task）当一个节点，socket/队列当网络；需要真实多节点时可用 Docker Compose 或多个终端各跑一个进程，文中会注明。
  • 代码约定：Python 3.10+，只依赖标准库（asyncio/socket/hashlib/random 等），个别对比实验用到 redis/redis-cli 时单独注明；所有演示代码完整可运行，关键处有中文注释。
  • 模拟约定：模拟代码里用 asyncio.sleep(随机延迟) 模拟网络延迟，用抛异常/直接不响应模拟节点宕机；模拟的目的是看清"协议怎么运转"，不追求网络栈级真实（真实网络栈请回到 OS 12 篇）。
  • 引用约定：DDIA 指 Martin Kleppmann《数据密集型应用系统设计》（Designing Data-Intensive Applications, 2017）中文版章节号；Raft 论文指 Ongaro & Ousterhout, In Search of an Understandable Consensus Algorithm (USENIX ATC 2014)；Lamport 论文给出标题与年份；经验做法不冒充定论。
  • 术语约定：优先中文术语、首次出现附英文；“分区”（partition，指数据分片）与"网络分区"（network partition，指网络断裂）在文中以语境区分，必要时写全称。
  • 本系列不使用 Obsidian 双链以外的特殊语法，任何 markdown 阅读器都能正常渲染。
