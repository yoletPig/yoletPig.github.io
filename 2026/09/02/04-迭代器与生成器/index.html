04 - 迭代器与生成器

本篇目标

  1. 搞懂迭代协议：for 循环背后是 __iter__/__next__ 两个方法的握手，可迭代对象（iterable）与迭代器（iterator）是两个概念；
  2. 掌握生成器函数的执行流：yield 暂停/恢复的完整图解，能画出逐步执行轨迹；
  3. 理解 yield from 的委托语义，以及"生成器 → 协程"的历史演进（asyncio 的来路）；
  4. 用实测数据理解惰性求值省内存，并掌握 itertools 精选工具。

1. 迭代协议：for 循环的幕后

官方术语表（Glossary → iterator）定义：**可迭代对象（iterable）**是实现了 __iter__、能返回迭代器的对象；**迭代器（iterator）**是实现了 __next__（无值可给时抛 StopIteration）且 __iter__ 返回自身的对象。for x in obj 的幕后流程是：

  1. 调用 iter(obj) → 即调用 obj.__iter__()，拿到迭代器；
  2. 循环调用 next(it) → 即 it.__next__()，取下一个值；
  3. 捕获 StopIteration，正常结束循环（对 for 来说不是错误）。

2. 生成器函数：yield 的暂停与恢复

生成器函数：函数体内出现 yield，这个函数就不再是普通函数——调用它不执行函数体，而是立刻返回一个生成器对象（生成器既是 iterator 也是 iterable，__iter__ 返回自身）。yield 的语义是暂停并交出一个值，下次 next 从暂停点恢复（官方文档：Python Language Reference → 6.2.8 Yield expressions）。

执行轨迹总结：gen() → 创建（不执行）；next() → 执行到下一个 yield 暂停；yield 值成为本次 next 的返回值；再 next → 从暂停点恢复；函数体执行完毕 → StopIteration。生成器的局部变量、执行位置全部被解释器保存在生成器对象里——这就是为什么 c1 = counter(); c2 = counter() 两个生成器互不干扰（对比 02 篇闭包：都是"函数 + 环境"的打包，只是恢复机制不同）。

3. yield from：委托子生成器

yield from iterable 把迭代工作委托给子可迭代对象：外层生成器逐个透传子生成器的值，直到子生成器耗尽。等价于一层透明的"管道"：

yield from 不只是语法捷径：它还建立了双向通道（外层 send 的值透传给子生成器、异常也透传），这正是它后来被用来实现协程嵌套的原因。但要注意 Python 3.10 起 yield 已从基于生成器的协程（@types.coroutine/@asyncio.coroutine）中移除，async/await 全面接管（PEP 476 之后的演进：PEP 492 引入 async/await，PEP 525 异步生成器）——新代码的协程一律写 async/await，yield from 只在"纯迭代委托"场景使用：

5. 生成器与协程：一段历史

理解这段历史，才能明白 asyncio 的术语从哪来（09 篇将接续这个话题）：

  1. PEP 255（Python 2.2）：引入生成器，yield 只用于产出值；
  2. PEP 342（Python 2.5）：yield 变成表达式（x = yield v），新增 send()/throw()/close()——生成器可以被外界喂数据、被驱动，"生成器协程"诞生；
  3. PEP 380（Python 3.3）：yield from 支持子生成器委托，协程可以嵌套等待；
  4. PEP 492（Python 3.5）：async def/await 原生协程成为一等语法，await 在机制上是 yield from 的受控特化；
  5. Python 3.8：@asyncio.coroutine 弃用；3.10：@asyncio.coroutine 移除、生成器协程谢幕；3.11：asend/athrow/aclose 支撑的异步生成器成熟（PEP 525，3.6 引入）。

也就是说：今天 asyncio 的事件循环，驱动协程的底层机制与驱动生成器同源——都是"暂停于一个 yield 点、保存现场、可恢复"。09 篇会用这个视角讲 await：它就是协程版的 next(g)。

陷阱一：生成器是一次性的——耗尽后再遍历得到空，且不报错：

陷阱二：生成器"惰性"到调用时才求值——捕获循环变量（late binding，02 篇）在生成器里同样存在且更隐蔽：

真正的雷是 genexp 捕获外部变量：x = 1; g = (x for _ in range(3)); x = 99; list(g) → [99, 99, 99]（首个值取定义时的 x，其后取当前值——CPython 行为，勿依赖，避免写法即可）。

陷阱三：生成器里抛异常被静默吞掉——for x in g 中生成器内部异常会传播出来，但若生成器函数用 try/finally 管理资源而迭代方提前 break，要靠 close()（触发 GeneratorExit）走 finally 清理；with 块写在生成器里时，确保生成器被耗尽或显式 close，否则资源释放推迟到 GC（承接 01 篇：CPython 引用计数通常很快，但 PyPy/跨引用循环不保证）。

陷阱四：在生成器函数中 return 值却想拿到它——return v 的值只在 StopIteration.value/yield from 表达式里可见，普通 for 循环拿不到；需要"迭代 + 结果"两个产物时用自定义类或让调用方显式处理。

陷阱五：把 map/zip 当列表用——它们是 iterator，len()、索引、二次遍历都会翻车；需要列表特性时 list(...) 物化（并想清楚内存代价，回到第 4 节的选型准则）。

本篇小结

  • 迭代协议：iter() 取迭代器、next() 取值、StopIteration 结束；iterable 可反复产迭代器，iterator 是一次性游标；
  • 生成器函数遇 yield 暂停交值、恢复续跑，gen() 不执行函数体；send 可喂数据（协程的雏形）；
  • yield from 委托子生成器并透传双向通道；新协程一律 async/await（3.10 起生成器协程已移除）；
  • 惰性求值省的是内存不是时间：一次性流水线用生成器（内存 O(1)），需要反复访问就物化成列表；
  • 生成器是 asyncio 的直系祖先：await 与 next(g) 同源（暂停-恢复机制），09 篇正式展开。
