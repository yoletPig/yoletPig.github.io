02 - 机器级表示：读懂汇编

本篇目标

  • 掌握 x86-64 的 16 个通用寄存器与职责分工，看懂 AT&T 语法下的 mov/lea/算术/比较/跳转/调用六大类指令。
  • 吃透 System V AMD64 调用约定：参数怎么传、栈帧怎么开、caller/callee-saved 谁负责保存、red zone 是什么。
  • 会用 objdump -d、readelf、gdb 三个工具把"一个 C 函数"拆到寄存器和栈的层面，亲眼看到 -O0 与 -O2 的产物差异。

前置：01 章的 ISA 概念与 gcc 四阶段；操作系统系列 04 篇（地址空间）有助于理解栈，但不强求。

1. 为什么要会读汇编

三个你绕不开的场景：① 性能归因——性能工程系列的火焰图把热点指到一个函数，但"慢在哪一行"只有汇编能回答（向量化了没有？内联了没有？多了几次访存？）；② 没有源码的依赖库——线上 so 出问题，objdump 是最后的眼睛；③ 验证编译器——你写的"优化"可能被编译器做得更好或完全忽略（04 章的 cmov 实验就是现场）。

本系列默认 gcc 的 AT&T 语法（objdump 默认输出），与 Intel 语法的显著差异：源操作数在前（mov %rax, %rbx 是 rbx←rax，与 Intel 相反）、寄存器带 %、立即数带 $、内存寻址用 offset(base,index,scale)。经验做法：看惯一种语法后，用 objdump -d -M intel 可切换到 Intel 语法，两边都认识会省很多查资料的功夫。

2. 寄存器全景：16 个通用寄存器与它们的分工

x86-64 有 16 个 64 位通用寄存器（CSAPP 第 3 章图 3-2；完整细节见 Intel SDM Vol.1 第 3 章）。名字里的历史包袱要认清：rax 的前身是 16 位的 ax，e 前缀（eax）是 32 位时代加的，r 前缀（rax）是 64 位时代加的——所以 mov %eax, %eax 是把 rax 的低 32 位"扩展"回自己（高 32 位清零）。

寄存器 低 32 位 职责（System V AMD64 ABI） 保存责任
%rax %eax 累加器 / 函数返回值 / 乘除法隐式操作数 caller-saved
%rbx %ebx 基址（历史） callee-saved
%rcx %ecx 计数器 / 第 4 参数 caller-saved
%rdx %edx 数据 / 第 3 参数 / 除法高位 caller-saved
%rsi %esi 源索引 / 第 2 参数 caller-saved
%rdi %edi 目的索引 / 第 1 参数 caller-saved
%rbp %ebp 栈帧基址指针（-O2 常省略） callee-saved
%rsp %esp 栈顶指针（方向向下） 专用
%r8~%r9 — 第 5/6 参数 caller-saved
%r10~%r11 — 临时（r11 常被 PLT 用） caller-saved
%r12~%r15 — 临时 callee-saved

另有专用寄存器：%rip（指令指针，程序计数器；x86-64 才能对它做相对寻址）、16 个 XMM 寄存器（%xmm0~%xmm15，浮点参数与 SIMD 用，04 章展开）。caller-saved = 调用别人后内容可能被毁，调用者自己负责保存；callee-saved = 被调用者保证原样归还。 这个分工决定了汇编里"谁在 push/pop"。

3. 数据传送与寻址模式

mov 家族是汇编里出现频率最高的指令，后缀表示操作数宽度：movb（1 字节）、movw（2）、movl（4）、movq（8）。注意两个特例（CSAPP 3.4.2）：movzbl 是"零扩展传送"（byte→long 补 0），movsbl 是"符号扩展传送"（补符号位）——扩展比缩短要多一条指令，因为高位必须被显式填上，这直接对应 05 章的符号扩展陷阱。

6. System V AMD64 调用约定：参数与返回值怎么走

Linux 上 x86-64 的函数调用规则由 System V Application Binary Interface (AMD64 Architecture Processor Supplement) 定义（下称 SysV ABI，2.3.2 节）。核心条款：

  • 整型/指针参数按顺序走 6 个寄存器：rdi, rsi, rdx, rcx, r8, r9，第 7 个起从右往左依次压栈，栈上每个参数 8 字节对齐。
  • 浮点参数走 xmm0~xmm7，返回值：整数在 rax，浮点在 xmm0。
  • 栈指针 16 字节对齐：在 call 指令执行前 rsp 必须 16 字节对齐（call 压完返回地址后进入函数时 rsp ≡ 8 mod 16）。SSE 指令 movaps 要求 16 字节对齐，对齐破了会直接段错误——手写汇编最常见的翻车点。
  • red zone：进入函数后、真正下探栈之前，rsp 之下的 128 字节区域允许函数直接使用（叶函数不用改 rsp 就有临时空间）。信号处理和中断会踩到 red zone，所以内核态不适用（内核用单独的内核栈）。
  • ARM 注：ARM64 的约定是 AAPCS64：参数走 x0~x7（8 个），返回 x0，无 red zone，链接寄存器 lr（x30）保存返回地址——ARM 的 call 不压栈，而是写进 lr，需要更深的调用时才把 lr 入栈。这是两边汇编最重要的形状差异。

常见误区

  1. “汇编很难，先学完 C++ 再说”：常用指令就 20 来个（mov/lea/add/cmp/jmp/call/push/pop/ret 占绝大头），其余现查。读不懂的真实原因是没建立"寄存器=变量、内存=数组/栈"的映射，本篇 2~5 节就是那张映射表。
  2. “AT&T 的 mov %rax, %rbx 是 rax←rbx”：反了。AT&T 是源在前，Intel 语法才是目的在前。判别技巧：看偏移方向——mov %eax, -4(%rbp) 只能是"寄存器→内存"，因为右边是地址。
  3. “call 就是跳转”：call 跳转前先把返回地址压栈，这 8 字节影响 rsp 对齐（进函数时 rsp ≡ 8 mod 16）和栈回溯。手写汇编写崩，九成是忘了这一条或忘了 16 字节对齐。
  4. “red zone 一直可用”：它是叶函数的特权——一旦你 call 别人，red zone 就成了别人的栈。信号处理函数运行在你"以为的" red zone 上，所以依赖 red zone 的代码在信号场景会坏（内核栈不用 red zone 正是为此，SysV ABI 3.2.2）。
  5. “-O2 只是 -O0 的加速版”：它经常改变程序形状——省略帧指针、内联、把分支变 cmov、循环变 SIMD（04 章）。在 -O0 上做的性能结论对 -O2 几乎无效；性能实验必须用与生产相同的优化级别编译。

本篇小结

  • 16 个通用寄存器分工：前 6 参数 rdi/rsi/rdx/rcx/r8/r9、返回 rax、栈 rsp、帧 rbp（-O2 可省）；caller/callee-saved 决定谁 push 谁。
  • 寻址 D(Rb,Ri,S) 是 C 指针运算的真身（比例因子=元素宽度）；lea 是免访存的地址算术，-O2 里当三数加法器用。
  • 条件码 + jcc/setcc/cmovcc 把 C 的 if 落到机器；有符号（l/g）与无符号（b/a）条件码是两套，05 章的符号坑在这里现形。
  • SysV AMD64 约定：6 寄存器传参、第 7 起走栈、16 字节栈对齐、red zone 128 字节（叶函数专用）；ARM64 是 8 寄存器 + lr 寄存器返回，call 不自动压栈。
  • 工具链：objdump -d 看产物、readelf -S 看节、gdb 断点 + info registers + x/4gx $rsp + bt 把栈帧"看"出来；-O0 与 -O2 的产物形状完全不同，性能结论必须匹配生产编译选项。

练习

  1. 把 01 章练习里的 add 函数改成返回 a*8 + 3，用 gcc -O2 -S 编译，验证产物是否只有一条 lea（提示：lea 0x3(,%rdi,8), %eax）。再试 a*12+5，观察编译器如何拆（两次 lea + add）。
  2. 写一个 8 参数的函数 int f8(int a,...,int h)，用 objdump -d 找出哪两个参数走了栈、它们的偏移是多少，并解释为什么偏移里含返回地址的 8 字节。
  3. 用 gdb 复现 7 节实验，但在 add7 内部下断点，执行 x/6gx $rsp 把栈上 6 个 8 字节槽位逐个打印，标出哪个槽是第 7 参数、哪个是对齐填充。
  4. 用 objdump -d -M intel 重新反汇编 abi.o，把你看到的 mov eax, edi 与 AT&T 版本逐条对应，总结两种语法的三条差异。
  5. （与 OS 系列联动）写一个会栈溢出的无限递归 C 程序，ulimit -s unlimited 前后分别运行观察崩溃点变化；用 gdb 跑崩溃现场 bt，解释为什么回溯栈是一长串相同的帧（呼应 5 节"返回地址链"）。
