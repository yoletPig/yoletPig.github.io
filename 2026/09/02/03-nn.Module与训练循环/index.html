03 - nn.Module 与训练循环

本篇目标

读完本篇，你应该能做到：

  1. 说清 nn.Module 的注册机制：为什么往 __init__ 里塞子模块/参数，parameters() 就能自动找到它们。
  2. 建立 optimizer 的直觉谱系：SGD → momentum → Adam，各自在"下山"比喻里对应什么。
  3. 背下并理解标准训练循环模板：train/eval 状态、zero_grad/backward/step 三连、with torch.no_grad()。
  4. 用模板从零跑通一个完整可运行的 MNIST 手写数字分类（CPU 十几分钟内可出结果）。

2 章我们把训练循环手写了一遍；本篇把"参数管理 + 更新策略"交给框架，换来的是：模型随便叠多深、优化器一行切换。骨架不变，零件升级。

1. nn.Module：PyTorch 的一切模型基类

1.1 为什么需要它

2 章的线性回归只有两个参数 w, b，我们手动创建、手动更新、手动清零。一个网络有几百个参数张量时，这种手工管理不可维护。nn.Module 提供三件事：

  1. 自动注册：赋值给 self 的子模块和 nn.Parameter 会被记录；
  2. 统一视图：parameters() 一次拿到全部可训练张量；
  3. 统一接口：forward() 定义前向，train()/eval() 切换模式，to() 搬设备。

1.2 最小示例与机制

注册机制的原理（读源码前的心智模型）：nn.Module.__setattr__ 被覆写过——当你给 self.fc1 = nn.Linear(...) 赋值时，父类发现值是 Module，就把它登记进 self._modules 这个有序字典；发现值是 nn.Parameter 就登记进 self._parameters。parameters() 就是递归遍历这棵"模块树"。

由此推出三条推论：

  1. 参数放进 Python list/dict 不注册：self.layers = [nn.Linear(64, 64) for _ in range(3)] 里的层不会被 parameters() 找到。正确做法是用 nn.ModuleList / nn.ModuleDict（8 章 miniGPT 用 nn.ModuleList 堆 Transformer block）。
  2. forward 里现算的张量不是参数：self.tmp = x * 2（普通张量）不进 _parameters，不参与训练。
  3. 一个张量是 Parameter 才默认 requires_grad=True：普通 nn.Linear 的 weight/bias 内部就是 nn.Parameter。

1.3 Parameter 与 buffer

nn.Parameter 是"要训练的张量"；还有一类"跟着模型走但不训练"的张量叫 buffer，用 self.register_buffer('mean', torch.zeros(5)) 注册——6 章 BatchNorm 的 running_mean/running_var 就是 buffer：推理要用（所以必须在 state_dict 里），但梯度不更新它们（由滑动平均维护，见 6.5）。

2. optimizer：怎么"下山"

2.1 为什么需要它

2 章我们手写 w -= lr * dw。optimizer 把"用什么策略更新"封装成对象，好处：换策略不用改训练循环、能保存/恢复自身状态、能对整组参数统一操作。

2.2 SGD：最朴素的下山

θ←θ−η⋅g\theta \leftarrow \theta - \eta \cdot g θ←θ−η⋅g

用当前 batch 估计的梯度 ggg 直接走。问题：梯度方向抖动大（尤其各方向陡缓差异大时），像一个人在峡谷里下山，每步都被两侧坡面弹来弹去，沿谷底方向却走得很慢。

2.3 momentum：给下山的"滚一个球"

v←βv+g,θ←θ−η⋅vv \leftarrow \beta v + g, \qquad \theta \leftarrow \theta - \eta \cdot v v←βv+g,θ←θ−η⋅v

β\betaβ 通常取 0.9，vvv 是梯度的指数加权平均（近 10 步左右的平均，因为 (1−0.9)≈1/10(1-0.9)\approx 1/10(1−0.9)≈1/10）。直觉：震荡方向来回抵消、平均后变小；一致方向不断累加、平均后变大。等效于"滚动的小球带着惯性冲过小坑"。

2.4 Adam：每个参数自己配步长

m←β1m+(1−β1)g（一阶矩：梯度的平均，≈momentum）m \leftarrow \beta_1 m + (1-\beta_1) g \qquad \text{（一阶矩：梯度的平均，≈momentum）} m←β1​m+(1−β1​)g（一阶矩：梯度的平均，≈momentum）

v←β2v+(1−β2)g2（二阶矩：梯度平方的平均，≈各方向陡峭度）v \leftarrow \beta_2 v + (1-\beta_2) g^2 \qquad \text{（二阶矩：梯度平方的平均，≈各方向陡峭度）} v←β2​v+(1−β2​)g2（二阶矩：梯度平方的平均，≈各方向陡峭度）

θ←θ−η⋅m^v^+ϵ\theta \leftarrow \theta - \eta \cdot \frac{\hat m}{\sqrt{\hat v}+\epsilon} θ←θ−η⋅v^​+ϵm^​

m^,v^\hat m, \hat vm^,v^ 是修正了"从 0 冷启动偏小"问题的版本（偏差修正，9 章推导）。直觉：哪个参数的梯度一直很大，v^\sqrt{\hat v}v^​ 就大，等效步长自动缩小；梯度小的参数步长相对放大——每个参数自带自适应步长，所以对学习率不如 SGD 敏感，是深度学习默认起步选择。

论文出处：Kingma & Ba, Adam: A Method for Stochastic Optimization, ICLR 2015（正式版标注 2014 年 12 月首次挂 arXiv）。

2.5 三者对比速查

SGD SGD+momentum Adam
更新依据 当前梯度 梯度平均 梯度平均 + 二阶矩自适应
对 lr 敏感度 高 中 低
收敛速度（小网络） 慢 中 快
最终泛化（视觉大任务） 常更好 常更好 视任务
典型用途 调参精修、CNN 基线 ResNet 类训练 Transformer/NLP/快速实验

"SGD 在某些视觉任务上泛化更好"有实证支持（如 Wilson et al., The Marginal Value of Adaptive Gradient Methods, ICML 2017），但并非普遍规律——标注为经验做法级别的共识，具体任务以实验为准。

3. 标准训练循环模板（背下来）

逐条说明：

  • model.train() / model.eval()：不是"开训练/关训练"，而是切换模块内部行为。只影响两类层：Dropout（train 随机置零，eval 全开）与 BatchNorm（train 用当前 batch 统计量并更新滑动平均，eval 用历史统计量，6 章详述）。忘了 eval() 是"测试精度异常抖动"的头号病因。
  • 四步顺序：zero_grad → forward → backward → step。backward 必须在 step 之前，zero_grad 在 backward 之前——顺序错了梯度就是脏的。
  • @torch.no_grad()：评估时不需要梯度，不建图可省下整张计算图的内存；另外 argmax 只在 eval 分支出现——训练精度要用 train 分支单独统计。

3.1 交叉熵损失：分类任务的标配

最大的陷阱：nn.CrossEntropyLoss 内部 = LogSoftmax + NLLLoss，它吃的是原始 logits。如果你在 forward 末尾加了 nn.Softmax，等于做了两次 softmax，训练会变得又慢又差，而且不报错——极其隐蔽。规则一句话：CrossEntropyLoss 配 logits，手动概率才配 NLLLoss。

数学定义（多类交叉熵，zzz 为 logits，ttt 为 one-hot 真值）：

L=−∑ktklog⁡ezk∑jezjL = -\sum_{k} t_k \log \frac{e^{z_k}}{\sum_j e^{z_j}} L=−k∑​tk​log∑j​ezj​ezk​​

幸运的性质：对 logits 的梯度恰好是 softmax(z)−t\text{softmax}(z) - tsoftmax(z)−t（可自行推导），干净且数值稳定（内部用 log-sum-exp 技巧防溢出）。

4. 完整可运行示例：MNIST 手写数字分类

数据：MNIST，7 万张 28×28 灰度手写数字，10 类。首次运行会自动下载约 12MB 到 ./data（需要网络；离线机器可手动下载后放到该目录）。

阅读这份代码时问自己四个问题（都能在前文找到答案）：

  1. 为什么 forward 末尾没有 Softmax？（3.1 节）
  2. 为什么评估要包 torch.no_grad()？（01 章 + 3 节）
  3. 为什么每个 epoch 都要 model.train()/model.eval() 切换？（本例的 MLP 其实没有 BN/Dropout，切换是"礼貌性"的；一旦网络里加了这两类层，不切就出 bug——6/10 章）
  4. zero_grad/backward/step 顺序为什么不能乱？（3 节）

5. 常见陷阱

  1. 忘记 zero_grad()：2 章手写过 .grad.zero_()，框架版换成了 optimizer.zero_grad()，忘掉的后果一模一样：loss 震荡甚至发散。新版 PyTorch 可用 set_to_none=True（默认）把 .grad 置 None 而不是清零，稍省内存。
  2. 在 nn.CrossEntropyLoss 前加了 Softmax：不报错、精度低，最阴险的 bug（3.1 节）。
  3. optimizer 在 .to(device) 之前创建：optimizer = Adam(model.parameters()) 之后又 model.to("cuda")，parameters() 返回的张量对象不变（.to 是就地语义），一般没事；但反过来"先 to 再重建 optimizer"则更稳。真正会翻车的场景是 model.half()/重新赋值 weight——经验做法：先把模型放好设备、定好 dtype，最后再建 optimizer。
  4. 把 .argmax 用在 softmax 后：softmax 是单调的，先 softmax 再 argmax 结果一样，但白算一次；直接对 logits argmax。
  5. 评估时也调 loss_fn 却忘了 eval()：带 Dropout 的网络评估 loss 异常高、精度抖动。
  6. train/eval 忘切换 与 optimizer.zero_grad() 忘调并列为两大"代码看着对、结果就是不对"的经典。

本篇小结

  • nn.Module 靠覆写 __setattr__ 自动注册子模块与 nn.Parameter；放进 Python list 不会注册，要用 nn.ModuleList。
  • optimizer 封装更新策略：SGD 是朴素下山，momentum 加惯性（梯度指数加权平均），Adam 给每个参数自适应步长（一阶/二阶矩 + 偏差修正）。
  • 标准训练循环：train() → zero_grad → forward → backward → step；评估：eval() + no_grad()。这个模板全书通用。
  • CrossEntropyLoss 吃 logits，网络末尾不要加 Softmax。
  • MNIST + 两层 MLP，CPU 几分钟就能跑到 97%+ 测试精度——你的第一个完整深度学习模型。

练习

  1. 把 MLP 改成三层（784→256→128→10），对比参数量与 5 epoch 后的测试精度。
  2. 把 Adam 换成 SGD(lr=0.1)、SGD(lr=0.1, momentum=0.9) 各训 5 epoch，记录 test_acc 曲线，验证"Adam 收敛更快"是否成立。
  3. 故意删掉 optimizer.zero_grad() 运行 3 个 epoch，观察精度如何崩坏，解释原因。
  4. 在 nn.Sequential 末尾加一个 nn.Softmax(dim=1) 复现"双重 softmax"陷阱，记录精度下降幅度。
  5. 写代码打印 model.state_dict() 的所有 key，指出哪些是参数、哪些属于"没有参数的层"（本例中没有 buffer，思考为什么）。
