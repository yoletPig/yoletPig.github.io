第 2 周教程：声纹验证的评价体系——EER、minDCF 与阈值校准

本周要回答的三个问题

  1. EER（等错误率）的定义是什么？为什么它能作为"单一数字"横向对比模型？
  2. minDCF 与 EER 的区别在哪？为什么 NIST SRE 用 DCF 而不是 EER？
  3. 生产部署时，为什么阈值不设在 EER 点，而要按业务代价重新选？

对应学习计划：第 2 周。交付物：构建迷你声纹验证评测（10 人 × 5 条），实现 compute_eer() 与 min_dcf()，画 DET 曲线；再合成一组伪造样本，观察系统鲁棒性。

1. 第一性原理：验证 = 假设检验

1.1 问题框架

声纹验证是一个二元假设检验：

  • H0H_0H0​：试语音与注册人不是同一人（冒用）；
  • H1H_1H1​：试语音与注册人是同一人（合法）。

模型输出相似度分数 sss，系统设定阈值 τ\tauτ：s≥τs \ge \taus≥τ 判"接受"（同一人），否则"拒绝"。

于是有四类结果：

实际同人 (H1H_1H1​) 实际异人 (H0H_0H0​)
判接受 正确接受 误识（FA, False Accept）
判拒绝 误拒（FR, False Reject） 正确拒绝

两个核心错误率：

FAR(τ)=P(接受∣H0)（误识率：坏人进来）\text{FAR}(\tau) = P(\text{接受} \mid H_0) \quad \text{（误识率：坏人进来）} FAR(τ)=P(接受∣H0​)（误识率：坏人进来）

FRR(τ)=P(拒绝∣H1)（误拒率：好人被挡）\text{FRR}(\tau) = P(\text{拒绝} \mid H_1) \quad \text{（误拒率：好人被挡）} FRR(τ)=P(拒绝∣H1​)（误拒率：好人被挡）

这个公式在干什么：FAR 是"拿所有异人试验对来考系统，有多大比例被放进来"；FRR 是"拿所有同人试验对来考，有多大比例被挡在门外"。两者都是阈值 τ\tauτ 的函数——同一个系统，配不同阈值，就有不同的 FAR/FRR，所以单独报 FAR 或 FRR 必须连带说明阈值（或用下文的 EER/minDCF/DET 这类阈值无关的指标）。

τ\tauτ 越高：FAR 降（更严，坏人难进）但 FRR 升（好人也被挡）；τ\tauτ 越低：反之。这是所有阈值系统的根本权衡。

1.2 EER：两条错误率曲线的交点

把 FAR 和 FRR 都画成阈值 τ\tauτ 的函数，两条曲线会相交——交点处 FAR=FRR\text{FAR} = \text{FRR}FAR=FRR，这个共同值就是 EER（Equal Error Rate，等错误率）：

EER:FAR(τ∗)=FRR(τ∗)\text{EER}: \quad \text{FAR}(\tau^*) = \text{FRR}(\tau^*) EER:FAR(τ∗)=FRR(τ∗)

这个公式在干什么：在整条阈值轴上找一个"天平恰好平衡"的工作点——误放进来的人和被挡住的好人一样多。它把"模型的判别能力"从"阈值怎么选"里剥离出来：分布重叠越小，这个平衡点越低。

深入拆解：亲手算一次 EER。假设 4 个试验对，同人、异人各 2 个（分数已按降序排好）：

分数 sss 标签 扫描到此处：FAR FRR
0.92 同人 0/2 = 0 1/2 = 0.50
0.80 异人 1/2 = 0.50 1/2 = 0.50
0.71 同人 1/2 = 0.50 0/2 = 0
0.40 异人 2/2 = 1.00 0

扫描规则：把每个观测分数依次当作阈值 τ\tauτ（判"分数 ≥ τ 为接受"），走到哪一行，就统计"此时异人被放进来的比例"（FAR）和"同人被拒在外的比例"（FRR）。第一行只有 0.92 被接受，另一个同人样本（0.71）还没放进来，所以 FRR = 1/2；扫到第二行（阈值 0.80），异人 0.80 也被放进来，FAR = 1/2——此时 FAR = FRR = 0.50，两条曲线恰好相交，EER = 0.50（4 个样本太少，EER 显得高；真实评测用数百上千对才能得到平滑曲线，第 2.2 节代码就是这套扫描的向量化版本，取 ∣FAR−FRR∣|\text{FAR}-\text{FRR}|∣FAR−FRR∣ 最小处报 EER）。

为什么 EER 能做单一数字对比：它不依赖具体阈值选择，只反映"模型把同人和异人分布分开的能力"——分布分得越开，交点越低。EER 从 3% 降到 2% 就是实打实的进步，适合论文打榜与模型选型。

一句话总结：EER = "拿一个公平的阈值考一次试"的总体成绩，衡量的是模型本身，不是部署策略。

1.3 DET 曲线

DET（Detection Error Tradeoff）图：横轴 FAR、纵轴 FRR（常用正态分位数刻度让曲线更直），每个点对应一个阈值。曲线越靠左下越好。EER 就是曲线与对角线的交点。

1.4 minDCF：带"代价"的评价

EER 假设误识和误拒"一样坏"——这在很多业务里不成立：

  • 支付场景：误识（别人刷走钱）远比误拒（本人重试一次）严重；
  • 会议转写：分错说话人影响可读性，但漏分几秒无所谓。

DCF（Detection Cost Function） 给两类错误加权：

DCF(τ)=CFA⋅PFA(τ)⋅(1−Ptarget)+CFR⋅PFR(τ)⋅Ptarget\text{DCF}(\tau) = C_{\text{FA}} \cdot P_{\text{FA}}(\tau) \cdot (1 - P_{\text{target}}) + C_{\text{FR}} \cdot P_{\text{FR}}(\tau) \cdot P_{\text{target}} DCF(τ)=CFA​⋅PFA​(τ)⋅(1−Ptarget​)+CFR​⋅PFR​(τ)⋅Ptarget​

这个公式在干什么：它是"一次验证请求的期望代价"。系统上线后，来的请求里同人和异人的比例是 Ptarget:(1−Ptarget)P_{\text{target}} : (1 - P_{\text{target}})Ptarget​:(1−Ptarget​)，每种错误各有一个业务代价 CCC，所以：

  • CFA,CFRC_{\text{FA}}, C_{\text{FR}}CFA​,CFR​：误识/误拒的代价权重（误识一次损失多少钱 vs 误拒一次损失多少钱）；
  • PtargetP_{\text{target}}Ptarget​：真实同人请求的先验概率（如 0.01——大部分验证请求是冒用）；
  • 直觉：“错误的种类 × 这种错误发生的频率 × 这种错误的单价” 求和 = 平均每次验证要付出的代价。

minDCF = 把 τ\tauτ 从头扫到尾，取 DCF 的最小值，再除以一个"笨系统基准"做归一化：

minDCF=min⁡τDCF(τ)min⁡(CFR⋅Ptarget, CFA⋅(1−Ptarget))\text{minDCF} = \frac{\min_\tau \text{DCF}(\tau)}{\min\big(C_{\text{FR}} \cdot P_{\text{target}},\ C_{\text{FA}} \cdot (1 - P_{\text{target}})\big)} minDCF=min(CFR​⋅Ptarget​, CFA​⋅(1−Ptarget​))minτ​DCF(τ)​

分母在干什么：全判"拒绝"的笨系统代价是 CFR⋅PtargetC_{\text{FR}} \cdot P_{\text{target}}CFR​⋅Ptarget​（挡掉所有合法请求），全判"接受"的是 CFA⋅(1−Ptarget)C_{\text{FA}} \cdot (1 - P_{\text{target}})CFA​⋅(1−Ptarget​)。取二者较小者为基准除一下，让"一个完全不学习的系统"恰好 minDCF = 1.0，归一化后 minDCF < 1 才说明系统学到了东西，数值可以直接跨评测比较。

NIST SRE 的惯例参数：现代 NIST 说话人评测（如 SRE19 CTS）中 Cmiss=Cfa=1C_{\text{miss}} = C_{\text{fa}} = 1Cmiss​=Cfa​=1，先验用 Ptarget=0.01P_{\text{target}} = 0.01Ptarget​=0.01 与 0.0010.0010.001 两档组成主指标 CprimaryC_{\text{primary}}Cprimary​——即评测刻意设置"验证请求大多来自冒用者"的现实场景，逼系统在极低 FAR 区间也保持低 FRR。NIST SRE 用 minDCF 而不用 EER，就是因为它反映了真实部署代价：一个模型可能 EER 略高但"错误都集中在便宜的那一类"，实际更好用。

EER vs minDCF 一句话：EER 度量"区分能力"，minDCF 度量"业务代价"。面试答到这一层就够了。

3. 分数校准：让分数"可比"

3.1 为什么原始分数不可比

两个模型（或同一模型在两个数据集上）的相似度分数尺度不同：模型 A 同人集中在 0.8-0.9，模型 B 集中在 0.5-0.7。直接用同一个阈值判断会完全错位。

3.2 校准方法

  • Logistic 校准：学一个映射 p=σ(a⋅s+b)p = \sigma(a \cdot s + b)p=σ(a⋅s+b)，把分数映射成"是同人的概率"（σ\sigmaσ 是 sigmoid，aaa 管斜率、bbb 管平移，用一批带标签的开发集试验对拟合）；
  • PAV（Pool Adjacent Violators，保序回归）：非参数单调校准，把分数分箱后强制"分数越高、后验概率不降"，更灵活。

校准后，不同模型/数据集的分数落到同一语义空间（0-1 概率），阈值可迁移。生产声纹系统一定有这一步。

3.3 打分归一化：AS-Norm

为什么还需要它：校准解决"全局分数不可比"，但同一模型里，不同注册人的分数分布也不齐——有人天生分数偏高（“羊群效应”：山羊型说话人的异人分数系统性偏移）。AS-Norm（Adaptive Score Normalization，自适应分数归一化） 的做法：

snorm(stest)=stest−μtopσtops_{\text{norm}}(s_{\text{test}}) = \frac{s_{\text{test}} - \mu_{\text{top}}}{\sigma_{\text{top}}} snorm​(stest​)=σtop​stest​−μtop​​

对每条测试语音，从**协同队列（cohort，一大群背景说话人的声纹）**里找出与它最相似的 top-NNN 个，用这 top-NNN 个相似度的均值 μtop\mu_{\text{top}}μtop​ 和标准差 σtop\sigma_{\text{top}}σtop​ 做标准化。直觉：给每个测试语音配一把"针对它自己难度"的尺子——如果它跟谁都像（top-N 相似度普遍高），就往下压；如果它天生分数低，就往上提。NIST SRE 与 VoxSRC 前排系统的打分链路里几乎都有它（通常在 PLDA/余弦打分之后、校准之前）。

4. 工程权衡与失效模式

4.1 权衡

  • 阈值选择：高阈值安全但扰民，低阈值顺滑但危险——按业务代价定，不按 EER 定；
  • 测试集设计：必须包含跨信道、跨时长的配对，否则评测虚高；
  • minDCF 的先验：PtargetP_{\text{target}}Ptarget​ 设多少取决于业务（门禁 0.5，支付 0.01）。

4.2 失效模式

  1. 阈值照搬：把论文的 0.75 或 EER 阈值直接上生产，误识率失控。修复：开发集校准。
  2. 测试集泄漏：同一说话人的录音同时出现在注册与测试，EER 虚低。修复：按说话人严格划分。
  3. 忽略攻击：只测真实语音，上线后被合成语音攻破。修复：攻击样本纳入评测 + 反欺骗模块。
  4. 样本不平衡误读：异人配对远多于同人，accuracy 会虚高（全判拒绝也能 99%）。必须看 FAR/FRR/EER，不看 accuracy。

5. 延伸思考题（含解析）

Q1：EER 的定义？为什么实际部署不用 EER 而用业务阈值？
A：EER 是 FAR = FRR 交点处的错误率，反映模型区分能力、与阈值无关，适合对比。但部署时两类错误代价通常不等（误识比误拒严重得多），必须按业务代价在 DET 曲线上另选工作点，而不是恰好在交点。

Q2：声纹门禁的阈值怎么定？
A：① 用开发集画 FAR/FRR 曲线；② 确定业务可接受的误识率上限（如 0.1%）；③ 取满足该 FAR 的最高阈值（此时 FRR 最小）；④ 上线后监控实际误识并定期重校。

Q3：minDCF 里的 PtargetP_{\text{target}}Ptarget​ 为什么重要？
A：它是真实"同人请求"的先验。支付场景 PtargetP_{\text{target}}Ptarget​ 极小（绝大多数验证是冒用），误识的期望代价被放大，系统会更偏向保守。先验错了，选出的阈值就错了。

Q4：为什么不能用 accuracy 评价声纹验证？
A：异人配对占绝大多数，一个"全拒绝"的系统 accuracy 也能到 99%，但完全没用。必须用与阈值、代价挂钩的 FAR/FRR/EER/DCF。

Q5：你合成的变声攻击让相似度下降了多少？这说明什么？
A：（填你的实测）通常变声让同人相似度下降 0.1-0.3，可能跌破阈值——说明声纹对音色扰动敏感；也说明高级攻击（零样本克隆，相似度可能不降反近）更危险，必须加反欺骗。
