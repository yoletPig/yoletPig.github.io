13 - 实战：完整请求旅程与抓包分析

本篇目标

  • 完成本系列的收官实验：从浏览器/curl 输入 URL 到收到响应，逐层用 tcpdump 抓包对照，把 06–12 章的知识点在真实报文里逐一指认。
  • 手写一个支持 keep-alive 的 HTTP 服务器（socket 版，约 80 行），并与 http.server 标准库版对比行为差异。
  • 用实测数据回答"HTTP/1.1 vs HTTP/2 对同一页面的连接数差多少"。
  • 收获 30 道面试高频题与要点答案（组成原理/网络基础/TCP/HTTP+TLS/系统设计五组）。

前置：06–12 章；本章实验全部可在 WSL2 本机完成（需要 sudo 的 tcpdump 已在 07 章验证可用）。

与 http.server 的对比：标准库版每默认串行处理（ThreadingHTTPServer 才多线程）、且老版本对 keep-alive 支持弱；手写版可以看到——keep-alive 不是协议魔法，只是**"响应后不断开，继续读下一个请求"的循环**。并发模型的选择（一连接一线程 → 线程池 → epoll 事件循环）是 OS 系列 09 篇的正题，此处只留一个钩子：把 threading.Thread 换成 selectors 实现，就是你自己 Reactor 的第一步。

5. 面试高频 30 题与要点

组成原理组（8 题）

  1. 从代码到执行，中间经过哪些阶段？ 预处理→编译（→汇编）→汇编→链接→加载；链接做符号解析与重定位（01 章）。
  2. ISA 是什么？与微架构的区别？ 软硬件契约（指令编码/寄存器/访存模型）；微架构是契约的实现（流水线/缓存大小），同一 ISA 多种微架构（01 章）。
  3. 为什么需要缓存？L1/L2/L3 的量级？ CPU 与内存速度鸿沟；L1 ~1ns(4cyc)/L2 ~4ns/L3 ~15-40ns/内存 ~100ns（03 章）。
  4. 缓存行多大？为什么？ 64B；空间局部性的硬件兑现 + 一次搬运摊薄元数据开销（03 章）。
  5. 行优先和列优先为什么差数十倍？ C 行优先存储，列访问步长=行大小，每次访问不同缓存行/页，预取失效、延迟主导（03 章实测 23 倍）。
  6. 什么是伪共享？怎么解决？ 无关变量同 64B 行导致 MESI 弹跳；alignas(64) 隔开（03 章实测 8 倍）。
  7. 分支预测为什么重要？误预测代价？ 流水线 20 级、误预测冲刷 15-20 周期；预测器赌历史重演（04 章实测 3.4 倍）。
  8. float 为什么不精确？0.1+0.2 的机器原因？ 二进制无法精确表示 0.1（无限循环），尾数舍入；IEEE 754 每步舍入有定义（05 章逐位拆解）。

网络基础组（6 题）

  1. OSI 与 TCP/IP 模型关系？ OSI 是参考语言，TCP/IP 五层是现实；同层对话、逐层服务（06 章）。
  2. 一个字节从应用到对端经过什么？ 封装：HTTP→TCP段→IP包→帧→比特；对端逐层剥头（06 章）。
  3. /20 子网手算？ 前 20 位网络号；网络地址=主机位清零，广播=置一，可用 2¹²−2=4094（06 章实例）。
  4. NAT 是什么？副作用？ 私网地址+端口映射改写；外不可达、端口稀缺、破坏端到端（06 章）。
  5. ping 的原理？TTL 说明了什么？ ICMP Echo；TTL=初始值−经过跳数，可反推路径长度（06 章实测 ttl=52→12 跳）。
  6. traceroute 为什么能逐跳显示？ TTL=1,2,3… 递增，每跳设备回 ICMP 超时暴露自己（06 章）。

TCP 组（6 题）

  1. 三次握手流程？为什么不是两次？ SYN/SYN+ACK/ACK；两次会让历史旧 SYN 建立幽灵连接且无法确认服务端 ISN（07 章）。
  2. 四次挥手？为什么不能三次合并？ 全双工独立关闭；FIN+ACK 可合并不常合（被动方还有数据/未 close）（07 章）。
  3. TIME_WAIT 为什么等 2MSL？ ①最后 ACK 丢失需重传 FIN 时应答；②旧报文自然死亡防污染新连接（07 章）。
  4. TCP 怎么实现可靠？ 序号/累计确认/超时与快速重传/SACK/滑动窗口（07 章）。
  5. 流量控制与拥塞控制的区别？ rwnd 保护对端缓冲（对端声明），cwnd 保护网络（自己估计）；取 min（07 章）。
  6. 慢启动和拥塞避免？ 指数探测→ssthresh 后线性加；丢包后快重传+快恢复减半；BBR 用 BDP 模型替代丢包信号（07 章）。

HTTP + TLS 组（6 题）

  1. GET 和 POST 的本质区别？ 语义：GET 安全幂等可缓存，POST 不幂等；不是"参数放哪"的实现差异（08 章）。
  2. 301/302/307/308 区别？ 301/302 永久/临时但可能吞 POST 成 GET；307/308 严格保持方法（08 章）。
  3. HTTP/2 解决了什么？没解决什么？ 多路复用/HPACK 治应用层队头阻塞；TCP 层队头阻塞仍在（丢包阻塞所有流）（08 章）。
  4. QUIC 为什么能根治队头阻塞？ 每流独立序号/重传 + UDP 上用户态可靠传输；附 1-RTT 握手与连接迁移（08 章）。
  5. TLS 握手做什么？TLS1.3 快在哪？ 协商密钥+验证证书；1.3 ClientHello 带 key_share 把 2-RTT 砍到 1-RTT，强制 PFS（09 章）。
  6. 浏览器怎么验证证书？ SAN 域名匹配→有效期→信任链逐环验签→吊销检查；系统时钟错误是隐蔽杀手（09 章）。

系统设计组（4 题）

  1. 浏览器输入 URL 到页面显示，全流程？ 标准答案框架：URL 解析→DNS（缓存/递归）→TCP 握手→TLS 握手→HTTP 请求→服务器（LB/缓存/应用/DB）→响应→渲染；每步都答"在哪一层、耗时量级"（本章 2 节+10/09/08 章）。
  2. 接口慢，怎么排查？ 三刀拆账（计算/网络/磁盘）→ping/mtr 定位网络→ss/tcpdump 看 TCP→应用日志/火焰图（12 章 1 节 + 性能工程系列）。
  3. 为什么加机器不等于变快？ 串行依赖/一致性往返/共享瓶颈三约束 + Amdahl 上限 1/(1-p)（12 章）。
  4. 设计一个全球低延迟 LLM API？ Anycast 就近终结（10 章）+ 边缘 TLS + 区域集群（GPU 集中）+ 流式返回（11 章）+ 延迟预算审计（12 章决策树）。

常见误区

  1. “抓包分析要先学完所有协议”：顺序反了——抓包是学协议的显微镜。本章 2 节的表就是方法论：每抓一个报文，问"这是哪层、哪个字段、哪章讲过"，系列知识自动复盘。
  2. “手写服务器玩具而已，生产用不到”：生产框架（uvicorn/gunicorn）的 keep-alive、并发模型、优雅关闭全是本章 3 节的放大版；理解了 socket 循环，再读 uvicorn 源码就是读"自己写过东西的精装版"。
  3. “回环实验没有代表性”：回环实验的优势恰恰是无干扰（无 NAT/丢包/拥塞），适合看清协议形状；真实环境的额外现象（慢启动、丢包重传、NAT）在 06/07 章已有专门实验。两种环境互补，不要只做其一。
  4. “num_connects 是请求数”：它是"第几条连接"的序号；统计连接数要数去重后的值（4 节输出里 HTTP/1.1 的 1 1 1 1 1 1 2 2 2 2 表示 2 条连接，不是 10 个连接）。
  5. “面试题背了就行”：27/28 题这类开放题考察的是分层拆解 + 量级数字（每层多少 ms、瓶颈大概率在哪）——本系列 06~12 章的每个"经验做法"都是这题的弹药库；只背流程不背数字，答不出"为什么慢"。

本篇小结

  • 收官实验把协议栈落到报文：S/S./. 是握手、P. 是推数据、F. 是挥手；每层报文对应 06–09 章的知识点，一张指认表全部串起。
  • keep-alive = 连接内循环处理多请求（80 行 socket 版实证）；解析纪律：空行终结头部、头名大小写不敏感、Content-Length 定体。
  • HTTP/1.1 并行 10 请求需多条连接（浏览器上限 6），HTTP/2 一条连接全包——curl -w '%{num_connects}' 两行命令坐实（经验做法）。
  • 30 题清单五组：组成原理答"量级与原因"、网络答"哪一层"、TCP 答"为什么这样设计"、HTTP/TLS 答"语义与版本演进"、系统设计答"分层拆解+延迟预算"。
  • WSL2 实验要点：回环用 -i lo、抓包需 sudo、代理会改写流量路径（停代理或换回环目标）、curl 无 h3 支持时用 httpx 替代。

练习

  1. 把 2 节实验完整复现一遍，tcpdump -X 抓出 HTTP 请求报文的原始字节，逐字节标注请求行/头/空行/体（对照 08 章报文解剖图）。
  2. 给 myhttp.py 加三个功能：① 返回 404（路径不存在时）；② 支持 HEAD 方法（只回头部）；③ 静态文件服务（读磁盘文件+Content-Length）。用 curl 验证每个功能（提示：HEAD 时 conn.sendall 只发到空行）。
  3. 用 myhttp.py + curl -w 对比 keep-alive 开/关时连续 10 个请求的 time_total 总和（本机回环 RTT≈0，差异在连接建立系统调用；把服务器放到另一台机器/容器里再测一次，感受 RTT 的放大）。
  4. 在 4 节实验里加入 -w '%{time_starttransfer}\n'，对比 HTTP/1.1（6 连接）与 HTTP/2（1 连接）抓 10 个资源的首字节时间；构造"一个大文件+9 个小文件"的场景重测，解释 HTTP/2 在队头阻塞语义下的新权衡（大流占满窗口时小流排队）。
  5. （综合复盘）不看正文，把 30 题里 27 题的"标准答案框架"默写成 300 字短文，然后对照本系列各章补充你自己缺的知识点——缺哪个补哪章，这就是本系列的"期末考试"。
