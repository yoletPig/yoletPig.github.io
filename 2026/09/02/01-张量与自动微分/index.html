01 - 张量与自动微分

本篇目标

读完本篇，你应该能做到：

  1. 熟练创建张量，说清楚一个张量的三要素：shape、dtype、device。
  2. 不需要运行代码就能判断两个形状的张量相加/相乘后广播成什么形状、会不会报错。
  3. 理解 autograd 的计算图原理：requires_grad、backward、.grad 之间到底发生了什么。
  4. 分清叶节点与非叶节点，以及 torch.no_grad() 和 detach() 这两个"长得像"的东西的本质区别。

自动微分是 PyTorch 存在的理由——神经网络训练的本质就是"对某个标量 loss 求所有参数的梯度"，后面 13 章全建立在本篇之上。

1. 张量：带类型和形状的多维数组

1.1 为什么需要它

NumPy 的 ndarray 已经能表示多维数组了，PyTorch 的 tensor 比 it 多两样东西：可以放到 GPU 上算，以及可以记录"我是怎么被算出来的"从而自动求导。前者解决速度，后者解决训练。

1.2 创建与三要素

三要素逐个看：

  • shape：每一维的长度。a.shape 返回 torch.Size([2, 2])，它就是个元组，支持 a.size(0) 按维取。
  • dtype：元素类型。深度学习里最常见的是 torch.float32（默认浮点）与 torch.int64（标签的默认类型）。9 章会讲半精度 float16/bfloat16。
  • device：数据在哪台设备上。CPU 张量和 GPU 张量不能直接运算，必须先 .to() 到同一设备。

常见陷阱：整数张量参与除法会做整除。torch.tensor([1, 2, 3]) / 2 得到 [0.5, 1.0, 1.5]（PyTorch 的 / 对整型做了真除法并转 float），但 torch.div 配合 rounding_mode 时行为不同；最稳妥的做法是先把数据转成 float 再运算。另外 torch.tensor([1, 2]) 是 int64，喂给只吃 float 的 nn.Linear 会直接报错 expected scalar type Float——这是新手报错榜第一名。

2. 形状操作与索引

view 与 reshape 的区别值得单独记：view 不会复制数据、速度更快，但要求张量内存连续；reshape 能复制也能不复制，永远成功。经验做法：明确知道连续时用 view（还能借它发现隐藏的非连续问题），不确定时用 reshape。

3. 广播规则（broadcasting）

3.1 为什么需要它

给一个 batch 的向量统一加一个偏置时，你不想写 for 循环，也不想 expand 一份大内存。广播让 PyTorch 逻辑上复制、物理上不复制地完成这种运算。

3.2 规则（两条）

把两个形状从最后一维开始向左对齐，逐维比较，每一维满足以下之一即可广播：

  1. 两个维度相等；或
  2. 其中一个维度是 1（此时该维被"拉伸"到另一个的长度）；或
  3. 某个张量缺少这个维（把它当作 1）。

任何一维不满足（两个都大于 1 且不相等）→ 报错。

3.3 真实形状示例

3 章会看到：nn.Linear 内部就是 x @ W.T + b，其中 + b 依赖的正是例 2 这种广播。

4. 自动微分：计算图

4.1 为什么需要它

训练神经网络 = 最小化 loss。最小化需要梯度。手工对百万参数求导不现实，于是框架在你做前向计算的同时把每一步运算记录成一张有向无环图（计算图），backward() 时沿图反向应用链式法则（5 章细讲数学），自动算出所有叶子（参数）的梯度。

4.3 grad 是"存回叶子"的设计

backward() 默认只把梯度存到 requires_grad=True 的叶节点的 .grad 上，中间变量的梯度算完就用完即弃（省内存）。想保留中间梯度要用 retain_grad() 或钩子（见 4.4）。

5. 叶节点与非叶节点

5.1 概念

  • 叶节点（leaf）：不是任何运算的结果，即由用户直接创建的张量（torch.tensor(...)、nn.Parameter）。x.is_leaf 为 True。
  • 非叶节点（non-leaf）：由叶节点经过运算得到的中间结果。

只有叶节点默认保留 .grad，因为训练要更新的是参数（叶节点）；中间量（激活值）的梯度没人消费。

验证过：x.grad 是 0.6667，y.grad 是 None（PyTorch 2.14 会给出上面提到的警告）。

6. torch.no_grad() 与 detach() 的区别

两者都会"切断梯度"，但作用对象不同——这是面试高频题，也是写推理代码绕不开的点。

6.1 本质区别

  • torch.no_grad()：一个上下文，作用于"上下文里发生的运算"——里面的运算不建图，产出 requires_grad=False 的结果。它不改变任何已有张量的属性。
  • t.detach()：作用于这一个张量——返回一个与 t 共享存储但切断计算图历史的新张量（requires_grad=False）。上下文之外、之后对它的运算默认也不建图（因为它是新叶子）。

一句话：no_grad 管"接下来的运算"，detach 管"这一个张量的出身"。

6.2 各自的典型用途

场景 用哪个 原因
推理/评估（3 章的 eval 循环） torch.no_grad() 或 torch.inference_mode() 一整段代码都不需要梯度
把网络输出当"输入特征"喂给另一个网络 y.detach() 只切这一个张量，别处还要继续训练
参数更新 w -= lr * w.grad with torch.no_grad(): 更新操作绝不能被记进图里
假数据/标签常量 torch.randn(..., requires_grad=False)（默认就是） 根本不需要切

torch.inference_mode() 是 PyTorch 1.9+ 引入的更强版本：不仅不建图，还把张量标记为"推理张量"，禁用版本计数器，比 no_grad 更快更省（官方推荐推理时优先用它，出处见 PyTorch 官方文档 Autograd mechanics）。代价是推理张量之后不能再参与需要梯度的计算——12 章部署时会再用到。

6.3 经典坑：用 no_grad 包了更新却忘了它包不住"赋值"

.data 是历史遗留写法，它绕过所有安全检查，能隐藏"就地修改破坏计算图正确性"的 bug。现代代码一律用 detach() 或交给 optimizer。

7. 常见陷阱清单

  1. 梯度累加不清理：连续两次 loss.backward() 中间不清零，.grad 是两次之和。默认一次 backward 后图被释放，再次 backward 会报 Trying to backward through the graph a second time；确实要复用图需 loss.backward(retain_graph=True)（7 章 seq2seq 有正当用途）。
  2. 标量判断：backward() 只能从标量调用。y 是向量时要 y.sum().backward() 或 y.backward(torch.ones_like(y))（等价于对每个分量梯度求和，5 章会解释这就是 JVP）。
  3. .item() 拿 Python 数：打印 loss 用 loss.item()，否则打印的是整个张量对象且梯度图被引用，训练久了内存涨。
  4. in-place 运算破坏建图：x += 1（in-place）在 autograd 需要原值做反向时（如 tanh 的反向需要输出值）会报错；用 x = x + 1（新建张量）。PyTorch 用版本号检测这种情况。
  5. detach 共享内存（见 6.1 的 c.add_ 例子）：想独立复制请用 t.detach().clone()。

本篇小结

  • 张量三要素 shape/dtype/device；dtype 不匹配与 device 不匹配是两大高频报错。
  • 广播从右对齐，逐维满足"相等 / 有一个为 1 / 缺失"三者之一，否则报错。
  • autograd 在前向时建图，backward() 沿图反向把梯度写回叶节点的 .grad；.grad 累加，需手动清零。
  • 叶节点才默认保留梯度；retain_grad()/hook 用于调试中间梯度。
  • no_grad 管上下文内的运算，detach 切单个张量的历史且共享存储，inference_mode 是更强的推理专用版。

练习

  1. 不运行代码，判断下列运算结果的 shape，哪些会报错：(2,3,1)+(3,)、(4,1)+(2,3)、(5,1,4)+(1,4)、(1,1,1)+(6,)。
  2. 写代码验证：对 x = torch.tensor(3.0, requires_grad=True)，计算 y = x**2 + 2*x + 1 并 backward，检查 x.grad 是否等于 2x+2=82x+2=82x+2=8。
  3. 复现 5.1 的例子，加上 y.retain_grad() 观察非叶节点的梯度，并解释为什么它是 0.3333 而不是 0.6667。
  4. 写一个最小实验证明 detach() 共享存储：对 c = w.detach() 就地加 1，打印 w。再用 clone() 修复。
  5. 思考题：为什么 optimizer.step() 必须在 no_grad 下进行？如果不用会发生什么？（提示：参数更新式 p←p−ηgp \leftarrow p - \eta gp←p−ηg 本身也是一个运算。）
