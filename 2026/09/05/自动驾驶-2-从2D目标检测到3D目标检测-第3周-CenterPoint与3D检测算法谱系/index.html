第 3 周教程：CenterPoint 与 3D 检测算法谱系

本周要回答的三个问题

  1. CenterPoint（CVPR 2021）为什么能甩掉 anchor？"中心热图 + 回归"的每个头在算什么？
  2. 跟踪为什么可以从"外观匹配"简化成"贪心最近点匹配"？速度头 (vx, vy) 在其中的角色是什么？
  3. Point-based / Voxel-based / Pillar-based / Transformer-based 四条路线各代表什么模型、怎么选？

对应学习计划：第 3 周。交付物：NumPy 实现中心热图生成 + 峰值解码 + 两帧贪心匹配验证。

1. CenterPoint：把 3D 框中心当关键点

1.1 出发点

第 2 周结尾留下伏笔：anchor 有三大痛点（逐类手工设计、正负样本分配繁琐、输出通道翻倍）。CenterPoint（Yin, Zhou, Krähenbühl, UT Austin，CVPR 2021）的答案是把 2D 关键点检测的思路搬进 BEV：物体是 BEV 平面上的一个点——车在俯视图里就是一个矩形，矩形中心天然是个好定位点。于是检测被重述为：

  1. 在 BEV 特征图上预测每类目标的中心热图（center heatmap）；
  2. 在热图峰值处回归框的其余属性（偏移、高度、尺寸、朝向、速度）。

没有 anchor、没有 IoU 匹配的样本分配、NMS 依赖大幅降低（峰值天然不重合）。

1.1.1 一笔通道账：anchor 头 vs heatmap 头

"甩掉 anchor"不只是审美，先用输出通道算笔账（第 2 周 5.3 节的 SSD 头在此回收）。设 BEV 特征图 512×512512 \times 512512×512、3 个类别：

anchor 头（PointPillars 原版） heatmap 头（CenterPoint）
输出构成 每类 2 个 anchor（0°/90°）×（7 回归 + 2 朝向 bin + 1 分数）= 60 通道，另有跨类分数通道 类别热图 3 + 偏移 2 + 高度 2 + 尺寸 2 + 朝向 2~3 + 速度 2 ≈ 13~14 通道
与位置的关系 每个位置都"押注"一组 anchor，背景格子的 60 通道全是陪跑 只有峰值附近有意义的输出
新增类别的成本 重新设计该类的 anchor 尺寸/朝向先验 加 1 张热图通道

省 4 倍输出通道只是表面收益，深层收益是把"先验设计"从任务里删掉了：anchor 的尺寸/朝向是人为超参，换一个数据集（卡车比例暴增）就要重调；heatmap 的"物体中心是一个点"这个先验与类别无关。代价也有：热图峰值分辨率受 BEV 格子限制（0.2~0.5 m 一格），比 anchor 头更依赖 offset 回归的精度——这就是 1.3 节表格里偏移头存在的理由。

1.2 热图与损失公式

热图头对类别 kkk 输出一张与 BEV 特征图同分辨率的图 Y^(k)∈[0,1]H×W\hat{Y}^{(k)} \in [0,1]^{H \times W}Y^(k)∈[0,1]H×W。监督信号是在每个真值中心 ppp 处画一个高斯斑：

Y(k)[p]=exp⁡(−∥p−pgt∥22σ2)Y^{(k)}[p] = \exp\left( -\frac{\|p - p_{gt}\|^2}{2\sigma^2} \right) Y(k)[p]=exp(−2σ2∥p−pgt​∥2​)

这个公式在干什么：真值中心处 Y=1Y = 1Y=1，随距离按高斯衰减到 0，σ\sigmaσ 控制斑的胖瘦（常与目标尺寸挂钩）。用"软斑"而不是"单点 1"训练，是为了容忍"中心预测偏 1~2 个像素"的样本不至于被一票否决——网络学的是"离中心多近"，而不是"是不是恰好压在中心上"。

训练用 focal loss 变体（CenterNet 同款）：

L=−1N∑p{(1−Y^p)αlog⁡Y^pYp=1(1−Yp)β Y^pαlog⁡(1−Y^p)Yp<1L = -\frac{1}{N}\sum_{p} \begin{cases} (1-\hat{Y}_p)^\alpha \log \hat{Y}_p & Y_p = 1 \\ (1-Y_p)^\beta\, \hat{Y}_p^\alpha \log(1-\hat{Y}_p) & Y_p < 1 \end{cases} L=−N1​p∑​{(1−Y^p​)αlogY^p​(1−Yp​)βY^pα​log(1−Y^p​)​Yp​=1Yp​<1​

这个公式在干什么：NNN 是真值中心数（归一化用）。正样本处（Yp=1Y_p=1Yp​=1）给"自信的漏检"（Y^\hat YY^ 小）施加重罚 (1−Y^)α(1-\hat Y)^\alpha(1−Y^)α；负样本处（Yp<1Y_p<1Yp​<1）用 (1−Yp)β(1-Y_p)^\beta(1−Yp​)β 降低"离中心很远的背景"的权重，防止海量易分背景淹没稀疏正样本。α,β\alpha, \betaα,β 通常取 2——这是关键点检测里"正负样本极度不平衡"的标准解法（一张 BEV 图上正中心只有几个，背景几万个）。

1.3 峰值处的回归头

在热图峰值处，其余属性由并行的回归头输出（每个头都是 1×1 卷积）：

回归头 输出维度 含义
偏移 offset 2 峰值格子到真实中心的亚格偏移 (Δx,Δy)(\Delta x, \Delta y)(Δx,Δy)——热图分辨率有限（每格 0.2~0.5m），量化误差用这个小头补回来
高度 hhh + 底面 zzz 2 物体高度与底面高度（pillar/voxel 特征里 z 被平均了，必须显式回归）
尺寸 (w,l)(w, l)(w,l) 2 直接回归宽长（不 encode 成 exp，BEV 中尺寸动态范围比 2D 图像小）
朝向 yaw 2+1 回归 (sin⁡Δθ,cos⁡Δθ)(\sin\Delta\theta, \cos\Delta\theta)(sinΔθ,cosΔθ) + 朝向 bin 分类——角度有 2π2\pi2π 周期性，直接回归一个数会让 −π-\pi−π 和 π\piπ 的样本互相打架，sin/cos 编码消除跳变
速度 (vx,vy)(v_x, v_y)(vx​,vy​) 2 下一小节的灵魂：预测物体在 BEV 平面的速度（m/s）

解码时：热图经 3×3 max-pooling 后取局部峰值（置信度 > 0.1），每个峰值读出全部回归量，拼成 7 自由度框 + 速度。整个过程没有任何 NMS 前的 anchor 排列组合，输出数量 = 峰值数量。

两个监督细节（实现时最常问的）：① σ 与目标尺寸挂钩——CenterPoint/CenterNet 的做法是让高斯斑半径约等于"目标框在 BEV 上能容许几个格子的偏移仍与真值 IoU ≥ 0.7"，大车斑大、行人斑小，这把"检测容差"直接编码进了监督；② 多个目标的高斯斑重叠时取 max 而不是相加——相邻两辆车的斑重叠区域若相加可能超过 1 甚至形成假峰，逐点取 max 保证监督永远 ≤ 1、峰的结构不被破坏。

动手验证：第 3 节代码用 NumPy 生成两个目标的高斯热图、提取峰值、解码 7-DoF 框，并模拟"按预测速度外推中心 + 贪心最近点匹配"。预期峰值数 = 目标数 = 2，匹配全部正确。

1.4 速度头与跟踪：为什么能"贪心最近点"

跟踪（tracking）传统上要算外观特征（Re-ID 向量）做数据关联。CenterPoint 的洞察：检测头顺手预测了速度，那么上一帧的中心 + 预测速度 × 帧间隔 = 这一帧中心的预测位置；把上一帧目标与"本帧检测中心"按最近距离贪心配对即可。数学上：

c^t=ct−1+vt−1⋅Δt,match(i)=arg⁡min⁡j∥c^t(i)−ct(j)∥\hat{c}_t = c_{t-1} + v_{t-1} \cdot \Delta t, \qquad \text{match}(i) = \arg\min_j \|\hat{c}_t^{(i)} - c_t^{(j)}\| c^t​=ct−1​+vt−1​⋅Δt,match(i)=argjmin​∥c^t(i)​−ct(j)​∥

这行式子在干什么：c^t\hat c_tc^t​ 是用上一帧状态外推的预测中心，arg⁡min⁡j\arg\min_jargminj​ 在本帧所有检测中心里找离它最近的。由于热图中心没有 NMS 抑制带来的 ID 切换、速度头显式建模运动，这个"零外观特征"的跟踪在 nuScenes 跟踪榜上当时直接拿下第一（论文摘要：单模型 63.8 AMOTA，nuScenes 检测与跟踪双榜最优；论文正文：跟踪阶段"runs in a negligible time, 1ms on top of detection"——在检测之上只加 1 ms）。直觉：对 10Hz 激光雷达，两帧间隔 100ms，车速 10m/s 中心才移动 1m，而相邻两辆车的中心间距通常 > 2m——运动预测本身就把匹配问题变得近乎平凡。

1.5 两阶段 CenterPoint

一阶段 CenterPoint 用的是 BEV 特征图上的单点特征（峰值处那一个向量）回归整辆车——对大目标粗糙。两阶段（two-stage）版本在检测后，用预测框的 3D 中心在多尺度 BEV 特征图上做点特征双线性插值采样，把对应位置的特征提出来，过几个轻量 MLP 精修位置、尺寸与朝向，并额外预测一个框质量置信度。最终打分规则（论文原公式）：

Q^t=Y^t⋅I^t\hat{Q}_t = \sqrt{\hat{Y}_t \cdot \hat{I}_t} Q^​t​=Y^t​⋅I^t​​

这个公式在干什么：Y^t\hat Y_tY^t​ 是一阶段热图置信度，I^t\hat I_tI^t​ 是二阶段新预测的框质量分——它的训练目标被设计成 I=min⁡(1,max⁡(0, 2⋅IoU−0.5))I = \min(1, \max(0,\ 2 \cdot \text{IoU} - 0.5))I=min(1,max(0, 2⋅IoU−0.5))，即"预测框与真值的 IoU 达到 0.5 以上才开始给正分、0.75 拉满"的连续打分。两个置信度取几何平均（等价于各取平方根再相乘）：一阶段置信度高但框质量烂的预测会被压分。几何平均的脾气是"偏心弱者"——两者必须都高，分数才高。

在哪里有效（以论文实验为准）：两阶段精修在 Waymo 上带来明显提升；在 nuScenes 上论文明确报告"两阶段未能超越单阶段"。论文最终报告的 nuScenes test 成绩 65.5 NDS / 63.8 AMOTA 来自**单模型（一阶段、voxel 骨干）**的 CenterPoint。验证集上单阶段参考值：voxel 骨干 64.8 NDS、pillar 骨干 60.2 NDS（论文 Table 6）。读 MODEL ZOO 时不要把"两阶段 = 更高 NDS"当成普适结论——它是一个数据集相关的增益。

2. 算法谱系：四条技术路线对比

先把第 2 周的 shape 链接到本章：PointPillars 输出的伪图像 (C,H,W)(C, H, W)(C,H,W) 经 2D backbone 后是一张 BEV 特征图——CenterPoint 的热图头就画在这张图上。所以 CenterPoint 论文里骨干写 “VoxelNet” 还是 “PointPillars”，指的是"BEV 特征图怎么来的"，与"热图头怎么解码"是两个正交的设计维度。

路线 代表模型 核心思想 优点 缺点 适用
Point-based（点基） PointRCNN（CVPR 2019）、3DSSD 直接在原始点上提特征，从语义点生成 3D 框 最大限度保留几何精度，不丢点 点数大时慢，工程部署难 精度导向研究
Voxel-based（体素基） VoxelNet（CVPR 2018）、SECOND（Sensors 2018）、Voxel R-CNN（CVPR 2021） 体素化 + 稀疏 3D 卷积 完整 3D 结构信息，精度上限高 需要稀疏卷积算子，部署门槛高 车端算力充足、追求精度
Pillar-based（柱体基） PointPillars（CVPR 2019）、CenterPoint（点云版骨干兼容 pillar/voxel 两种） 柱体化 + 纯 2D 卷积 快（62 Hz 级）、部署友好、无特殊算子 丢失 z 维结构，精度略低于 voxel 量产首选
Transformer-based DETR3D（CoRL 2021）、后续 BEV 系列 多相机图像 + 3D object query 通过 3D→2D 投影从图像采样特征 纯视觉（不依赖激光雷达），端到端集合预测 精度仍依赖图像质量，算力需求大 视觉为主方案（详见 Stage 5 BEV）

读表要点：

  • 这四条是特征提取的路线之争，检测头（anchor / heatmap）可以交叉组合——CenterPoint 论文的骨干既接 voxel 也接 pillar；
  • PointRCNN 一句话：从原始点云直接生成 3D proposal（前景点分割 + 框回归两步），是 point-based 的代表作，精度高但逐点处理慢；
  • Voxel R-CNN 一句话：在 SECOND 稀疏体素骨干上补一个"体素集合上做 RoI 特征池化"的两阶段精修，把两阶段精度拉到接近 point-based 而速度保持在 voxel 量级；
  • DETR3D 一句话：把 DETR 的 object query 引入多相机 3D 检测——每个 query 在 3D 空间有个参考点，投影回各相机图像用 2D 特征更新自己，最后解码出 3D 框；它开启的 BEV Transformer 路线是 Stage 5 的正主，本阶段知道"纯视觉也能出 3D 框"即可。

怎么选（决策小结）：给出三条常用判据——① 目标是否需要精确的 z 结构（多层/悬空场景 → voxel）；② 车载芯片有没有稀疏卷积算子支持（没有 → pillar）；③ 有没有激光雷达（没有 → Transformer/纯视觉路线）。三条判据都有例外，但作为初筛足够。

4. 单模态 3D 检测的局限：为什么还有 Stage 4 和 Stage 5

纯点云检测做到了"快且准"，但天花板清晰可见：

  1. 远距离小目标：50m 外的行人只命中几十个点，点云特征不足以可靠检出——而相机在远距离上纹理信息远比几十个点丰富；
  2. 反光/透明/遮挡：玻璃幕墙、黑色吸光车漆在激光雷达上近乎隐形（intensity 极低或无回波）；相机看得见却测不出距离；
  3. 语义细节：点云没有颜色纹理，“警车还是出租车”"包装箱还是石头"这类问题图像一望便知；
  4. 瞬时失效：雷达脏污、雨雪散射会让单一模态整帧崩溃，安全架构要求多模态冗余。

这四个局限分别指向两条出路：多传感器融合（相机补语义与远距、激光补距离与几何、毫米波补速度与恶劣天气——Stage 4 的主题），以及BEV 统一表示（把所有模态投影到统一的鸟瞰图空间里做检测与融合——Stage 5 的主题）。CenterPoint 的 BEV 热图表示正是 Stage 5 BEV 时代的直接入口：当你把相机特征也"画"进 BEV，CenterPoint 的热图头可以直接吃多模态特征。

5. 常见坑

  1. yaw 的 sin/cos 回归解码：Δθ=atan2(sin⁡,cos⁡)\Delta\theta = \text{atan2}(\sin, \cos)Δθ=atan2(sin,cos) 求回来后要加朝向 bin 才是完整角度；只用一个 atan2 会丢 180°（车头车尾不分）。
  2. 峰值阈值过高漏检小目标：远处行人热图峰值可能只有 0.2~0.3，阈值卡 0.5 直接漏掉——部署阈值要按类别和距离分档。
  3. 速度头监督需要前后帧标签：速度不是单帧标注能提供的，训练数据必须有连续帧且做目标级关联（nuScenes 有，KITTI object 单帧没有）——跨数据集迁移时速度头可能"无师可从"。
  4. 贪心匹配的顺序敏感：目标密集时先匹配谁会影响结果（论文按距离从小到大贪心）；高密度场景要升级到匈牙利算法，但那已经超出 CenterPoint 论文的范围。
  5. 混淆 CenterPoint 的两个"两阶段"：两阶段精修（1.5 节）与 voxel/pillar 两种骨干是正交的设计维度，读 MODEL ZOO 表格时别把 “CenterPoint-vg”（voxel 两阶段）当成一个独立结构。

6. 延伸思考题（含解析）

Q1：CenterPoint 的热图为什么按类别分通道，而不是一张热图所有类别共享？
A：共享热图时同一位置可能同时是"行人中心"和"骑行者中心"（重叠类），单通道无法表达多峰竞争；分类别热图让每个类独立学峰值，代价是输出通道数 × 类别数，可接受。

Q2：为什么热图监督用高斯斑而不是单点？
A：单点监督下，预测偏 1 格的样本与预测偏 20 格的样本在监督上同样是错的，梯度信号过 harsh 且正样本极稀疏；高斯斑给了"接近程度"的连续度量，训练稳定。

Q3：速度头预测的是 (vx, vy) 两个 BEV 速度，为什么不预测 vz？
A：路面目标 vz ≈ 0（车不会垂直起飞），且相邻帧点云的 z 噪声远大于速度信号；省掉的维度既是先验也是降噪。

Q4：把 CenterPoint 的贪心跟踪用在两条平行车道上等速同向的两辆车上，会出错吗？
A：不会错配——两车中心距 > 3m，一帧内位移 < 1m，各自预测中心离自己的实际中心远小于离邻车中心。会出错的是：目标近距汇入/汇出（如超车并线），此时需要外观或航向信息辅助。

Q5：如果把 BEV 格子从 0.2 m 加粗到 0.8 m 来省算力，CenterPoint 与 anchor 头各受什么影响？
A：两者共享的 BEV 特征图都变粗，空间信息都变糊。CenterPoint 受伤更重：峰值只能定位到 0.8 m 一格，中心误差下限从 ~0.1 m 涨到 ~0.4 m，nuScenes 的 0.5 m 档 mAP 直接受损，offset 头要补的量化误差也更大；anchor 头的框尺寸与 anchor 网格解耦（anchor 中心粗一点，回归量可跨格），受损相对小。这是"heatmap 头更依赖特征图分辨率"的具体表现。
