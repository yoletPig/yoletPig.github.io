uv 系列教程：一个工具统一 Python 工具链

面向被 Python 环境与依赖问题折磨过的学习者：pip、venv、virtualenv、pyenv、pip-tools、pipx、poetry……每样都要学、彼此要配合、坏了不知道怪谁。uv（Astral 出品、Rust 编写）用单一工具替换了这条工具链，并把速度提升了一个数量级（官方口径 10~100 倍）。
事实基准：uv 由 Astral（Ruff 的作者团队）开发，2024 年 2 月发布；本系列按 uv 当前稳定版命令面编写，细节以官方文档为准——uv 迭代很快，以文档为准是本系列反复强调的原则。

学习路径

篇 主题 你将学会
01-uv是什么与安装 定位、安装、新旧映射 一张"旧工具 → uv 命令"对照表，替换决策
02-项目管理基础 init/add/sync/lock/run 以 pyproject.toml 为中心的标准项目流
03-依赖管理与锁文件 uv.lock、版本约束、groups/extras 可复现依赖图的机制与团队协作纪律
04-Python版本与虚拟环境 python install/pin、venv 让"环境问题"从玄学变成确定操作
05-uvx与工具管理 uvx、tool install 一次性工具与常驻 CLI 的正确姿势
06-工作区与monorepo workspaces Cargo 式多包仓库的搭建与依赖共享
07-脚本与单文件程序 PEP 723、run --with 依赖内嵌的单文件脚本，替代"环境小抄"
08-迁移CI与团队落地 从 pip/Poetry 迁移、CI 缓存、发布 老项目接入、流水线提速、uv publish、决策清单

阶段划分

  1. 上手（01–02）：装上、建项目，覆盖 80% 的日常。
  2. 依赖工程（03–04）：锁文件与 Python 版本——可复现性的两根支柱。
  3. 效率与规模化（05–07）：工具运行、monorepo、单文件脚本。
  4. 落地（08）：把 uv 带进老项目与团队。

与本仓库其他系列的衔接

  • Git 系列：uv.lock 与 pyproject.toml 必须提交、uv 自身的缓存目录不提交——"哪些文件入库"的决策表在 Git 02 篇；
  • 量化投资系列：其"数据层/策略层"分层的项目骨架，可直接用 02 篇的 uv init 搭建；
  • Agent 系列：生产部署篇强调"依赖锁定 + 版本化部署"，uv.lock 就是 Python 侧的实现载体。
