设计模式与架构系列教程：从代码模式到系统架构

面向"能写代码，但面对变化时不知道怎么组织代码"的初学者。前一阶段学设计模式（类与对象层面的可复用方案），后一阶段学软件架构（系统层面的结构决策）。全系列基于 GoF 经典定义、《设计模式之禅》式的中文语境解读，以及《Fundamentals of Software Architecture》等公认架构著作，关键出处均已标注。

学习路径

篇 主题 你将学会
01-为什么需要设计模式 变化、耦合与抽象 理解模式解决的本质问题，摆脱"背模式"式学习
02-SOLID原则 五大面向对象原则 用原则判断代码"好不好"，而不是用感觉
03-创建型模式 工厂/建造者/单例/原型 对象创建的解耦
04-结构型模式 适配器/装饰器/代理/外观等 组合类与对象的套路
05-行为型模式-上 策略/观察者/命令/模板方法 对象间职责分配（最常用的一半）
06-行为型模式-下 状态/迭代器/中介者/责任链等 剩余模式与"模式滥用"反思
07-架构思维入门 架构师的第一课 架构定义、架构决策、trade-off 分析
08-核心架构模式 分层/模块化单体/微内核/事件驱动 常用架构风格的选择逻辑
09-架构质量属性与演进 性能/可用性/可演进性 非功能需求如何塑造架构
10-架构实战-演进一个系统 综合案例 从单体到模块化到服务化的完整推演
11-进阶-模式综合实战-重构案例 重构实战 从 400 行烂模块出发，用 6 个模式完成重构——包括"为什么不用某些模式"的论证
12-进阶-API设计与契约管理 API 工程 资源建模、兼容性判别表、破坏性变更流程、契约测试与团队治理
13-进阶-数据架构与一致性 数据工程 存储选型框架、隔离级别的准确理解、Saga/事务性发件箱、缓存治理
14-进阶-大型系统风格案例剖析 案例内化 用本系列眼光拆解 Redis/Kafka/PostgreSQL/SQLite 的公开设计与取舍

阶段划分

  1. 代码设计（01–06）：原则 + 23 个 GoF 模式中的重点 14 个（未展开的模式会指路）。
  2. 系统架构（07–10）：从"这段代码怎么写"上升到"这个系统怎么长"。
  3. 进阶篇（11–14）：真实工程纵深——重构实战、API 契约、数据一致性、著名系统案例剖析。基础篇对应章（04/08/09）先读，进阶章才有落点。

学习建议

  • 每个模式问三个问题：它解决什么变化？不用它会怎样？它的代价是什么？（第三问最常被忽略）
  • 模式是词汇表不是语法：读到能认出"哦这是装饰器"即可，不要为了用而用；
  • 与本仓库 C++ 系列互为补充：C++ 篇讲语言机制，本系列讲组织方式；例如 04 篇装饰器与 C++ 06 篇移动语义组合出零成本包装，03 篇单例的线程安全实现在 C++ 12 篇有对应。

参考书目（贯穿全系列）

  • GoF, Design Patterns: Elements of Reusable Object-Oriented Software（1994，模式定义与 23 模式分类的原典）
  • Robert C. Martin, Agile Software Development: Principles, Patterns, and Practices（2002，SOLID 的系统阐述）
  • Mark Richards & Neal Ford, Fundamentals of Software Architecture（O’Reilly, 2020；架构定义、"架构决策"与"质量属性"框架）
  • Sam Newman, Monolith to Microservices（O’Reilly, 2019，演进式拆分策略）
