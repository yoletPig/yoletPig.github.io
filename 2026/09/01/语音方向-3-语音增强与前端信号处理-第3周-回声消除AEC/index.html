第 3 周教程：回声消除（AEC）

本周要回答的四个问题

  1. 免提通话里那个"自己的声音又回来了"的回声，物理上是怎么产生的？
  2. 自适应滤波器如何用远端参考信号估计回声路径？NLMS 的步长为什么那样归一化？
  3. 双讲（Double-talk）时为什么必须冻结滤波器更新？不冻结会发生什么灾难？
  4. 线性滤波消不掉的残余回声，NLP/RES 怎么收尾？为什么 AEC 是 WebRTC 里最难的模块？

对应学习计划：第 3 周。交付物：手写时域 NLMS 回声消除器（频域 PBFDAF 为延伸阅读），合成回声数据，画回声路径收敛曲线（ERLE 随时间）；对照 WebRTC AEC3 差距清单自检。

1. 第一性原理：回声是"扬声器声音被麦克风重新采集"

1.1 物理成因

免提/会议场景中，远端语音 x[n]x[n]x[n]（far-end，对方说话）从扬声器播出，经房间传播后被麦克风重新采集，与本地说话人语音 s[n]s[n]s[n] 一起传回给远端——对方就听到了自己声音的延迟版本，即回声。

1.2 数学模型

麦克风采集信号：

d[n]=s[n]+∑k=0L−1h[k] x[n−k]⏟回声+v[n]d[n] = s[n] + \underbrace{\sum_{k=0}^{L-1} h[k]\, x[n-k]}_{\text{回声}} + v[n] d[n]=s[n]+回声k=0∑L−1​h[k]x[n−k]​​+v[n]

这个公式在干什么：麦克风在时刻 nnn 收到的声音是三股来源的叠加。逐符号拆开：

  • d[n]d[n]d[n]：麦克风信号（desired，含回声）——自适应滤波器要"修正"的对象；
  • x[n]x[n]x[n]：远端参考信号（扬声器播的，我们已知——这是 AEC 能成立的关键）；
  • h[k]h[k]h[k]：回声路径（房间 + 扬声器 + 麦克风的脉冲响应），长度 LLL 可达数百毫秒；
  • s[n]s[n]s[n]：近端语音（本地说话人）；v[n]v[n]v[n]：噪声。

那个求和式 ∑kh[k]x[n−k]\sum_k h[k]x[n-k]∑k​h[k]x[n−k] 就是卷积：当前麦克风里的回声，不只是"此刻播的声音"，而是过去 LLL 个时刻播出的声音各自经房间反射、按不同强度（h[k]h[k]h[k]）衰减后的总和。类比合唱团：你（麦克风）听到的是对方（扬声器）过去 300 ms 内唱出的每一句、各自拖着不同混响尾巴的叠影。AEC 的任务：已知歌词 xxx，反推出"混响规律" hhh，再合成出回声减掉。

目标：用已知的 x[n]x[n]x[n] 估计回声 h^∗x\hat{h} * xh^∗x，从 d[n]d[n]d[n] 里减掉，留下 s[n]s[n]s[n]。

1.3 核心难点：双讲

当本地说话人同时说话（s[n]≠0s[n] \neq 0s[n]=0），麦克风信号里既有回声又有近端语音。此时若继续用 d[n]d[n]d[n] 去更新滤波器 h^\hat{h}h^，近端语音 s[n]s[n]s[n] 会被当成回声路径的一部分"学进去"，污染 h^\hat{h}h^，导致回声消不干净甚至发散。这就是双讲（double-talk）问题——AEC 的灵魂难题。

类比：自适应滤波器像一个学做菜的学生，唯一的反馈是"成品好不好吃"（误差 eee）。只要厨房里只有一种食材（回声），差评就能准确指导改进；可一旦有人往锅里乱加调料（近端语音），学生把差错全归咎于自己的手法，把好好的手艺改坏——这就是污染。所以"有人加调料时（双讲）必须停止学习"。

2. 自适应滤波：估计回声路径

2.1 LMS / NLMS

用滤波器 h^[k]\hat{h}[k]h^[k] 卷积参考信号 xxx 得到回声估计 y^[n]=∑kh^[k]x[n−k]\hat{y}[n] = \sum_k \hat{h}[k] x[n-k]y^​[n]=∑k​h^[k]x[n−k]，误差信号：

e[n]=d[n]−y^[n]e[n] = d[n] - \hat{y}[n] e[n]=d[n]−y^​[n]

这个公式在干什么：e[n]e[n]e[n] 是"麦克风实际听到的"减去"按当前估计应该出现的回声"。理想情况下它只剩近端语音 + 噪声；估计不准时它还混着残余回声。e[n]e[n]e[n] 是唯一可用的反馈信号——一切自适应都围绕"让残余回声从 eee 里消失"。

LMS（Least Mean Squares，最小均方）按梯度下降更新滤波器：

h^[k]←h^[k]+μ e[n] x[n−k]\hat{h}[k] \leftarrow \hat{h}[k] + \mu\, e[n]\, x[n-k] h^[k]←h^[k]+μe[n]x[n−k]

这个公式在干什么：误差 e[n]e[n]e[n] 大，说明当前路径估得不准；往哪个方向修？梯度告诉我们：哪个抽头 kkk 此刻的输入 x[n−k]x[n-k]x[n−k] 越大，它对误差的"贡献嫌疑"就越大，就越该被 e[n]e[n]e[n] 推动修正。μ\muμ 是学习率。类比蒙眼调音台：误差是"观众的嘘声"，x[n−k]x[n-k]x[n−k] 是"这路推子刚刚推了多少"，嘘声越大、刚才推得越猛的那一路，越要往回拉。

NLMS（Normalized LMS，归一化 LMS）——用参考信号能量归一化步长，消除输入幅度影响：

h^←h^+μ∥x∥2+δ e[n] x\hat{\mathbf{h}} \leftarrow \hat{\mathbf{h}} + \frac{\mu}{\|\mathbf{x}\|^2 + \delta}\, e[n]\, \mathbf{x} h^←h^+∥x∥2+δμ​e[n]x

为什么分母必须是 ∥x∥2\|\mathbf{x}\|^2∥x∥2（本周自测题）：LMS 的实际步幅 = μ⋅e⋅x\mu \cdot e \cdot xμ⋅e⋅x——输入越大步子越大。大音量时一步迈过头来回震荡（发散），小音量时又挪得极慢（学不会）。除以当前参考向量能量 ∥x∥2\|\mathbf{x}\|^2∥x∥2，等于"按音量归一化的步幅"：无论对方说多大声，每次修正都是"相对音量的一小步"。小例子：μ=0.5\mu=0.5μ=0.5、∥x∥2=100\|\mathbf{x}\|^2=100∥x∥2=100（大声）时实际步幅系数 0.005；∥x∥2=1\|\mathbf{x}\|^2=1∥x∥2=1（耳语）时系数 0.5——自动缩放。δ\deltaδ 是防除零的小常数。μ∈(0,2)\mu \in (0,2)μ∈(0,2) 保证收敛（理论稳定界），实际取 0.5-1：μ\muμ 越接近 2 收敛越快但残留的"梯度噪声"越大。

为什么频域做（FDAF，Frequency-Domain Adaptive Filter）：回声路径 LLL 很长（几百毫秒 = 数千抽头），时域 NLMS 每个样本要 O(L)O(L)O(L) 次乘加，CPU 吃不消。频域用 FFT 把循环卷积变成逐 bin 相乘，每个块（如 LLL 样本）只需 O(Llog⁡L)O(L\log L)O(LlogL)，摊到每样本约 O(log⁡L)O(\log L)O(logL)。工程上常用分块版本 PBFDAF（Partitioned-Block Frequency-Domain Adaptive Filtering）：把长路径切成若干子块分别频域更新，兼顾延迟与效率。

2.2 ERLE：回声抑制效果指标

ERLEdB=10log⁡10E[d2]E[e2]\text{ERLE}_{\text{dB}} = 10\log_{10} \frac{\mathbb{E}[d^2]}{\mathbb{E}[e^2]} ERLEdB​=10log10​E[e2]E[d2]​

这个公式在干什么：ERLE（Echo Return Loss Enhancement，回声抑制增益）= “滤波前回声能量 / 滤波后残余能量”——被消掉的回声有多少 dB。注意它只在纯回声段（近端闭嘴）测量才有意义：此时 ddd 就是回声本身，eee 是残余；若在双讲段测，eee 里近端语音占主导，ERLE 自然低，不代表 AEC 变差了。ERLE 越大回声消得越干净。收敛曲线 = ERLE 随时间上升，是本周交付的核心图。

2.3 双讲检测与冻结

双讲期间冻结更新：

这套逻辑在干什么：把 1.3 节的"学生学做菜"类比变成代码——检测到"锅里可能进了别的食材"就暂停学习，保住已学到的路径估计。工程上常配一个保持期（hangover）：触发一次双讲后继续冻结几十毫秒，因为双讲是连续语句而非孤立样本。

双讲检测（DTD，Double-Talk Detection）的常用判据：

  • 能量检测：滤波器已收敛后，误差能量突然远超"回声估计的能量"——多出来的能量只能来自新声源（近端）。实现简单，是本节代码采用的方案（需配收敛门控：滤波器还没收敛时误差本来就大，不能误判为双讲——否则永远不收敛）；
  • Geigel 检测器：经典判据 ∣d[n]∣>τ⋅max⁡(∣x[n]∣,…,∣x[n−L+1]∣)|d[n]| > \tau \cdot \max(|x[n]|,\dots,|x[n-L+1]|)∣d[n]∣>τ⋅max(∣x[n]∣,…,∣x[n−L+1]∣)（τ\tauτ 常取 0.5，假设回声路径损耗至少 6 dB）；
  • 更先进：相干性检测、卡尔曼滤波（把"路径是否突变"建成状态估计，无需硬冻结，WebRTC AEC3 一脉即此思想）。

3. 实现与验证（交付核心）

3.1 合成回声数据

为什么要把路径能量归一化：扬声器到麦克风有声学损耗，回声能量必然低于远端信号（典型 -6 ~ -15 dB）。如果不做归一化，随机生成的 hhh 可能让"回声比远端还响 18 dB"——物理上荒谬，而且会让后面按远端能量校准的双讲检测全部失灵。

3.2 时域 NLMS 回声消除（教学版）

这段代码的两处关键设计（都是初学者实现 AEC 最容易踩的坑）：

  1. 收敛门控：dtd_on 的作用是防止"滤波器还没学走路就被禁止迈步"。若一开始就按"误差大 → 双讲"冻结（误差大恰恰是没收敛的表现！），滤波器会永远停在 h^=0\hat{h}=0h^=0。所以先让滤波器自适应，直到它解释了至少一半的麦克风能量，才允许冻结机制介入；
  2. 保持期 hangover：双讲是连续语句。逐样本触发/解冻会让滤波器在语句的音节间隙"偷学"近端，污染缓慢累积。触发一次冻结 100 ms 更安全。

3.4 WebRTC AEC3 对照（认知目标）

先泼冷水：完整的 AEC3 目前没有维护良好的纯 pip 安装方案。webrtc-noise-gain 这个包只封装了 NS + AGC + VAD（不含 AEC）；PyPI 上的 webrtc-audio-processing 绑定（0.1.3）基于老版本 C++ 库（约 2016 年的 v0.3，对应老 AEC 而非 AEC3），且对新版 Python 兼容性差。要真正跑 AEC3，需要自行编译 freedesktop 的 webrtc-audio-processing C++ 库（≥1.0 版含 AEC3）并写绑定，或用桌面端 WebRTC 生态。因此本节以"对照认知"为目标，不要求跑通。

对照结论（面试可用）：你的教学版能让你理解原理，但工业级（WebRTC AEC3）在延迟估计、双讲鲁棒、残余抑制、非线性路径四方面全面更强——这正是"为什么 AEC 是 WebRTC 最难模块"。

4. 工程权衡与失效模式

4.1 权衡

  • 滤波器长度：长 → 能建模长回声路径，但计算与收敛慢；短 → 反之。需覆盖房间实际混响时长；
  • 步长 μ\muμ：大 → 收敛快但不稳；小 → 稳但慢。0.5-1 常用；
  • 双讲检测灵敏度：太灵敏 → 频繁冻结、收敛慢；太迟钝 → 污染滤波器。

4.2 失效模式

  1. 双讲污染：冻结失效，近端语音被学进 h^\hat{h}h^，回声残留甚至放大。定位：看双讲段 ERLE 是否骤降；修复：加强双讲检测、用卡尔曼。
  2. 延迟失配：扬声器到麦克风的延迟与参考信号 xxx 对不齐，滤波器永远学不到。定位：互相关找延迟；修复：延迟估计与对齐（WebRTC 的 delay estimator）。
  3. 非线性回声：扬声器过载产生谐波失真，线性滤波器建模不了。修复：NLP/RES 非线性后处理。
  4. 收敛慢：长路径 + 小步长导致开头几秒回声明显。修复：频域加速、合理步长。

5. 延伸思考题（含解析）

Q1：为什么 AEC 必须依赖"远端参考信号"？没有它行吗？
A：回声 = 参考信号经未知路径的卷积。已知参考 xxx，才能用自适应滤波反解路径 hhh。没有参考，退化为盲源分离/纯降噪，难度陡增且无法精准消回声。这是 AEC 与降噪的本质区别。

Q2：双讲时为什么要冻结滤波器更新？不冻结会怎样？
A：双讲时误差 eee 里含近端语音 sss，若继续更新，sss 会被当成回声路径的一部分学进 h^\hat{h}h^，污染估计，导致回声消不净甚至发散。冻结即"近端说话时不学习"，保护 h^\hat{h}h^。

Q3：NLMS 分母为什么要除以 ∥x∥2\|x\|^2∥x∥2？
A：归一化步长，消除参考信号幅度影响：参考能量大时自动减小步长防止震荡，能量小时放大步长加快收敛。使算法对输入音量鲁棒，收敛行为一致。

Q4：线性滤波后为什么还要 NLP/RES？
A：线性滤波消不掉的残余回声来自：非线性路径（扬声器失真）、路径估计误差、双讲期间的残留。NLP（非线性处理）/RES（残余回声抑制）用频谱抑制把残余压下去，是最后的收尾。

Q5：AEC 为什么要在 NS（降噪）之前？顺序颠倒会怎样？
A：AEC 假设回声是参考信号的线性卷积；若先降噪，降噪的非线性谱改动会破坏回声与参考的线性关系，AEC 无法对齐消除。所以流水线必须 AEC → NS → AGC。这是本阶段主线的硬约束。
