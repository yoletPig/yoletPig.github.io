本篇回答的问题

前置：09-函数模板。本篇所有带"预期输出"的示例都在 g++ -std=c++17 -Wall -Wextra -pedantic 下编译运行验证过，零警告。

1. 为什么需要类模板

第 09 篇的 my_min 把一个函数泛型化了。但容器类的问题更根本：int 版栈和 double 版栈连成员变量、成员函数签名都不同，函数模板帮不上忙。类模板把占位符提升到整个类的层面：

Stack<int> 和 Stack<std::string> 是两个完全独立的类——正如 std::vector<int> 和 std::vector<double> 没有任何继承或转换关系。第 07 篇用的每一个 STL 容器，本质上都是你马上要亲手写的这个东西。

2. 先看教材常见版本里的三个 bug

很多课堂笔记用"数组栈"讲类模板，代码长这样（节选，有错）：

三个坑都在下标 top 的语义上（约定 top 指向栈顶元素）：

  1. empty() 是死代码。构造时 top = 0（栈"空"却等于 0），而 top <= -1 在正常操作下永远为假——除非调用 setEmpty() 手工把 top 设成 -1。也就是说忘记调 setEmpty 的栈在弹出时会把没存过的 elem[0] 当数据返回，读未初始化内存。
  2. full() 提前一格报满（off-by-one）。top = MAXSIZE - 1 时 elem[MAXSIZE-1] 才刚被占用，这是合法的满栈状态，可 full() 在这一刻已经返回真——如果 push 里先判满，elem[MAXSIZE-1] 这个格子永远用不上，容量 10 只能存 9 个。
  3. push 是先 ++top 再写入，首元素落在 elem[1]，elem[0] 被跳过——第 2 个坑的另一半。加上 pop 返回硬编码的 0（对 T = std::string 都编译不过），这套约定自相矛盾。

修正方案其实很简单：构造时 top = -1（-1 表示空），push 先判满再 ++top，pop 先判空再取 top--，empty/full 与这个约定严格对齐。下面照此重写。

逐点讲解：

  • 两个模板参数各司其职：typename T 是类型参数（存什么），std::size_t MaxSize 是非类型模板参数（存多少）——它必须是编译期常量，编译器用它决定 elems_ 数组大小，所以零堆分配、零内存碎片，这正是嵌入式音频代码偏爱固定容量的原因。
  • 成员函数外置定义的固定格式：类内只写声明；类外 template <typename T, std::size_t MaxSize> 返回类型 Stack<T, MaxSize>::push(...)，模板参数列表和 Stack<T, MaxSize>:: 限定都要重写一遍。简单函数（empty/full/size）直接类内定义更省事，也是标准库风格。
  • 使用处的显式模板实参：类模板不能像函数模板那样从函数实参推导（构造时常常没有能反映 T 的实参），所以 Stack<int, 10> 的 <int, 10> 在 C17 前必须手写；C17 的 CTAD 只能减免"构造实参可推导"的那部分，见第 5 节。
  • 行为核对：容量 10 真的装下 10 个（旧版只能装 9 个）；空栈 pop 有明确提示而不是读垃圾。

规则总结：

  • 编译器为每个构造函数自动生成一条隐式指引，所以 Stack t(std::string("x")) 不用你写任何东西。
  • 需要改变策略（“收到 const char* 就升级成 std::string”）时才写显式指引，语法是"伪构造函数签名 -> 目标类模板实参"，放在类定义同一作用域。
  • 标准库大量使用这个机制：std::pair p{1, 2.5}、std::lock_guard lk(m) 都是 C++17 起才免写模板实参的。

7. 变参模板类：std::tuple 一句话

类模板的参数也可以是参数包：template <typename... Ts> class Tuple;。标准库的 std::tuple<int, double, std::string> 就是它——递归地"存第一个元素 + 存剩下元素的 Tuple"。第 11 篇还会见到同门的 std::variant。日常业务代码一般直接用现成的 std::tuple / std::pair，不必手写变参类，知道机制即可。

8. 实战：模板化 RingBuffer<T, N>

把本篇知识全部用上：类型参数 T（样本类型）+ 非类型参数 N（容量，编译期）+ static_assert（编译期约束）+ 位运算环形绕回。环形缓冲区是音频系统的呼吸器官——录音回调把麦克风数据生产进去，推理线程消费出去；whisper.cpp 等引擎内部的核心数据通道就是它（第 13 篇会做完整的音频实战）。

设计要点：

  • 2 的幂 + 位运算取模：(write_ + 1) & mask_ 等价于 (write_ + 1) % Capacity，但一次与运算代替除法，实时回调里关键。static_assert 把"容量必须是 2 的幂"这个前提写进编译期——传 RingBuffer<float, 6> 直接编译失败，错误发生在运行前而不是录音事故后。
  • 返回 bool 而不是抛异常：满/空是音频流的常态（生产消费速度不等），用返回值让调用方 if 处理，理由见第 11 篇。
  • 单生产者单消费者场景下这个结构可以做到无锁（配合第 12 篇的 std::atomic），是零堆分配、确定性延迟的典型模板类设计。

常见坑

  • 照抄教学版 Stack：top 从 0 起步 + empty() 判 top <= -1 + push 先 ++top，三个 bug 叠加——空栈弹出垃圾数据、容量少一格。本文第 2 节已逐条修正。
  • pop 返回 T{} 充数：return 0 对 T = std::string 编译不过；return T{} 编得过但调用方无法区分"空栈"和"存了个默认值"。正确姿势见第 11 篇的 std::optional<T>。
  • 类模板名 ≠ 类型名。C++17 之前，类模板自己的名字里必须带实参：成员函数外置定义要写 Stack<T, MaxSize>::，类内可以用注入类名 Stack。漏写 Stack<T, MaxSize> 是外置定义最高频的编译错误。
  • 以为两个模板参数必须同种。RingBuffer<float, 4> 一个是类型、一个是整数，完全独立；非类型参数只能是编译期常量（整型/枚举/指针等，浮点要 C++20）。
  • 给非类型参数传运行期变量。RingBuffer<float, n>（n 是运行期变量）编译错误——容量参与类型本身，RingBuffer<float,4> 和 RingBuffer<float,8> 是两个不同的类。
  • 模板定义放 .cpp。与函数模板同理：实例化点必须看到完整定义，否则链接期 undefined reference。类模板整体放头文件。

小结

  • 类模板把类型占位符提升到整个类；Stack<T, N> 中 N 是非类型模板参数，带来零堆分配的编译期容量。
  • 成员函数外置定义要重复模板参数列表与 类名<参数>:: 限定；成员只在被调用时实例化，错误延迟到使用点。
  • C++17：构造实参可推导时免写模板实参（CTAD）；策略特殊时写推导指引（如 const char* → std::string）。
  • 全特化服务个别具体类型；按"类型类别"分支优先用 if constexpr，一份代码胜过 N 份特化。
  • 实战 RingBuffer<T, N>：static_assert 编译期约束、位运算绕回、返回 bool 适应实时音频——whisper.cpp 等推理引擎的核心结构之一，第 13 篇实战再会。

自测题

  1. 教学版 Stack（top 从 0 起步、push 先 ++top、full() 判 top >= MAXSIZE - 1）容量 10 实际能存几个元素？为什么？
  2. Stack<std::string> 的 pop() 里写 return 0; 会怎样？写 return T{}; 的隐患是什么？
  3. RingBuffer<float, 6> 能编译吗？RingBuffer<float, n>（n 为运行期变量）呢？分别为什么？
  4. Parser<int> 有个成员函数用了 T::begin()，却编译通过了，为什么？什么时候会报错？
  5. Stack s("hello"); 在 C++17 下如何推导？若类定义了指引 Stack(const char*) -> Stack<std::string>;，与没有指引的隐式推导有何区别？

答案

  1. 9 个。push 先 ++top 使首元素落在 elem[1]，且 top 达到 MAXSIZE-1 时 full() 已为真，elem[0] 被跳过、elem[MAXSIZE-1] 永远写不进去——两头各浪费/错位一格。
  2. return 0; 直接编译失败：0 无法构造成 std::string。return T{}; 编译通过但语义有歧义——调用方拿到空串分不清"栈是空的"还是"栈里存的本来就是空串"，应返回 std::optional<T>。
  3. RingBuffer<float, 6> 被 static_assert 拒绝（6 不是 2 的幂，位掩码技巧失效）；RingBuffer<float, n> 编译失败：非类型模板参数必须是编译期常量，n 是运行期值。
  4. 成员函数只在被调用时实例化。Parser<int> 若从未调用那个成员，T::begin() 这行代码从未生成；一旦在某处以 Parser<int> 调用它，实例化时报"int 没有 begin"。
  5. 走 CTAD。没有指引时隐式指引从构造实参推出 Stack<const char*>（存裸指针，有悬空风险）；有指引时强制推导为 Stack<std::string>，构造时把 C 字符串拷贝成管理内存的 std::string。
