05-类设计与资源管理

本篇回答的问题

  • class 和 struct 差在哪？成员初始化列表为什么好于函数体赋值？
  • 深拷贝/浅拷贝怎么回事，Rule of Three / Five / Zero 各怎么写？
  • =default、=delete、explicit、const、运算符重载怎么用？
  • 综合实战：手写管理动态缓冲区的 AudioBuffer（Rule of Five）。

前置：03-内存模型与RAII、04-智能指针与所有权。带"预期输出"的示例都在 g++ -std=c++17 -Wall -Wextra -pedantic 下验证过。

1. class vs struct

两者唯一的语法区别：struct 成员默认 public，class 成员默认 private。区别在设计意图：

  • struct：没有不变式要守护的一堆数据（一帧参数包），成员开放、可用聚合初始化 RawConfig c{16000}；
  • class：有不变式要维护（“采样率必须有效”“指针非空”），数据藏起来，只暴露接口。
    语音代码里，配置结构体用 struct；引擎、解码器、缓冲区这类对象用 class。

2. 构造函数与成员初始化列表

构造函数负责"让对象出生即有效"，析构函数是 RAII 的释放点（03 篇）。这里聚焦一个细节：成员初始化列表（冒号后那一段）。它好于在函数体里赋值，因为：

  1. 函数体里是"先默认构造、再赋值"，白干一遍活；初始化列表直接一步构造到位；
  2. const 成员和引用成员只能用初始化列表，函数体赋值编译不过；
  3. 成员实际初始化顺序 = 声明顺序，与列表书写顺序无关——这是常见陷阱。

3. 拷贝：浅拷贝事故与 Rule of Three

不手写拷贝函数时，编译器自动生成逐成员拷贝。对 std::string、std::vector 这没问题；但对象里有裸指针时，逐成员拷贝只复制指针值——两个对象指向同一块内存，析构时释放两次。这是浅拷贝。

4. Rule of Zero / Rule of Five

最好的一条规则：一个特殊成员函数都不写，把资源交给会自我管理的成员（std::string / std::vector / 智能指针，见 04 篇）。

5. =default、=delete 与 explicit

= default 明确采用编译器生成的版本（写了析构后想保留默认构造时必需）；= delete 禁止某个操作，编译器替你把关；explicit 禁止单参数构造函数的隐式转换——set_gain(-3.0) 悄悄把 -3.0 变成 Decibels 往往不是你想要的，宁可编译报错。

6. const 正确性与运算符重载

const 是写给调用者的合同：const 成员函数（签名末尾）承诺不修改成员，const 对象只能调它们；const 引用参数不拷贝、只读、能接收临时对象；同名成员函数还能按 const 重载。this 在成员函数里是"当前对象自己的地址"（const 成员函数里是 const T*），operator== 就通过 *this 拿到自己。而 operator<< 的左操作数是 std::ostream，不可能是本类的成员函数，只能写成友元（有权访问 private 成员的外部函数）：

用法：std::cout << clip 直接打印对象；operator<< 返回 std::ostream&，所以能像 std::cout << clip << '\n' 一样链式调用。

8. 常见坑

  • 写了析构就丢掉隐式移动：编译器不再隐式生成移动构造/赋值，std::move 后退化为深拷贝——要么补齐 Rule of Five，要么 Rule of Zero。
  • 浅拷贝不一定马上崩：两对象共享内存可能"没事"跑很久，直到一方析构、另一方悬空；测试用 -fsanitize=address 当场抓。
  • 拷贝赋值忘记自赋值检查，或先 delete 后 new（分配失败时对象已残废）。
  • 初始化顺序想当然：列表里写 b_(a_ + 1) 不代表 a_ 先初始化——只看声明顺序。
  • explicit 忘加：隐式转换悄悄通过，单位/参数张冠李戴。
  • operator<< 试图写成成员函数：左操作数是流不是本类，必须友元或普通函数。

9. 小结

  • struct 默认 public（数据聚合），class 默认 private（有不变式）；初始化列表是"初始化"不是"赋值"，const/引用成员只能用它，实际顺序 = 声明顺序。
  • 编译器默认逐成员拷贝对裸指针是浅拷贝；手写资源就要凑齐 Rule of Three/Five，能 Rule of Zero 就 Zero。
  • =default/=delete/explicit 是精修工具，const 是调用者能依赖的合同。

10. 自测题

  1. 只手写了析构函数的类，std::move 之后会发生什么？

    答案 编译器不再隐式生成移动构造/赋值，重载决议选中拷贝构造——本想 O(1) 的移动退化成 O(n) 深拷贝。要么补齐 Rule of Five，要么 Rule of Zero。

  2. 拷贝赋值里为什么"先 new 成功、再 delete 旧内存"，而不是反过来？

    答案 若先 delete 再 new，`new` 抛 `bad_alloc` 时数据指针已悬空，对象残废。先分配成功，中途任何异常都不影响原对象完整性（异常安全的基本功）。

  3. 为什么 operator<< 不能写成 Clip 的成员函数？

    答案 成员函数的左操作数永远是本类对象（`*this`），而 `std::cout << clip` 的左操作数是 `std::ostream`。必须是友元/普通函数：`std::ostream& operator<<(std::ostream&, const Clip&)`。
