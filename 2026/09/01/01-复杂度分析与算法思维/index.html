01 - 复杂度分析与算法思维

本篇目标

  1. 掌握大 O 记号的严格定义，能区分"快"与"增长慢"这两件不同的事；
  2. 熟记常见复杂度类与它们对应的真实规模上限（n=10^5 时 O(n²) 意味着什么）；
  3. 理解摊还分析（amortized analysis）的动机：为什么动态数组 append 是 O(1)；
  4. 建立两个核心直觉：对数直觉（为什么二分是 log）与空间换时间思维。

1. 为什么先学复杂度：预判而非测量

写完代码再跑基准测试当然能知道快慢，但面试和工程里更常发生的是：你要在写代码之前判断"这个思路能不能在时限内跑完"。这就是复杂度分析的作用——它不测量，它预判。

一个工程上极有用的经验数字（经验做法，来自竞赛与工业界常见约定）：Python 每秒大约能执行 10^6 ~ 10^7 次基本操作（视操作类型与解释器版本浮动，简单整数运算取 10^7、含方法调用取 10^6 更稳妥）。据此可以估出常见时限（1 秒）下的规模上限：

复杂度 1 秒内大致能处理的 n
O(1) / O(log n) 任意（n 上限通常是数据表示范围）
O(n) 10^7 左右
O(n log n) 10^6 左右
O(n²) 3×10^3 ~ 10^4
O(n³) 200 ~ 500
O(2^n) 20 ~ 25
O(n!) 10 ~ 11

面试里这句话非常值钱：题目说 n ≤ 10^5，你立刻知道 O(n²) 出局、O(n log n) 起步——数据范围就是出题人对复杂度的提示（经验做法，算法竞赛通用常识）。

2. 大 O 的严格定义：不谈"快"，只谈"增长"

很多教程把 O(n) 说成"这个算法很快"，这是错的。严格定义（见 CLRS 第 3 章）：

定义：若存在正常数 c 与 n₀，使得对一切 n ≥ n₀ 都有 f(n) ≤ c·g(n)，则称 f(n) = O(g(n))。

拆开读三个关键词：

  1. 存在常数 c：允许常数倍误差。2n² 和 500n² 都是 O(n²)；
  2. 存在 n₀：只看足够大之后的趋势。n < 100 时 f 可能很大，无所谓；
  3. ≤（上界）：O 给的是上界。O(n) 的算法同时也"是" O(n²)——业界口头的"复杂度是 O(n²)"习惯上指最紧的已知上界（Θ，见下）。

三个常用记号，面试常考区别：

记号 含义 类比
O(g) 增长不超过 g（上界） ≤
Ω(g) 增长不低于 g（下界） ≥
Θ(g) 增长与 g 同阶（上下界夹住） =

最好情况、最坏情况、平均情况是另一根轴，别和记号混淆：快排最坏 O(n²)、平均 O(n log n)，这是对同一个算法在不同输入分布上取界；而"O 是上界"说的是记号本身的含义。面试时能主动分清这两根轴，是加分项。

提示：二分相关的循环，先问"循环变量每步怎么变"——乘 2、除 2、开方，都是对数；步长为 1 才是线性。

记住几个硬结论（CLRS 第 8 章）：基于比较的排序下界是 Ω(n log n)——所以任何"比大小排序"都不可能突破它；要更快只能不用比较（计数排序、基数排序，靠值域做文章）。这个"信息量下界"的论证方式（n! 种排列，每次比较最多提供 1 bit 信息）值得单独记住，面试常问"排序为什么最快 n log n"。

4. 摊还分析：为什么 append 是 O(1)

Python 的 list（以及 C++ 的 vector）扩容策略是：空间满了就开一块约 1.5~2 倍大的新内存，把旧元素整体搬过去。单次扩容是 O(n)，但我们说 append 的均摊复杂度是 O(1)。为什么？

定义（聚合法）：对操作序列求总代价 T(n)，均摊复杂度 = T(n)/n，即"平均到每次操作上"的代价。

设容量倍增因子为 2（倍增因子 α = 2，实际 CPython 约为 1.125 的增量模式但形式类似，见 CPython 源码 listobject.c 的 list_resize；倍增分析同理）。从容量 1 开始，连续 append n 次，搬移只发生在容量 1, 2, 4, …, 2^k 这些时刻，总搬移次数为：

n 次 append 总代价 ≤ 3n（n 次写入 + 不足 2n 次搬移），均摊 ≤ 3 = O(1)。关键在几何级数：每一项是前一项的 2 倍时，总和被最后一项支配。

摊还有三种经典方法（CLRS 第 17 章）：聚合法（上面这种，算总账）、记账法（每次多收一点"手续费"付将来的扩容）、势能法（定义一个势函数度量"欠账"）。工程上记住聚合法就够了。

陷阱：均摊 O(1) 不等于单次 O(1)。实时系统（如引擎控制循环）里一次 append 可能触发 O(n) 搬移，造成尾延迟尖刺——对策是预分配（[None] * n）或 deque 分块链。端侧推理中张量预分配的道理相同（衔接模型性能优化系列：预分配是消除延迟抖动的通用手段）。

5. 对数直觉：为什么二分是 log

对数是"指数的逆"：log₂n 回答"2 连乘几次得到 n"。n = 10^9 时 log₂n ≈ 30。每次把问题规模砍半，砍 k 次剩 n/2^k，砍到 ≤1 需要的次数就是 log₂n——这就是二分查找是 O(log n) 的全部原因（形式化推导见 06 篇）。

把 log 的尺度感建立起来（10 亿级数据）：

操作次数 能区分的状态数
10 ~10³
20 ~10⁶
30 ~10⁹
40 ~10¹²
64 ~1.8×10¹⁹（一个 uint64 的范围）

反过来的直觉同样重要：n² 的反向是 n·log n。n=10⁶ 时，n² 是 10¹²（不可行），n·log n 约 2×10⁷（轻松）——这就是"排序后预处理"这类技巧存在的原因：花一次 O(n log n)，把后面每次查询从 O(n) 降到 O(log n)。

6. 空间换时间：算法工程的第一杠杆

几乎所有"加速"手段都遵循同一个模式：用一份预先算好/存好的表，换掉重复计算。三个层级：

判断"该不该用空间换时间"的三问（经验做法）：

  1. 重复代价高吗：重复的子计算越贵（越深/越大），缓存收益越大；
  2. 内存装得下吗：表的大小 O(n) 或 O(n²)？估算字节数（1e6 个 int64 是 8MB）；
  3. 命中率有保证吗：查询分布如果永远 miss，缓存反而更慢。

这套思维直接通向：前缀和（03/12 篇）、记忆化（12 篇）、以及模型推理里的 KV Cache（衔接模型性能优化系列——本质就是"已算过的注意力结果缓存起来"）。

本篇小结

  1. 大 O 是增长阶的数学刻画，不是"快慢"的同义词；O/Ω/Θ 分别对应上界/下界/紧界，最好/最坏/平均是另一根轴；
  2. 数据范围反推复杂度上限：10^5 → n log n，10^4 → n²，20 → 2^n（经验做法）；
  3. 摊还分析回答"昂贵操作能不能便宜地平均掉"，核心是几何级数；倍增 append 均摊 O(1)，但实时系统要警惕单次 O(n)；
  4. 每次砍半 = O(log n)；30 次操作能区分 10⁹ 个状态；
  5. 空间换时间是通用杠杆：预计算查表、记忆化、KV Cache 是同一思想在不同层的名字。
