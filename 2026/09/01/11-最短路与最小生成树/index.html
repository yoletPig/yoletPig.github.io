11 - 最短路与最小生成树

本篇目标

  1. 掌握单源最短路三件套的适用边界：Dijkstra（非负权）、Bellman-Ford/SPFA（负权）、Floyd（全源）；
  2. 手写 Dijkstra（heapq 版）与 Kruskal/Prim，理解贪心在两者中成立的条件差异；
  3. 建立 A* 的启发函数直觉——自动驾驶规划算法的共同祖先；
  4. 能对任何场景回答"该用哪个最短路算法"。

1. 最短路问题地图

加权图 G=(V, E)，边权 w(e)，求从源点 s 到各点的最小代价路径。三个算法按"问什么、图长什么样"分工（CLRS 第 22–25 章）：

算法 问题 权重要求 复杂度 场景
BFS 无权单源 全 1 O(V+E) 10 篇已讲
Dijkstra 单源 非负 O(E log V)（堆版） 地图导航、网络路由
Bellman-Ford 单源 允许负权（检负环） O(V·E) 有负代价、汇率套利检测
SPFA 单源 允许负权 平均 O(k·E)（经验常数 k 小，最坏 O(V·E)） BF 的队列优化
Floyd-Warshall 全源 允许负权（检负环） O(V³) 小图全对最短路、传递闭包

为什么 Dijkstra 怕负权：它的贪心前提是"已确定的最短路不会再被更新"，负边能让"晚确定的节点"通过负边反过来改善"早确定的节点"，前提崩塌。记住这句话，四个算法的边界就全清楚了。

2. Dijkstra：贪心 + 优先队列

不变式：每次从候选集取出"当前 dist 最小"的节点 u，断言 dist[u] 已是最终最短路（非负权下，任何其他路径都要经过更远的中间节点）。候选集用什么维护？——09 篇的堆：

路径重建：松弛成功时记 prev[v] = u，结束后从终点回溯。复杂度：堆操作 O(E) 次入堆 + O(V) 次出堆，每次 O(log) → O(E log V)（惰性删除让堆里可能有陈旧条目，09 篇的懒删除惯用法正是为此准备）。优化到 O(E log V) 严格版用"decrease-key"，但 Python 无此 API，惰性删除是标准做法（经验做法）。

3. Bellman-Ford 与 SPFA

Bellman-Ford：不做贪心假设，蛮力松弛 V−1 轮——每轮把所有边都试一遍更新。正确性：最短路至多 V−1 条边（无负环时），i 轮后所有"至多 i 条边"的最短路都已确定（归纳可证，CLRS 24.1）。

SPFA（队列优化的 Bellman-Ford，中国竞赛圈流行叫法；学术名 Bellman-Ford-Moore）：只有"上一轮被更新的节点"才可能松弛别人——用队列代替全量轮次，被更新的节点入队待处理。平均很快，但被构造数据打成 O(V·E)，负权稠密图才用它，否则无脑 Dijkstra（经验做法）。

4. Floyd-Warshall：全源最短路

问题：所有点对之间的最短路。Dijkstra 跑 V 遍是 O(V·E log V)；Floyd 动态规划做到 O(V³)、代码五行（思想上是 12 篇 DP 的又一变体：dp[k][i][j] = 只允许经过中间点 1…k 时 i→j 的最短路，转移"经过 k 中转 or 不经过"）：

陷阱：k 必须放最外层循环——它是 DP 的阶段（"允许的中转点集合"逐个扩张），放里层语义就错了。这是 Floyd 唯一容易记错的地方。负环检测：结束后 dist[i][i] < 0 的节点在负环上。

5. 最小生成树：Kruskal 与 Prim

问题（LC 1584）：无向带权连通图中选 V−1 条边把所有点连通，总权最小。两个贪心，成立条件不同：

  • Kruskal：边按权排序，从小到大加入，不成环就要（用并查集判环，O(α) 近似 O(1)，CLRS 21 章）。贪心依据：割性质（cut property）——任何把点集分成两半的割中，权最小的跨割边必在某棵 MST 里。
  • Prim：从任意点开始，每次把"离已长成部分最近"的新点拉进来——Dijkstra 的亲兄弟，把"路径长"换成"单边长"。

选型：稀疏图 Kruskal（排序即可，代码短）；稠密图 Prim（邻接矩阵版 O(V²) 反而占优）。MST 的工程影子：网络布线、聚类（单 linkage）、以及 TSP 的 2-近似解（用 MST 的两倍遍历，CLRS 35 章）。

6. A*：带先知的 Dijkstra

动机：Dijkstra 均匀地向四周扩张（像水波），去往"东边 5 公里"却把西边探了个遍——浪费。A*（Hart, Nilsson, Raphael 1968；自动驾驶规划教材必引）给扩张方向加"先知"：优先级从 dist[u] 改为

h 必须可采纳（admissible，不高估真实剩余代价）——这是正确性的全部条件：估计可以悲观（绕远才到），不能乐观（以为很近实际很远），否则可能提前"确定"错误的路径。地图上 h 用欧氏/曼哈顿距离（直线距离不可能被超过，物理事实）。

直觉总结（衔接自动驾驶规划）：Dijkstra 答"从起点能到的所有地方各多远"（全局必要）；A* 答"从起点到这个终点"（目标导向，探索范围向终点收窄）。h 设计得越准（越接近真实且不高估），探索越少；h 是 0 就是 Dijkstra。Stage 5/6 里规划模块的 Hybrid A*、lattice planner 都在这一族上做扩展——本篇给的是它们的共同内核。

7. 决策表：给我场景，我给算法

场景 算法
无权图/等权最短路 BFS（10 篇）
非负权单源 Dijkstra（首选，无脑选）
有负权边、要检负环 Bellman-Ford / SPFA
所有点对、V 小（≤ 几百） Floyd
所有点对、V 大、非负权 每点跑一遍 Dijkstra
n 个点全连通且只求"连起来" Kruskal / Prim（MST）
单源单汇 + 有地理坐标 A*（Dijkstra + 启发）

本篇小结

  1. Dijkstra 贪心成立靠"非负权"，dist[u] 出堆即终值；堆版 O(E log V)，惰性删除是 Python 标准姿势；
  2. Bellman-Ford 蛮力 V−1 轮松弛换负权兼容，第 V 轮还能松弛 = 负环；SPFA 是它的队列优化，平均快、最坏同阶；
  3. Floyd 用"允许中转点 1…k"的阶段化 DP 做全源，k 在最外层；
  4. Kruskal 按边贪 + 并查集判环，Prim 按点贪 + 堆——割性质给两者背书；
  5. A* = Dijkstra + 可采纳启发 h，h=0 退化为 Dijkstra；自动驾驶规划器的共同祖先。

练习

  1. （LC 743 - 网络延迟时间）Dijkstra 模板题：所有节点收到信号的时间 = 最大 dist；顺手判不可达（返回 -1）。
  2. （LC 787 - K 站中转内最便宜的航班）带"至多 k 条边"约束——Bellman-Ford 天然适配（只跑 k+1 轮），体会 Dijkstra 为什么此处不直接适用。
  3. （LC 1584 - 连接所有点的最小费用）MST：任意两点都有边（完全图），稠密图——用 Prim 矩阵版 O(n²) 而不是 Kruskal（边数 O(n²) 排序吃亏）。
  4. （LC 1631 - 最小体力消耗路径）“路径上最大边权最小化”——用 Dijkstra 变体（dist = 路径最大边，松弛取 max）或二分答案 + BFS（06 篇），两种都写。
  5. （LC 778 - 水位上升的泳池游泳）同 1631 的"瓶颈路径"思想 + 时间轴二分或并查集按时间加边（10 篇连通分量的动态版）。
