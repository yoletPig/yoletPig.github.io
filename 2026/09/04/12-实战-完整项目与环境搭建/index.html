12 - 实战：完整项目与环境搭建

本篇目标

读完本篇，你应该能做到：

  1. 搭建一个分文件、可复现、CPU 十几秒收敛的完整 PPO 训练 Pipeline：向量化环境、GAE 缓冲区、评估回调、checkpoint、日志全齐（本章代码在真实环境跑通并给出运行结果）。
  2. 按 gymnasium 规范写出自定义环境（reset/step/seed 契约、terminated/truncated、边界情况全覆盖）。
  3. 用"不收敛 10 大原因排查表"系统化调试 RL——顺序比灵感重要。
  4. 过一遍 25 道面试高频题，检验 01–11 章的概念是否真正长在了脑子里。

本章项目在开发过程中真实踩了一个坑（向量化环境忘记自动 reset，eval 卡死在固定值），调试过程原样收录在 §6——RL 工程的真实样貌就是"跑通不难，跑对要命"。

2. 核心模块全量代码

2.1 envs.py——向量化环境（本章精华）

两个设计决定，都是"血换来的"：

  • done 后自动 reset 并返回新观测：这是所有向量库（SB3/rlpyt/tianshou）的统一契约——训练循环不该感知 reset。忘记它是本章 §6 的头号事故。
  • finals 单独传出：truncated 的 bootstrap 需要"真实末状态"，而自动 reset 把它覆盖了——不单独传，截断语义就丢了。

2.2 network.py 与 buffer.py

跨环境 GAE 的要点：每个 env 一条独立的递推链（gae 是长度 nnn 的向量），done 只截断该 env 自己的链——这是向量化相比单环境循环的实质复杂度所在。

3. 真实运行结果

python train.py --total 100000（seed=0，8 env，CPU，实测）：

三个读数，每一个都是方法论：

  1. 10k 步（1.2 秒）评估即 483——8 环境并行的吞吐优势（09 章单环境版 10 万步才 466）。
  2. train50 与 eval 长期背离（111 vs 500）且 train50 后期不升反降——不是退化：策略越好回合越长，固定 2048 步的采集窗口里能完成的回合数骤降（本实验实测：从 84 回合/批降到 17 回合/批），ep_returns[-50:] 滚动窗口里混着大量"策略还很差时"的旧回合。训练统计是滞后指标，评估才是真相——这也是 §6 排查表里"别用训练回报当进度条"的实证。
  3. checkpoints 每 10k 步一个，带 eval 分数存进 extra——崩了能回滚，调参能对比。

4. gymnasium 自定义环境规范

RL 工程里一半的 bug 源于自定义环境不符合 API 契约。最小规范模板（含全部边界情况）：

契约清单（每条都对应一类真实 bug）：

  1. 随机源唯一：一切随机用 self.np_random（super().reset(seed=) 注入），混入 np.random/random 会让 env.reset(seed=s) 的可复现性形同虚设；
  2. terminated/truncated 语义分明：真终止（任务失败/达成）vs 截断（时间上限）——01 章埋线、05/06 章事故、本章 buffer 的 finals 机制，全靠这两个标志的诚实；
  3. done 后 step 是未定义行为：不要假设用户不会多调 step；向量化封装（§2.1）负责自动 reset；
  4. obs 的 dtype/space 一致：声明 float32 就返回 float32，声明的上下界要真实（network 输入非法值会静默污染训练）；
  5. reset 必须完全重置内部状态（包括计数器、缓存、历史），隐藏的"上回合残留"是"换个 seed 就复现不出来"类 bug 的头号来源；
  6. 奖励不依赖未定义状态：终止那一步的奖励要在 terminated=True 的同一 step 里给出，不要推迟。

5. 不收敛 10 大原因排查表

按出现频率排序（“经验做法”，来自本系列全部实验 + 社区高频问题；先查 1–5 再查 6–10）：

# 症状 原因 检查/修复
1 loss 下降但 eval 恒定 target 计算没包 no_grad（06 章）或 logp_old 用当前网络重算（09 章） 检查 ratio 是否恒为 1
2 前期学得动、中期突然归零 truncated 被当 terminated 清零 bootstrap（05/06 章事故） 打印两种 done 的比例；buffer 存分开的标志
3 梯度范数巨大、eval 卡随机水平 共享主干 + MSE 价值损失量级失控（08 章实测事故） 换 Huber；查 v_loss 与 pg_loss 的量级比
4 完全不学、优势全零 GAE 递推链被 done 错误截断 / 向量化环境没自动 reset（本章 §6 事故） gymnasium 警告 “step after terminated” 必看
5 学到一半震荡加剧、发散 lr 过大 + epochs 过多；KL 飙升（09 章消融） 监控 approx_kl（健康 0.003–0.03）；降 lr
6 回报上去了但行为明显错 reward hacking / 奖励写错（10 章）：奖励与真实目标错位 人工看 10 条轨迹；检查"刷分路径"
7 每次跑结果完全不同 种子没固定全：env.reset / np / torch / python random 四处 统一 seed 注入（本章 self.rng 模式）
8 表格法不收敛（03–05 章） 终止状态被更新 / γ=1 且策略可能死循环 / θ 太小 终止状态 continue；continuing 用 γ<1
9 离线设定下学出胡乱策略 外推误差：对未见动作乐观（11 章实测） 策略约束/悲观估计；检查数据覆盖度
10 "收敛"到次优策略就躺平 熵塌缩探索死亡（08 章误区 5）或 ε 衰减过早（05 章） 监控策略熵/ε 曲线；提 ent_coef

通用诊断顺序（经验做法）：固定种子重跑 → 看梯度范数与 loss 量级 → 打印 5 条完整轨迹人工检查 → 二分法砍组件（去掉熵项/归一化/价值损失各试一次，定位引入坏处的改动）。

6. 一次真实的调试过程（本章项目开发实录）

本章 pipeline 第一版跑起来后 eval 卡死 17.2、train50=0.0。完整调试轨迹（教学价值在于"症状→定位"的推理链）：

  1. 症状：每 10k 步 eval 恒等于 17.2（分毫不差），train50 全 0。
  2. 线索一：train50 = 0.0 不可能——CartPole 每步至少 +1，只有"回合回报从未被记录"才会是 0。怀疑回合判定链路。
  3. 线索二：控制台里躺着 gymnasium 的警告——You are calling 'step()' even though this environment has already returned terminated = True。终止后没有 reset，还在对同一环境继续 step（未定义行为，状态停格，所以 eval 恒定）。
  4. 定位：SyncVecEnv.step 只是转发 step，没有任何 done 后 reset 逻辑；collect 也没有。
  5. 修复：step 契约改为"done 后自动 reset + finals 传出真实末状态"（§2.1 现版）；同步修 buffer 的 last_obs 三分支（term/trunc/进行中）。
  6. 验证：重跑 100k 步 → eval 10k 步到 483、61k 步满分（§3 结果）。
  7. 附带收获：修复后还发现 train50 后期下降的"假象"（§3 读数 2），顺带把"训练统计滞后"写进了方法论。

教训：RL 的静默失败远多于报错失败——terminated 后继续 step 不抛异常、obs 停格不告警、advantage 全零 loss 照样下降。永远读环境库的 warning，永远打印一批数据人眼过一遍。

7. 面试高频 25 题（带要点）

基础概念

  1. RL 与监督学习的本质区别？→ 数据分布由策略决定/奖励延迟/无正确答案只有分数（01）。
  2. MDP 五元组与马尔可夫性？→ (S,A,P,R,γ)(S,A,P,R,\gamma)(S,A,P,R,γ)；历史无关；不满足时帧叠加/RNN（01）。
  3. 折扣因子的两重身份？→ 收敛保证 + 视野旋钮（视野 ≈ 1/(1−γ)1/(1-\gamma)1/(1−γ)）（01）。
  4. episodic vs continuing，terminated vs truncated？→ 后者是工程口径：截断不清零 bootstrap（01/05）。
    5.贝尔曼期望方程与最优方程的差别？→ 策略平均 vs max；线性 vs 非线性（03）。

表格法

  1. MC 与 TD 的偏差-方差？→ MC 无偏高方差、TD 有偏差低方差；n-step/GAE 参数化光谱（04/08）。
  2. on-policy vs off-policy？→ 两问：数据谁采、更新谁；Q-learning off（可复用数据），SARSA on（学含探索的值）（05）。
  3. Q-learning 为什么会高估？→ max 作用在噪声估计上；Double DQN 解耦选动作与评估（05/06）。
  4. CliffWalking 上 Q-learning 与 SARSA 的路径差异？→ 最短贴崖 vs 安全离崖；“学得优"vs"走得稳”（05）。
  5. 表格法什么时候够用？→ 状态可枚举、能覆盖、表示稳定；否则函数近似（05）。

深度 RL

  1. Deadly Triad？→ 自举+函数近似+off-policy；正反馈高估回路（04/06）。
  2. 经验回放的两个作用？→ 打破时间相关性 + 样本复用；代价：off-policy 偏差（06）。
  3. 目标网络为什么稳定？→ 冻结自举目标，“追自己尾巴"→"朝固定靶回归”；偏差换稳定（06）。
  4. DQN 的 loss 该用 MSE 还是 Huber？→ Huber 对离群 TD 误差钝感；梯度裁剪配合（06）。
  5. 为什么 DQN 处理不了连续动作？→ 内层 max 是优化问题；策略梯度直接输出分布参数（06/07）。

策略梯度

  1. 策略梯度定理怎么来的？→ log-导数技巧消环境因子；score function × 回报加权（07）。
  2. 基线为什么无偏降方差？→ E[∇log⁡π⋅b]=0\mathbb{E}[\nabla\log\pi \cdot b]=0E[∇logπ⋅b]=0（∑aπ∇log⁡π=0\sum_a\pi\nabla\log\pi=0∑a​π∇logπ=0）；最优基线是 score 平方加权均值（07）。
  3. 优势函数与 TD 误差的关系？→ E[δt]=A(s,a)\mathbb{E}[\delta_t]=A(s,a)E[δt​]=A(s,a)；一个 V 网络三用（基线/自举/优势估计）（08）。
  4. GAE 的 λ 是什么？→ k 步优势的指数加权；λ=0 纯 TD、λ=1 MC；实测 λ=0 不学习（08）。
  5. PPO 的 clip 为什么稳定？→ 挡"继续推"不挡"退回"；数据有效域内截断优化；无 clip 消融 KL 飙 3.2（09）。
  6. PPO 调参看什么指标？→ approx_kl（0.003–0.03）与 clipfrac（<0.3）；loss 几乎无信息（09）。

LLM 对齐

  1. RLHF 三阶段？→ SFT → RM（Bradley-Terry MLE）→ PPO+KL；InstructGPT 1.3B 胜 175B（10）。
  2. KL 惩罚为什么必须？→ RM 只在数据分布附近可信；β 的 U 型权衡（实测 −100 → +12.5 → 10.5）（10）。
  3. DPO 推导主线？→ KL 约束 RL 闭式解 → 隐式奖励 r=βlog⁡(π/πref)r=\beta\log(\pi/\pi_{ref})r=βlog(π/πref​) → 代回 BT 时 Z(x) 相消 → sigmoid 交叉熵（10）。
  4. GRPO 为什么敢删 Critic？→ 组均值 = 免费的 prompt 级基线（基线只需与动作无关）；代价是推理 ×G（10）。

答题要领：每题先一句定义、再一句机制、最后给一个本系列的实验锚点（如"λ=0 实测不学习"、“无 clip KL 飙到 3.2”）——有实验锚点的回答在面试里辨识度极高。

8. 常见误区

  1. 把 train 回报当训练进度（§3 读数 2 的实证：eval 500 时 train50 才 111）。评估协议（独立种子 + 贪心 + 多回合均值）是唯一可信进度条。
  2. 向量化环境不自动 reset（§6 实录）。gymnasium 的 warning 是唯一线索，别忽略。
  3. checkpoint 只存模型不存优化器。恢复训练时 Adam 的动量/二阶矩全丢，等效学习率突变。正确姿势：{"model", "opt", "step"} 三件套（§2.3）。
  4. 自定义环境里用全局随机源。np.random 绕过了 reset(seed=) 的注入，种子固定形同虚设（§4 清单 1）。
  5. GAE 的 bootstrap 在向量化和截断下想当然。跨 env 递推链 + finals 语义（§2.2/2.3）是向量化实现里最容易错的 20 行——写完用"小 rollout 手算对照"验证一次。

本篇小结

  • 完整 pipeline 的分层：环境封装（契约严格）→ 缓冲与 GAE（每 env 独立递推链）→ 训练器（采集/更新/评估/checkpoint 解耦）→ 入口脚本；全部 CPU，100k 步 12.1 秒收敛到 eval 500。
  • 向量化环境的契约：done 后自动 reset、finals 传出真实末状态、terminated/truncated 分开——三条都对应真实 bug。
  • 自定义环境六条契约：随机源唯一、双终止语义、done 后行为、obs dtype/space 一致、reset 完全重置、奖励即时性。
  • 不收敛排查是顺序工程：10 大原因表按频率排序，配合"固定种子→梯度范数→人看轨迹→二分砍组件"的诊断流。
  • 面试 25 题的答法：定义 → 机制 → 实验锚点；本系列的每个实验数字都是你的弹药库。

练习

  1. 把 n_envs 从 8 改成 1、其余不变，重跑 100k 步。对比达到 eval 500 所需步数——量化向量化并行的收益（预期 5–10 倍）。
  2. 给 pipeline 加 KL early-stop（approx_kl > 0.015 跳出 epoch 循环）与"评估最优 checkpoint 保存"（best.pt），跑三种 lr ∈ {2.5e-4, 7e-4, 1.5e-3}，报告各自首个 eval 500 的步数。
  3. 按 §4 模板写一个自定义环境 GridMaze-v0（n×n 网格、四个动作、终点奖励 +10、每步 −0.1、200 步截断），接入本 pipeline 用 PPO 训练。验收：env.reset(seed=42) 两次的 obs 完全一致。
  4. 制造并修复 §5 表中的 #2：把 buffer 的 term/trunc 合并成一个 done 传入 compute_gae，观察训练后期是否出现"约 490 步送死"与 eval 卡 500 以下——然后修复并对比。
  5. 思考题：如果把本 pipeline 搬到 GPU（网络与 batch 在 GPU、环境在 CPU），瓶颈会移到哪一段？结合"每批 2048 步里网络前向次数"（采集 T 次单步前向 + 更新 10×8 次批量前向）估算，说明为什么小任务上 GPU 反而可能更慢。
