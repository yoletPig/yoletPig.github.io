09 - PPO 从零实现

本篇目标

读完本篇，你应该能做到：

  1. 从"一步更新太大就崩"推出 TRPO 的动机与约束优化形式，再看懂 PPO 如何用一行 clamp 把 TRPO 的二阶问题变回一阶。
  2. 分步推导代理目标与重要性采样视角，理解 ratio πθπold\frac{\pi_\theta}{\pi_{old}}πold​πθ​​ 为什么是"策略改动量的测量仪"。
  3. 实现完整 PPO（CartPole，10 项标准超参），跑出真实收敛曲线，并用消融实验实测去掉 clip 后 KL 飙到 3.2、训练震荡——clip 的稳定性作用有数据背书。
  4. 掌握 PPO 调参的"先看什么再动什么"，以及它统治 RLHF 的工程逻辑（10 章的入口）。

08 章 A2C 的遗留问题：策略梯度是一阶方法但没有步长控制。学习率稍大，一次更新把策略推离采样数据的分布太远 → 新策略在旧数据上"过度解读" → 策略崩坏（07 章高方差的另一面）。PPO（Proximal Policy Optimization，Schulman et al., 2017, arXiv:1707.06347）用最朴素的手段解决它，并成为至今 most-widely-used 的 RL 算法。

1. TRPO 的动机：一步更新太大就崩

考虑一个具体失败：当前策略 πold\pi_{old}πold​ 采样了 1000 步数据，其中动作 aaa 平均回报不错。你做了一次"过猛"的策略更新，π(a∣s)\pi(a|s)π(a∣s) 从 0.3 拉到 0.95——但这次更新的依据只有旧策略访问过的那些状态。在旧数据没覆盖的状态上，新策略的行为完全是外推，可能一塌糊涂。RL 里没有"验证集报警"：崩了就崩了，接下来只能从崩坏策略采的崩坏数据里慢慢爬（01 章"数据分布由策略决定"的惩罚）。

TRPO（Trust Region Policy Optimization，Schulman et al., ICML 2015）的形式化解法：把策略改进写成约束优化——在"新旧策略不要离得太远"的约束下最大化改进量：

max⁡θ  Lπold(θ)s.t.DˉKL(πold,πθ)≤δ\max_\theta \; L_{\pi_{old}}(\theta) \quad \text{s.t.} \quad \bar{D}_{KL}(\pi_{old}, \pi_\theta) \le \delta θmax​Lπold​​(θ)s.t.DˉKL​(πold​,πθ​)≤δ

Lπold(θ)L_{\pi_{old}}(\theta)Lπold​​(θ) 是代理目标（下一节），DˉKL\bar D_{KL}DˉKL​ 是新旧策略的平均 KL 散度（"信任域"半径）。名字的含义就在这：只信任当前数据所支撑的一小片策略空间（trust region），出了域的改进不予考虑。TRPO 用二阶方法（KL 的 Fisher 信息矩阵近似 + 共轭梯度）求解——精确但昂贵且难实现，PPO 的全部动机就是把这个二阶问题拍回一阶。

2. 代理目标：从策略梯度定理出发

2.1 重要性采样视角

策略梯度定理（07 章）的期望是按当前策略 πθ\pi_\thetaπθ​ 采样定义的——每更新一步 θ\thetaθ，旧数据的分布就不匹配了，数学上不能再直接用。重要性采样（importance sampling）允许"用旧分布的数据估计新分布的期望"：

Ex∼p[f(x)]=Ex∼q[p(x)q(x)f(x)]\mathbb{E}_{x \sim p}[f(x)] = \mathbb{E}_{x \sim q}\left[\frac{p(x)}{q(x)} f(x)\right] Ex∼p​[f(x)]=Ex∼q​[q(x)p(x)​f(x)]

把 ppp 换成新策略、qqq 换成旧策略，轨迹级期望的修正因子是新旧概率之比的连乘——这就是 ratio。TRPO 论文用 Kaplan 近似把它化简到单步（per-state）形式：

Lπold(θ)=E(s,a)∼πold[πθ(a∣s)πold(a∣s)Aπold(s,a)]L_{\pi_{old}}(\theta) = \mathbb{E}_{(s,a) \sim \pi_{old}}\left[\frac{\pi_\theta(a|s)}{\pi_{old}(a|s)} A^{\pi_{old}}(s,a)\right] Lπold​​(θ)=E(s,a)∼πold​​[πold​(a∣s)πθ​(a∣s)​Aπold​(s,a)]

两个好消息：ratio 只需要旧数据里存下 log⁡πold(a∣s)\log \pi_{old}(a|s)logπold​(a∣s)（一个标量/样本），不用重算轨迹概率；AπoldA^{\pi_{old}}Aπold​ 用 08 章的 GAE 估计。

2.2 读出三个性质

  • θ=θold\theta = \theta_{old}θ=θold​ 时 ratio = 1，LLL 就是当前策略的优势均值——起点处的梯度与普通策略梯度一致（可以验证：对 θ\thetaθ 求导在 ratio=1 处退化为 ∇log⁡π⋅A\nabla \log \pi \cdot A∇logπ⋅A）；
  • ratio > 1 表示"新策略更爱这个动作"，LLL 按优势正负决定该不该继续推高它；
  • ratio 就是"策略改动量的测量仪"——它偏离 1 多远，更新就偏离采集数据的策略多远。PPO 的一切机制都围绕"看着这个仪表盘开车"。

3. Ratio 裁剪：一行的信任域

3.1 从约束到 clamp

PPO 的观察：TRPO 想要的只是"别让 ratio 跑太远"，那何必二阶优化？直接把目标裁剪：

LCLIP(θ)=Et[min⁡(rt(θ)A^t,  clip(rt(θ),1−ϵ,1+ϵ)A^t)],rt(θ)=πθ(at∣st)πold(at∣st)L^{CLIP}(\theta) = \mathbb{E}_t\left[\min\left(r_t(\theta) \hat{A}_t,\; \text{clip}\big(r_t(\theta), 1-\epsilon, 1+\epsilon\big)\hat{A}_t\right)\right], \qquad r_t(\theta) = \frac{\pi_\theta(a_t|s_t)}{\pi_{old}(a_t|s_t)} LCLIP(θ)=Et​[min(rt​(θ)A^t​,clip(rt​(θ),1−ϵ,1+ϵ)A^t​)],rt​(θ)=πold​(at​∣st​)πθ​(at​∣st​)​

ϵ=0.2\epsilon = 0.2ϵ=0.2。逐情形拆开（配图，ratio 横轴、目标值纵轴）：

为什么取 min 还能"单向放行"？ 关键的不对称：裁剪只挡"进一步优化"的方向，不挡"退回"的方向——若 A^>0\hat A > 0A^>0 且 rrr 已经超过 1+ϵ1+\epsilon1+ϵ，min 取裁剪支（梯度 0，不再推高）；但若此时做一次让 rrr 回落的更新，min 会重新选到未裁剪支，梯度恢复。bad case 被锁定，correction 仍被允许——这是它比"硬约束"聪明的地方，也是论文标题 Proximal（“邻近的”）的含义：优化被限制在数据邻域内。

3.2 实测：clip 的稳定性作用（消融实验）

同一实现（§5，lr=7e-4，10 epochs），只把 ϵ\epsilonϵ 从 0.2 改成 10910^9109（等效无裁剪），400 回合对比：

无 clip 时 KL 飙到 3.2（健康值约 0.01 量级）：第 2–10 个 epoch 的更新不断把策略推离采集数据的策略，后面 epoch 的"梯度"在优化一个已经失真的代理目标——没有信任域的 on-policy 复用数据，等于变相 off-policy 还不做任何修正。这就是"为什么 clip 稳定"的完整答案：它在数据的有效性范围内截断优化。

seed=0、CPU 实测：

读数三则：

  1. ep150 的 KL 尖峰是活教材：clipfrac 冲到 0.38（38% 样本的 ratio 出界被裁剪）——裁剪机制自动"踩刹车"，KL 下一窗口回落到 0.006。训练日志里看到这种尖峰不用慌，它是机制在工作，不是失控；持续 >0.05 才需要干预。
  2. 对照组（lr=2.5e-4，其余同）：400 回合 train50=488.1——太保守，学得慢。lr 与 KL 监控的联动见 §6。
  3. 对比 08 章 A2C（ep700 才满分）：样本步数上 PPO（~150 万步）没有优势，但全程没有任何一次崩塌（对照 06 章 DQN 的 ep600 崩塌）——稳定性正是 PPO 的卖点。

6. PPO 调参经验（经验做法）

以下为社区长期共识 + 本文实验支撑，逐条标注依据：

  1. lr 与 epochs 的乘积感：每批数据的有效学习量 ≈ lr × epochs × 过批次数。CartPole 上 lr=7e-4 × 10 epochs 快而稳（§5.3）；lr=2.5e-4 × 10 保守（488@400）。先固定 epochs=10 动 lr，再看 KL 响应。
  2. clip ϵ\epsilonϵ 几乎不用动：0.2 是万金油（论文消融在 0.1–0.3 间差异不大）。需要更"信任域"的场景（大模型 RLHF）常见 0.1–0.2；更激进的机器人任务 0.3。
  3. 监控 approx_kl 与 clipfrac，而不是盯着 loss：健康区间（经验做法）kl ∈ [0.003, 0.03]、clipfrac < 0.3。kl 持续 > 0.05 → lr 太大或 epochs 太多；clipfrac 长期 ≈ 0 → 学得太保守（可加 lr/epochs）。PPO 论文和 Spinning Up 都以此为核心诊断量。
  4. minibatch 内的 advantage 归一化：全局（每批 rollout）归一化一次（本实现）；不要在 minibatch 内各自归一（样本少、噪声被放大——08 章同款教训）。
  5. 价值损失系数：共享主干 → Huber + cv=0.5c_v=0.5cv​=0.5（08 章 §5 事故的直接继承）；PPO 论文原版用 MSE + cv=1.0c_v=1.0cv​=1.0，在大任务上配合 return 归一化使用。
  6. 每批数据 epochs 上限由 KL early-stop 兜底：工程实现常加"若 approx_kl > 1.5×目标值则提前终止本批 epoch 循环"（Spinning Up 的实现包含此逻辑）——教学版省略，生产版必备。

7. 为什么 PPO 统治了 RLHF（10 章的引子）

四个原因，全部是工程性质而非理论性质：

  1. 兼容现有基建：PPO = 监督训练循环 + 采样 + 两个网络， transformer 生态（PyTorch/HF）上改造成本最低；TRPO 的二阶求解器没有生产级实现。
  2. 超参稳定域宽：clip 的"自动刹车"让 lr/epochs 的错误在一定程度上自我修正（§5.3 的 KL 尖峰自愈就是证据）——这对奖励信号噪声极大的 LLM（奖励模型打分天然带噪）是刚需。
  3. 天然支持 KL 正则：RLHF 需要约束策略别离 SFT 参考模型太远（10 章主题），PPO 的 per-token ratio + KL penalty 机制正好承载——InstructGPT（Ouyang et al., 2022）的 RL 阶段就是 PPO。
  4. 分布式友好：采样（生成）与更新解耦，rollout 可以在推理集群上跑——10 章会看到 Stage 7 的 verl 把这个解耦推到极致（HybridEngine）。

代价也要说清：LLM 上 PPO 需要同时驻留 4 个模型（actor、ref、reward、critic），显存与工程复杂度极高——这正是 DPO（10 章）"用推导换工程"的出发点。

8. 常见误区

  1. ratio 忘了 exp() 或把 log 直接相除。ratio = logp / logp_old（错）与 ratio = (logp - logp_old).exp()（对，利用对数恒等式数值更稳）。错误实现的 ratio 量级完全失真，clip 机制形同虚设。
  2. logp_old 存档时不是 no_grad 或存成了带图的张量。采集时 dist.log_prob(a) 建图后 .item() 存 float 是对的；存张量本身会抱着整张图，第二批 epoch 更新时报"backward twice"。另一个常见错误：用当前网络重算 logp 当 old——那样 ratio 恒 1，clip 永不触发，训练退化为普通 A2C。
  3. minibatch 梯度不裁剪 / 裁剪阈值忘改。PPO 单步更新间隔大（rollout 级），梯度尖峰比 A2C 更猛，max_norm=0.5 的保险不能省。
  4. 把 clipfrac 当失败信号。§5.3 显示 clipfrac=0.38 的尖峰后训练照常到满分——它和 KL 一起看才有意义（clipfrac 高 + KL 回落 = 机制在工作；两者都高且持续 = lr 过大）。
  5. rollout 太小 + epochs 太多。批数据 500 步配 10 epochs，相当于同一小撮数据反复读十遍——过拟合单批数据，KL 飙升。经验做法：每批 rollout 至少 ≥ 1000 步（工程默认 2048），epochs 与 batch 大小反比调节。
  6. 价值头回归目标是 GAE 优势而不是 return。critic 应拟合 R^t=A^t+V(st)\hat R_t = \hat A_t + V(s_t)R^t​=A^t​+V(st​)（λ-return），直接拿 A^t\hat A_tA^t​ 当回归目标会把 V 学成优势（尺度完全错），策略损失的基线随之失效。

本篇小结

  • TRPO：约束优化实现"稳步改进"；PPO 用 min(r·A, clip(r,1±ε)·A) 一行实现同等意图——裁剪挡住"继续推"，不挡"退回修正"。
  • ratio 是策略改动量的测量仪；重要性采样视角解释了为什么 on-policy 数据能重用 10 个 epoch。
  • 消融实测：无 clip 时 KL 飙到 3.2、曲线震荡（ep400 回落 423）；有 clip 时 KL 尖峰自愈、ep350 满分——clip 的稳定性有数据背书。
  • 调参核心仪表盘是 approx_kl 与 clipfrac，健康区间 [0.003, 0.03] / < 0.3（经验做法）；loss 本身几乎不提供信息。
  • PPO 统治 RLHF 靠的是工程性质：基建兼容、超参稳定域宽、天然承载 KL 正则、采样与更新解耦。10 章把它接上 LLM。

练习

  1. 复现 §3.2 的无 clip 消融（ϵ=109\epsilon=10^9ϵ=109），画出你的 kl 曲线。确认 KL 是否出现过 > 1 的尖峰，并观察它与训练回报回落的时间对应关系。
  2. 实现 KL early-stop：在每个 minibatch 更新后检查 approx_kl > 1.5 * 0.01 则跳出本批 epoch 循环（Spinning Up 逻辑）。对比有/无 early-stop 在 ep150 尖峰处的行为差异。
  3. 把 GAE 换成 MC 优势（A^t=Gt−V(st)\hat A_t = G_t - V(s_t)A^t​=Gt​−V(st​)，即 λ=1\lambda=1λ=1），重跑 400 回合。对比收敛速度与稳定性——验证 08 章 λ 消融的结论在 PPO 里是否保持。
  4. 把 rollout 从 10 回合减到 1 回合（epochs 保持 10），观察 KL 与 clipfrac 如何爆炸。用 §8 误区 5 解释。
  5. 思考题：GRPO 把 PPO 的 value/critic 整个删掉，用"组内回报减均值"替代优势（库内 Stage 7 的核心设计）。用本章的仪表盘语言说明：GRPO 保留了 PPO 的哪些保险丝、删掉了哪些部件？它为什么敢删（提示：LLM 场景奖励只在句尾、且稀疏）？（10 章正式展开。）
