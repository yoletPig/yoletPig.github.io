11 - C++ 测试与双语言工程：GoogleTest 到 pybind11

本篇目标

  1. 掌握 GoogleTest 的日常主干：EXPECT vs ASSERT、夹具 TEST_F、参数化 TEST_P 与死亡测试；
  2. 会用 CMake FetchContent 把 gtest 接进项目，理解 CTest 的注册与过滤；
  3. 理解 C 代码的链接期注入桩思想——为什么 C++/C 侧不需要运行时 mock 框架也能替换依赖；
  4. 建立双语言项目（Python 调 C++/pybind11）的测试布局，把 Sanitizer 与 gtest 组成组合拳。

1. GoogleTest 基础：断言宏与夹具

GoogleTest 是 C++ 测试事实标准（Google 内部最大规模使用，开源生态同）。先看它与 pytest 的概念对应：TEST ≈ def test_，夹具 ≈ pytest fixture 的类形态。

断言分两族：EXPECT_*（失败后继续执行本测试）与 ASSERT_*（失败后立即返回）。实测一段失败代码的输出：

选择规则一句话：失败的值要拿来继续用（解引用指针/访问容器），必须 ASSERT——否则下一行就是对无效状态操作，轻则报错刷屏，重则段错误掩盖真相；只是多查几个独立断言，用 EXPECT 一次看全。常用宏族：EQ/NE/LT/LE/GT/GE、TRUE/FALSE、浮点用 NEAR(v, abs_error)（浮点直接 EQ 是新手经典错误）、字符串 STREQ/STRNE。

夹具（TEST_F）：需要共享构建逻辑时，继承 ::testing::Test，SetUp()/TearDown() 对应 pytest 的 yield 前后段（03 篇的洋葱模型完全适用，但注意：gtest 夹具每个测试各建一个新实例——成员变量天然隔离，等价 pytest 的 function 作用域）：

与 pytest 的分工建议：pytest fixture 的依赖注入更灵活（03 篇），gtest 夹具胜在类型安全与编译期装配——C++ 侧没有 pytest，这套夹具就是标准答案。

**参数化（TEST_P）**＝ C++ 版的 @pytest.mark.parametrize：

TEST_P 定义模板、INSTANTIATE_TEST_SUITE_P 实例化——三组数据生成三个独立用例（Normal/DiviParam.MatchesConvention/0..2，实测 5 tests passed）。选失败的用例：./calc_tests --gtest_filter='Normal/DiviParam*'（pytest 的 -k 等价物，还有 --gtest_repeat、--gtest_shuffle 对应 08 篇的独立性体检）。

死亡测试：断言"这个调用应当死/抛"——C++ 版的 pytest.raises：

EXPECT_DEATH(func(), "正则匹配崩溃输出") 则面向真正的崩溃（assert 失败/abort），验证崩溃发生在预期的检查点上——防御性编程的自检必须有测试，否则有人删掉 assert 你都不知道。

4. C 代码注入桩：链接期替换思想

Python 的 mock 靠运行时对象替换；C/C++ 的等价机制在链接期——链接器解析符号时，谁被链进最终二进制，谁就是实现。于是"替换依赖"变成一个构建系统问题：

测试方案：写一个同名同签名的桩文件 sensor_stub.c，测试目标链接桩、生产目标链接真实现：

这就是 Feathers 说的 link seam（06 篇）在 CMake 里的标准实现：不改一行被测代码，替换发生在链接命令的文件清单里。三个进阶形态按需取用：① 函数指针表（运行时注入，等价 06 篇构造函数注入，适合"同一进程内要切换"的场景）；② weak symbol（__attribute__((weak)) 让真实现默认可覆盖，测试文件直接定义强符号——侵入源码，谨慎）；③ ld --wrap=symbol（链接选项级替换，-Wl,--wrap=read_temperature 把调用重定向到 __wrap_read_temperature，不用改任何文件，适合"只想在测试时截获某个第三方调用"）。经验做法：优先"两套 object library"方案——它最显式，CMake 图谱上一眼可查；--wrap 留给动不了构建图的遗留死角。

5. Python 调 C++：pybind11 绑定的边界测试

双语言项目的典型结构：性能内核 C++，胶水与业务 Python（pybind11 出 bindings）。测试分三层，风险集中在第二层：

  1. C++ 内核单测（gtest，第 1~3 节全覆盖）——测到 C++ 语义层为止；
  2. 绑定层边界测试——pybind11 只是把 C++ 类型翻译成 Python 对象，但翻译有损耗：类型转换失败（C++ 抛 std::invalid_argument，Python 侧应看到 ValueError）、GIL 与回调、引用生命周期（返回 const T& 的临时悬垂）、numpy 数组步长/dtype 不匹配。这层用 pytest 测（Python 是边界的母语），每条边界一个用例：
  1. 端到端冒烟——import 后调用一条核心链路，验证 .so 与 Python 包版本匹配、依赖库（ldd 检查）完整。绑定层的编译产物跟 Python ABI 相关（pybind11::ABI），CI 矩阵里 Python 版本 × C++ 编译器两个维度都要覆盖（08 篇矩阵策略）。

经验做法：绑定层薄是纪律——pybind11 文件里不写业务逻辑（只写翻译），业务进 C++。这样第 2 层的测试面恒定且小，gtests 覆盖业务，pytest 只守翻译。

布局背后的三条纪律：

  1. 每种语义用它的母语测：C++ 语义（RAII、移动、溢出）gtest，Python 语义（接口、协议、异常翻译）pytest——跨语言硬测（用 pytest 触发 C++ 内存 bug）既慢又盲；
  2. 两层测试经 CI 矩阵正交组合：gtest×(gcc/clang)×(Debug/ASan)、pytest×(py3.10/3.12)，绑定层只在"两边都绿"的组合上跑端到端（08 篇 yaml 的 cpp/python job 对应）；
  3. 版本与 ABI 显式对齐：pybind11 版本、C++ 标准、Python 版本三者在 CI 的同一个缓存键下（uv 08 篇 + ccache），漂移即红。

常见误区

误区一：EXPECT_EQ 比较浮点。 0.1+0.2 != 0.3 在 C++ 同样成立，浮点一律 EXPECT_NEAR 或比较 ULP。

误区二：夹具里放共享可变状态。 gtest 每测试新建夹具实例是对的，但成员是静态（static）或指向全局的单例时，隔离即失效——等价 03 篇的"session 级禁放可变状态"。

误区三：死亡测试吞掉所有崩溃。 EXPECT_DEATH 用过宽的正则（如匹配任意输出）会连"错误位置的崩溃"都判绿；正则必须锚定预期的检查点消息。

误区四：链接期桩造成"测试通过假象"。 桩与真实现签名漂移（真实现改了参数，桩还是旧的）后测试全绿而线上崩。对策：桩与真实现共用同一个头文件声明，头改了两边一起编译失败；这正与 04 篇"Fake 与真实现共享接口"的原则同构。

误区五：绑定层里塞逻辑。 pybind11 文件越写越大最后变成"第二实现"，C++ 单测覆盖不到它、pytest 也不懂它的语义。绑定层只翻译，行数超阈值就是重构信号。

本篇小结

  • gtest 主干：EXPECT（继续）vs ASSERT（中止），指针/容器解引用前必 ASSERT；浮点 NEAR；夹具=每测试新建实例的 TEST_F；
  • TEST_P+INSTANTIATE 参数化、--gtest_filter 精确选择；EXPECT_THROW/DEATH 把"应当死"变成规格；
  • FetchContent 五行接 gtest，gtest_discover_tests 让 CTest 逐用例粒度；版本钉死可换源；
  • C 侧替换是链接期问题：同名桩 + object library 二选一（link seam），进阶有函数指针/weak symbol/--wrap；桩与真实现共头文件防漂移；
  • pybind11 绑定层薄且只翻译：pytest 测异常翻译/dtype/生命周期边界，CI 矩阵覆盖 Python ABI；
  • 双语言布局"各测各的母语"，正交矩阵组合；Sanitizer+gtest 换装不换用例，nightly 全量跑。

练习

  1. 把 1 节的 Stack 补全 pop 空栈行为（抛异常或返回哨兵），用 EXPECT_THROW（或 EXPECT_DEATH）把它钉进测试。
  2. 给 DiviParam 加第 4 组用例（负数除法），并用 --gtest_filter 只跑它；再用 --gtest_shuffle 跑三遍验证测试间独立性。
  3. 按第 3 节从零搭一个 FetchContent 项目（钉 v1.14.0），记录首次配置与第二次配置的耗时差，解释 FetchContent 的缓存目录（build/_deps）为什么能让第二次几乎瞬间完成。
  4. 实现第 4 节的两套 object library：core_tests 链 sensor_stub，另一个 sensor_tests 链 sensor_real（真实现桩成读环境变量），跑通并解释链接清单如何决定行为。
  5. 给 pybind11 绑定写"异常翻译矩阵"：C++ 的 invalid_argument/runtime_error/std::out_of_range 三种异常，pytest 侧断言翻译成什么、消息是否保真。
