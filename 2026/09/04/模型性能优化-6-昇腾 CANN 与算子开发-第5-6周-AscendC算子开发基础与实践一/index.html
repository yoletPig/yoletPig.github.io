1. 第一性原理：为什么要"显式流水"编程

1.1 GPU 与 NPU 编程模型的差异

CUDA 里，数据在显存，线程自己去读，硬件帮你调度访存。Ascend C 更显式：你要亲自安排数据在内存层级间的搬运（HBM → L1/UB → 计算单元），并让"搬运"与"计算"流水并行——这是性能的关键，也是难点。

1.2 内存层级

计算单元不能直接高效吃 HBM 数据，要先搬到 UB；搬完才能算。若"搬一块→算一块→搬下一块→算下一块"串行做，搬运和计算互相等待。double buffer 流水就是来解决这个问题的。

2.2 Tiling：任务怎么分给多个核

一块芯片有多个 AI Core。Tiling 决定"总任务怎么切、每个核算哪部分、每块多大"。Tiling 参数在 host 侧算好，传给 kernel。

对 (R, C) 的矩阵：

  • 按行切：每核分 rows_per_core 行；
  • 每核内再按 tile_rows 分块，逐块流水处理。

Tiling 的取舍：块太小 → 流水启动/收尾开销占比高；块太大 → UB 装不下。要满足 块大小 ≤ UB 容量 且让每个核都有足够活干。

深入拆解：Tiling 公式在干什么（手算小例）

Tiling 的核心约束是一条显存预算不等式：一次流水处理的中间数据必须全部装进片上 UB。对本算子，一次要同时在 UB 里放输入 xxx、残差 rrr 和输出 yyy 三块 FP16 数据：

tileRows×C×2B⏟x+tileRows×C×2B⏟r+tileRows×C×2B⏟y≤UB 容量\underbrace{\text{tileRows} \times C \times 2\text{B}}_{x} + \underbrace{\text{tileRows} \times C \times 2\text{B}}_{r} + \underbrace{\text{tileRows} \times C \times 2\text{B}}_{y} \le \text{UB 容量} xtileRows×C×2B​​+rtileRows×C×2B​​+ytileRows×C×2B​​≤UB 容量

  • 为什么需要：UB（Unified Buffer，片上缓冲）容量有限，装不下就要么溢出报错、要么被迫分成更多小块；
  • 符号含义：tileRows 是每次流水处理的行数，CCC 是每行列数，FP16 每元素 2 字节；UB 容量随芯片型号而异（910B 一代约 256 KB，老型号 192 KB——以官方规格为准）；
  • 手算小例：C=4096C = 4096C=4096（一行 FP16 = 8 KB），UB 取 256 KB：tileRows≤256/(8×3)≈10\text{tileRows} \le 256 / (8 \times 3) \approx 10tileRows≤256/(8×3)≈10，即每次流水最多搬 10 行（再留点余量取 8）；
  • 结果拿来做什么：这个 tileRows 就是写 kernel 时每次 DataCopy 的分块大小，也是 Tiling 结构体要传给 kernel 的关键参数。

2.3 Double Buffer 流水

用两块缓冲轮流：搬第 2 块的同时算第 1 块，算第 1 块的结果往外搬的同时搬第 3 块……搬运与计算重叠。

3. fused Add + RMSNorm 算法回顾

输入 xxx、残差 rrr、权重 γ\gammaγ，目标：

三步：① 逐元素加；② 求每行的均方根（归约）；③ 逐元素乘缩放与 γ\gammaγ。对应到硬件：①③ 是 Vector 逐元素，② 是 Vector 归约。

6. 工程权衡与失效模式

6.1 权衡

  • 块大小：受 UB 容量约束，太小流水开销大、太大装不下；
  • 累加精度：归约用 FP32 累加防误差累积，但略慢；
  • 半精度：FP16 省带宽但需注意范围。

6.2 失效模式

  1. UB 溢出：块太大装不下。修复：减块大小、核对 UB 容量。
  2. 流水没起来：串行等待、未用双缓冲。修复：核对 EnQue/DeQue 顺序，让搬与算重叠。
  3. 归约误差大：FP16 累加溢出。修复：中间用 FP32 累加。
  4. Tiling 分块不均：某核没活干/越界。修复：处理不能整除的余数行。

7. 延伸思考题（含解析）

Q1：Ascend C 的 Kernel、Tiling、流水各管什么？
A：Kernel 是设备侧每核的计算逻辑；Tiling 在 host 侧决定任务怎么切给多核、每块多大；流水（double buffer）让数据搬运与计算重叠。三者协作：Tiling 定分工，Kernel 定算法，流水定执行节奏。

Q2：double buffer 为什么能隐藏访存延迟？
A：用两块缓冲，搬第 2 块的同时算第 1 块、搬出第 0 块，三个阶段重叠。稳定后每步同时有搬入/计算/搬出在进行，访存延迟被计算掩盖，硬件利用率提高。

Q3：Tiling 的块大小怎么定？
A：上界是 UB 容量（块必须装得下）；下界是让流水启动/收尾开销占比可接受。在两者间选能整除或余数最少、且每核有足够活的值。

Q4：fused Add+RMSNorm 里哪步是归约？为什么它比逐元素难？
A：求每行均方根是归约（把一行压成一个数）。它需要跨元素累加、涉及累加精度（要 FP32 防溢出）和分块时的跨块合并，比纯逐元素复杂。

Q5：为什么归约要用 FP32 累加，即使输入是 FP16？
A：FP16 范围小，长累加易溢出/精度丢失。用 FP32 累加器累计平方和更稳，最后再转回。这是数值稳定性的常见实践。
