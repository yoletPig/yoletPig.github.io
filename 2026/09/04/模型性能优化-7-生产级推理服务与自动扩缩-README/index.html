Stage 7 教程索引：生产级推理服务——Ray Serve / K8s 与自动扩缩

本目录是《学习计划》的配套教程，按周组织。每篇教程遵循统一框架：第一性原理与设计推导 → 系统架构与数据流 → 工程权衡与失效模式 → 实现与验证（可运行代码）→ MVP 交付指导 → 延伸思考题（含解析）。

⚠️ 模拟环境约束：本阶段所有 K8s 实验在单台云主机上用 Kind/minikube 模拟多机，不做真实多机压测。教程会明确标注"模拟能验证什么、不能验证什么"，压测数据用小规模外推并标注来源。这是你前一轮确认的约束——架构设计与可复现的模拟演练优先。

贯穿全阶段的一条主线

请求→接入层→路由层→推理层（引擎集群）→存储层响应\text{请求} \xrightarrow{\text{接入层}} \xrightarrow{\text{路由层}} \xrightarrow{\text{推理层（引擎集群）}} \xrightarrow{\text{存储层}} \text{响应} 请求接入层​路由层​推理层（引擎集群）​存储层​响应

从"单引擎调优"（Stage 5）上升到"生产级服务架构"：容量规划定规模、编排定结构、扩缩定弹性、可观测性定信心、成本定可持续性。本阶段的最终产出是一份生产级部署设计文档——它同时是你架构面试的主答卷。

前置依赖

  • Stage 5 的单引擎调优结论（单卡最优配置与压测基线）；
  • 单台云主机（跑 Kind 集群与模拟）；
  • 依赖：pip install ray[serve] locust，Docker + Kind。

与语音方向的接口

本阶段的架构设计要能承载语音方向的云端服务（ASR/TTS/Omni serving）。第 2 周的 Ray Serve 多模型编排会直接用"VAD→ASR→LLM→TTS"级联做例子——两个方向在这里汇合。
