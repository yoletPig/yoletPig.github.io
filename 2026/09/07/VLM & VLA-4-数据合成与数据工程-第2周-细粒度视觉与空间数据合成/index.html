第 2 周教程：细粒度视觉、空间与感知数据自动化合成

本周要回答的三个问题

  1. Grounding DINO 与 SAM 的分工是什么？"开放词表检测 + 无监督分割"为什么能组成自动标注流水线？
  2. 检测框坐标如何变成符合模型训练规范的归一化坐标与空间关系 QA？
  3. 从 2D 到 3D/Pose 的数据拼接，几何量到自然语言 prompt 的映射逻辑是什么？

对应学习计划：第 2 周。交付物：自动标注脚本，输入 50 张普通场景图，用 Grounded-SAM 提取核心物体 BBox，生成 200 条含归一化坐标与空间方向逻辑的 Grounding/Spatial Reasoning 训练数据。

这是三条合成产线中唯一能产出物理级精确真值的一条——教师模型会幻觉，但检测器的坐标不会"大概觉得"。Stage 3 诊断出的定位/空间短板，主要靠这条线补。

1. 第一性原理：程序化工具为何优于教师模型

1.1 根本矛盾：语言模型给不了"数字级真值"

Stage 1 讲过 VLM 的空间编码先天薄弱；Stage 3 证实了教师 VLM 在空间任务上同样不可靠（Adversarial POPE 的脆性）。而 Grounding 数据需要的真值是精确数字（框坐标），让任何 LLM/VLM"说出"坐标都是在赌它的内在回归头——可控性与可验证性都差。

解法是把任务分解给两个各司其职的专家模型：

Grounding DINO⏟语言→框 (开放词表检测)+SAM⏟框/点→精确 Mask (类无关分割)⇒自动化标注\underbrace{\text{Grounding DINO}}_{\text{语言} \to \text{框 (开放词表检测)}} + \underbrace{\text{SAM}}_{\text{框/点} \to \text{精确 Mask (类无关分割)}} \Rightarrow \text{自动化标注} 语言→框 (开放词表检测)Grounding DINO​​+框/点→精确 Mask (类无关分割)SAM​​⇒自动化标注

  • Grounding DINO（Grounding DINO: Marrying DINO with Grounded Pre-Training for Open-Set Object Detection）：把文本编码（BERT）与图像特征做跨模态融合，输出任意文本短语对应的检测框——不需要预定义类别表（这是"开放词表"的含义，传统检测器如 YOLO 只认训练时见过的类别）。
  • SAM（Segment Anything）：类无关的提示式分割，输入框/点提示即输出高质量 Mask。它"不懂语义"但"描边极准"。

互补的关键在误差结构：DINO 的框位置有像素级误差，SAM 的 Mask 边缘极准但需要语义提示——Grounded-SAM 把 DINO 的框喂给 SAM 取 Mask，语义来自 DINO、精度来自 SAM。这种"语义头 + 几何头"的组合，误差可独立校验（框对不对看 DINO 置信度与人工抽检，Mask 精度由 SAM 的架构保证），而教师 VLM 的输出误差不可分解、不可校验。这就是自动标注流水线的第一性优势。

1.2 坐标规范的工程决策

原始检测框是像素坐标 [x1,y1,x2,y2][x_1, y_1, x_2, y_2][x1​,y1​,x2​,y2​]（左上、右下）。训练数据需要归一化——归一化基准必须与目标模型的推理约定完全一致（Stage 3 失效 3 的教训）：

约定 公式 采用者
0~1000 整数（相对坐标） ⌊1000⋅x/W⌋\lfloor 1000 \cdot x / W \rfloor⌊1000⋅x/W⌋ Qwen2-VL（官方 grounding 约定，输出也按此解读）；Qwen3-VL 回归此制
绝对像素坐标 xxx（原图/缩放后图的像素值） Qwen2.5-VL（改用输入图实际尺寸的绝对坐标，bbox_2d: [x1,y1,x2,y2]）
0~1 浮点 x/Wx / Wx/W 部分学术模型
0~100 浮点 100⋅x/W100 \cdot x / W100⋅x/W 部分历史实现

注意代际差异：Qwen2-VL 系是 0~1000 归一化，Qwen2.5-VL 切换为绝对像素坐标（相对模型实际读入的缩放后图像，若自己又 resize 需回缩放），选错约定会让定位数据全部失效。学习计划写的 [ymin, xmin, ymax, xmax] 顺序提醒我们另一件事：分量顺序也是约定的一部分。Qwen2-VL/2.5-VL 实际使用 [x1,y1,x2,y2][x_1, y_1, x_2, y_2][x1​,y1​,x2​,y2​] 顺序。铁律：以目标模型的官方文档/数据样例为准，配一条静态校验断言（Stage 3 第 3 周 3.1 的正则校验器直接复用），整条管线全局唯一约定。

1.3 从几何到语言：空间关系的可计算定义

把两个检测框变成"空间关系 QA"，需要把"左/右/上/下"变成可计算的几何谓词。以水平关系为例（aaa, bbb 为框中心）：

left(a,b)  ⟺  (xacenter<xbcenter)∧(∣yacenter−ybcenter∣<α⋅min⁡(ha,hb))\text{left}(a, b) \iff (x_a^{center} < x_b^{center}) \wedge \left(|y_a^{center} - y_b^{center}| < \alpha \cdot \min(h_a, h_b)\right) left(a,b)⟺(xacenter​<xbcenter​)∧(∣yacenter​−ybcenter​∣<α⋅min(ha​,hb​))

这个公式在干什么：把人类语言里的"在左边"翻译成两个几何条件——① aaa 的中心 x 严格小于 bbb 的（主条件）；② 两者中心的纵向偏差小于 α×\alpha \timesα×（两框高度的较小者）（护栏条件，α\alphaα 经验值 0.5~1.0）。两个条件同时成立才允许生成"a 在 b 左边"的 QA，否则跳过。

第二个条件是抗角度歧义带：两物体一高一低时（对角线摆放），纯 x 比较会说"左"，但人类感知会犹豫。引入 α\alphaα 限定"只在纵向偏差不悬殊时才断言水平关系"，否则生成"左上方"这类复合关系或干脆跳过——宁可少生成，不生成真值含糊的数据。这是空间合成最重要的纪律，因为模型无法从自相矛盾的标注中学到一致的方位概念。

垂直关系对称（yyy 比较为"上"，注意图像坐标系 y 轴向下）。相对尺寸关系（“大的那个”）用面积比较，同样设显著性阈值（面积比 >1.5 才断言"更大"）。

2. 系统架构与数据流

2.1 Grounded-SAM 自动标注流水线

QA 组装器刻意不用 LLM：模板化生成保证措辞可控（不会引入教师幻觉），几何真值保证答案精确。LLM 的用武之地在"多样化问法改写"——但那是第 1 周管线的职责，且改写只动 question 不动 answer（答案永远由几何计算产生，这是本条线的红线）。

2.2 三类模板的数据样例

provenance 字段记录每条数据的真值来源与置信度——第 4 周过滤与后续坏例回溯全靠它。

2.3 3D / 多视角数据的构建逻辑（概念层）

学习计划要求的 3D/Pose/相机参数拼接，核心是几何量 → 自然语言的映射表设计：

几何量 来源 语言映射示例
相机内参/外参 标定文件或 SfM 重建 “相机距桌面约 0.8 米，俯视角约 30°”（量化分桶后模板化）
物体 3D 框 / 6D Pose RGB-D 传感器 / 位姿估计模型 “马克杯在桌面左前方，杯口朝向右上方”
深度图 深度相机 / 单目估计 “离相机最近的物体是键盘（约 0.6m）”
ERP 全景 全景相机 “正北方向是门，右侧（东）是窗户”

工程要点：连续几何量必须先分桶再进语言——"俯视角 27.3°"这种数字对模型是噪声，"俯视/平视/仰视"三桶才是可学习的离散监督。映射表本身要版本化：换个分桶方案，全量数据要能重新生成（provenance 记录映射表版本）。
