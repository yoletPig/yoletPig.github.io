第3周-剪枝从非结构化到结构化

发表于 2026-11-05 分类于 模型性能优化 ， Stage 1-剪枝与量化基础实战 阅读次数： 本文字数： 4.1k 阅读时长 ≈ 15 分钟

第 3 周教程：剪枝——从非结构化到结构化（Wanda / SparseGPT / LLM-Pruner）

本周要回答的问题

  1. 剪掉一半权重，为什么模型还能用？"重要性"到底怎么定义？
  2. Wanda 的激活加权 ∣W∣⋅∣X∣|W| \cdot |X|∣W∣⋅∣X∣ 凭什么不重训就能剪？它与 SparseGPT 的二阶补偿差在哪？
  3. 2:4 结构化稀疏在 Ampere Tensor Core 上的硬件机制是什么？为什么 50% 稀疏能真提速而普通稀疏不能？
  4. 通道剪枝后为什么要微调恢复？剪枝率-精度曲线长什么样？

对应学习计划：第 3 周。交付物：① 对 Qwen2.5-1.5B 做 Wanda 50% 非结构化剪枝并测困惑度损失；② ResNet-18 CIFAR 通道剪枝 + 微调恢复曲线；③ 解释 2:4 稀疏的硬件加速原理。

1. 第一性原理：稀疏 = 用"重要性排序"换参数预算

1.1 问题定义

剪枝要解的问题：给定预算（保留 k%k\%k% 参数），找出使任务损失最小的参数子集。形式化为

min⁡m∈{0,1}∣W∣ L(m⊙W)s.t.∥m∥0≤k∣W∣\min_{m \in \{0,1\}^{|W|}} \ \mathcal{L}(m \odot W) \quad \text{s.t.} \quad \|m\|_0 \le k|W| m∈{0,1}∣W∣min​ L(m⊙W)s.t.∥m∥0​≤k∣W∣

这是组合优化（NP 难），所有实用算法都是在用不同的**重要性代理（importance proxy）**做近似。

1.2 三代重要性代理

算法 重要性定义 需要重训？ 代表
Magnitude ∣Wij∣|W_{ij}|∣Wij​∣ 需要（经典 30 轮迭代剪枝） Han et al. 2015
Movement 训练中 ∣Wij∣|W_{ij}|∣Wij​∣ 的移动量 需要 Movement Pruning
Wanda ∣Wij∣⋅∣Xj∣|W_{ij}| \cdot |X_j|∣Wij​∣⋅∣Xj​∣（权重 × 输入激活范数） 不需要 Sun et al. 2023
SparseGPT 剪一列后的二阶输出误差（Hessian） 不需要（一次性） Frantar & Alistarh 2023

1.3 Wanda 为什么有效：一行输出的误差分解

考虑线性层 y=Wxy = Wxy=Wx。剪掉 WijW_{ij}Wij​ 造成的输出误差期望约为 ∣Wij∣⋅∣xj∣|W_{ij}| \cdot |x_j|∣Wij​∣⋅∣xj​∣——权重小但输入通道幅度大的连接，剪掉同样致命。Wanda 的重要性即按列激活范数加权：

Sij=∣Wij∣⋅∥X⋅j∥2,每行保留 S 最大的 k% 个S_{ij} = |W_{ij}| \cdot \|X_{\cdot j}\|_2, \qquad \text{每行保留 } S \text{ 最大的 } k\% \text{ 个} Sij​=∣Wij​∣⋅∥X⋅j​∥2​,每行保留 S 最大的 k% 个

两个关键设计：① 按输出行独立剪（保持每行稀疏率一致，避免某些神经元被剪空）；② 激活范数用一小批校准数据统计——与第 2 周校准完全同构。这就是"不重训也能工作"的原因：它用的是一阶泰勒项的幅度，而 LLM 权重在预训练后已处于良好局部极小，一阶近似足够。

1.4 SparseGPT：把剪枝写成逐列最小二乘

SparseGPT 把每层剪枝视为

arg⁡min⁡W^∥XW⊤−XW^⊤∥F2s.t. W^ 满足稀疏约束\arg\min_{\hat W} \|XW^\top - X\hat W^\top\|_F^2 \quad \text{s.t. } \hat W \text{ 满足稀疏约束} argW^min​∥XW⊤−XW^⊤∥F2​s.t. W^ 满足稀疏约束

用 Hessian H=2XX⊤H = 2XX^\topH=2XX⊤（与 GPTQ 完全同源的累积式，Stage 2 第 1 周会再推一遍）做二阶补偿：剪掉某元素后，把该行其余元素的误差按 H−1H^{-1}H−1 最优摊还。相比 Wanda 的一阶近似，它在 60%+ 高稀疏率下显著更稳，代价是要逐层解小线性系统（慢一个量级，但仍免重训）。

1.5 LLM-Pruner：结构化剪枝的依赖图

非结构化剪枝产生稀疏矩阵，通用硬件上并不加速（稀疏存储格式与密集计算单元的矛盾）。LLM-Pruner 转向结构化剪枝：直接删整条通道/头/层。难点是 Transformer 内部存在耦合结构（残差、RoPE 多头、共享 FFN 门控），盲删会破坏形状一致。它的方案：

  1. 依赖图（dependency graph） 分析：识别必须同剪同留的结构组；
  2. 对每个结构组用 LoRA 式低秩恢复：剪掉的主干旁挂一个低秩分支做少量数据恢复训练（通常 < 3 小时），避免全参微调。

1.6 2:4 稀疏：为硬件而生的结构化格式

NVIDIA Ampere 引入的 2:4 结构化稀疏（2:4 Structured Sparsity）：每连续 4 个权重中至多 2 个非零。

硬件机制（A100 稀疏 Tensor Core）：

  • 权重侧：非零值按 2:4 模式压缩存储——只存 2 个非零值 + 2-bit 索引（记录位置），体积近减半；
  • 激活侧：保持密集，但 Tensor Core 的 MMA 单元内置选择逻辑，每个时钟周期跳过索引标记为零的乘累加；
  • 效果：等效算力翻倍（FP16 312 → 稀疏 624 TFLOPS 量级），且不需要稀疏矩阵格式（CSR/COO）的间接寻址。

2:4 压缩存储=2×16-bit 值⏟非零权重+2×2-bit 索引⏟位置编码⇒每 4 个权重共 36 bit≈9 bit/权重\text{2:4 压缩存储} = \underbrace{2 \times 16\text{-bit 值}}_{\text{非零权重}} + \underbrace{2 \times 2\text{-bit 索引}}_{\text{位置编码}} \Rightarrow \text{每 4 个权重共 } 36 \text{ bit} \approx 9 \text{ bit/权重} 2:4 压缩存储=非零权重2×16-bit 值​​+位置编码2×2-bit 索引​​⇒每 4 个权重共 36 bit≈9 bit/权重

为什么任意 50% 稀疏不加速而 2:4 可以：普通稀疏需要索引间接访存 + 不规则计算，访存与调度开销抵消算力收益；2:4 的固定模式让硬件用确定性电路跳过零元素——稀疏要变成硬件指令才有收益。cuSPARSELt / torch.sparse 的 to_sparse_semi_structured 是软件入口。

2. 系统架构与数据流

结构化通道剪枝则多一步：剪完必须微调恢复（其余权重重新适配新容量），曲线先掉后回升。

3. 实现与验证（本周交付核心）

3.1 手写 Wanda（完整可运行，小模型本地可跑）

3.2 在真实模型上跑：两条路

  • 官方路线（推荐先跑）：Wanda 官方仓库（locuslab/wanda）对 Qwen 系模型即改 --model 参数即可：
    python main.py --model Qwen/Qwen2.5-1.5B --sparsity_ratio 0.5 --sparsity_type unstructured --save out/，
    随后用第 2 周的 PPL 脚本评测（Neural Magic 的 SparseML 生态也有对应的 Wanda 修改器，可按环境二选一）。预期：WikiText-2 PPL 从 ~10（1.5B FP16 基线，按你实测）上涨 1~3 点——50% 稀疏下可接受，70% 开始崩。
  • 手写路线：把 3.1 的 WandaPruner 挂到 transformers 模型全部 q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj 上，校准 128 条后统一剪枝，与官方版 PPL 对比（误差应 < 0.2，差异来自激活统计的 batch 聚合方式）。

3.3 通道剪枝 + 微调恢复（ResNet-18 CIFAR-10 曲线）

说明：上面是教学骨架——真实的通道剪枝要联动修改下游层的 in_channels、BatchNorm 与 shortcut，建议用 torch-pruning 库完成依赖图处理，把精力放在"剪枝率-精度"曲线本身。

3.4 2:4 投影：把任意掩码变成硬件能吃的形状（可运行）

任意 50% 稀疏掩码不能直接进稀疏 Tensor Core——必须投影到"每 4 个元素恰好 2 个非零"的 2:4 模式。最小投影算法：每个长度为 4 的窗口内，保留重要性最高的 2 个。

预期输出：三个断言通过；2:4 的保留占比略低于自由掩码——这个差值就是为硬件加速支付的"格式税"。面试讲 2:4 时把三层说全：① 硬件机制（索引压缩 + 选择逻辑）；② 投影算法（组内 top-2）；③ 格式税与训练感知稀疏（SparseGPT 2:4 变体在量化/剪枝时就按 2:4 约束选元素，避免事后投影的损失）。

3.5 剪枝-量化叠加：先剪后量的误差预算视角

本周收尾把"组合拳"的数值直觉补上：50% 剪枝后，剩余权重的分布通常更集中（大幅值权重更可能被保留，但整体方差结构变化），量化网格更容易贴合——这是"先剪后量常比单独量化更好"的经验来源。但两者误差会复合：

总误差≈εprune⏟容量损失+εquant⏟网格损失+εcross⏟复合项（不可线性外推）\text{总误差} \approx \underbrace{\varepsilon_{\text{prune}}}_{\text{容量损失}} + \underbrace{\varepsilon_{\text{quant}}}_{\text{网格损失}} + \underbrace{\varepsilon_{\text{cross}}}_{\text{复合项（不可线性外推）}} 总误差≈容量损失εprune​​​+网格损失εquant​​​+复合项（不可线性外推）εcross​​​

实践规则：叠加后必须重测全指标（PPL + 长输出），绝不能用"剪枝掉 0.5 + 量化掉 0.3 = 共掉 0.8"的线性估计。第 5-6 周基线矩阵里预留一行"剪枝+量化"组合实验，正是为了实测这个交叉项。

4. 工程权衡与失效模式

4.1 权衡

  • 非结构化精度高但无通用加速：Wanda/SparseGPT 的 50% 稀疏只在稀疏 Tensor Core / cuSPARSELt 上有收益；CPU、普通 GPU、NPU 上推理速度不变甚至变慢（稀疏格式间接寻址）。
  • 结构化直接减体积但精度代价大：删通道 = 真减 FLOPs，任何硬件都加速；但容量硬损失，必须微调恢复，且高剪枝率下不可逆。
  • 免重训剪枝的隐含假设：模型处于良好极小点、校准集代表部署分布——微调过的下游模型上效果会打折。
  • 剪枝-量化叠加：先剪后量是可行方向（稀疏权重分布更集中，量化网格更好定），但两者误差会复合，叠加后必须重测全指标，不能线性外推。

4.2 失效模式

  1. 剪枝后 PPL 正常、长文本崩坏：与量化同款陷阱——局部指标不敏感于累积漂移；修复——加长输出评测（Stage 2 第 5-6 周）。
  2. 按行剪导致神经元死亡：症状——某些输出行非零元素极少，激活饱和；根因——全局 top-k 而非按行；修复——Wanda 的按行保留设计（§3.1 已实现）。
  3. 2:4 投影误差：把任意 50% 掩码强行投影到 2:4 模式会丢掉"重要但位置不合"的连接；修复——训练感知稀疏（SparseGPT 有 2:4 变体，直接按 2:4 约束选元素）。
  4. 通道剪枝后忘记重校准 BN：症状——剪完精度崩得离谱；根因——BatchNorm 统计量还对应旧通道集；修复——剪后先跑几个 batch 重建 BN 统计再微调。

5. 延伸思考题（含解析）

Q1：Wanda 为什么按输出行独立保留 top-k，而不是全层全局 top-k？
A：全局 top-k 会让"整行权重都偏小"的神经元被剪空（该行全零 → 神经元死亡、输出恒为 0）。按行保留保证每个神经元至少存活 k%k\%k% 的连接，维持层内表达维度。

Q2：SparseGPT 的 Hessian H=2XX⊤H = 2XX^\topH=2XX⊤ 与 GPTQ 是同一个东西——这暗示了什么？
A：两者都在解"逐列修改权重使层输出重构误差最小"的 OBS 问题：剪枝把某列置零、量化把某列舍入到网格，都是对单列的受约束修改，都用 H−1H^{-1}H−1 把误差摊给其余列。所以 GPTQ 可以看作"把量化当成一种特殊剪枝/约束投影"。（Stage 2 第 1 周推导。）

Q3：为什么 2:4 稀疏的加速只在 batch 较大（算力瓶颈）时明显？
A：batch=1 的 decode 是访存瓶颈（Stage 3 Roofline），稀疏 Tensor Core 翻的是算力上限，对访存瓶颈无用武之地；只有 batch 拉大、GEMM 变成算力瓶颈后，2:4 的 2× 算力才兑现。

Q4：LLM-Pruner 为什么用依赖图？直接删通道会发生什么？
A：Transformer 里残差分支要求加和两侧维度一致、多头注意力的头维耦合、门控 FFN 的两分支必须同维。盲删会产生形状不匹配直接报错，或（若只删一侧）语义破坏。依赖图把必须同剪的结构绑成组，保证剪后仍是合法网络。

Q5：同一个模型，50% 剪枝 vs INT4 量化，哪个对 LLM 更划算？
A：INT4 量化：体积 4×↓、精度损失小（配 GPTQ/AWQ）、所有引擎通吃；50% 剪枝：非结构化无通用加速、结构化掉点大。端侧/云端通用结论都是量化优先，剪枝作为叠加项——这也是本方向课程把量化放在主线的原因。

6. 本周方法论小结：三种压缩路线的误差预算视角

路线 动了什么 误差的性质 恢复手段
量化 数值的分辨率 网格舍入（有界、可补偿） 校准、二阶补偿、QAT
剪枝 参数的存在性 容量永久损失（无界、靠冗余吸收） 微调恢复、依赖图
蒸馏 模型规模 知识损失（用教师分布补） 软标签、反向 KL

这张表就是第 4 周"组合拳"的路线图：三条路线的误差性质不同、恢复手段不冲突，所以可以叠加——但叠加顺序有讲究（先动结构的蒸馏/剪枝，后动数值的量化），第 4 周展开。
